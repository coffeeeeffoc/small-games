# 设计与验收记录

2026-10-06（北京时间）。先生成 `concept.png`，再实现 Canvas 场景；`home.png`、`layouts.png`、`play.png`、`aim.png`、`paused.png`、`result.png`、`shell.png` 是运行时截图。

采用竖屏：反向拖动弹射适合单指操作，圆形擂台不需要横向行进空间。390×780 逻辑画布等比适配，浏览器按安全区留白；横屏缩放居中而不中断对局，不强制方向锁。原生小游戏配置 portrait，宿主全屏，不显示浏览器全屏按钮。

视觉将参考图的暖木、三色小侠与武馆气氛转化为可实时绘制的二维场景。实际原型采用俯视圆形擂台以保证可见边缘与碰撞边界一致；边缘纹理只是装饰，不是阻挡墙。与概念图相比，人物采用原创简化矢量图形，避免静态效果图遮挡动态棋盘。

主菜单突出开始匹配，练习摆位/帮助为次级操作。游玩仅显示回合、行动者、存活者、暂停和场景内方向/力度；避免堆叠说明。暂停用两根等宽平行实心竖条。主路径为主页→匹配/摆位→游玩→结算→再战/回放/主页；设置与玩法页有直接返回路径。

已执行：

- Node 规则/生命周期测试 12 项；五个配置 × 60 个 seed 共 300 场人机模拟，均在 5 次出招内结束。该数据用于发现死局，不代表真实玩家胜率。
- Chromium 390×844、320×568、844×390；CDP 原生触摸拖拽、取消、多触点、转屏保留对局、暂停恢复、失焦、结算、回放不重复奖励、重开及禁用存储均通过，未捕获页面错误。
- shell-web TypeScript 检查与 Vite pages 生产构建；实际生产 iframe 中主页、准备、拖拽出招、暂停、返回、全屏入口通过。
- 微信原生预览包构建与无 DOM SDK 模拟，验证本地音频资源、触控取消、真实输入启动弹射、前后台暂停及释放监听；包体约 206 KB，不含概念图或截图。
- 统一开发模式单元检查、H5 全屏公共回归、小游戏构建测试、依赖边界和 Pages 选择检查。

限制：本次运行环境 Node 24.19.0 / pnpm 11.19.0，仓库声明为 Node ≥24.21.0 / pnpm 12.6.0；实际执行项均以记录结果为准。全量游戏素材准备因既有赛车素材缺失没有完成；单款游戏制品与 Shell 入口单独验证。未验证微信真机、广告或联网功能。
