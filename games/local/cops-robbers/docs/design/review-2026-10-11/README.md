# 围捕小队多角色复核与 120 关扩展

2026-10-11。沿用 [10 月 10 日手机效果图](../viewport-refresh-2026-10-10/viewport-concept.png)、街区角色与棋盘呈现；本次修改集中于选关目录、进度、续玩、触控热区与取消。采用仓库 `game-ui-ux` 的移动布局与输入流程要求，参照 `game-feel` 检查现有选中、移动和围捕反馈，保留减弱动态与声音设置。

## 复核发现与处理

| 角色 | 发现 | 改造 |
| --- | --- | --- |
| 新玩家 | 首页开始只打开地图，进入玩法还需再选一次 | 主操作直接开始或继续有效巡逻，地图入口可单独选关 |
| 玩家与成长设计 | Web 选关、菜单和直链可越级；对抗下一关在未胜利时可进入 | 三套巡逻按目录前关解锁；双方对抗各自保存进度，下一图需胜利；旧已完成 ID 可重玩 |
| 老玩家与存档维护 | 原开放选关留下的有效后期巡逻可能被新锁关丢弃 | 保留旧有效巡逻的进入权限与原局状态，未伪造通关记录 |
| 关卡策划 | 主线、两种对抗各 100 图；接力 6 图，试炼 3 图 | 五种目录均扩至 120；原主线 1–100、试炼 1–3、原接力六个 ID 与顺序保持不变 |
| 规则审查 | 大多数主线图在轮流换人的接力规则下无解 | 接力使用专编地图，120 关均有该规则下的最短解及合法完整回放 |
| 手机触控 | SVG 热区缩小，重叠时可能按绘制顺序选中路口；第二根手指可能结束主拖拽 | 按屏幕坐标选择 22 CSS px 半径内最近路口；第二触点取消拖拽并防止释放产生额外行棋 |
| 内容可发现性 | 单长列表不适合 120 图，切换玩法也可能停在不合适章节 | 试炼、接力各八组，每组 15 图；打开各自存档或下一可玩目标的章节 |
| 学习与挑战设计 | 自动展示完整步骤不适合长期试炼 | 前三关保留完整教学，其后按需请求提示；第三图后正常进入第四图 |
| 性能与开发工具 | 大量试炼启动搜索增加负担，任意试玩会改变玩家成绩 | 新配置和最短解离线生成、静态读取；开发试玩使用独立 practice 存档 |

## 内容与递进

- 围堵挑战 120 图，120 个实际道路布局。远港章节有 22–24 个路口、双目标、双出口；章内前十图平均最短 11.2 步，后十图 13.5 步。各章战术节奏不同，没有填充无意义等待来增加步数。
- 换防接力 120 图，111 个道路布局与 120 套不同地图/起点/出口配置。前后二十图平均最短分别为 6.7、9.8 步。每关三位队员参与，留守不转移接力棒。
- 短场试炼 120 图，105 个道路布局与 120 套不同配置。前三图保留原教学，后续由两人、单目标过渡到三人、岔路与双目标；前后二十图平均最短 4.4、6.7 步。
- 出口竞速、限步周旋各 120 图，各有 120 个唯一道路图。原 1–100 图不变，后期控制在 6×6 路口内，未继续缩小手机节点。
- 生成器只负责离线创作，运行时读取游戏自有内容文件；主线、接力、试炼分别校验 ID、完整路线与普通解锁。

## 实际验证

环境：Linux，Node.js 24.21.0，Chromium 151.0.7922.173；浏览器手机视口与触屏事件模拟，不是实体手机或小游戏宿主验收。

- 主线 120 条合法路线共 1,919 步，全部出口忽略会实际失败、当前局面可提示；原 60 图继续通过缺任意队员全状态穷举。4,800 场随机走位仅 1 场胜利。
- 独立逐层搜索证明 120 条主线最短解，复核 1,410 次提示；120 条接力最短解与 1,014 步回放、120 条试炼路线及限步预算通过。
- 240 个对抗图的连通、唯一道路、有界开局审查、双方先手与 9,600 场随机回放通过，包含第 120 图电脑对局。
- 手机触屏走通普通开始/续玩、锁关、直链、通关解锁、试炼第三图到第四图、三个巡逻第 120 图、返回/继续、旧未完成第 100 图和开发试玩存档隔离；显式 `dev=0` 覆盖存储启用。
- 9 项游戏主界面与手势场景（含真实双触点取消）、20 项交互、72 项弹窗、5 种聚焦布局、11 项双方对抗角色/先手/生命周期检查通过。
- 320×568 与 667×375 覆盖 38/38 页面检查：首页、帮助、设置、玩法、分享、换装、选关、胜负和公共好友 UI。检查真实命中、44 px 热区与视口内位置；好友 API 使用本地响应替身与实际服务端规则。
- 生产静态构建通过，`--dist` 服务再次通过普通玩家、后期触屏、存档与开发试玩隔离检查。

汇总见 [verification.json](verification.json)，生产触屏记录见 [browser-report.json](browser-report.json)。关键实图是 `standard-120-playing.png`（320×568）、`relay-120-playing.png`（390×844）、`quick-120-playing.png`（667×375）及对应结算，沿用既有手机效果图的场景与拇指操作区。

复现：`npm test`、`npm run test:progress`，浏览器检查支持 `BASE_URL` 指定开发或生产服务。准确候选 SHA、提交与 dev 推送由仓库主会话统一处理。公网好友服务、实体手机及微信/抖音等宿主未在本次验证。
