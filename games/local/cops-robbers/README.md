# 围捕小队

手机友好的街区追逐游戏。双方采用中性的 **追逐队 / 突围队**，蓝色盾牌与橙色圆形闪电在轮廓、颜色、队名字样上均有区分。大厅可更换双方队徽、动物、太空造型或上传本地头像；头像只保存在当前宿主设备浏览器，不发送到服务器。即使双方使用相同头像，队色与角色标记也保留。

| 玩法 | 地图 | 目标与角色 |
| --- | --- | --- |
| 快速战术试炼 | 3 张专编小地图 | 两侧夹击、先封后追、双巷分工；分别在 2/3/4 步内全部合围，已验证最短见证为 2/2/4 步 |
| 围堵挑战 | 100 关 / 7 街区 | 操控追逐队，一步调动一人；固定策略电脑全员行动，封住全部相邻退路完成拦截；任意一人到出口即失败 |
| 换防接力 | 6 个精选街区 | 两次实际移动必须换队员，留守不交棒；第 1、4、7、12、16、27 关均有满足约束的完整获胜路线，独立保存星级与步数 |
| 出口竞速 | 100 关 | 人机或好友各操控一队、交替行动；追逐队接触对手完成拦截，突围队到任意出口或撑过回合上限获胜 |
| 限步周旋 | 100 关 | 不设出口；追逐队须在限步内接触拦截，突围队坚持到回合上限获胜 |

自由对抗在人机开局前可选双方角色以及我方先手 / 我方后手 / 系统分配；重试保留该局已分配的先手。好友房间可选角色、交换角色，选择追逐队先手 / 突围队先手 / 系统分配，由服务器确定真实行动顺序并校验每一步。对战画面只提交玩家意图，不在客户端结算排名。

**解法与胜负边界：**挑战 100 关均有击败固定电脑策略的完整回放见证，不代表对真人任意策略均可强制获胜。自由对抗的 200 图均排除了六步内可证明的强制胜利开局，并排除了双方先手情况下不受追逐队任何潜在走位威胁的出口捷径；这是有界开局审查，不是完整博弈均势证明。没有把它们标成数学保证的五五开地图。

## 操作与本地进度

大厅显眼的“先来 2 步收网”按钮直接进入快速试炼。三张地图分别练两侧夹击、先封出口和双巷分工，不复用原 100 关；目标为 2/3/4 步内收网，最短获胜见证为 2/2/4 步。点队员、再点带提示环的路口即可执行第一手。提示会核对剩余步数，来不及完成时明确建议撤销；限步失败可撤销最后一步继续学习。第三场胜利后可直接进入换防接力。

快速试炼独立保存成绩，普通挑战、换防接力和快速试炼分别保留一局未完成巡逻。切换玩法后可继续各自原局；“先来 2 步收网”则明确重新开始第一题。`?mode=quick&level=1&rule=standard` 可分享同题，`level` 仅接受 1–3，角色和先手固定。

挑战与单机对抗都有“分享同题”入口。链接只携带公开地图、玩法和规则；对抗还固定我方角色与该局实际先手。好友从同一题重新开始，链接不携带成绩或好友赛凭证。换防接力的接力棒随撤销和存档恢复，提示也遵守当前接力次序。

- 首次进入大厅，先选玩法、角色、先后手与头像。选择“开始”后进入专注游戏界面。
- 挑战：点队员后点亮起的相邻路口即走；点脚下数字留守；支持拖动、取消拖动、撤销、提示与重开。提示显示当前局面最短还需几步，点高亮数字执行移动或留守。提示使用经过完整广度优先搜索验证的最短路线；偏离后按当前局面重新求最短解。搜索预算不足或超时时不显示未经确认的落点，只有穷尽可达状态后才判定当前局面无解。
- 对抗：点自己的队员与路口移动；可直接点击相邻对手进行接触拦截。电脑行动、对局结束时仍有返回大厅和重新挑战入口。
- 键盘 Tab 选择，Enter / 空格激活；挑战还支持 Ctrl / ⌘ + Z 撤销。
- 人机对抗的选人和双方行动后保留键盘焦点；撤销与空格留守只在当前挑战生效，返回大厅或进入对抗时保留挑战进度。
- 挑战记录沿用 `cops-robbers-v3`，保留原 60 图记录；新对抗的模式、角色、先后手偏好和按角色分开的完成标记使用 `cops-robbers-duel-v1`。清理浏览器数据会删除本地记录和头像。
- `?level=100&motion=reduce` 可直接进入指定挑战关。直接选关不改变之后刷新恢复当前挑战的行为。

## 本地运行与检查

需要 Node.js 22+。运行时无第三方依赖，Playwright 用于浏览器验收。

```sh
npm install
npm run dev
npm test
npm run build
npm run preview
```

默认端口为 43420，PowerShell 可先设置 `$env:PORT=43441`。静态服务只提供游戏资源，不暴露源脚本目录或依赖；构建不删除已有其他文件。头像源文件由仓库根的同步脚本从 `platforms/h5/role-appearance.js` 同步。

保持本地服务开启，在另一个终端运行（可用 `BASE_URL` 指向对应服务）：

```sh
npm run test:browser
npm run test:hints-browser
npm run test:interactions
npm run test:focus
npm run test:dialogs
npm run test:input
npm run test:duel-browser
npm run test:ranking
npm run test:competition-renderer
```

- `test`：100 条原挑战解法逐步回放、合法道路/出口、当前局面恢复、忽略出口必然实际失败；原 60 图继续执行缺任意队员的全状态穷举，新增 40 图检查完整队伍解法及全员参与。另用独立逐层可达性搜索证明全部 100 关最短步数、逐步检查 1,163 次最短提示、六图接力最短路线、偏离路线后的最短恢复，以及搜索未完成和无解的区别。
- `test:optimal`：单独执行最短解与提示审查，报告为 `outputs/optimal-audit.json`。
- `test:hints-browser`：手机上逐关只按提示通关全部 100 关，用真实屏幕坐标点击高亮中心；额外检查 320 像素第 100 关、偏离路线、六图接力、三图试炼以及无解/搜索未完成/错误文案。`LEVEL_IDS` 可用于定点回归；支持 `BROWSER_EXECUTABLE` 指定 Chromium 路径。
- `test:duel`：200 个独立道路图，连接性、真实节点与循环递增、双方角色和先手、接触/出口/限步结算、非法动作、六步开局审查、8,000 场随机回放及分层 AI 对局；报告为 `outputs/duel-audit.json`。
- `test:browser`：真实输入回放全部挑战地图，同时检查触摸、首末关、选关、重开、撤销和存档。`LEVEL_IDS` 可用于定点回归，并生成独立报告以免覆盖全量结果。
- `test:duel-browser`：双方角色 × 两种先手 × 两个模式的真实触摸，电脑响应、重试、返回、完整结果、本地完成标记和窄屏布局。
- `test:dialogs`：桌面、320/390 像素触屏竖屏与横屏检查全部七类弹窗，重复及嵌套开关、胜负退出与继续、返回大厅、主游戏全屏保留；弹窗不含全屏按钮或右上角关闭叉号。
- `test:input`：大厅与人机对抗不会触发后台挑战快捷键、双方角色选人与行棋保持键盘焦点、返回挑战后仍能撤销；支持 `BROWSER_EXECUTABLE` 指定 Chromium 路径。
- `test:relay` / `test:relay-browser`：六图完整接力解与逐步提示、等待与历史边界、重复参数拒绝和干净链接；真实触摸通关六图，检验独立成绩、错误动作、撤销、手机布局和原生分享取消反馈。
- `test:quick` / `test:quick-browser`：三张新图最短解、限步结算和剩余预算提示；真实触摸通关、失败撤销、320 像素竖屏与横屏、同题分享、独立成绩和三种巡逻存档互相恢复。
- `test:ranking` / `test:competition-renderer`：与真正服务器规则模块一致的双方视图和意图校验；这些本地测试不代替公网服务或实体手机验收。

## 关卡维护

`generate-levels.mjs` 维护原 60 关；`extend-levels.mjs` 从其前 60 图构造并验证新 40 关，整批成功后才写入地图与参考路线。修改地图或规则后必须运行 `npm run levels:optimize`，整批精确求解并回放成功后更新 `optimal-solutions.js` 和各关三星步数，再跑规则、最短解与浏览器验收。`solutions.js` 保留原有获胜见证供回放与教学使用；最短提示只使用经过独立审查的 `optimal-solutions.js`，接力步数单独计算。

挑战各街区实际平均最短步数为 **6.1 / 10.1 / 9.0 / 9.1 / 12.6 / 14.3 / 15.8**；第 100 关最短为 **17 步**。原 100 条见证中 78 条比最短路线长，已纠正提示和三星目标。地图仍沿用原布局，最短步数并非逐街区严格递增。自由对抗由前 20 图平均 16 个路口、约 3 条独立环路、6 个分岔路口，增加至末 20 图 36 个路口、约 12 条独立环路、约 20 个分岔路口；电脑由 2 层搜索逐步提升到 4 层。
