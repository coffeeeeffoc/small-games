# 冰川主题核对与接入

2026-09-19。主题独立于路线图；不改变车辆物理、路线控制点、检查点和护栏碰撞。

## 实际查看的图

- 美术目标：`assets/carding-car/expansion/scenes/glacier/concept.png`（仓库根目录下）。蓝冰峡谷、巨大冰拱、分层雪峰、橙白护栏、暖色极地科研站与有高光的冰路。
- 原始模型预览：`assets/carding-car/expansion/scenes/glacier/preview.png`。是一整块自带道路的模型，不能作为任意路线的驾驶表面。
- 改造前实机截图：游戏目录 `reports/glacier/desktop-20m.png`、`desktop-42m.png`、`desktop-85m.png`。已有冰拱、冰壁、冰路和护栏；科研站仅是方盒且被积雪遮住，山峰是单锥，冰壁重复明显。

## 素材差距与准备

复用素材库 `glacier-sample/road.jpg`、`runtime-expansion/textures/glacier.jpg`，以及游戏已有标准材质、生成天空、太阳、阴影和雾。无需新下载、生成图片或复制原始 GLB。

缺少的可适配模块直接用现有合批几何准备：科研站加入米白墙体、橙色屋顶、窗门、架高平台、护栏、台阶和通讯天线；雪峰加入锯齿山脊；冰壁宽度和轮廓有轻微变化。移除主题里固定坐标的整片冰川模型与两座雪峰，避免出现多余道路和与新路线穿插的地块。

## 路线接入

- 冰路与雪岸同时绘制主路及近道，宽度、高程和长度都来自所选路线。护栏只渲染 `track.barriers`。
- 冰壁、雪堆、岩块、科研站依据 `besideRoad` 布置，使用 `clearOfRoad` 避让全部道路分支；科研站前留出视线。
- 冰拱按路宽调整开口。对冰拱所有三角面的保守包围空间调用 `sceneryFits`，同时检查弯道、坡度、其他路段及近道；不适合的落点移动到邻近路段。所有尝试都不安全时省略该座拱桥。
- 冰柱基底落到地面，雪冠、积雪和科研站跟随所在道路高程；远山围绕所选路线包围范围布置。
- 冰柱支撑和垂落冰锥也检查道路净空。冰川退出时同步恢复进入前的天空、环境光、雾、阴影状态；延迟销毁回调带身份检查，不能覆盖新主题的状态。

## 验证

- `node --test tests/glacier.test.ts`：通过。检查法线和索引、8 条现有路线及额外 34 米宽的高程近道路线；每条均保留三座拱桥，逐面采样验证所有分支净空。
- `pnpm --filter @coffeeeeffoc/carding-car typecheck`：通过。
- 本代理未运行 Cocos 构建；改造后的浏览器截图、切换灯光恢复和手机触控检查由主智能体统一执行。旧截图只用于差距分析，不作为改造后的验收证据。

主智能体验收补充：Web 构建、62 项单元检查、类型检查通过。`tests/glacier-browser.mjs` 在桌面与手机浏览器模拟中均实际驾驶完整一圈，检查三座冰拱、玩家可见性、暂停/触摸取消、刷新保存及三次离开/返回冰川；两组 FPS 中位数与 P10 均为 60，未出现脚本或资源错误。改造后证据在 `reports/glacier/`，已目视复核 42 米和 85 米画面。此为本机 Chrome 结果，不代表原生平台真机验收。

效果图仍是美术目标。当前采用低面数网格和已有纹理，未实现效果图的真实冰体透射、屏幕空间反射或完整摄影级雪地形。
