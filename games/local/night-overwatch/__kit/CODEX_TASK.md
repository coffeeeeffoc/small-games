# 给 Codex + Astra 的执行提示词

你在当前仓库中担任本项目的游戏开发工程师。请实现一款原创的横屏“空中火力支援与车队护送”小游戏，工作名《夜航守望》。请先阅读同目录 GAME_REQUIREMENTS.md、SOURCES.md 和 ASSET_MANIFEST.example.json，然后开始实施，不要只输出方案。

## 目标与参考边界

参考《Spectre Command》的体验类型：高空观察地面、切换火力、处理弹着延迟和积热、保护友军。不要复制其代码、名称、图标、地图、声音、HUD 构图、任务文案或整套参数。用户的操作截图只是说明“复杂动作要有可随时查看的帮助”，不是逐像素 UI 复刻要求。没有实际读取或游玩到的信息不要假装了解。

本项目的差异点是“打通撤离走廊”：车队沿固定路线行驶，在标记待命点可等待/继续；玩家要清理前路而不是只刷击杀。世界与任务倒计时不因车队等待而暂停。

## 环境与技术决策

1. 先检查当前仓库、已有实现、依赖、工具、运行方式和未提交修改，保留用户工作。不要无理由推倒已有可用项目。
2. 新项目主线使用本地可用的 Cocos Creator 3.8 LTS 系列版本 + TypeScript；记录并锁定具体版本。不要将“3.8 LTS”描述为未经核实的最新版本。
3. 先导出 Web Desktop / Web Mobile；随后分别验证微信、抖音。Cocos 内部 HUD 使用引擎 UI，不依赖 React DOM、浏览器 DOM 布局或 CSS 承担游戏核心功能。
4. 已存在 Three.js 工程时，先报告保留它与多平台目标的冲突和迁移成本，未经确认不自动重写、不维护两套完整渲染器。
5. 检查 Creator 可执行程序、合法项目模板、CLI 与图形环境。缺少工具时明确报告具体缺少项和最少的人工准备；可以继续实现可独立测试的纯 TS 规则，但不能把静态网页或伪造构建当成 Creator 成果。不要未经批准自动安装系统级软件、购买素材或使用收费 API。
6. 使用可信模板、编辑器正常生成的配置或已验证的示例完成 Bootstrap 场景，不随意拼凑未知版本的序列化文件、UUID 和构建选项。CLI 退出状态按对应版本文档和日志解释。
7. core 保持纯 TypeScript，包含武器、单位、任务、评分、车队状态；runtime 使用 Cocos；platform 只隔离存储、生命周期、广告、音频恢复和安全区等必要差异。不要为“以后全部复用”制造庞大的抽象框架。

## 第一轮只完成 M0 和 M1

### M0：最小验证

先完成最小可运行场景：地面、一个移动目标、准星、速射炮、命中/击毁反馈、鼠标与触控输入。确认 Web 构建能启动，再扩大系统。

同时验证一个模型的目标引擎导入路径；没有外部模型时可用程序化几何体，不阻塞原型。确认相机坐标、缩放、地面拾取和 UI 点击拦截正确。

### M1：一关可玩的完整灰盒

- 一张公路地图、一个约 2 分钟的护送任务、车队路线和至少一个待命点。
- 三类目标：快速轻型单位、重甲单位、固定威胁；有限事件表，不无限刷怪。
- 三档火力：速射炮按住连射，爆破炮按住按节奏射击，重型炮每次按下只射一发。
- 发射时固定落点和弹着时间，目标移动后会影响是否命中；不让已发射炮弹跟随准星。
- 武器热量、冷却和弹药彼此一致，切枪不清空积热。初始参数参考需求文档，全部数据化并允许后续调参。
- 基础热成像和日光模式：对象有热特征，不能只给整屏加黑白滤镜；目标标记独立于热值。
- 友军与保护区、友伤警报；保护区阻止开火并显示原因；标准模式关键车辆被毁则失败。
- 车队等待/继续的状态正确：moving / holdRequested / holding / arrived。
- 任务进度、成功、失败、评价、暂停和快速重试。
- 必须能靠鼠标/键盘和手机触控分别完整通关。

不要在第一轮开发多人、开放世界、自由驾驶、驾驶舱、商城、广告、复杂成长或全部关卡。不要先堆豪华主页而只有不可玩的战斗画面。

## 输入与复杂操作提示是必做功能

建立 ActionRegistry，将真实动作绑定、HUD 提示、教程、完整帮助统一成单一来源。不要三套地方硬编码快捷键。

建议默认绑定：
- 鼠标移动：瞄准；左键/Space：开火。
- 1/2/3 或 Q/E 或滚轮：切枪。滚轮不再同时缩放。
- Z/X：缩小/放大；右键按住：临时放大，松开恢复。
- V：传感器；T：车队等待/继续；R：回到车队。
- M：任务目标；H 或 ?：帮助；P/Esc：暂停。
- F：侦察扫描；G：紧急冷却。这两项在 M2 实现，未实现前不能作为可用技能出现在 HUD。

手机横屏：非 UI 区域相对拖动瞄准；独立 FIRE 按钮；三档武器按钮；缩放 +/-；传感器、车队指令、任务、帮助、暂停、定位按钮。不要依赖右键、滚轮、hover 或双指缩放才能通关。

保证不同 touch/pointer ID 独立：一指瞄准、另一指射击；点击 UI 不穿透。抬起、取消触控、失焦、进入后台和暂停都要清理连续开火状态；恢复后重新按下才能射击。

第一次教学按真实完成事件推进，一次讲一个动作。主 HUD 显示快捷键/可点按钮与功能名称。根据场景说明：提前量、重甲换枪、武器过热、友伤风险、待命点继续，以及每次不能开火的准确原因。

完整帮助面板按“基础 / 进阶 / 战斗规则”分类，默认展示最近输入类型，可切换键鼠/触控。标题与关闭按钮固定，正文滚动；小横屏也能看到第一条和最后一条说明。打开帮助暂停单人任务。

帮助、任务、普通暂停、旋屏提示、后台和后续广告使用暂停原因集合；关闭一个面板不得错误恢复另一个仍暂停的任务。UI 中的操作文字有中文与英文配置，动态按键不烘焙进图片。

## 视觉、音频和素材

使用稳定北向的高位斜俯视相机，玩家不驾驶飞机。不追求写实大地图。优先实现目标可辨识、三种火力反馈和车队危机感。

没有资源就生成盒子/低模/简单矢量 UI 等可替换占位资产，确保每项资源通过统一 assetId 引用。不能使用没有获得的 GLB 文件路径导致启动失败。

目标：低模、少材质、共享贴图与合理粒子上限；具体预算按 GAME_REQUIREMENTS.md。模型导入先试一件，之后再批量压缩。不要将专为 Three.js 配置的 Draco/KTX2 资源假定成 Cocos 直接可用。

所有外部资源记录来源、授权、商用条件和署名要求。需要收费生成/外部上传时先征求批准，未批准保持占位。AI 生成模型入库前仍要检查尺度、面数、节点、材质和兼容性；API 密钥不得写入客户端。

没有音频工具/素材时先用能够在当前引擎与目标 Web 运行的合法占位方案，并清楚标注；不要把桌面专有音频实现伪装成小游戏已适配。关卡进入要通过用户交互初始化音频，后台返回正确恢复。

## 验证要求

核心规则测试至少覆盖：武器冷却/积热、重炮按住不连发、弹着快照、范围伤害去重、友伤/保护区、车队状态切换、暂停冻结、重试复位与任务胜负。

运行项目真实的构建和检查命令。能使用浏览器工具时启动可玩包，完成至少一次成功与失败路径，检查控制台和截图。不能仅以 TypeScript 编译通过作为游戏完成。

测试视口至少包括 667×375、844×390 和 1366×768。验证低高度帮助滚动、关闭按钮、安全区、多点触控、后台恢复和缩放准星一致性。浏览器模拟触控不是手机 GPU/真实宿主验证，报告中要区分。

不编造 FPS、内存、平台上线情况和真机结果。没有设备或 SDK 时将该项标为未验证，并给出精确的人工复测步骤。不要声称所有小游戏平台已经兼容。

性能以目标设备实测为准：中档手机争取稳定 30 FPS、桌面 60 FPS，首局实际下载争取约 10–15MB；这些是目标，不是保证或平台上限。记录单位数、draw calls、可见面数、粒子数量与首局加载量。

在 docs/PLAN.md 中保存短计划，在 docs/STATUS.md 记录当前里程碑、已实现、未实现和阻塞；按阶段更新而非一次写大批空文档。

2. 启动/构建方法和真实本地预览地址（只有启动成功后才给地址）。

## M1 验收后可直接使用的后续提示

### 第二轮：操作与关卡

继续当前项目，阅读 docs/STATUS.md。只实施 M2：两套地图三个任务，完善车队指令、扫描/冷却、ActionRegistry 和四层操作提示；检查多点触控、暂停原因、小横屏帮助面板和重试资源重置。选择一个具备开发环境的小游戏平台做实际构建与真机烟雾测试，未测试的不写“通过”。不要增加商城或多人。

### 第三轮：素材与手感

继续当前项目，只实施 M3。先通过资产台账确认来源与可用性，优先替换车辆/地面、三种火力效果、音频和热成像材质。所有资产先测试再批量替换；低画质不降低目标识别能力。对同一关进行前后对比，记录实测帧率/下载量和未验证项，不新增玩法系统。

### 第四轮：渠道

继续当前项目，按已确认的目标平台实施 M4。逐个实际构建、接入 SDK、验证资源加载和生命周期，保持未实现接口明确返回不支持。广告只按平台允许的阶段与流程接入，测试回调和去重，不能影响任务核心流程。完成渠道验收表、授权台账与真实游戏发行素材后再讨论提交。
