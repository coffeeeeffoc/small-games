# 夜航守望 · 开发需求包

2026-10-28 更新：执行入口已改为当前项目的增量开发与完整视觉交付，不再要求完成一关灰盒后停工。产品研究中的早期参数和素材预算保留来源身份，当前任务以用户最新要求、认可效果图和仓库通用规范为准。

## 文件

- [CODEX_TASK.md](CODEX_TASK.md)：可直接交给开发代理的当前执行提示，包含目标核对、完整实现、逐页视觉与功能验收、资产收尾和平台交付。
- [GAME_REQUIREMENTS.md](GAME_REQUIREMENTS.md)：产品、操作、素材研究与验收要求；早期玩法和数值建议不覆盖现行实现。
- ASSET_MANIFEST.example.json：素材台账样例，不表示已取得第三方资产授权。
- [SOURCES.md](SOURCES.md)：公开参考资料与事实边界。

## 使用

先读取根 `AGENTS.md`、[通用开发规范](../../../../docs/game-development.md)、[游戏 README](../README.md)和最近设计记录，再引用执行提示。已有工程直接按本轮范围改造，不从旧原型重新起步。

可直接发送：

> 请阅读 CODEX_TASK.md、GAME_REQUIREMENTS.md 与当前项目文档，按本次要求完成相关玩法和认可效果图的完整视觉实现。新样式落实到对应页面、场景、材质与细节，补齐必要素材；用同尺寸实际截图逐页对照并修正差异，分别报告视觉与功能结果。不要停在灰盒、只改布局框架或用占位资产交付；不要虚构构建、真机和平台验证。提交与推送按本轮授权及仓库规则执行。

第三方操作截图用于理解操作信息和帮助组织，不复制其受保护素材；本项目已认可的原创效果图仍是视觉实现与验收依据。
