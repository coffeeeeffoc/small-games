# 战斗补给威力校准：消耗追踪弹采用 120

采用 `HOMING.damage = 120`、速度 70、单体且不误伤友军。普通追踪增益只改变制导，保留所属武器的伤害、速度、护甲系数、爆炸半径、友伤、弹药与热量；射速增益使用发射间隔 `/ 1.3`。两种增益持续 60 秒战斗模拟时间。

## 复现与证据版本

在仓库根目录使用 Node 24（本次 v24.21.0），无需依赖：

```powershell
node games/local/night-overwatch/tests/supply-balance.mjs
```

## 场景与断言

- 射击网格：山谷 `corridor-01`、高地 `ambush-02`；目标原点 `(-110,-45)、(-110,55)、(35,-45)、(35,55)、(110,-45)、(110,55)`；巡逻年龄 `0、2.5、5、7.5、10、12.5、15、17.5` 秒；默认飞机位置和姿态，步长 `1/60` 秒。车队停驻，已标记所有任务事件为生成，移除原始敌人并关闭地面交火，保留友军和真实地形。
- 普通炮分别瞄准当前位置、精确预判位置；预判迭代 12 次，使用真实巡逻规则、重甲朝最近友军运动和飞行时间。普通追踪增益瞄准当前位置。消耗追踪弹两种初始瞄准都显式锁定同一敌人，因此锁定后轨迹相同。三类敌人、三种普通炮与消耗弹合计 3,168 个单发场景。目标 HP 设为 10,000，统计未被剩余血量截断的单发伤害和实际命中率，并记录友伤。
- 断言真实发射速度、飞行中制导速度、冷却、热量、弹药消耗和伤害上限；消耗弹必须命中、造成 120 点伤害且无友伤。普通弹保留实际失误与地形遮挡，不强行断言 100% 命中。
- 击毁阈值：两张地图分别使用真实 32/90/180 HP，断言轻车与炮塔各一发、重甲两发，重甲第一发后剩余 60 HP。
- 范围与友伤：在 `(35,-20)` 布置炮塔，x 偏移为 `0、2、3.5、6、7`，偏移 2 处放置友军。断言每个实际落点使用普通伤害衰减/护甲规则，普通追踪与非追踪的伤害向量一致；消耗弹仅伤害锁定对象。
- 射速：在 `[0,60)` 每步尝试发射；保留原始弹药、热量与散热，目标 HP 100,000。直接调用真实射速增益，不改武器间隔配置。使用 `1/60` 与 `1/600` 两种步长；重炮假定玩家每次冷却后立即手动再次发射。
- 时间：两种增益在手动暂停、补给、广告、倒计时和后台暂停时均冻结模拟，包括在途弹药与枪械状态；60 秒到期，普通弹在途中失去制导但仍存在。

## 采用 120 的理由与局限

120 小于重炮的 140；既保留轻车/炮塔一发击毁，又让满血重甲需要两发。一次两发补给可处理一辆重甲，或两辆较弱敌人。重炮仍有大范围总伤害优势，普通追踪则保留各武器专长和友伤代价。120 是当前产品取舍，不是实验推导出的唯一最优值。

此处没有浏览器、触屏、真机、真实广告 SDK 或整局胜率验证。靶场不含人类瞄准误差；只覆盖默认发射姿态、六个原点和八个巡逻阶段。年龄变化只改变轻车，静止/重甲存在重复用例，不能当作独立统计样本。高地结果已说明山谷结论不能直接推广到所有地形。降低伤害无法单独平衡无限次暂停领取、可囤积的消耗弹经济。

后续核心、关卡运动、地形、碰撞或热量规则改变时，重新运行脚本并对照 JSON 哈希及本文表格；不要只根据旧 Git HEAD 或旧报告宣称当前实现已校准。
