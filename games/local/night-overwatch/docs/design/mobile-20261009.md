# 夜航守望 · 移动端交互改版

## 页面与路径审查

原主页同时堆放四个任务与操作说明；战斗上沿有飞行、车队、追踪弹、倍率，下沿三种武器与双行开火文案。追踪弹入口实际立即发射，缺少选择状态，双指只计算间距。炮舱的近景模型会随当前武器换位，可能进入观察相机视锥；传感器视角应完整观察战场。

采用现有深蓝夜景、薄荷绿友军与琥珀敌军的横屏视觉，场景优先。保留 Cocos 实时地形与规则，不更换渲染框架。方案选择：删除多余常驻说明、把追踪弹接入既有瞄准/开火路径；不增加另一个发射面板或自动替玩家开火。

## 输入与规则

- 追踪弹槽点击后进入选中状态；空库存才打开原补给流程。完成补给自动选中，显示库存。
- 点场景敌人或将准星拖到敌人，显示明确锁定框；以屏幕热区选目标，友军和保护区不能成为目标。锁定保持跟随该敌人，死亡/失效取消，不自动更换目标。
- 已选追踪弹时，右侧统一发射按钮发射一发，鼠标/空格遵守同一语义；未锁定提示点选敌人，不能误扣弹或发射普通炮。普通三炮切回原规则。
- 双指间距控制倍率，中点位移拖动整个观察区域，保持手势下的地面位置；相机仍固定在真实飞机传感器上。双指结束后剩余手指取消，避免变成单指误瞄/射击。
- 全部控件约 44 CSS px 以上有效热区，小屏、安全区、屏幕旋转与全屏保持对局。Web 竖屏使用 Cocos 横屏适配，须以实际输入验证映射，不只显示方向阻塞提示。
- 传感器相机不渲染近景炮舱；真实炮口与弹道起点保留。实际截图覆盖三炮、缩放与视角变化。

## 影响范围和验证

影响 HUD、Overwatch 输入路由、World 相机手势、AircraftModel 的渲染可见性、Simulation 追踪锁定、帮助文案及相应规则/浏览器测试。保持奖励存档格式、任务目录和普通炮弹规则。原生适配使用源码指纹保护，改源后审查并同步精确指纹。

效果图先于实现生成：`mobile-concept-20261009.png`，仅用作 UI 设计基准，不当作游戏运行证据。实际截图和生产构建 hash 记录于 `reports/mobile-20261009/`。规则/输入测试、类型检查、手机触屏核心流程、横竖屏、暂停、奖励库存、Shell/独立入口、准确候选 SHA 增量发布验证均须完成；真机与真实广告 SDK 无证据时明确未验证。
