## 后续补充：同时显示当前与最新版本

按用户继续反馈，弹窗分别显示“当前版本”和“最新版本”，两项下方各附构建摘要。当前版本号、渠道和 hash 只读客户端包内 `__COMPETITION_CONFIG__.release`，不依赖服务端或被服务端同名字段覆盖，接口失败时仍显示。Runtime 元数据新增 `latestVersion`，取该客户端渠道发布目标的版本号，其他渠道的更高版本不会混入；没有发布目标／目标没有登记版本号时返回 null。旧接口缺字段时显示“暂未获取”；仅最新 buildId 与本地相同且本地版本已知时可以显示两者相同，不猜测不同构建的版本。

本地 `1.0.21 · web-h5` 构建通过，59,605,402 字节，源码摘要 `96448e08de71e21fe510b8f1b119dfff019f96626883eb0b5f9c88285d737a61`，保留 Sakura 测试接口配置。103 项 Online/HUD、3 项开发工具、10 项 Runtime 版本／运营测试通过，前后端类型检查、Runtime 改动文件 lint 和全屏边界检查通过。三尺寸浏览器检查覆盖版本不同、版本相同、旧接口缺字段和离线当前版本，沿用实际桥接与 IndexedDB、仅替换 HTTP 响应的夹具；无 pageerror 或布局遮挡。夹具故意返回错误的 currentVersion=0.0.1，界面仍显示包内 1.0.16，验证当前版本来自客户端。

## 最终行为

- 首次进入默认完整特效，不再随系统减少动态效果而默认精简；玩家在游戏中明确保存的选择继续生效。两种模式都先播放 2.2 秒开箱演出，再展示奖励，覆盖单箱、批量数量及礼包一键打开。精简模式保留连续小幅晃动、缩放弹起、渐亮光晕、8 个粒子和轻微漂浮，取消全屏爆闪、旋转光束并减小振幅；完整模式保持 22 个粒子及原反馈。
- 首页入口为“发现新版本”，弹窗为“游戏更新”；主信息是版本号与渠道，构建摘要放在下方。手动检查使用刷新图标。删除“保存与重进说明”按钮和默认不可用／保存／重进段落。
- 元数据提示旧版或 admissions=false 不再提前拦截开局；实际服务继续决定操作能否成功。仅在版本落后且真实兼容／服务请求失败后显示相应说明、自动提交本地记录。密码等业务拒绝不归因于版本。成功重试清除同一 method＋path 的提示，读取列表不会清除创建失败。
- 版本检查每 60 秒及相关入口自动触发，并共享在途检查；成功重试、身份与 bridge 切换会使迟到错误失效。自动保存等待日志与存储提交成功后才显示已保存；失败每 5 秒重试，即使兼容提示已清除也继续，且不暂停、结束或刷新对局。
- 复用已有清理：确认结算且回执提交后删除行动日志；防重复回执保留 7 天；删除失败以同键 tombstone 继续重试，覆盖内存、IndexedDB 与旧 localStorage。未确认／未提交记录保留，避免为了腾空间丢失待补传结算。本次未另建保存副本或缓存系统。

共享请求通知同时接入普通服务和录制器服务，观察者异常不影响原请求；补全版本停用错误的 `update-required` 分类，修正终止结算复查中漏写的 `await stopRecovery()`。原生暂存同步 Platform 与 BattleStatusView 摘要，并补齐既有 legacy-polyfills 输入。
