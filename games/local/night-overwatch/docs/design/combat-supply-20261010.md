# 战斗补给实施方案

目标：在既有横屏战斗中主动暂停看广告，完成后获得一次三选一资格，领取后倒计时三秒继续。复用现有广告适配、暂停原因集合、固定步长模拟、存档与 Canvas HUD。

## 页面与规则

- 战斗画面新增独立「战斗补给」44px 热区；暂停页也可进入。补给页仅显示「观看广告」「返回暂停」。沿用现有横屏与竖屏旋转兜底、安全区、全屏适配。
- 广告成功展示三张奖励卡：追踪模式 60 秒、追踪弹补给 2 发、射速提升 60 秒（发射间隔 / 1.3）。不提供恢复耐久。领取追踪弹后仍由玩家手动锁定并发射。
- 广告无次数上限；计时增益存在时，补给与倍率解锁广告都不可请求。库存不阻止广告。待选奖励存在时先领取，不再发起新广告。
- 所有战斗模拟，包括敌人、在途弹药、生成、关卡时间、枪械冷却与增益，使用同一战斗时间。补给、广告、选奖、倒计时和后台均不推进模拟。
- 领取后显示 3、2、1；后台中断倒计时则回到暂停，玩家继续时重新倒计时。恢复帧不补算后台时间，输入清空。
- 取消/失败回暂停页。完成广告立即持久保存待选资格；「稍后选择」、返回主页、刷新不丢失资格。单次请求身份与领取消费防止重复回调/重复领取。存储不可用时保留本次会话资格并允许游戏继续。
- HUD 显示计时增益名称/秒数，最后五秒使用轻微琥珀色提示，到期提示并恢复正常；库存立即更新。计时增益不跨新对局，未领取资格跨对局保存。

## 弹道与平衡

普通弹追踪与一次性追踪弹必须区分；前者只改变制导方向，保持各武器原伤害、速度、爆炸半径、友伤和弹药/热量/冷却。增益到期停止普通弹的追踪能力。射速提升保持单发伤害、热量与弹药消耗。一次性弹保持手动单次消耗、单目标定位；以可重复场景比较三种常规武器的命中率、伤害、间隔及范围后确定威力并记录结果。

## 实施范围与验证

1. `core/Simulation.ts`、`core/Data.ts`：增益、冻结/倒计时、普通弹制导和消耗弹平衡；规则测试覆盖暂停完整状态、到期、伤害/速度/范围/友伤不变及实际间隔。
2. `core/Rewards.ts`、`Platform.ts`、`Overwatch.ts`：旧存档迁移、待选资格、统一广告互斥、单次领取与后台恢复；测试广告失败/取消/重复结果/存储降级。
3. `HUD.ts`、`core/Actions.ts`：补给、三选一、倒计时、增益和库存，使用 `combat-supply-concept-20261010.png` 对照实机渲染截图（浏览器模拟，不称真机）。同步旧浏览器测试中的广告和库存契约。
4. 规则与类型检查、Creator 3.8.8 生产构建、844×390/568×320/390×844 触屏与桌面检查、Shell/iframe 相关入口、开发模式相关检查。记录真实广告 SDK/物理手机未验证项。
5. 提交后基于远端 dev 准确 SHA 执行增量候选门禁，正常 hooks 推送 dev，核对远端及 CI/Pages 状态。

不新增中心框架、依赖、养成机制或额外奖励。
