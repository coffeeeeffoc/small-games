# 二级页面顶部安全区修复

2026-11-06。基线 `dcc5d0ed24e1c2558e584d92f82ae8812e6afd85`，针对 Redmi K90 / TapTap H5 顶部工具栏下移反馈。

## 修改与边界

`ProgressionView.header()` 以前从 `safe.top` 绘制整条背景，因此非零安全区上方会露出独立的游戏背景空带。背景现在从屏幕顶部绘制至原下边缘 `safe.top + headerHeight`，与首页处理一致；所有使用此 header 的军需二级页面共用修复。

返回键、文字、金币、胶囊避让、主体内容与触控坐标保持原值。`safe.top=0` 时新旧绘制参数相同。本次修复背景覆盖，不把安全区清零、不按 Redmi 型号设置负偏移，也未确认 K90 的 CSS / SDK 安全区上报是否过大。

## 2026-11-11 横屏状态栏高度

上面的背景修复没有消除下移。K90 两张实机截图（碎片合成页、状态栏已隐藏的首页）按控件位置反推，`safe.top` 与 `safe.left` 均约 58 CSS px，而 TapTap 胶囊位于 23–56px，落在这段“状态栏”高度之内：宿主横屏并不保留状态栏，只是继续上报它的名义高度。`core/SafeArea.ts` 原先把 `statusBarHeight` 与宿主 `safeArea.top` 无条件并入顶部，于是整屏下移。

现在仅竖向窗口（高 ≥ 宽）合并这两个宿主顶部值；横屏顶部只取引擎 CSS `env(safe-area-inset-top)` 与胶囊矩形。假设是各宿主横屏都隐藏状态栏，若某宿主横屏仍显示，状态栏会压在顶栏上，届时需要按宿主的可见性标志放开。顶部归零后，二级页正文起点取 `max(safe.top + 顶栏高, 胶囊下沿 + 6)`，大厅在线人数改用 `topRight()` 避让胶囊。

未确认项：58px 具体来自 `statusBarHeight` 还是宿主 `safeArea.top`（两者都已处理）；若实为 CSS `env()` 上报，本次修改无效。开发包“运行信息”快照的 `safeSources`（画面尺寸、引擎安全区矩形、各宿主原始读数与胶囊）可在真机上直接区分。本轮只跑了单元测试与类型检查，未重建、未在 K90 验收。
