# 夜航后管运营与发布版本验证

日期：2026-11-09。当前分支 `codex/night-overwatch-versioned-release`，准确起点 `9c9c3797a7a85d3b5cd2f18dbc8d39cd6fd1f001`。本轮只提交、推送源码，不部署，不改已有测试服/生产数据库，不上传平台包。

## 行为与使用入口

- 后管“游戏配置 → 夜航运营”维护公告、补偿和版本。继续复用权限、发布理由、草稿和 CAS 冲突保护。
- 公告支持时间窗及启停；补偿支持金币/EXP/补给箱、注册截止时间和指定玩家。已发布补偿只能启停；旧投递和领奖回执保留，重试不重复发放。自定义文案在中英文界面均按原文展示，长正文可滚动。
- 夜航 H5/网页每次实际构建分配前端版本并自增，绑定显式后端兼容版本。后端发布/预备必须指定 `--version`，从健康验证后的上线回执读取当前及最近五次部署。
- 关闭、恢复或移除旧构建控制新局；按后端兼容版本统一关闭/恢复绑定构建。已开对局沿用原规则与奖励。快速回退改变渠道推荐构建，保留公告、补偿和资产。
- 控制数据库新增 005/schema v5，旧迁移不改写，保留历史配置原文、摘要与账本。能力检查阻止 v5 上恢复不识别运营字段的镜像；审计写入结果不确定时保留已核验健康的镜像。

完整操作约束见[配置中心](../../../../docs/admin-console/control-center.md#夜航公告补偿与游戏版本)、[构建编号](../../../../docs/operations/game-builds.md#夜航的前后端发布版本号)、[错峰发布架构](architecture/versioned-release.md#7-本次最小实现与发布配置)。这些开关不启动历史 Docker 实例，执行器与数据库的不可兼容变更仍需要迁移设计。
