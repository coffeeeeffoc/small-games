# 一笔造关

用一笔画出可碰撞的赛道，再亲自控制小球到达终点。独立的 Vite + 严格 TypeScript + Phaser 3.90 项目；只使用 Phaser 内置的 Matter 世界。所有形状与音效均由代码生成，无远程资源、账号或 API Key。

## small-games 接入

源码位于 `games/local/one-stroke-course`，Shell 游戏 ID 为 `one-stroke-course`。在仓库根目录执行 `pnpm install --frozen-lockfile` 后，可用 `pnpm --filter @coffeeeeffoc/one-stroke-course dev` 启动；`pnpm build:pages` 会将游戏打包到大厅，`pnpm test:pages` 验证入口和实际操作。原型测试记录保留在 docs，测试截图由测试重新生成。

## 启动和验证

在本目录执行（推荐 Node 22/24，最低 Node 20.9，pnpm 8+）：

```powershell
pnpm dev
```

打开 <http://localhost:4171>。手机与电脑在同一局域网时，可使用终端输出的局域网地址；手机请横屏。不要通过 `file://` 打开 HTML。

```powershell
pnpm typecheck
pnpm test
pnpm test:browser
pnpm build
pnpm preview --port 4172 --strictPort
```

浏览器测试默认使用系统 Google Chrome。没有 Chrome 时安装 Playwright Chromium，并选择对应 channel：

```powershell
pnpm exec playwright install chromium --no-shell
$env:PLAYWRIGHT_CHANNEL = 'chromium'
pnpm test:browser
```

启动 4172 的生产预览后，另开终端执行 `node tests/production.mjs`，验证打包资源、真实画线、键盘通关和生产环境不暴露开发控制器。`test-results/results.json` 是最近一次浏览器测试报告；测试截图在 `docs/`。详见 [测试记录](docs/TESTING.md)。

`dist/` 可直接部署到静态服务器的根目录或子目录。Vite `base: './'`，无后端、无 SPA 深层路由要求。首包包含本地 Phaser，引擎 JS 约 1.52 MB，gzip 约 352 KB。

## 怎么玩

1. 从左侧圆环按下，连续画到右侧圆环，松手结束一笔。绘制阶段球与时间都冻结。
2. 线条通过检查后才能开始试跑。有效笔画不可补第二笔；无效笔画可直接从起点重画。
3. **A/D 或 ←/→** 施加水平力，**空格** 跳跃；手机同时按方向与跳跃按钮。球不会自动沿线移动。
4. 收集三颗星，绕开灰色实体和红色尖刺，抵达旗帜。几何合法只表示赛道可创建，不保证任何画法都能通关。
5. 失败可直接再跑，保留赛道、重置星星与时间；重新画线会清空笔画。试跑中可通过暂停菜单直接重跑或重画。

已有部分或完整笔画时，画布下方提示条变为浅橙色，并显示醒目的「重新画线」按钮；点击即可清空。提示条固定高度，出现按钮不会挤动画布或改变绘制坐标。试跑时隐藏该入口。

结算弹窗出现时，失败自动聚焦「再跑一次」，成功聚焦「下一关」；自由实验没有下一关，仍聚焦重试。可直接用回车或空格触发，Tab 切换后的焦点不会被刷新抢回。

**Esc / 暂停** 停止试跑；切出页面自动暂停并释放所有按键、触摸状态，返回后主动继续。窗口变化中正在画的笔会取消。手机竖屏显示横屏引导。提供真实 Fullscreen API 按钮；浏览器不支持时会显示说明，CSS 铺满不会冒充全屏。

现在包含 **12 个挑战关卡 + 自由实验**。横向滑动关卡栏选择后续关卡，通关后也可直接下一关。“查看示例”和“另一种画法”只载入笔画，仍需亲自操控。除第 1 关教学外，其余 11 条主参考路线一直按右均不能通关。

| 关卡 | 目标与操作 | 画线的取舍 |
| --- | --- | --- |
| 01 简单连接 | 学习一笔连线及方向控制 | 平路最容易入门 |
| 02 借坡取钥 | 终点上锁；在金框前起跳，碰到悬空钥匙。金框允许球进入，禁止画线 | 隆起的缓坡把球托高，直线省墨但需要更准确的起跳时机 |
| 03 巡游锯轮 | 锯轮上下移动，需要避开接近赛道的时段 | 改线高度会改变通过窗口，低路会错过部分星星 |
| 04 等门一拍 | 门前按左减速，松开等待，绿灯时向右穿过压门 | 直线最快；下凹路线方便减速停留，但会错过一颗星 |
| 05 驻足充能 | 整球在蓝台低速接地 0.5 秒；提前离台会清空进度 | 坡度改变进入充能台的速度和刹车位置 |
| 06 收住惯性 | 提前反方向刹车，整球在终点框内低速接地 0.6 秒；越过断崖失败 | 下坡收星更全但惯性更大；低位接上坡更容易减速，会错过高处两颗星 |
| 07 连续双跳 | 两把钥匙都必须取得，落地后才能第二次起跳 | 第一跳的落点决定第二跳的准备空间 |
| 08 双门错拍 | 两门错峰开放，门间再次减速 | 需要给两次等待留下稳定路段 |
| 09 取钥急停 | 跳跃取钥后在终点停稳 | 收星坡度与末段刹车距离同时影响结果 |
| 10 蓄能发车 | 停稳充能，再抓住前方压门的开放窗口 | 发车地点、坡度改变到门时间 |
| 11 逆风取钥 | 左向风持续施力，空中会被吹回 | 靠近钥匙再跳，或提高起跳坡面 |
| 12 一笔终章 | 取钥、落地刹车等门、过门后再停车 | 连续动作需要兼顾起跳点、等待区和收尾坡 |

失败留下淡红色运动轨迹及叉号，重跑或重画时可以对照；切换关卡会清除。可用 `?level=saw-crossing`、`?level=charge-stop`、`?level=final-exam` 等模板 ID 直达对应关卡。所有关卡可自由选择，不强制解锁。

参考操作在 [tests/replay.ts](tests/replay.ts)，实际结果见 [验证数据](docs/challenge-validation.json)。输入只含左、右、松开和跳跃；没有改变球的位置、速度或绕过碰撞。操作时机不是所有自绘路线的通用解，也没有证明所有合法画法都必须刹车或跳跃；合理画线绕开风险是玩法允许的解法。

| `src/challenges.ts` | 钥匙、压门、锯轮、充能台、逆风、停车及组合判定；共用 Matter 世界 |
| `src/scene.ts` | 绘制/就绪/试跑/成功/失败状态、暂停、关卡切换、绘图与运行结算 |

核心规则与几何不依赖 DOM、Phaser 或音频。第一版没有引入 React、另一套物理世界、在线存储或平台 SDK。

## 几何和物理参数

- 固定逻辑坐标 `1100 × 560`；输入使用 canvas 实际 CSS 边界映射到该坐标系，DPR 不重复乘入输入。Phaser FIT 保持等比；文本纹理最高采用 2 倍分辨率。DPR 3 的横屏触摸输入已用浏览器模拟检查。
- 小球半径 14，轨道半径 6（实际厚度 12）。起点/终点平台顶面与线顶面齐平；出生点比平台多留 3 的净空。
- `GEOMETRY` 提供距离采样阈值 7、原始采样上限 1600、最终点上限 200、锚点吸附半径 30、绘制高度 130～500。横向绘制范围 155～955。
- 锚点区域的首尾采样先合并，再检查原始边界，避免手指在圆环边缘或 CSS 亚像素取整导致误报。处理后再次检查自交、非相邻段过近、障碍、尖刺、预算与端点。
- 渲染、长度、墨水、存档及计分全部使用同一份处理后几何。已保存的处理后笔画直接复验，不重复平滑。
- 每段为旋转矩形，顶点为半径 6 的圆连接，矩形增加 0.4 的微小重叠避免浮点漏缝。不将开放折线填充成多边形。最多 399 个轨道刚体。
- **只有 `CoursePhysics.step()` 调用 `world.step(1000/120)`**；`autoUpdate` 关闭。RAF 累计器每帧最多处理 100 ms；更长的卡顿丢弃超额时长，不在恢复后补跑。计时是本次实际模拟步数，不含绘制、暂停、结算或被丢弃的卡顿时间。
- Matter 速度以每 60 Hz 基准帧为单位；`MOTION.maxX=6.2`（约 372/s），`maxY=12`（约 720/s）。物理子步水平位移约 3.1，最大落速位移约 6，均小于轨道厚度。步进前后均限速。
- 地面驱动力为质量乘 `0.0019`，空中为质量乘 `0.00065`。保留惯性、低摩擦、空气阻力和真实转动。水平控制不改位置；只有出生/重置设位置，跳跃设置向上速度。
- 接地要求真实碰撞法线朝上且接触点位于球心下方，侧墙和天花板不能刷新接地。土狼时间 100 ms，跳跃缓冲 120 ms，起跳后短暂防止旧接触再触发。
- 重试销毁旧刚体及接触缓存，再重建球、星星和轨道。输入监听只在场景初始化时注册，场景关闭时清理；不随每次重试增加。

几何校验采用有界的成对线段检查，第一版只面向最多 200 点的短赛道；不引入空间索引。尖角会圆滑，但极端合法回弯仍可能难以通过，这正是需要自测试跑的部分。

## 评分与本机作品

基础通关 50 分，星星每颗 10 分（按唯一 ID 删除传感器并记录，最多 30 分）。

```text
clamp01(x) = min(1, max(0, x))
墨水 = round(10 × clamp01((inkBudget - usedInk) / (inkBudget - parInk)))
时间 = round(10 × clamp01((slowTime - runTime) / (slowTime - parTime)))
总分 = 50 + 10 × stars + 墨水 + 时间
```

所有分项先四舍五入到整数，再相加，因此展示的分项总和始终等于总分。时间显示两位小数、几何长度一位小数，内部使用原始数值计分。失败只展示实际进度、星星和原因，无通关总分。赛道长度/折点是几何统计，不是作品创意或客观质量评价，也不推断玩家通关率。

每个模板一个本地草稿槽，键为 `one-stroke:draft:<templateId>`：

```ts
{ version: 1, templateId, points, rulesVersion, tested, best }
```

手动保存覆盖本模板的本机草稿；通关后自动保存当前作品和最佳分。重新绘制或载入示例创建新作品，`tested=false, best=null`；规则版本不匹配时加载几何并复验，旧验证与旧分失效。此前保存的未修改作品可再次加载，这不会把其验证状态赋给新笔画。浏览器数据清理会丢失草稿；记录可由本机用户修改，不是防篡改证明。存储损坏、禁用或配额失败都会提示，当前游戏不崩溃。

## 配置或增加关卡

编辑 `levels.ts` 的模板数据。坐标均为逻辑像素：

1. 起点固定 `(155,410)`，出生位置由平台推导；终点 x 固定 955，参考笔画最后一点决定终点高度。
2. `solids` 是 `{x,y,w,h}` 实体；`hazards` 是相同格式的尖刺传感器；恰好三颗唯一 ID 星星。
3. 配置 `inkBudget > parInk`、`slowTime > parTime`，加载时有断言。
4. 配置原始 `reference` 点序列，必须使用与玩家相同的 `finishStroke` 流程得到合法路线。
5. 用实际 Matter 试跑校准三颗星、时间和墨水，再调整参数；不要只证明线条能连接。
6. 修改影响通关或评分的布局、几何或物理规则时递增 `RULES_VERSION`，使旧自测失效。改变序列化结构时递增存档 `version` 并明确迁移策略。

`challenges` 是机关数组，空数组表示没有特殊机关。组合关要求所有钥匙/充能/停车条件均完成，独立机关的进度不互相替代：

- `key`：钥匙坐标及禁墨矩形，只在玩家起跳后空中碰到时收集。
- `gate`：横坐标、宽度、关闭/升降/开放时长（秒）、可选 `offset` 错峰时间。
- `parking`：停靠边界、断崖位置、允许速度、连续停留时长。要求整球入框并接地。
- `charge`：平台中心 `x,y`、宽度、允许速度、停留时间。未充满时离开或跳起会重置进度，充满后保持解锁至本次试跑结束。
- `saw`：`x,y` 中心、上下振幅、周期、半径、起始相位偏移（秒）；危险圆传感器在同一个 Matter 世界运动。
- `wind`：矩形 `area`、水平 `force`（乘球质量）。与玩家驱动力累加，不直接设置位置或速度。

全部周期机关使用试跑模拟时间，暂停时冻结。允许速度以 Matter 单位计，停车 0.65 约为 39 逻辑像素/秒。新增路线应在 `tests/replay.ts` 添加可以复现的普通输入，并检查盲冲、满分、复位与组合条件。

`alternate` 提供第二种原始笔画，`guide` / `alternateGuide` 是对应操作提示。当前规则版本为 `1.2.0`，旧版本验证和成绩在加载时失效；重做的关卡采用新 ID，旧草稿不冒充新关卡作品。

自由模板保留起终点、星星、绘制边界和更宽松墨水，不是地图编辑器。

## 已知限制与未实现

- 已验证桌面 Chrome、浏览器模拟移动触摸/DPR/横竖屏；未用真实 Android/iPhone 验收，未验证 Safari/Firefox。音效合成路径已接入，尚未做不同真机扬声器与静音开关的听感验收。
- 极端低帧率会丢弃超过每帧 100 ms 的积压模拟时间，实际墙钟时间与模拟成绩时间可能不同；本地分数不用于竞赛公平性。
- 任意自绘路线不保证可通关；官方参考路线已实测，不进行自动寻路、磁吸、终点传送或跳过障碍。
- 当前形状/物理参数面向短关卡，不做地图缩放编辑器、撤销分段或第二笔补画。
- 没有账号、排行榜、在线分享/分享码、UGC 社区、联机、评论点赞、广告或内购。没有微信、抖音、B站 SDK 或平台适配完成声明。

实现时参考 [Phaser Matter World 官方说明](https://docs.phaser.io/api-documentation/3.88.2/class/physics-matter-world) 的手动步进约定，并核对已安装 3.90 源码；Phaser 的 `Query.collides` 存在于实现但漏于声明，通过一个本地声明补充，未替换物理引擎。
