# Echo Weaver / 回声编织

原创、可静音游玩的 Web 节拍谜题。一次发声分为三道回声；玩家点按场景中的反射板、延迟段和分声器，使它们分别在第 1、2、3 拍抵达接收器。首版 8 关，全部开放，预计每关 2–6 分钟；不使用麦克风、歌曲、商业音源或真实声场模拟。

## 运行与打包

无运行时依赖，无外部字体、图片、音频请求；直接打开文件不支持 ES 模块，请使用 HTTP 服务。

```sh
cd games/local/echo-weaver
node server.mjs                    # http://localhost:4411
node --test tests/*.test.mjs       # 引擎、关卡、存档、音频降级
node build.mjs                    # 输出 dist/
node server.mjs --dist             # 验证发布产物
node tests/browser.mjs            # 构建后走真实浏览器测试
```

也可在仓库根目录运行 `pnpm --filter @coffeeeeffoc/echo-weaver build` / `test` / `dev`。大厅已在 `apps/shell-web/src/standalone-games.json` 登记，Pages smoke 覆盖编辑、撤销、试奏、结算、重置及切关。

`dist/` 可作为静态 HTML 游戏上传至 itch.io，ZIP 根目录应直接包含 `index.html`。支持子路径托管，不需要后端。当前没有接入广告或付费系统。

浏览器测试使用 Python Playwright 和 Chromium（`pip install playwright`，随后 `playwright install chromium`，或通过 `BROWSER_EXECUTABLE` 指定现有浏览器）；Node 包只做构建和服务编排。可设置 `GAME_URL` 使用已有服务、`GAME_PORT` 指定预览端口，截图与报告默认写入 `/tmp/echo-weaver`。

## 玩法与判定

- 发光的反射板可点按循环切换固定声路；暗色机关已固定。长路线增加抵达时间，反射次数增加损耗。
- 延迟段增加等待时间和少量损耗，不增加路程。分声器在不同分配方案之间切换，总能量始终为 300。
- 每格路径耗时 1 tick，4 ticks = 1 拍，默认每拍 850 ms。关卡目标独立配置，不限于整数拍或 1/2/3。
- 剩余能量 = 分路初始能量 − 路程 × 4 − 反射次数 × 6 − 延迟/吸音额外损耗；至少 18 点才能触发。硬吸音块直接阻断信号。
- **三路都必须同时满足准确到拍和能量阈值才通关。** 接通路线、三声同时抵达或提前抵达都不算成功。
- 路径图是可点击的声道示意，时间以标注的格数为准；图形的像素长度不参与计算。右侧读数实时给出拍数、提前/迟到量、反射次数和能量，场景及侧栏的节拍灯同步反馈。
- 可无限试奏、撤销、重置、选关；传播中可停止或暂停，切到后台会暂停，回来后手动继续。中文/英文切换，默认静音，开启后使用原创 Web Audio 合成音。
- 触屏可完成全部玩法。键盘 `Z` 撤销、`R` 重置、`P` 暂停、`H` 提示；页面非按钮焦点下 `Space` 试奏/停止。按钮保留原生 Enter/Space 操作。

`simulate()` 先从配置计算完整结果，渲染根据内部 tick 推进；音频设备延迟、静音、动画帧率与设备像素比例均不参与胜负。存档只保存已完成关卡的最佳尝试次数、选关、语言与音效偏好；本地存储不可用时仍可游玩。

## 首章关卡

| 关  | 名称         | 教学重点                   |
| --- | ------------ | -------------------------- |
| 01  | 绕远一点     | 第二拍需要更长路线         |
| 02  | 留给第三拍   | 最远一声与半拍差值         |
| 03  | 三声合奏     | 同时编排三路抵达           |
| 04  | 让回声等一等 | 路程与延迟相加             |
| 05  | 留住余音     | 等时路线，反射损耗不同     |
| 06  | 分配一口气   | 远路需要更多初始能量       |
| 07  | 墙里的寂静   | 绕开吸音块，延迟补拍       |
| 08  | 回声编织者   | 路线、等待和能量的综合谜题 |

所有初始状态均未通关，所有关卡由穷举独立验证可解；第 7 关允许两种方案，其他关卡各有一种。测试还覆盖精确能量阈值、准时但太弱、足够响但错拍、吸音阻断、半拍延迟，以及未来自定义节奏。

## 扩展关卡

- `levels.mjs`：纯数据，定义中英文标题/提示、`targets`、`ticksPerBeat`、`beatMs`、能量参数、分声方案与三条声路。
- `engine.mjs`：无 DOM / 音频 / 时钟依赖的模拟、控制状态、配置校验、穷举解法。
- `render.mjs`：SVG 声路、原生按钮叠层和粒子/节拍反馈。
- `main.mjs`：播放状态机、交互、提示、结算与语言。
- `progress.mjs` / `audio.mjs`：独立存档和可选合成音效。

复制现有关卡添加到 `LEVELS`，使用稳定且唯一的关卡和机关 ID。每个选项显式声明 `length`、`reflections`、`loss`、`delay`，需要硬阻断时加 `blocked: true`；每种分声方案的 `energy` 必须合计 300。`solution` 是可验证的参考解，用于提示；实际胜负仅由 `simulate()` 判定。新增条目自动进入选关、进度与中英文界面。

当前首版场景布局支持 **三路，每路一块反射板，随后最多一个延迟段**，`baseLength/baseLoss` 均为零。引擎支持更多顺序段和公共前置耗时，但若加入多块连续反射板、多个延迟段或非零公共前置段，应同时扩展渲染布局及移动端热区测试；不要只加数据就宣称支持新布局。

添加关卡后执行 `validateLevel`、`enumerateSolutions`，检查初始状态不通关、参考解通关、提示与目标一致，并通过真实手机尺寸/触摸浏览器测试。保留已有 ID 即可兼容旧进度。

## 验证环境

在 Linux Chromium 无头浏览器中验证桌面 1440×1100（大厅集成另测 1440×900）、触屏模拟 390×844、窄屏 320×844 及横屏；桌面和手机均以真实按钮点击/点按走通 8 关。覆盖失败重试、机关坐标、动画移动、双竖条暂停图标、暂停/继续、停止、取消触摸、切关、静音通关、中英文与进度重载、存储拒绝及无横向溢出。尚未进行实体手机和 itch.io 线上嵌入验证。
