# Echo Weaver / 回声编织

原创、可静音游玩的 Web 节拍谜题。2.0 将预设声路选项改为可摆放器件的网格：玩家使用有限数量的反射板、分声器和延迟块，自己搭出声路，再发声检验回声是否按目标节奏抵达。

本轮只保留 5 个重新设计的关卡，从一道回声逐步增加到三道。重点验证玩家是否理解“接通还不够，绕路和共享等待才能准时”，以及是否愿意根据试奏结果调整布局；尚不能据此认定玩法的乐趣、难度或时长已得到玩家验证。不使用麦克风、歌曲、商业音源或真实声场模拟。

## 运行与打包

无运行时依赖，无外部字体、图片或音频请求。ES 模块需要 HTTP 服务。

```sh
cd games/local/echo-weaver
node server.mjs                    # http://localhost:4411
node --test tests/*.test.mjs       # 引擎、关卡、存档、音频降级
node build.mjs                    # 输出 dist/
node server.mjs --dist             # 验证发布产物
node tests/browser.mjs            # 构建后执行浏览器交互检查
```

仓库根目录可运行 `pnpm --filter @coffeeeeffoc/echo-weaver build` / `test` / `dev`。大厅在 `apps/shell-web/src/standalone-games.json` 登记；共享 smoke 通过实际点击/点按覆盖摆放、旋转、回收、撤销、失败试奏、重置和切关。

`dist/` 可作为静态 HTML 游戏上传至 itch.io，ZIP 根目录应直接包含 `index.html`。支持子路径托管，无需后端；尚未接入广告或付费系统。

浏览器检查使用 Python Playwright 和 Chromium（`pip install playwright`，随后 `playwright install chromium`，或通过 `BROWSER_EXECUTABLE` 指定浏览器）。可设置 `GAME_URL` 复用已有服务、`GAME_PORT` 指定预览端口；截图与报告默认写入 `/tmp/echo-weaver-v2`。

## 核心规则

- **空间是真正的声路。** 声音沿网格上下左右传播，每前进一格消耗 1 tick；空格直行，墙体阻断，越出边界则丢失。源、接收器、墙体和固定器件不能被覆盖。
- **反射板改变方向。** `/` 与 `\` 两种朝向按照入射方向反射。可移动器件数量有限，摆到某处就不能同时用于另一处。
- **分声器改变路线与能量结构。** 一支继续直行，另一支按照反射面转弯；扣除分声损耗后，两支各分一半能量。第二次分声只能再分配它收到的能量，因此先后分声关系会影响远路是否够响。
- **延迟块只负责等待。** 每块具有固定的 `delayTicks`，不提供无限调节时长的旋钮。放在分声前会影响之后的多路回声，放在支路上只影响那一路；有限器件让共享等待成为布局决策。
- **路程、反射、等待与吸音都会损耗能量。** 吸音格是地面属性，可以经过或在上面放器件。低于 `minEnergy` 的声音无法触发接收器；固定墙与吸音格是不同机制。
- **到达时间是通关条件。** 所有目标 tick 都必须有一支有足够能量的回声准确抵达，不能有多余抵达或丢失的分支。路线接通、声音够响、三声同时抵达，都不能替代目标节奏。

`simulate(level, state)` 使用离散 tick 计算完整传播轨迹，渲染与合成音只负责回放。每关独立配置 `ticksPerBeat` 和 `beatMs`；音频设备延迟、动画帧率与设备像素比例不参与胜负。

## 操作与试奏反馈

从器件栏拖到格子，或先点选器件、再点目标格子；场上的器件也可移动、旋转和回收。核心操作均可用触屏完成，支持撤销和重置；拖动取消或释放到非法位置不应改变布局。

摆放时不显示未来到达时间和实时解答。发声后观察声波经过的格子、分流、等待、能量损耗和到达节奏；结果保留本次传播轨迹及失败位置，用于决定下一次如何调整。失败时直接留在棋盘继续修改，成功才显示结算。目标与实际抵达时间共同展示，区分提前、迟到、丢失和能量不足；可以重放上次试奏，改变布局后需要再次发声验证。

可选中文/英文和原创 Web Audio 合成音，默认静音。支持暂停、继续及停止试奏；切到后台会暂停。v2 存档保存完成记录与偏好，与旧版记录分开，布局编辑不永久保存；浏览器存储不可用时仍可游玩。

## 五个关卡

| 关  | 名称           | 回声数 | 主要决策                                       |
| --- | -------------- | ------ | ---------------------------------------------- |
| 01  | 绕远才准时     | 1      | 直线已能抵达但太早，用有限反射板搭出绕路       |
| 02  | 两条路，一声响 | 2      | 在有限器件下分声并绕墙，分别安排两路时长       |
| 03  | 三声织成节奏   | 3      | 用两级分声自行组建三道回声的网络               |
| 04  | 同一段等待     | 3      | 三路接通仍然错拍，用同一个延迟块同时推迟后两路 |
| 05  | 微弱的第三声   | 3      | 调整分声先后，让经过吸音区域的远路保留足够能量 |

前四关为 8×8 网格，第五关为 9×9。每关提供作者参考布局并由引擎验证；关卡允许探索其他合法解，不声称解法唯一，也不对整个自由摆放空间做穷举。

## 扩展与验证

- `levels.mjs`：纯数据关卡，包含网格、固定环境、有限器件、目标节奏、中英文说明与参考布局。
- `engine.mjs`：无 DOM、音频或时钟依赖的配置校验、合法放置、旋转、回收与传播模拟。
- `render.mjs`：网格、器件、轨迹和播放反馈。
- `main.mjs`：编辑、触屏/拖动、播放状态机、提示、结算与语言。
- `progress.mjs` / `audio.mjs`：独立存档与可选合成音效。

新增关卡时复制 `LEVELS` 中的条目，并指定：

| 字段                                                        | 含义                                                                 |
| ----------------------------------------------------------- | -------------------------------------------------------------------- |
| `id`、`title/titleZh` 等                                    | 稳定且唯一的 ID 与双语文案                                           |
| `cols`、`rows`                                              | 网格尺寸                                                             |
| `source: {x, y, dir}`、`receiver: {x, y}`                   | 起点、初始方向 `N/E/S/W` 与终点                                      |
| `walls`、`absorbers`                                        | 墙坐标和吸音格 `{x, y, loss}`                                        |
| `fixed`、`inventory`                                        | 固定器件与可移动器件；每件有唯一 `id`、`type` 和坐标                 |
| `targets`、`ticksPerBeat`、`beatMs`、`maxTicks`             | 目标 tick、显示节拍与播放速度、传播上限                              |
| `sourceEnergy`、`minEnergy`                                 | 初始能量与触发下限                                                   |
| `travelLoss`、`reflectionLoss`、`splitterLoss`、`delayLoss` | 单格、反射、分声与每 tick 等待的损耗                                 |
| `solution`                                                  | 作者参考摆法数组 `{id, x, y, orientation}`，仅供验证；不参与胜负判定 |

器件 `type` 为 `mirror`、`splitter` 或 `delay`。镜面和分声器使用 `orientation: '/'` 或 `'\\'`；延迟块使用正整数 `delayTicks`。器件栏中的对象坐标为 `x: null, y: null`，已预置的可移动器件使用实际网格坐标。运行状态为 `{pieces: [...]}`；改变位置或朝向不应改变器件种类、数量和固有延迟。

通过 `validateLevel` 检查数据，通过 `simulate(level, createState(level))` 确认初始布局未通关；将 `solution` 的摆法按器件 ID 合并到初始状态后，验证能够通关。应额外检查教学中的错误布局确实失败，例如“已接通却提前”“延迟放错上游影响第一拍”“长路只分到四分之一能量”。正交网格同一起终点的路径长度具有相同奇偶性，设计目标时间时需考虑这一约束。

新增关卡、器件类型或更大网格后，执行单元测试和浏览器交互检查，使用手机尺寸与触屏输入检查热区、拖动取消、失败反馈和横向溢出。浏览器自动化只能验证规则与交互流程；实体手机操作感受、itch.io 嵌入和真实玩家对推理过程的理解仍需单独验证。
