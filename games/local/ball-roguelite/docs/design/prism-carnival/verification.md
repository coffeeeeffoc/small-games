# 星云游乐场验证记录

## 设计与实际画面

先保存产品方案并生成 `concept.png`，再实现 UI。生成的星云背景用于正式素材 `assets/nebula.png`；球珠、裂纹、碎片、按钮与文字由真实 Cocos 3.8.8 Sprite / Graphics / Label 绘制。游戏仍采用官方源码编译的 Cocos Web 引擎，不将其描述成 Creator 工程或已验收原生包。

实际截图位于 `actual/`。检查 390×844、320×568、844×390 三种视口、2× 像素比及触屏输入。已逐页对照首页、选关、游戏、设置、暂停、奖励和补给：保留蓝紫/青金配色与透明球珠，中心选择区周围仍可观察场地，顶边明确可见，44 CSS px 热区适应小屏与横屏。横屏采用完整竖屏场景居中，不裁切或重置对局。

## 规则、存档与音效

`pnpm --filter @coffeeeeffoc/ball-roguelite test`：74 项通过。覆盖连续碰撞、圆珠/六边形轮廓、折射边界、弱重力、碰撞损能、7° 浅角、吸收器、自然/手动/24秒超时回收、24/60/144 fps 一致性、八关可达性、无尽加球节奏与奖励上限。

迁移测试使用由原 `ba3f3966` 规则生成且原校验器接受的六关存档。保留当前砖阵、关卡进度、双模式槽、设置与已消耗奖励次数；超限旧球数归入22球上限并一次性折算现有耐久。schema 2 继续执行原数值上限，不把缺失奖励次数当成未领取。

音效测试用可控制异步完成顺序的 AudioContext，验证静音、暂停、后台与恢复竞争；解决菜单点击造成迟到 resume 重新开声的问题。所有音效共用20声部预算，碎裂噪声缓存。浏览器用真实 AudioContext 检查设置、暂停、继续及刷新后的静音状态；没有将无声运行的自动化浏览器当作人工听感验收。

## 难度与性能预算

`balance-report.json` 保存三种种子、三种合法发射策略的结果与逐轮方向。八关固定竖直发射 0/24 通关、危险目标直射 15/24、搜索借墙角度 24/24。两关专家关均为直射 0/3、搜索 3/3。无尽直射策略存活 99/111/103 轮，角度搜索为139/160（仍存活）/133轮；这些结果证明路线选择有影响，不代表真人胜率或永久平衡保证。

每次更新最多呈现4组新碎片，最多48个实际碎片节点循环复用；损伤裂纹仅在阶段变化时重绘。减弱动态关闭粒子、旋转、拖尾和收集扩散圈，保留规则与可读状态。资源释放经页面退出路径检查。尚未在低端手机测帧率。

## 验证边界

环境为 Linux、Node 24.21.0、pnpm 12.6.0、Chromium 151 手机触屏模拟。广告完成、关闭、迟到回调和一次性奖励使用明确的本地 SDK 夹具；生产未配置 SDK 时补给入口显示未就绪，不模拟观看发奖。TapTap 实际广告位、真机声音/振动、原生包和真实广告结算仍需渠道验收。

生产构建浏览器结果见 `actual/browser-report.json`；发布前另对已提交的准确 base/head 执行仓库增量候选校验。远端 CI 与 Pages 状态在交付时独立核对，本地验证不代替线上部署成功。
