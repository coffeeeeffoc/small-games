# 此时此地 · 时空探索手记

观察历史全景，猜测地点与年代。竖屏移动端以历史档案、旧地图和朱砂印记组织首页、探索章节、小关卡、好友战书、全站榜、玩法说明、设置和个人手记。所有结算仅显示评分，不公布正确答案或误差。图片属于 AI 历史想象复原，不是史料照片，年份为游戏设定。

美术效果图与玩法方案：[移动端 PK 改造](docs/design/mobile-pk-2026-10-09/README.md)。先出效果图，再实现界面；同目录保存实际浏览器截图与验证记录。

## 本地运行

仓库工具链为 Node.js 24.21.0、pnpm 12.6.0。在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter here-and-then dev
```

打开 `http://localhost:4175/`。本地练习无需服务端；好友 PK 和全站榜连接独立的 History 服务。在另一个终端启动：

```sh
pnpm --filter here-and-then server
```

Vite 开发及预览将 `/api/history` 代理到 `http://127.0.0.1:4185`。跨域部署可在构建时设置 `VITE_HISTORY_API_URL`，并在服务端显式允许前端 Origin。访问在线功能失败时显示重试和本地旅途入口，不使用本机成绩伪造全站榜。

```sh
pnpm --filter here-and-then test
pnpm --filter here-and-then build
pnpm --filter here-and-then preview
PLAYWRIGHT_EXECUTABLE=/usr/bin/chromium pnpm --filter here-and-then test:browser
```

`dev` 与 `preview` 共用 4175 端口，不同时启动；浏览器测试的 `PLAYTEST_URL` 可指定其他地址。正式候选还需遵循仓库 [准确候选验证流程](../../../docs/operations/incremental-publication.md)。

## 游玩与竞技

三章九个小关卡，每关三幕，正常逐关解锁。拖动/缩放全景观察，在离线世界地图选点或搜索城市，用滑杆和数字输入猜年份。每幕 25 秒，每幕满分 5000，时间与地点各 2500；超时零分。没有公元 0 年。练习记录、成长与个人最佳保存在本机，已有 v1 足迹可迁移。

| 记录 | 规则 | 用途 |
| --- | --- | --- |
| 全站今日榜 | 可信身份每日一次、五题，开始即占用机会 | 比较当天表现 |
| 全站本周榜 | 北京时间周一换周，本周最高五天相加 | 主竞技榜，允许缺席两天 |
| 好友 PK | 五题同题同限时，每人一次，24 小时战书 | 激励分享和挑战，不累加全站分 |
| 个人成长 | 章节通关与探索记录 | 称号、进度和本机手记 |
| 关卡最佳 | 同一练习关的个人纪录 | 展示个人提升，不跨关求和上榜 |

同分并列，不按网速或设备敏感的提交速度加分。游客可练习和好友 PK；全站正式成绩需要受信身份，不能通过清除浏览器存储无限创建游客刷榜。部署者通过服务器验证的短期签名接入已有账号体系；浏览器只接收签名凭证，不能持有签名密钥。协议与配置见 [服务端说明](server/README.md)。

好友发起者先完成五题，再分享不含题目、种子、答案或开发开关的战书链接。受邀者挑战冻结的同一题组和图像版本，成绩由服务端计算。正式计时切后台、断线或刷新均继续；练习可暂停。接口重试不会重复记分。

## 部署与统计

前端 `dist/` 可部署到静态站点及子目录；不支持 `file://`。服务端为 Node 24 + SQLite，包含建表迁移、持久化存储、健康检查、环境示例、容器和启动说明；可以同时托管 `dist/`，避免前后端跨域。数据卷必须保留。当前设计支持单实例，横向扩容前应迁移到共享数据库。

每日成绩以 `(player_id, competition_date)` 唯一保存，今日榜按分数查询；周榜通过 SQL 窗口函数筛选每人最高五天后求和。以日成绩为事实来源，避免为每个关卡维护全站排行榜；数据增长后可增加 30–60 秒榜单缓存或周汇总投影。

题库按统一难度结构动态抽题并冻结到对局。可以通过 `HISTORY_QUESTION_DIR`、`HISTORY_ASSET_DIR` 指向服务端私有题库；服务端重载新版本后仅新对局使用新题，已生成战书保持一致。正确年份、地点及误差不进入在线题目响应、结算或分享。题图使用短期票据和无语义地址。

现有 28 幕是启动和联调用的公开种子内容，离线练习包仍可被分析，不能把它们当作保密题库。公开上线应换成独立私有题池并持续补充轮换。限时、隐藏答案和限次能降低总结效率，无法保证杜绝截图搜图、历史常识传播、小号或串通。

## 代码与兼容

- `src/main.js` / `src/style.css`：移动端页面、触屏操作和状态切换。
- `src/chapters.js`：独立章节、小关卡、解锁关系和配置校验。
- `src/api.js`：在线身份、限时对局、战书和榜单客户端。
- `src/viewer.js` / `src/map.js`：Three.js 全景、无 WebGL 平面兜底和 Leaflet 本地地图。
- `src/scenes/*.json` / `src/catalog.js`：本地练习内容、校验和素材；内容扩展见 [场景接入说明](docs/scene-authoring.md)。
- `server/`：在线权威规则、SQLite 存储、HTTP API 与部署配置。
- `native.js` / `competition-renderer.js`：已有原生和旧竞技入口同步改为只评分；不代表新增原生平台已经验收。

HTML 的 `data-competition-launch="integrated-history"` 标记复用公共竞技挂载器的已有入口检测，防止 Shell 另外注入旧的浮动 PK 弹层。统一开发模式仍由 `dev-mode.js` 提供，公开战书不带 `dev` 参数，开发解锁仅用于本地练习。

旧 `daily` / `route` 链接对应可重复的本地休闲题组，不是新正式榜；新战书使用 `invite`。旧共享 Runtime 竞技适配保留兼容规则和旧榜单，不与新日榜/周榜混算。

浏览器手机尺寸和触屏模拟不等于真实 iPhone、安卓或原生小游戏平台实测。当前交付不声称已配置真实账号、部署公网服务或完成原生发行。
