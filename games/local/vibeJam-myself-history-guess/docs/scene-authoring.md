# 场景接入与架构决策

## 添加一幕

1. 复制 `src/scenes/kaifeng.json` 为 `src/scenes/你的唯一英文-id.json`。
2. 修改 `id`、中文文案、坐标、年份、容限和背景资料，填写 `location`（可用 `现代名 / 古地名`）。年份支持 -3000 至 2026，不允许 0。
3. 放入独立的 2:1 全景图片到 `public/assets/你的唯一英文-id.webp`，把 `image` 填成 `assets/你的唯一英文-id.webp`。不要填写 `/` 开头的绝对 URL。
4. 可选 `view: { "yaw": 180, "pitch": 0, "fov": 75 }`，决定本幕初始与重置视角；范围依次为 0–360、-65–65、35–90。普通场景省略即可。
5. 执行 `pnpm test`、`pnpm build`。启动预览后执行 `pnpm test:browser`，或使用首页「指定场景练习」实际观察与答题。

无需修改 `main.js`、`viewer.js`、城市表或任何注册清单。Vite 自动发现同目录下所有 `.json`（不扫描子目录）；新增内容自动进入随机题库、练习列表、足迹、计数和中文地点搜索。`region` 为 `china` 或 `world`，后者表示中国以外的历史场景。「世界漫游」随机池包含全部场景。

开发时添加文件由 Vite 重新扫描；静态线上版本需要重新构建和部署才更新。这里没有运行时上传服务或后台管理。

## 配置约束与素材

必填字段以现有 JSON 为模板。`source` 是 `[资料名称, HTTPS链接]`，`details` 是非空纯文本数组。文案不允许 HTML、尖括号或 ASCII 引号，可使用中文引号。ID 必须唯一且只含小写字母、数字和分隔用短横线。坐标须在当前地图范围内（纬度 ±85，经度 ±180），容限为非负整数。

图片仅允许 `assets/文件名.webp|jpg|png`。每幕应有独立画面与能观察到的时代、地理线索，配以宽容合理的评分；不要复制同图充数。避免以标题或图内年份直接泄露答案。历史背景与艺术想象须分清，精确事件锚点应有资料支持。

统一校验函数同时供构建与浏览器调用，错误会指向场景 ID 与字段；构建还检查图片缺失与空文件。浏览器逐幕回归检查图片解码、尺寸比例、真实选点、计分、揭晓、单幕结算及足迹持久化。修改校验规则时执行单元检查。

## ADR：沿用全景渲染基座，场景改为独立数据文件

状态：已采用。需求是持续扩充大量历史全景，同时保留原 8 幕的画面和交互。

选择：`scenes/*.json → rounds.js 自动发现 → catalog.js 校验与默认值 → main.js 流程 → viewer.js / map.js`。`main.js` 只关心当前场景的同一数据结构，查看器只加载当前图片并释放上一张 GPU 纹理。回合进度与结算从当前题组长度计算，支持五幕随机和单幕练习。存档沿用稳定 ID，原有足迹和最佳分不迁移、不清空。

考虑过的替代方案：继续扩充一个大数组更省初始代码，但多人加场景容易冲突且依赖手动维护；每幕独立 JS 插件可以写不同玩法，但本需求都是同一种全景猜谜，会重复控制器和生命周期；远程题库服务允许免构建更新，但增加网络和运维依赖。当前采用独立 JSON 与静态构建。

边界：场景元数据在启动时统一加载，图片按当前幕加载，足迹缩略图懒加载。没有声明数量硬上限，但极大题库（数千幕）应在实测启动体积或选择器性能出现问题后再分页或拆包。图片仍是球面投影的艺术复原，不是可行走的几何场景，也不保证完全无接缝。资源失败使用现有重试；切换与销毁使用请求代次隔离过期响应。
