# 水位联动站 · 移动端 Cocos 改版

## 产品方案（实现前）

保留 50 个稳定关卡 ID、现有离散水量规则、机关锁存、溢流动力、最短解、星级和历史存档。以竖屏触屏解谜为主：观察水槽 → 点击场景阀门 → 水位联动 → 完成箱子、船与水轮目标 → 解锁下一站。竖屏适合无实时移动的分步解谜，避免横屏旋转门槛；宽屏居中呈现同一竖屏舞台。

页面顺序：主页 → 章节选关 / 继续 → 游玩 → 结算 → 下一站 / 重试 / 主页。暂停、帮助和设置作为独立页面，有明确返回路径。正常关卡依次解锁，旧存档的已通关关卡及已选关卡保持可访问，开发者模式允许调试选关，挑战记录与正常成长隔离。

## 效果图方向

先生成 `concept.png`：三张手机比例画面覆盖主页、游玩和选关。深海蓝底、淡薄荷色文字、青绿色水体、暖橙阀门和黄铜管线。画面表现为精致的平面水站剖面插画，避免桌面仪表盘、文字侧栏和表单布局。

主页：站点铭牌、三水槽主视觉、章节进度、主按钮“继续调度”、次按钮“航线选关”，底部帮助与设置。

游玩：顶部返回/关卡名/标准双竖条暂停，下方剩余操作与目标，中央三个至五个水槽及管道，阀门触点直接位于管道上；底部撤销、预测、提示。水槽上显示出口线/开关线与必要的水位值，锁定阀门提示解锁条件。每个主要触点至少 44 CSS px。

选关：当前章节名、进度、十个关卡节点；可用、当前、完成、未解锁状态同时通过形状/文字区分；切换五章不依赖横向细小标签。

## 技术与验收

采用仓库已验证的真实 Cocos Engine 3.8.8 官方源码 Web runtime；场景、绘制、动画更新与触摸分发使用 Cocos。它不是 Creator 编辑器导出，也不宣称已生成原生小游戏包。纯规则与关卡配置继续独立；DOM 仅用于加载错误、无障碍镜像与浏览器平台适配。

保留预测确认、撤销、一次免费加步、提示、分享挑战隔离、音效偏好与统一 dev 模式。遵循最新仓库约定，不增加浏览器全屏入口。处理触点取消、多触点、窗口失焦和前后台暂停。加载失败提供重试；禁止 WebGL 时显示明确失败。

验证覆盖：手机尺寸真实浏览器触屏输入、主页/选关/游玩/暂停/结算/返回、解锁与存档、挑战隔离、复杂五槽关卡、预测/撤销/失败加步、屏幕尺寸变化和 dev 开关。运行规则测试、游戏构建、相关 Shell/开发模式检查及准确候选校验。实际截图与效果图对照后保存；桌面手机模拟与真机验收明确区分。

## 实现与效果图对照

实际场景沿用概念图的深蓝港口、青绿水体、黄铜管道和橙色阀轮；采用原创程序插画与 Cocos Graphics，使水量、船箱、机关和阀门状态可随规则变化。没有把概念图当作游戏画面。主页、游玩与选关保持同一视觉语言；复杂关卡的水位数值位于槽外，选中管线高亮两端，箱子平台与规则阈值对应。

竖屏是主要布局；568×320 等短横屏改为场景与工具分栏，降低装饰文字密度。实际测试曾发现仅修改设计分辨率会留下旧的 Cocos 内部相机尺寸，现已同步 render root 与画布像素尺寸，并通过旋转后真实阀门输入验证。主要操作区至少 44 CSS px。

## 验证环境与边界

Node 24.21.0 / pnpm 12.6.0，Linux Chromium 151 手机视口与真实浏览器触屏事件。80 项规则、布局、存档测试通过；50 关逐步触屏求解均与纯规则状态一致；覆盖 320×568、390×844、568×320、844×390，禁用存储、开发试玩和分享降级。

CDP 主动取消触摸时，官方 Cocos 输入适配器可能输出一条“非 cancelable touchcancel 调用 preventDefault”的浏览器 intervention；测试仅将这条精确诊断单列记录，其他应用错误与资源加载失败仍阻断。手机模拟不等于真机验收，源码运行时不等于 Creator 编辑器导出或原生小游戏包。
