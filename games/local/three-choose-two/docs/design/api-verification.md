# 在线排位验证记录

2026-10-07，Linux 容器内运行 Node 24.21.0、pnpm 12.6.0、PostgreSQL 17.11。数据库仅监听 `127.0.0.1:15432`，使用隔离的 `competition_test` 与 `runtime_app` 权限；执行既有 010、011 迁移和新增 012 迁移，未连接生产库。

验证命令：

```sh
pnpm --filter @coffeeeeffoc/runtime-api typecheck
pnpm --filter @coffeeeeffoc/runtime-api lint
THREE_CHOOSE_TWO_TEST_DATABASE_URL="$LOCAL_COMPETITION_TEST_URL" pnpm --filter @coffeeeeffoc/runtime-api test
```

结果：类型与 lint 通过；7 个测试文件、36 个测试通过。新集成用例启动真实 Fastify TCP 服务，以 `fetch` 向本机随机端口发送 HTTP 请求，所有确认状态、操作和成绩均写入真实 PostgreSQL。集成用例要求显式配置测试连接，且强制数据库名为 `competition_test`；未配置时明确跳过。测试结束删除本次生成的用户与成绩，不导入游戏正式榜。

已验证：

- 同一真实身份并发创建时只获得一个活动排位会话；他人不能恢复或结束该会话。
- 响应只包含当前候选和必要游戏状态，未返回种子、随机生成器状态、未来序列或撤销快照。
- 伪造积分、候选编号或身份被拒绝；跳号、同序号不同操作、重复使用槽位和错误组号被拒绝。并发重复提交同一步只确认一次。
- 刷新恢复棋盘、组号、积分与确认序号；终结幂等，仅写一条结果，终局不能继续刷分。
- 固定测试种子引用 20261007（测试内补齐为 64 位字符串）采用 `sha256-counter-v1`，合法 16 步取得 525 分。每步 HTTP 确认积分及统计与纯规则层一致，结束时从原始种子和全部操作重放得到相同结果。随后 0 分对局不覆盖 525 分最高分或首次达到时间。
- 24 小时到期按最后确认的第 1 步棋盘和积分结算，重复恢复不改变结算时间。
- H5 guest 可使用匿名在线会话，结果明确为 `ineligible`，不会进入真实用户榜。
- 异常成绩保留重放记录并等待复核；通过受保护的本机内部接口批准或撤销后，个人最高分和榜单重新计算。
- 独立归档规则版本中的 300、300、100 分显示竞赛名次 1、1、3；同分按首次达到时间排序；每人只占一条记录；返回自身及前后 2 个位置；新旧榜不会混排。
- Runtime Service 使用真实数据库启动后的 `/health` 返回 200，数据库及竞赛依赖均为 `ok`。

本记录证明本地服务与真实 SQL 行为。微信/B站官方 code 换取身份沿用既有服务端实现，其 HTTP 边界测试仍通过；当前记录不等同于平台真机登录、生产部署或线上排位验收。
