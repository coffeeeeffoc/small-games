# 三块选两块实施方案

日期：2026-10-07。产品依据：[product-spec.md](product-spec.md)。竖屏积木拼盘玩法明确适合竖屏；主页、选关、游戏及结算均采用同一竖屏适配策略。概念图已于代码实现前完成。

## 1. 交付目标与能力边界

实施完整的移动端优先游戏闭环：首页 → 选关 → 关卡说明 → 游玩 → 暂停/结算 → 下一关/重玩/首页。30 个配置关卡逐步引入清线、多线同消、交叉消除与弃格预算；无尽沿用统一规则和计分。前三关以场景内单句提示介绍拖放、两次落子后自动丢弃、先后顺序打开空间。保留设置、帮助、排行榜与开发模式，避免摆放尚不可用功能入口。

按真实仓库能力接入身份、Game Host 存档、在线会话、全站排行、广告与分享。没有在线排位服务时，无尽必须清楚显示“本地练习”，只保存个人本地纪录；不生成虚构玩家、排名、校验成功或“击败百分比”，不以客户端自报数字代替产品要求的服务端重放。没有激励广告能力时，不展示无法兑现的观看广告续局入口。平台接入和真机验收按交付记录陈述实际完成情况。

## 2. 规则层与配置层

- 核心规则为不依赖 DOM、平台或 Shell 的纯状态转换：8 × 8 棋盘、24 种左右固定朝向形状、每组三候选放两块、满行列并集消除、得分与连击、目标/失败、撤销及重放。
- 每关有稳定 ID、内容版本、初始棋盘、完整固定候选序列、最大组数、最多两项目标、嵌套星级阈值、解锁条件、最多一次续局固定附加序列及一条最高星级合法解法。关卡独立数据文件或可登记的数据项，不在规则循环按 ID 特判。
- 配置校验检查形状 ID、格子坐标、目标合理性、候选序列长度、唯一关卡 ID、连续解锁引用和奖励阈值；重放保存的解法确认所有落子合法且最高星级可达。
- 无尽形状库/发块分布/计分版本独立登记，随机序列用可序列化种子和确定性生成器。三大块的极端组合约束属于统一规则，不能按广告、充值或历史成绩改变。
- 状态保存棋盘、组号、候选及已用槽位、组内落子数、积分、连击、清线数、多线/交叉次数、弃块/弃格、随机状态或候选游标、目标、设置及最近一次可撤销快照。

## 3. 精确结算顺序

一次合法落子必须按以下次序完成：整体写入形状 → 在同一盘面计算全部满行/列 → 计算消除线数、交叉、积分和目标 → 清除行列并集 → 优先判定关卡胜利 → 判断当前组是否完成 → 若第二次落子则自动丢弃唯一未用槽并计弃格 → 判预算、组数与可放性 → 若仍可继续，发出确定性下一组。

关卡第一步已达标即胜利，不强制第二步或计算尚未丢弃的格数。最后一组第二步达标判胜；未达标判组数耗尽。只要当前剩余候选中任意一个能放，就不得提前判失败。没有合法落子和弃格超预算不能通过加两组续命。完整行列并集一次性消除，交叉格仅清一次，棋盘不下落、不压实。

积分仅来自消除：`100L + 50L(L−1) + 25L × min(C−1,4)`。零线时 C 重置，消线时 C 增加一次；丢弃、暂停、拖放失败和跨组都不改变 C。首次两线消除得 300 分。

撤销每局三次，仅回退最近一次成功落子，消耗次数；快照恢复候选/游标/随机状态以及全部目标计数。跨组撤销回到第二次落子之前，同操作重放获得同一后续组；不允许连续追溯旧落子。无尽排位/练习保持与排位一致的不撤销规则。

## 4. 页面与触屏

| 页面 | 主操作与信息 |
| --- | --- |
| 首页 | 大块插画；开始/继续闯关；无尽挑战；个人纪录；底部选关、排行榜和设置 |
| 选关 | 三章各十关，五列关卡卡片；星级、当前关、锁定状态；只解锁已通关关卡的下一关 |
| 关卡说明 | 关名、至多两项明确目标、最多组数、一个开始按钮；独立页面或清晰完整的准备状态 |
| 游戏 | 两侧返回/暂停，中间关卡；目标和组数/积分；大 8 × 8 棋盘；三个固定槽；撤销/帮助 |
| 暂停 | 继续、重开、回首页；音效、音乐、振动与高对比/减弱闪光设置；H5 全屏入口 |
| 关卡结算 | 成败原因、清线/目标、组数、星级；下一关、重玩、仍有效撤销、可用续局；回首页 |
| 无尽结算 | 最终分、个人纪录、清线、最高单步、最大连击、组数及真实校验/排名状态；重玩/榜单/分享/回首页 |
| 排行榜 | 只显示真实已校验成绩；离线或未接入时解释状态并保留返回；无虚构榜单 |

拖动使用 Pointer Events，捕获当前主触点。手指与积木锚点有向上偏移，预览按棋盘实际格距显示完整轮廓；合法预览正常色，非法预览清晰禁止色/符号，预览预计清除的行列。松手非法、pointercancel、失焦和退出页面回弹，不计落子、不扣机会。多触点不能重复提交。200–350 ms 消除反馈期间锁定落子，候选槽位固定且已使用槽保留空位；第一次落子后提示“再放 1 块，剩下的自动丢弃”；第二次后未用块缩小淡出。不可放候选弱化并保留轮廓与可感知禁用状态，盘面改变立即重算。

主要热区不少于 44 CSS px。暂停图标必须是两根等宽等高且分离的实心竖条，并提供“暂停”无障碍名。按钮与重要设置提供可访问名称；颜色以外使用星级、锁、目标数字及状态短句传达规则。

## 5. 适配、宿主与存档

竖屏视口采用 CSS 动态高度、安全区 env 与最大宽度约束；棋盘按可用宽度等比缩放，短屏减少纵向留白而不缩小必要操作热区。360 × 780、390 × 844 和 412 × 915 手机视口可玩。桌面居中显示同一竖屏游戏面板。Shell 嵌入游玩时隐藏外围目录/品牌内容，iframe 坐标使用实际 board DOMRect，不能依赖绝对屏幕坐标。

复用 Game Host 提供的存档与导航；独立运行采用已有适配或可靠本地存储回退。关卡进度存历史最好星级、最佳用组数、最新可继续对局；存储失败不阻断本地对局。页面离开、后台和暂停统一取消拖动并暂停反馈计时，恢复不跳帧、不重复提交。H5 全屏复用公共 fullscreen 能力；原生平台不显示浏览器全屏按钮。

开发模式复用统一 SmallGamesDev URL/存储语义，默认关闭，显式关闭优先；面板按需打开，配置跳关与玩家正常解锁分离，开发测试成绩不写入真实榜单。不得修改同步副本以产生私有语义。

## 6. 验证与交付

1. 规则测试覆盖产品验收 1–9、11、15–17 的规则部分：合法性、同步交叉消除、计分、即时胜利、最终组判断、跨组可逆撤销、存档/确定性重放及配置解法可达。
2. 触屏浏览器按实际手机尺寸走通主页、选关、准备、拖放、暂停/继续、胜负结算、解锁和恢复；检查非法回弹、取消、多触点、输入锁与候选固定位置。
3. 实际截图与先行 SVG 对照，保存于 `docs/design/actual/` 与 `docs/design/native-actual/`；验证记录写明浏览器/视口、实际检查项、截图路径及尚未完成的真机/平台验证。
4. 按改动范围执行配置、开发模式、宿主入口/生产构建相关检查，复用仓库已有命令，不扩大为无关全量测试。
5. 实现与校验后连同附件、方案、概念图、实际截图和验证记录提交，按 AGENTS 规定同步远端准确候选，执行相关检查并立即推送 dev；保留已有改动与 hooks。
