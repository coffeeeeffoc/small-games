## 1. 术语与最小状态

| 术语 | 精确定义 |
| --- | --- |
| 回合 | 一次收入/整备开始、玩家经营、全大厅战斗与结算 |
| 行动 | 一次战斗主动普攻；与备战中一次购买/施法等操作不同 |
| 卡牌定义 ID | 同一种牌共用的稳定 ID；不随显示名称改变 |
| 实例 ID | 一次生成的具体卡；相同名称可以有多个实例 |
| 自有角色 | 自己战场或手牌中的角色实例，不含未购买的商品 |
| 友方角色 | 效果未另外注明时，指自己战场角色 |
| 本体 | 锁定阵容时存在的原始战场角色，与战斗召唤物区分 |
| 永久 | 仅本局跨回合保留，不是跨对局账号养成 |
| 下场战斗 | 本回合即将进行的那一场战斗；未上场也会在该场结束时消耗 |
| 牌面基础属性 | 角色在 L1、无装备和其他增益时的攻击与最大生命 |

后续实现所需状态包括：对局版本/回合/阶段/随机状态、8 人的血量/金币/P/商店/冻结/手牌/六格战场、累计胜场/开局席位优先级/上轮配对/镜像轮转记录/已淘汰者锁定快照、卡实例 L/装备/准备效果/本回合计数、当前锁定战斗快照及结算标记。卡面静态文本与基础属性由定义 ID 查找，不在每张卡实例里复制整套定义。

## 2. 等级与成长

### LEVEL-01：同名直接叠加

只能在备战操作。选择同卡牌定义的目标和材料，均须为自有角色且实例不同；允许战场↔手牌、手牌↔手牌、战场↔战场组合。

```text
L目标(新) = L目标(旧) + L材料
材料实例被消耗
```

- 不需要凑三张、不升星、不改道具品阶、不凭空多发一张牌。
- 材料被消耗不算出售、阵亡、牺牲，也不支付卖价；它的被动随后不再监听事件。
- 保留目标的位置、装备和准备效果。材料所穿装备原样返还手牌，材料的准备效果清除；不自动塞到目标身上。
- 先计算操作结束的容量，再决定能否执行。例如材料来自手牌时先释放一个位置，再计算装备返回占位。
- 合并不会重新触发登场、装备获得、回合开始等事件。次数状态不重置；同名角色的对应已用次数取目标与材料的较大值，避免用合并清洗限制。
- 一次 L4+L3 合并只生成一个 `LevelGained(delta=3, reason=merge)`，不是三个事件。

### LEVEL-02：直接成长与联动成长

任何成长增量必须为正整数。法术或独立被动直接提供等级时记为 `gain`；合并记为 `merge`。它们让等级实际增加后，发出一次含「目标、实际增量、原因」的成长事件。

监听这次成长而追加给自己/其他角色的等级记为 `link`，只改变 L 并产生视觉日志，**不再通知成长监听器**。一个事件可让多个符合条件的监听者各触发一次；单卡次数限制仍按牌面执行。

```text
给甲 +3（gain） → 甲实际增加3 → 乙监听后 +1（link）
                                          └ 不再引发甲/丙的成长监听
```

效果若按增量奖励，牌面必须写明计算方式；写「每当升级」表示每次事件一次。不能把 L+10 拆成十次操作来多触发十次。

商店增级只改商品实例，不产生自有角色成长事件。买入时保留商品当前 L，但购买本身不补发过去的成长事件。实例从手牌移动到战场也不补发之前的升级。

### LEVEL-03：等级转移与交换

基础转移只搬可转移成长 `G = L源 - 1`。源与目标是两个不同的自有角色；不必同名或同流派，除非法术有明确限定。G 必须大于 0。

```text
转移前：A=L21，B=L4
搬运量：G=20
转移后：A=L1，B=L24
双方总L：25 → 25
```

- 源保留基础 1 级和自身身份，目标只增加 G。不会从 A 的基础 1 级反复生成额外资源。
- 只发一次 `LevelTransferred(source, target, amount=G)`；不发普通成长事件。转移专属奖励若加等级统一记 `link`。
- 每张转移法术必须从手牌消耗，有费用来自购买；反复 A→B→A 不是免费指令。
- 装备、品阶、独立准备效果、次数限制均留在原实例。临时攻击/生命/护盾不是等级，不可转移。
- 原子地完成两者等级变化，再处理转移监听；目标选取不得看到「源已减级、目标尚未增加」的中间状态。
- 等级交换是 `G_A` 与 `G_B` 对调，等价于双方 L 交换；发一次 `LevelsSwapped`，不发两次 `LevelTransferred`。L 相同的交换视为无效操作，不耗卡。只有牌面明确监听交换的能力才响应。
- 未来若设计「吃掉 A、搬走 A 全部等级」法术，必须另立消耗源实例的规则，不能借用保留源角色的上述转移指令。

### LEVEL-04：属性与无上限

对角色牌面基础攻击 A0、基础最大生命 H0：

```text
永久攻击 A = A0 + (L - 1)
永久最大生命 H = H0 + 2 × (L - 1)
战斗初始属性 = 永久属性 + 装备持续修正 + 本场准备效果
```

L 不设游戏上限，不使用满级星数替代。高品阶主要提供更强机制和较高基础属性；高等级低阶角色依然能用。L21 的 A0=2/H0=7 角色为 22 攻、47 血，无装备时进入战斗即满 47 血。

没有默认暴击、闪避、护甲、法力或技能冷却系统。基础攻击最低为 1，最大生命最低为 1；护盾可以为 0。需要倍率时用整数分子/分母，向下取整，例如攻击的 50% 表示 `floor(A/2)`，除非牌面写明最低值，不另补 1。

无限成长要求精确整数；后续实现可用 BigInt 处理等级/攻击/生命，存档存十进制字符串，禁止先转 Number 再计算大数。显示缩写不改变内部值。不能因为动画数字宽度、JSON 限制或浮点精度偷偷封顶；有限回合、金币和触发次数控制一局实际可达增长量。

## 3. 区域、出售与装备

### ZONE-01：区域及容量

| 区域 | 容量 | 允许内容 | 默认效果状态 |
| --- | --- | --- | --- |
| 商店 | 3角色格 + 1法术格 + 1装备格 | 未购买的商品实例 | 仅明确针对商店的效果可修改 |
| 手牌 | 10 格，三类卡共用 | 已买角色、未用法术、未穿装备 | 被动默认不生效；写明「手牌」者例外 |
| 战场 | 6 格，前排 F1–F3、后排 B1–B3 | 已买角色 | 默认被动生效 |
| 装备位 | 每角色 2 格 | 穿在该角色身上的装备 | 宿主在战场时生效；手牌宿主携带但不生效 |
| 已消耗区 | 不作为玩家可操作容器 | 法术、合并材料、售出卡的历史记录 | 不监听事件，不可取回 |
| 战斗副本 | 每方仍最多 6 格 | 本体及临时召唤物 | 仅战斗状态，结算后销毁 |

手牌角色携带的装备不另占手牌格，直到装备卸下或角色出售/作为材料合并。战场允许多个同名角色，主动选择是否合并；同名能力叠加受各自计次限制约束。

### ZONE-02：合法流转

| 操作 | 起点→终点 | 成功后的特殊处理 |
| --- | --- | --- |
| 购买 | 商店→手牌 | 扣商品当前价格，原货架留空；发一次 Purchased |
| 部署 | 手牌→空战场格 | 无默认免费成长或产金 |
| 替换 | 手牌角色↔战场角色 | 战场旧角色进入所选手牌格；装备随角色 |
| 调位 | 战场两格互换或移入空格 | 只改位置，不重新开回合/触发购买 |
| 撤回 | 战场→手牌空格 | 手牌满则失败，装备随角色 |
| 合并 | 同名材料→保留的目标 | 按 LEVEL-01；销毁材料并返还材料装备 |
| 穿装备 | 手牌装备→自有角色装备位 | 两个装备位满时必须显式选择替换 |
| 换装备 | 手里一件↔角色所穿一件 | 旧装备占原手牌槽；整体一次提交 |
| 卸装备 | 角色装备位→手牌 | 需要空手牌格；同一装备实例与计数保留 |
| 使用法术 | 手牌→已消耗 | 先完成所有目标和容量验证；成功后发 SpellCast |
| 出售 | 自有角色或其他手牌道具→已消耗 | 固定1金，角色装备返手 |

法术只能在备战使用；不直接拖到敌方商品或对方手牌。本版面向敌人的法术效果都是先准备，再在下一场战斗执行。

### ZONE-03：装备约束

- 同一角色不能同时佩戴两件同名装备。不同角色可以各戴同名装备。
- 装备卡不自行长经验、不合并。固定攻击/最大生命加值只计算一份，不因穿脱重复累加。
- 穿脱和转移装备免费；「每回合一次」绑定原实例，与装备当前在哪个区域无关。
- 本体升级时装备附加固定数值不按 L 倍乘。牌面明确基于佩戴者等级或攻击计算的特殊效果，才在指定时点计算一次。
- 普通装备效果取当前佩戴者；附着在角色上的法术准备效果留在原角色，不随装备移动。

### ZONE-04：出售与操作原子性

所有购买、卖出、合并、换装、施法遵循：**验证阶段/归属/金币/有效目标/最终容量 → 一次提交 → 派发事件**。非法或取消动作不扣钱、不丢牌、不推进规则随机状态，也不触发奖励。

卖角色固定得 1 金，角色等级不会折算卖价。已穿装备返还手牌而不是一起销毁/变现；空间不足则不能卖，提示需要腾出的格数。手牌本身释放的位置参与容量计算。

出售被移除者不再触发自己的普通战场监听；若未来有「出售此牌时」卡文，需要显式的自身售出事件。其他卡的「出售其他角色」可读取被售出实例的旧 L、T 和原区域快照。

产金奖励使用总纲每名指挥官每回合 3 金额度，超过部分不获得，界面显示剩余额度。卡面折扣不属于产金，但价格不能低于 1 金；折扣只绑定当次商品，刷新销毁后失效。不存在同一商品买入后免费退货再领购买奖励。

## 4. 事件、次数与准备效果（EVENT-01）

| 事件 | 发生时间 | 常见排除项 |
| --- | --- | --- |
| PrepStarted | 新回合重置次数、发收入、处理自动刷新/冻结补货之后 | 不把上下场当整备开始 |
| Purchased | 商品成功进入手牌之后 | 不等于部署、合并、获得装备效果 |
| PaidRerolled | 扣1金并生成完整新商店之后 | 不含回合自动刷新、冻结补位、法术效果刷新 |
| LevelGained | gain/merge 实际增加角色 L 之后 | 不含 link/transfer/商店历史增级 |
| LevelTransferred / LevelsSwapped | 对应原子操作完成之后 | 不互相代发，也不代发 LevelGained |
| SpellCast | 一张法术完整结算并被消耗之后 | 无效/取消目标不触发；技能效果不是打出法术牌 |
| CharacterSold | 角色移出自有区、返还装备及收取卖价之后 | 合并材料、召唤物死亡、出售装备均不算 |
| BattleStarted | 战斗副本建好、满血和准备属性生效之后 | 新召唤物不重触发全队开战 |
| AttackResolved | 一次主动普攻与反击及随之而来的死亡链处理完成之后 | 反击、反伤、技能伤害均不生成新的主动攻击事件 |
| DamageTaken | 一批同时伤害及死亡移除完成后，向本次确实损失生命且仍存活者发出 | 纯护盾损耗、生命归零的主动牺牲、不存活的受击者不发 |
| CharacterDied | 战斗角色生命≤0被同时移除后 | 不含备战卖出/合并；默认监听本体，含召唤物必须写明 |

### 稳定顺序

1. 一个备战动作及其连锁完整结束后才接受下一个动作。事件内先完成主体数值变化，再以事件快照筛选合法监听者。
2. 备战同事件监听顺序：战场 F1→F2→F3→B1→B2→B3，再按牌面明确允许的手牌顺序；每角色先角色能力，再装备位1、位2。候选目标重新取执行时合法对象。
3. 战斗涉及双方时，以本场种子指定的首攻方优先，其次另一方，同侧仍按槽位/装备顺序。死亡本体自己的明确阵亡能力使用死亡前快照执行一次。
4. 通用「随机」在卡牌列出的合法对象中等概率抽取；列表稳定排序后用规则种子选。未写随机而只写「最低等级/最左/最高攻击」的效果按牌面排序，同值默认槽位顺序。
5. 同一事件的监听列表固定后，按先后加入队列；新事件追加到尾部。实际执行时检查来源仍能生效、目标仍合法、次数尚余。无目标不触发、不占次数；已经产生并排队的独立阵亡能力不要求死亡来源重新存活。
6. 发起主动普攻的角色在该次死亡链后仍存活才可触发自身「攻击后」能力；已死攻击者不靠其他新召唤物代替自己触发。

次数按卡牌实例、效果 ID、回合/战斗记账，跨区域保留。合并时依 LEVEL-01 继承已用次数，装备返手不清次数；下一回合/下一场战斗才统一重置。卡面「本回合前N次自身在场时发生的事件」统计本实例在生效区域实际监听到的事件，不追溯其入场前的操作；下场再上场继续原计数。另买新实例有独立计数，但要付正常购买成本；不存在免费刷新实例的操作。

「下场战斗」效果绑定被选角色实例或指挥官，使用时牌面说明。附着角色的准备效果不因撤回手牌而清除，但该角色若没上本回合战斗，也在结算时清掉；卖出/作为合并材料则直接丢弃。转移/交换只处理等级。不同法术给予的同类数值可加，明确「每个角色仅一次」者不可重复；没有隐藏复制或永久化。

不能单靠战斗60行动上限阻止技能无限递归。成长 link 不回传，反击/反伤不触发攻击后，召唤和阵亡相关监听有明确次数，免费移动没有收益。后续每增加一个事件关系，都检查是否形成无成本的闭环。

## 5. 自动战斗（BATTLE-01）

### 开场与存续

1. 从双方锁定状态建立副本；在场本体继承 L、装备及本回合准备效果。双方同时应用装备持续属性、准备攻击/生命和准备护盾，初始生命为完整最大生命；没有准备护盾者为0盾。
2. 记录每个本体开场生命 Hstart（包含装备与准备属性，尚未发生开战技能伤害）；此表只用于超时判定。
3. 先按 EVENT-01 顺序执行角色/装备的 BattleStarted 被动，本版这些效果提供开场护盾；再执行法术及施法监听附加的开场准备技能。同一角色的多份准备技能按附加顺序，角色之间按首攻方/槽位顺序。每项开场能力及其派生事件链结清，再执行下一项；未执行的来源若已死亡则跳过。所有开场项目与队列处理完再判断胜负。这样准备护盾及开场被动护盾一定早于开场进攻。
4. 本场胜负结束后销毁副本；阵亡不会删除经营区角色，受伤不会带到下一回合，召唤物不加入手牌。v0.1 不设置战斗过程直接写回永久等级/金币的卡；未来新增必须单独定义结算奖励。

### 行动顺序与目标

首攻方用本场种子 50% 抽签，双方各有从 F1 开始的轮询游标。轮到一方时，从其游标向后循环寻找存活角色，让其执行一次普攻，游标移到该槽下一格；随后轮到另一方。召唤物占固定空槽，轮询经过时可正常攻击；不能凭插入同一槽无限获得额外回合。

普通攻击目标顺序：任意位置的嘲讽角色优先 → 敌前排存活者 → 敌后排存活者；同一集合选最左槽。无需手动点敌人。无嘲讽时，前排倒下才会直接攻击后排。

定向非普攻技能默认可在全部存活敌人中选目标，不受前后排或嘲讽保护，但按各卡文字明确选择方法。这是处理单核/后排发动机的手段；不另加入寻路、攻击距离或地形。

### 一次普攻的结算

1. 在宣告时记录攻击者/目标及双方当前攻击，确定主动攻击伤害和目标反击伤害。
2. 双方各承受对方攻击值的一次伤害，**同时提交**。护盾先吸收，剩余扣生命；反击者在本次会被击杀也照常反击。伤害修正只改变该次主动伤害，不默认提高反击值。免死效果在扣盾后、死亡移除前处理：符合条件的首次致死伤害将生命置1并消耗其一次效果。
3. 同时找到生命≤0的角色，全部移出战场并释放槽位。对确实受伤且幸存者排入 DamageTaken，再排入阵亡能力与其他阵亡监听；同类按 EVENT-01 顺序处理。治疗不能让本次已移除的角色复活。
4. 技能造成的新伤害再次按同样批次处理死亡，直到队列为空；不因中途一方暂时空场而跳过已排队阵亡召唤。
5. 无论原攻击者是否存活，都发一次 AttackResolved；只有仍存活的原攻击者能执行自身攻击后能力。处理这些效果与新死亡链，然后判断胜负并切换行动方。

普攻反击不再触发另一次普攻，反伤不再触发新的反伤链或攻击后。牌面写「攻击后」均只算本人的主动行动，不把被别人攻击算一次。伤害被护盾完全吸收也算已完成主动普攻。

### 护盾、治疗与召唤

- 护盾是临时数值池，可叠加，先于生命吸收伤害；拆盾按卡文移除盾，不扣生命。护盾不算最大生命，不转移为成长。
- 主动牺牲直接令战斗副本中的角色生命归零，再走正常阵亡流程；它不是伤害，不触发 DamageTaken，也不能被不屈挂坠等免死效果阻止。若卡文要求先增益队友再牺牲，两步仍属于同一个效果，按文字顺序执行。
- 治疗如卡文存在，只恢复到当前战斗最大生命，不复活；增加最大生命的效果必须注明是否同时补当前生命。本版装备/准备生命加值在开场满血时统一生效。
- 召唤先找 F1→F2→F3→B1→B2→B3 的第一个空槽，不挤走现存角色。若牌面指定「原位置」，优先用它，已占则按上述顺序找空槽。
- 每方在场最多6个，每方每场累计成功召唤最多12个。每次召唤超出空位/总数时略过，多只请求按顺序尽量生成；累计成功数只增加实际生成量。
- 临时召唤物有独立战斗 ID、牌面规定的攻击/生命、无商店品阶和可转移的永久 L；不能出售、合并、装装备、触发自有角色成长，不在战后留下。
- 默认阵亡监听只计本体；明确写「包括召唤物」的卡可监听它们，仍受牌面次数限制。召唤物没有未写明的遗言技能。

### 胜负与60行动上限

完整事件链后，一方无存活单位，另一方有，后者胜；双方均无则平局。双方开局均空场也是平局；单方空场判负。不得对空阵容做生命比例除法。

完成第60次主动行动及其所有连锁后仍双方存活，用原始本体的生命留存比例：

```text
S = Σ clamp(本体当前生命, 0, 本体Hstart)
D = Σ 本体Hstart
比例 = S / D
```

已死本体贡献0。召唤物、护盾不计入分子或分母，临时加血不会让单个本体贡献超过开场值。比较双方 `S_A × D_B` 与 `S_B × D_A`，避免浮点误差；较高者胜，相等平局。如果只剩召唤物且两边本体都死，双方比例均0，平局。

快进/快速结算只省略等待和动画，不能改行动上限、事件顺序、种子或胜负结果。防守阵容不能靠拖慢手机帧率取得超时胜利。

## 6. 经济与模拟的完整性

### ECON-02：收入、刷新与升级

回合开始顺序固定为：轮次增加 → 重置本回合次数与卡牌产金额度 → 发基础收入 → 自动刷新或冻结保留并补空位 → 执行 PrepStarted → 玩家经营。

付费刷新先验证至少1金，再扣钱并生成新货，最后发 PaidRerolled。法术只重抽指定类型格时不改变固定槽位类型，保留冻结开关，也不发 PaidRerolled。付费或法术的全店刷新都清除冻结；冻结补空位不触发刷新流的付费奖励。

P5 升级按钮禁用，金币不足升级无效。升级后现有店货、冻结状态、商品折扣和等级保留，只改变之后生成的品阶分布。游戏里能看到下一级费用、当前概率与高于 P 的锁定项。

### BOT-02：状态与随机

机器人买不到超出自己 P 的商品，不能负金币买牌，不能凭空拥有高等级角色。其角色合并、卖出、成长来源应可从操作日志解释。

配对、奇数镜像、排名按总纲。各组战斗结果先暂存，齐全后提交本回合结算；同一 `matchId / round` 只能结算一次。镜像永不领取金币、改变排名或生成下一回合经营状态。

存档恢复后机器人不能重新抽一个更强阵容，付费刷新的随机状态不能回滚成免费试牌。快进只改表现，预览对手不推进抽卡随机数；相同存档、种子和动作序列产生相同结果。

## 8. 改机制时检查什么

1. 是否新增了区域间复制资源：等级、金币、装备或准备效果有没有被无成本复制。
2. 是否混淆了事件原因：刷新、合并、转移、出售和阵亡有无误当同一事件。
3. 是否存在可重复的正收益闭环：免费移动、折扣买卖、阵亡召唤互相触发，退出重进重领收益。
4. 是否保留原子性：失败后所有东西还在，合法操作的最终容量不超限。
5. 是否可向玩家解释：卡面、预览、日志和实际规则一致，而不是藏一个未写明的截断。
6. 是否同步更新总纲参数、卡牌定义、验收例和版本记录；新能力复用现有原语即可时，不先增加通用框架。
