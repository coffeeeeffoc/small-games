# 榫间 · 鲁班锁

以触屏操作体验为重点的 3D 榫卯解谜游戏。20 关分为四章，包含分岔、双钥合流、方向选择、局部让位与综合拆装。每关使用真实盒体碰撞，玩家可以结合多轴与组合移动探索不同解法。这些结构是原创玩法设计，不是历史鲁班锁的精确复刻。

每根榫条都可以沿世界坐标 X、Y、Z 三个方向平移，也可以将多根榫条选为组合，保持相对位置整体移动。移动由真实实体的接触约束决定，没有预设拆解顺序或固定的抽出轨道。玩家可以旋转整体观察视角，不能旋转单个零件；当前没有自由刚体模拟、金属环扣或九连环。

## 运行

在仓库根目录安装 workspace 依赖后运行：

```sh
pnpm --filter @coffeeeeffoc/luban-workshop dev
pnpm --filter @coffeeeeffoc/luban-workshop typecheck
pnpm --filter @coffeeeeffoc/luban-workshop test
pnpm --filter @coffeeeeffoc/luban-workshop build
pnpm --filter @coffeeeeffoc/luban-workshop preview
pnpm --filter @coffeeeeffoc/luban-workshop test:browser
```

开发和预览端口为 `4338`；预览前先构建。遵循仓库的 Node / pnpm 版本要求。Vite 输出到 `dist/`，使用相对资源路径，可部署在子目录。运行环境需要支持 WebGL 2 的浏览器；无法创建画布时会显示重新尝试入口。

## 操作

- 点场景中的任一榫条，或底部对应的颜色 / 字母按钮选中零件。已经取出的零件也可继续选中和移动；被遮挡时可通过底部按钮选中。
- 直接拖动榫条时，根据当前镜头下的手势方向推断 X、Y、Z 中的一条移动轴；本次拖动确定方向后锁定该轴，直到松手。转动镜头后，移动仍按轴在画面中的投影跟随手势。
- 用底部 X / Y / Z 按钮明确选择横向、上下或纵深方向，再拖动场景中的 ± 手柄；点按手柄或底部 ± 按钮，每次微移半格。移动轴接近正对镜头时，转动视角或用微移按钮操作。
- 点“组合”开启多选，再点零件按钮加入或移出组合。拖动组合中任一已选榫条，或操作手柄 / 微移按钮，所有已选零件会保持相对位置一起移动；可以先拆出一组，再继续分解其中的零件。
- 拖动空白处旋转视角；双指捏合缩放，双指平移也可调整视角。右侧提供缩放、看全机关和透视观察按钮；看全机关会根据零件当前的位置重新取景。
- 受阻时相关零件变红并显示反馈；手指反向移动可立即退回。组合与外部零件之间同样检查碰撞，不能利用组合穿过其他榫条。
- 拖动中连续跟手，松手后吸附到经过碰撞验证的邻近半格位置，与 ± 微移的步长一致；一次有效拖动只记一次移动，完全受阻的尝试不增加次数。组合移动也作为一次操作撤销或重做。
- 撤销、重做和重新开始均可触屏操作。「思路」解释观察要点；「下一步」根据当前状态指出零件、组合与方向，不替玩家移动。建议方向保持高亮，直到达到目标或更换操作。
- 零件彼此分离后完成拆解；将整件机关一起搬离原点不会误判为完成。点“开始复原”后保留当前散开位置，选中件显示原位虚线轮廓，亲手将各件送回装配位置；完成后可进入下一关或重玩。
- 电脑可用方向键沿当前选定轴微移，`Ctrl / ⌘ + Z` 撤销，`Ctrl / ⌘ + Shift + Z` 重做；鼠标滚轮缩放。

触点取消、失去捕获、窗口失焦或切到后台会回退尚未完成的拖动；双指接管镜头前也取消当前零件拖动。观察与零件移动分别处理，镜头操作不计入移动次数。

## 结构与边界

| 文件                            | 职责                                                        |
| ------------------------------- | ----------------------------------------------------------- |
| `src/levels/index.ts`           | 20 关四章的机制、线索、默认方向与实体盒体                   |
| `src/core/types.ts`             | 关卡、零件、三维位移、组合、拖动事务和提示的数据接口        |
| `src/core/collision.ts`         | 单件 / 组合实体的连续碰撞检测，返回合法位置及阻挡零件       |
| `src/core/game.ts`              | 拆解 / 复原状态、计步、拖动提交与取消、撤销重做、完成判定   |
| `src/core/hints.ts`             | 从当前状态搜索合法移动，给出下一步提示                      |
| `src/core/routing.ts`           | 为复原寻找避开其他构件、兼容半格操作的三维绕行路径          |
| `src/core/persistence.ts`       | 三维存档序列化、旧版迁移、碰撞与历史路径合法性校验          |
| `src/view/PuzzleScene.ts`       | Three.js 场景、盒体并集表面、选中与阻挡效果、拾取、镜头投影 |
| `src/input/gestures.ts`         | 手势方向判定、单指零件 / 组合拖动、双指镜头与取消           |
| `src/input/taps.ts`             | 触屏按钮松手激活、移动/取消过滤，以及浏览器补发点击去重     |
| `src/storage.ts`                | 局内提示记录、完成印章、浏览器存档与内存回退                |
| `src/main.ts` / `src/style.css` | 页面组装、界面状态、手柄位置、存档时机与响应式布局          |

规则、提示和关卡数据不依赖 DOM、Three.js 或浏览器时钟。渲染与碰撞读取同一份 `boxes`，可见表面由实体盒体并集生成，阻挡关系来自实际几何接触，不在关卡中写死拆解顺序。

碰撞检测检查整个移动区间，不只检查终点；快速长拖动和松手吸附都不能穿过其他零件。多选移动将选中零件视为保持相对位置的实体并集，只检查它们与未选零件的接触；任一成员受阻，整个组合都会停在同一合法位移。不会用固定的移动范围截断合法操作。每次拖动先产生预览状态，松手统一提交历史，取消则恢复手势开始前的完整状态。

拆解进度由零件之间的几何分离关系决定，与它们离原点的距离无关。整体搬动装配体不会增加拆解进度；尚未分开的组合需要继续拆解，不能直接算作所有成员已经取出。

提示根据当前三维位置探索单件或组合的合法移动，并使用与实际操作相同的碰撞规则。复杂复原位置会先寻找可分离姿态，再规划避开其他构件的半格绕行路径；缓存路径的每一步仍会检查碰撞。搜索设有计算上限，适用于本版的小型机关；更复杂的结构需要重新评估搜索空间与操作设计。

## 本轮评估与改造

先由玩法、关卡、触屏交互三个独立评审汇总，再实施以下改造。合并 dev 的多轴与组合移动后保留全部新能力，关卡中的让位关系描述可选探索策略，不限制玩家沿其他轴寻找解法：

| 原有问题                                   | 改造结果                                                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------------- |
| 三关是同一依赖链的前缀，发现钥匙后操作重复 | 保留前 3 关几何与 ID；新增分支、共同阻挡、方向差异和可探索中途让位的关卡，共 20 关 |
| 三张长卡片无法承载更多关卡                 | 四章紧凑选关、两位编号、章节完成数与当前关标记，全部关卡可自由选择                 |
| 提示直接给答案，两个方向视觉相同           | 分为思路和下一步；下一步仅高亮建议方向                                             |
| 局部让位缺少发现感                         | 当移动释放另一件零件时即时提示；完整拆解和复原分别记录                             |
| 复原位置难辨，散件容易离屏                 | 选中件原位虚线轮廓、已归位标记、显式「看全机关」取景                               |
| 完成只有一个布尔标记，缺少复玩目标         | 解开、复原、独立三枚印章；拆装总移动与最佳个人纪录；一键重玩                       |
| 多零件时触控区缩小                         | 至少 44px 的零件按钮，横向滚动与选中项可见；小横屏结算可滚动                       |
| 新关卡分支使同步提示可能变慢               | 有界三维搜索与合法路线缓存，保持当前状态的碰撞验证                                 |

「独立」需从开局到复原不使用思路或下一步提示。提示使用独立存储，不会被撤销清除；重玩保留已获得印章，重置本次提示记录。旧存档和已复原标记继续可读，未知的旧过程不补发独立印章。

拖动和半格微移的计步方式不同，因此移动次数只作个人记录，不设步数星级或硬性门槛。撤销、透视和观察镜头不影响独立印章。

## 关卡扩展

1. 在 `src/levels/index.ts` 添加稳定且唯一的关卡 ID、零件 ID 和说明。现有 ID 用于存档，发布后应保持稳定。
2. 用 `boxes` 定义每个零件的连续实体，保留稳定的默认方向供初次选中与旧存档迁移使用。每个零件都支持三轴平移；初始三维偏移均为零，初始装配不能互相穿插。
3. 验证三个轴的正反方向移动、局部松动后的让路关系、组合移动、完整拆解和复原。增加关卡应扩展规则测试；新增旋转、关节或任意方向的连续运动，需要同时改变规则、提示与交互接口。
4. 设置 `chapter`、`mechanic`、`clue`；机关匣数量与两位编号动态生成，仍需检查章节布局、取景范围和触控热区。
5. 修改已有几何时考虑存档版本与迁移。当前存档为 v2 三维位移格式，兼容迁移 v1 单轴位移；非法、碰撞或历史路径无效的存档会被拒绝，并从该关初始状态开始。

## 存档与接入

游戏无后端、账号、广告或外部素材请求。Three.js 随构建打包；关卡进度、拆装状态、撤销历史和完成记录存于当前浏览器的 `luban-workshop:v1:` 命名空间。命名空间保持不变，存档内容已升级为 v2 三维位移格式；读取 v1 存档时将单轴位移映射到零件原来的默认轴，以保留已有进度。存储不可用时仍可完成本次游戏，界面会提示无法保存。

作为独立 H5 Game 接入现有 Web Shell，通过同源 iframe 装载；目录登记在 `apps/shell-web/src/standalone-games.json`。当前未接入 Game Host 云存档，也未适配原生小游戏 Canvas SDK。

按仓库 [Pages 三环境部署规则](../../../docs/deployment/github-pages.md)，`dev` 分支发布成功后的独立入口为 `/small-games/dev/games/luban-workshop/`，大厅分享入口为 `/small-games/dev/#/games/luban-workshop`。提交推送不代表部署已经成功；实际发布结果以 Pages 工作流和线上版本为准。同一站点的 main / dev / test 路径共用 origin，因此本地存档也共用命名空间。

## 验证

`test` 覆盖实体连通性、初始无重叠、三轴移动、组合连续碰撞、几何分离判定、动态提示、长距离拖动防穿透、事务取消、计步、撤销重做及存档迁移与非法数据拒绝。

浏览器回归脚本 `tests/browser.mjs` 使用 Playwright 与 Chromium CDP 触摸事件，验证桌面代表关、手机 20 关拆装，以及三轴/组合移动、阻挡反馈、镜头操作、取消、提示、重玩印章与存档恢复。Shell 冒烟检查另覆盖选关、微移、撤销和重做。

手机尺寸和触屏输入模拟不能替代实体 Android / iOS 设备的性能、手感与兼容性验证，当前尚未完成真机验收。
