# 《来电之间》H5 防诈骗游戏设计草案

状态：用户已确认实施；首章已实现。实际运行方式和已验证范围见 `../README.md`；本文保留设计目标，后续章节仍为候选内容。

## 体验定位

玩家使用一部属于虚构角色的手机，完成生活中的具体事务。真实业务、普通闲聊、营销消息和诈骗联系交错出现。玩家通过接听、回拨、查订单、翻聊天记录、预约、填写信息和支付等操作，判断一个请求是否值得执行。

核心目标是“把事情安全地办成”。仅仅拒绝所有消息不能完成生活任务；先挂断，再从可靠入口自行办理，是完整有效的通关路径。安全核验不扣分，不把立刻接电话当成优秀表现。

首版暂按普通成年人设计，手机竖屏，单章约 10–15 分钟。名称、场景和人群均可在实现前调整。

## 方向选择

| 方向 | 主要体验 | 取舍 |
| --- | --- | --- |
| 生活任务模拟，推荐 | 一边办事，一边处理真假混杂的联系 | 最贴近用户目标，需要做好跨应用的连续状态 |
| 悬疑剧情解谜 | 通过聊天和电话追查一个骗局 | 故事感更强，但玩家容易把所有联系都当成破案线索 |
| 短情境训练 | 每次处理一通电话或一组消息 | 容易快速体验，但容易退化为判断题 |

采用生活任务模拟作为主体，章节结束后再用简短复盘承担教学。主界面不常驻反诈知识、真假按钮或风险分数。

## 手机里的可操作空间

采用统一的虚构手机与服务品牌，沿用常见手机操作习惯。手机端内容铺满可用区域，不再套一个缩小的手机外框；电脑端居中显示竖屏区域。

| 界面 | 玩家操作 | 与任务的联系 |
| --- | --- | --- |
| 桌面、通知中心 | 打开应用、展开或划走通知、查看未读、返回原页面 | 通知不是独立关卡；划走通知不等于办完业务 |
| 电话 | 接听、拒接、挂断、查看记录、拨号、从已有联系人回拨 | 玩家可以中断对方的话，换渠道核验 |
| 短信与聊天 | 滚动历史、查看时间与联系人详情、回复、打开附件、复制虚构业务数据 | 旧记录、原联系人和本次请求可交叉核对 |
| 订单与服务 | 查询物流、变更投递点、查看费用、预约安装、联系订单客服 | 提供独立于来电者和短信链接的业务记录 |
| 生活缴费与钱包 | 对照户号和地址、输入金额或验证码、查看收款方、确认支付、查回执 | 合法付款确实要完成；操作结果同步到订单和消息 |
| 游戏内浏览器 | 查看完整地址、前进后退、填写表单、关闭页面 | 承载可疑链接与仿冒页面，显示页面来源 |

首版只实现章节会用到的应用功能。每个被展示为可用的关键控件都应有实际作用；没有业务内容的功能不放占位按钮。

## 一段完整的玩家体验

玩家正在给快递更改投递位置，突然接到电话：“你买的路由器运输损坏，我们给你办理赔付。”对方能说出角色姓名、商品和订单尾号。

玩家可以继续询问，也可以挂断。回到桌面，主动打开原来的订单应用，找到路由器订单，查看物流和售后记录，再从订单内部进入客服核实。没有异常记录本身只是疑点；客服核实和当前配送记录共同形成依据。

与此同时，真正的派件员也会联系玩家。玩家通过原订单里的配送入口确认后，选择新小区驿站，提交改投。订单、物流和确认通知随之更新，任务才算完成。

如果玩家沿着假赔付消息进入表单，仅打开页面不直接造成资金损失。继续提交角色的模拟账户凭据、把特定用途的验证码交给对方，或确认向错误收款方付款，才触发对应的泄露或资金后果。中途停止应保留停止时的实际状态。

屏幕上不会出现“请选择：诈骗 / 正常”。玩家的实际行为就是判断。

## 首章：搬家第一天

开局由备忘录和已有聊天自然交代三件事：把路由器快递改投到新小区、预约宽带安装、缴清新家的电费。角色资料、订单、住址和余额均为游戏预设。

| 任务 | 必须实际完成的操作 | 穿插的信息 | 完成依据 |
| --- | --- | --- | --- |
| 快递改投 | 找到订单，核对包裹，选择投递点并提交 | 真派件来电、假损坏赔付消息、普通促销 | 订单投递点改变，出现改投回执 |
| 预约安装 | 查看服务订单，核对费用，选可用时段并确认 | 真预约确认、假安装主管索要额外保证金 | 原服务订单内出现有效预约，无须向陌生账户转账 |
| 电费缴纳 | 从既有租房资料核对户号与地址，查看账单，确认收款方并支付 | 真缴费提醒、玩家主动操作触发的验证消息 | 正确户号账单结清，钱包产生匹配回执 |

首章包含两条诈骗事件链：快递赔付、安装保证金。仿冒风险提示作为诈骗网页内的后续步骤出现；让玩家有机会发现它来自网页，而不是凭弹窗外观判断。

节奏安排：

1. 开局先允许玩家翻看已有订单、联系人和备忘录，认识这部手机；不立即弹出骗局。
2. 玩家查看物流后，派件消息与假赔付联系先后到达。真假消息不用固定顺序或固定颜色区分。
3. 玩家可以先完成快递，也可以去缴费。返回时保留阅读位置、表单草稿和业务进度。
4. 安装预约提交后，真实确认消息到达，随后假主管来电要求额外付费。玩家可以查询已显示的费用明细，并从原服务订单联系客服。
5. 完成三项任务后可主动结束本章。未接来电允许回拨，已忽略的业务可从应用中补办。

计划配置约 12–16 条新增信息、3–4 通来电，以及开局已有的历史记录。数量随试玩调整，不保证每局逐条出现；完成或失效的事件不重复轰炸玩家。

## 真实感应落在交互与后果上

- 来电会响铃，有接通延迟、通话计时、语气停顿和挂断反馈。可选字幕和重听，不要求玩家听力敏锐才能找到证据。
- 通话中可以回到桌面，顶部保留通话状态；对方继续讲话，玩家也能查询订单。挂断后音频和对话推进立即停止。
- 新通知以顶部横幅出现，不强制跳走当前页面；可以稍后处理。来电可以打断办事，但不能清空输入。
- 聊天有历史、时间、已发送状态和符合剧情的回复延迟。可信联系人也可以回复慢、文字简短；骗子也可以措辞专业、准确说出个人资料。
- 数字和备注使用正常输入框；订单号可复制粘贴。复制仅涉及角色的虚构信息，不读取玩家原有剪贴板。
- 支付展示金额、收款方、用途和确认步骤。成功后同步余额与回执；失败不扣款，反复点击不重复提交。
- 可疑页面保留可查看的来源地址。锁图标、漂亮排版、姓名和来电号码都不被设计成单独证明身份的答案。

首版通话采用配音和少量符合上下文的回应，例如“请给我工单号”“我查一下原订单”“我稍后联系”。回应控制对话走向，真正的核验仍由跨应用操作完成。首版不承诺任意语音对话或任意文本理解。

## 核验与公平性

同一部游戏手机内可以有可信的业务记录，但必须交代这些入口来自开局已经存在的应用、原订单或既有联系人。可疑消息给出的新链接、号码和二维码不能替自己完成身份核验。

真实联系人允许玩家暂停、查记录和换渠道办理。谨慎导致延后时，应能改约或补办；不设计“为了拿高分必须立刻相信陌生人”的机制。

验证码按用途和去向处理：角色主动在可信业务流程中发起验证，并在对应页面输入，与把验证码发给来电者是不同操作。教育内容不能简化成“看见验证码就是诈骗”。

不要求每条消息都判定真假。无关广告可以不处理；玩家不愿与可疑来电交流，可以直接完成原业务。主动报告并非每个任务的强制通关步骤。

剧情压力来自对方催促和多个待办，不使用一边阅读一边快速流失的全局倒计时。页面进入后台时暂停剧情时钟、音频和来电超时，恢复后不集中爆发消息。

## 结果与复盘

分别呈现任务完成、资金与资料结果、核验行为，不把三者相加成一个能够用速度抵消损失的总分。所有合法任务办成且没有发生受骗损失，才是本章的安全完成结局；全部拒绝只会留下未完成事务。

过程不弹红绿判题反馈。结束后按真实行为回放，例如：

> 14:06 接到赔付电话 → 14:07 挂断 → 14:08 从桌面打开原订单 → 14:09 通过订单客服核实 → 14:10 完成改投。

复盘分别说明当时已经掌握的证据、对方要求的关键操作、玩家实际造成的结果。没有查过的资料不能写成“你已经核实”。合理通过其他路径完成任务也应被认可。

玩家走错可以继续处理剩余事务。提供回到关键节点重试；重试恢复该节点的完整状态，不与第一次结果混算。可以通过模拟账户保护与报告操作练习止损，但不承诺已经转出的款项必然追回。

## H5 实现边界与最小结构

电话、短信、账户、付款、下载和屏幕共享均在游戏世界内模拟；不接入真实通信或支付。角色的姓名、证件、账户和验证码使用预设资料，界面不要求玩家提供自己的敏感信息。

音频在玩家点击“开始体验”时初始化，并处理播放被阻止的情况。通知主体使用页面内横幅与通知中心，避免把完成关卡建立在系统通知权限上。移动浏览器对音频自动播放和系统通知存在限制，不能承诺退出网页后仍像电话应用一样运行。[MDN 音频自动播放](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)、[MDN Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API)。

用普通网页界面实现可点击、可滚动的应用页面，用一个共享的章节状态保存任务、订单、消息、通话与钱包。事件按操作和前置条件触发，必要时附短延迟；不靠一条固定计时轴强迫玩家按脚本点击。

基本数据流：玩家操作 → 校验当前业务条件 → 更新共享状态 → 产生对应回执或下一事件 → 刷新有关页面。相同提交只生效一次，隐藏窗口不会继续结算剧情。只有已经披露或剧情预先设定泄露的数据，才能被诈骗角色引用，不能随意读取玩家所有操作。

首版保存当前进度并支持重新开始；只需要静态站点和本地存档。先把一个章节打通，不引入账号系统、管理后台、实时 AI 对话或关卡编辑器。

## 首版可玩的验收标准

1. 在手机上实际完成接听、挂断、返回桌面、查询订单、回复消息、预约、输入和支付的连续流程；控件不是演示图片。
2. 至少有一条完整安全路径和两条具有实际后果的诈骗分支；能在不同操作顺序下完成合法任务。
3. 全部拒绝不能算任务完成；拒接后经原应用安全办妥，应当通关。
4. 打开可疑页面但未提交，不直接扣款；错误支付按实际金额结算；重复点击不重复扣款。
5. 同一订单在消息、服务页面与钱包中的状态一致，挂断、返回、刷新和恢复进度不会制造重复事件。
6. 真机确认竖屏布局、软键盘、页面返回、音频开启与静音、字幕、后台暂停；Chrome、Safari 和微信内打开的结果分别记录，不用桌面模拟结果代替。

## 现实依据

剧情使用虚构人物和服务。核验机制参考公开反诈提示，不把具体文案、号码或页面样式当成永久识别规则。

- [辽宁省邮政管理局：关于防范取件短信骗术的公告](https://ln.spb.gov.cn/lnsyzglj/c101876/c101879/202506/164737e88ef744f7907ad86a7a352f0b.shtml)：从快递短信引流到虚构扣费和远程协助；应通过官方应用或网站核实业务。
- [福建省公安厅：快递丢失能理赔？当心是诈骗](https://gat.fujian.gov.cn/ztzl/fjjffpzxrx/spjq/202301/t20230106_6087654.htm)：诈骗者可能掌握真实购物信息；姓名和订单资料不足以证明身份。
- [国家金融监督管理总局浙江监管局：退改签诈骗风险提示](https://www.nfra.gov.cn/branch/zhejiang/view/pages/common/ItemDetail.html?docId=1134281&itemId=1173)：独立核实业务，谨慎提供敏感信息和开放屏幕共享。
