# 一炮拆城 · 远距离实时炮战需求

日期：2026-10-09。状态：玩法方向已确认，等待效果图、代码实现与实际验收。本文是下一阶段改造依据，不表示功能已经实现。

游戏 ID 继续使用 `castle-cannon`。保留玩家认可的炮身、城楼材质与主题美术，将主玩法改为双方各守一座城的远距离实时炮战。现有单向攻城、多轮士兵及双击目标发射的实现和证据留作历史记录，不作为新玩法的完成证据。

第 1 节记录讨论确认的原则；后续标注“默认”“首版”及第 13 节数值属于实施默认方案或试玩初值。未定的平衡和异常处理参数须在对应验收前落实，不能当作已经验证的结论。

## 1. 产品目标与已确认原则

- 主模式为 1 对 1 玩家对战，双方同时行动、同时炮击，不轮流等待。未匹配到真人时安排明确标识的系统机器人。
- 双方各有一座城、一名由玩家操控决策的角色、多个合理安置的普通炮位，以及一处地堡。两城距离足够远，观察对方细节需要望远镜。
- 通过炮管角度和蓄力控制真实弹道。观察、试射、修正、多次尝试后命中是核心技巧；点击目标不能自动保证命中。
- 玩家点击炮位或“回地堡”，角色沿实际路线自动移动。主要手动操作是观察、调角度、蓄力发射、趴下及选择转移位置。
- 角色生命值归零立即失败，不论城池是否完好。没有倒地后治疗、复活或城池保护下的免死状态。
- 城未毁时在城门地面或城墙上的普通炮位攻击；城完全毁坏后普通炮位停用，只能从地堡防御炮位攻击。
- 地堡提供有限补给和恢复。城毁后地堡暴露，仍有掩护，但内部角色可受伤，不能无限治疗或永久免伤。
- 保留装填、操炮、后坐、受伤、抱头趴下、移动与治疗动作，动作和真实状态相对应。
- 轻伤有轻量恢复提示；重伤、濒死有醒目提示和窗口边缘红色阴影。提示不代替玩家作撤退决定。

## 2. 核心循环与对局结束

核心循环：观察敌城 → 调整炮管 → 蓄力试射 → 观察落点并修正 → 命中建筑或角色 → 根据敌方火力决定继续攻击、趴下、换炮位或回堡治疗 → 城毁后进行地堡防守 → 角色生命值归零结束。

- 可以精准击杀仍处于完整城池中的角色，直接获胜。拆城通过消除遮挡、摧毁炮位、暴露地堡创造优势，不是获胜的强制前置条件。
- 同一权威模拟步内双方生命值同时归零时判平，不能按客户端消息先后决定胜负。
- 角色死亡后停止新操作和伤害结算，已有炮弹和坍塌可收尾播放；不能继续产生结算后的第二次死亡、奖励或反转结果。
- 普通失败后可以再次匹配或练习，不能通过广告、付费或补给复活当前对局。
- 首版不靠不断刷士兵、自动夺旗或必须拆完所有碎石维持战斗。

| 对局菜单 | 设置、帮助、离开；真人对战继续进行，须明确告知；纯机器人练习可暂停         |

## 4. 战场、城池与炮位

### 4.1 空间与美术

- 继续使用手机横屏和现有 3D 美术方向，展示两座相隔较远的城、各自炮阵、战壕/矮墙、撤退路线和地堡。对手的炮位不能摆在自己的城旁边。
- 首版默认一张双方结构和资源等价的战场。后续地图可改变距离、地形、遮挡和炮位分布，通过配置增加，不在核心中按地图 ID 特判。
- 双方视角均以自己的城和角色为近景，对手为远景。镜像视角、水平瞄准与触点转换须一致，不能让一方获得隐蔽的操作或射界优势。
- 炮台需要实体平台、支撑、可达的操炮位置和弹药箱。城墙炮位有合理的通道和撤离路径，不悬空、不穿墙移动。

### 4.2 炮位与掩护

- 首版默认每方两个普通炮位：城门附近的地面炮位、城墙平台炮位；另有一个地堡备用炮位。具体数量可调，双方初始等价。
- 一名角色同一时间只操作一门炮。每门炮分别保存角度、装填进度及已装好的炮弹，选择炮位不等于远程控制它，必须到达才能操作。
- 普通炮位可受损和停用；摧毁炮位限制对方选择，炮架不是无限承伤且仍照常开炮的装饰。损坏炮位可点击到场检修，持续 6 秒，趴下/离开暂停，近处爆炸重置进度；完成后仍需装填。这样避免双炮失效而城未毁时永久失去反击能力。城毁后的普通炮不能恢复。
- 城墙、矮墙和地形依据真实位置阻挡炮弹或减弱爆炸伤害。趴下可利用低掩体；战壕保留有因果作用的掩护，不另加自动冲锋士兵循环。
- 地堡备用炮在城毁前不作为额外攻击入口；城毁后成为唯一可用攻击炮位。

## 5. 观察、瞄准、蓄力与弹道

### 5.1 望远镜与反馈

- 普通视野可辨认远方城池轮廓和明显炮击，望远镜用于看清建筑、炮位和暴露的角色。望远镜不会自动锁定角色或计算必中解。
- 保持横屏触控：在炮管或瞄准控制区拖动调整方向和仰角；在望远镜区域拖动只改变观察位置，不偷偷改变炮管角度。
- 显示当前角度、蓄力和上一次射击的角度、力度及落点，保留适度的上一炮轨迹或落点标记，用于判断打近、打远、偏向或被遮挡。
- 不显示能精确指向最终落点的完整预判轨迹。角度和力度固定时，结果应可重复，不能靠隐藏的随机散布制造难度。
- 支持短暂跟弹观察或放大落点；实时互轰时不长时间强制锁镜头，观察敌方仍须感知自己的受伤和来袭。

### 5.2 发射操作

- 在角色到达可用炮位、站立且装填完成后，按住发射控件开始蓄力，松手按当前角度和力度立即出弹。
- 蓄力有上限；到上限后保持，等待松手，不自动发射。取消、失焦、转移、趴下、炮位失效均取消蓄力，不补发一炮。
- 蓄力主要控制初速与射程。满蓄力不必然最优，过大的力度可能越过目标；伤害由弹种、命中力度和爆心距离等配置计算。
- 发射时角色已经位于操炮位置，松手后不额外插入走路等待。后坐、点火、烟尘和角色动作服务于已经发生的发射。
- 新主玩法的发射入口使用蓄力松手。旧“双击目标直接发射”不沿用为绕过角度和蓄力的自动命中捷径。
- 初版触屏通过横向拖动调有限水平转角、纵向拖动调仰角，射界朝向对方。多点触控允许观察、调炮和蓄力的有效组合，其他手指不能意外释放发射触点。

### 5.3 弹道与命中

- 炮弹从当前炮管口按姿势和初速生成，在飞行中与地形、建筑、炮位和角色实际碰撞；发射时不能预先登记某个目标必定受伤。
- 首版采用稳定重力，先验证距离、角度和力度，风、雨及复杂弹道干扰暂不加入。
- 炮弹飞行、两方同时发射、移动角色和动态城墙破洞必须参加同一套规则判断；双方与机器人共用弹道规则。
- 打空、撞墙、命中角色、局部爆破和建筑坍塌应有不同反馈。炮弹出界或超过寿命时正常结束，不产生悬空命中或无限残留。

## 6. 弹种、伤害与城毁阶段

### 6.1 伤害

- 基础弹种为实心弹和爆破弹，双方拥有相同基础能力，不以广告或付费解锁对战优势。
- 实心弹偏向集中命中和建筑破坏；爆破弹偏向范围伤害，离爆心越远伤害越低。穿透能力、半径、伤害上下限由配置约束。
- 建筑结构值与角色生命值分别计算。爆炸可以同时伤害附近建筑和角色，完整遮挡会降低或阻止伤害；不能隔着完整城墙无条件扣人血。
- 建筑受损先出现裂纹、缺口等可见变化，归零后坍塌，并同步更新遮挡、碰撞与可用通路。不能只变血条或只放坍塌动画。
- 血量和结构值不得为负，单次命中不能重复结算。对自己一侧误射的伤害采用同一物理规则，不能穿过自家墙直接飞往敌城。

### 6.2 城毁判定与切换

- 地图明确登记所有计入城毁的主要结构，例如城墙、城楼、城门及主体建筑。它们全部摧毁后该方进入城毁阶段，碎石和地基不要求清理。
- 城毁时所有普通炮位停用，取消尚未发射的蓄力；已经发射的炮弹继续正常飞行，直到对局结束。
- 存活角色沿可见的有效撤离路线转向地堡，途中不能攻击且仍可受伤。坍塌动画、原炮位停用和撤离通路必须一致，不能瞬移或继续从消失的高台开炮。
- 进入地堡不重置生命值，不赠送治疗或补给；受伤和死亡仍按同一规则结算。
- 因城毁被动撤入地堡时不自动消耗医疗补给，玩家选择恢复或地堡防御炮位；若原本已在治疗，则保留原治疗进度，不重复扣补给。
- 城毁后的地堡防御炮默认射界较窄、装填略慢，保留反击能力，同时体现失去城池的劣势。
- 地堡不增加一套必须先打空才能伤害角色的第二城池血条。外壳/射孔被命中可对内部角色造成减伤后的震伤，暴露炮手可受直接伤害；治疗位置也不免伤。

## 7. 角色行动与时间

| 状态          | 行为                         | 时间与打断规则                                         |
| ------------- | ---------------------------- | ------------------------------------------------------ |
| 炮位站立/瞄准 | 手动调角度；自动装填         | 只有在有效炮位才能操炮                                 |
| 装填          | 自动取弹、装弹、回到操炮位置 | 短距离动作计入装填时间；离开或趴下暂停，返回继续       |
| 蓄力          | 按住发射，准备初速           | 松手发射；取消、趴下、转移或炮位失效作废               |
| 发射/后坐     | 炮弹立即生成，播放动作       | 随后进入下一次装填，不另加走路延迟                     |
| 换炮位        | 点击目的炮位，自动沿路线走   | 移动时间与路径长度一致，途中不可攻击                   |
| 撤回地堡      | 点击常驻“回地堡”             | 沿实际路线撤回，抵达前不能回血，途中可受伤             |
| 趴下          | 按住趴下，松开起身           | 暂停装填、取消蓄力，保留角度；减小命中范围，不免疫爆炸 |
| 地堡治疗      | 抵达后使用有限医疗补给       | 与攻击互斥，可提前结束转向可用炮位                     |
| 地堡操炮      | 城毁后选择地堡防御炮位       | 先结束治疗并到达操炮位置，不能边回血边开炮             |
| 死亡          | 生命值归零                   | 立即结束对局，不能再撤回、治疗或发射                   |

- 不要求玩家每炮手动搬弹、点装填或从炮口跑到点火处；取弹箱就在炮位附近，自动动作须与实际进度一致。
- 默认只有角色留在该炮位时装填推进，换炮位不让原炮位的无人装填自行完成。已经装好的炮弹不因换位消失。
- 第一版主动趴下用于炮位附近的掩体，自动转移过程中不另加自由跑动、任意改路和途中趴下操作。
- 轻微受伤不反复打断装填，避免被连续小伤害锁死操作；炮位摧毁、转移和趴下按上表处理。
- 动作是规则状态的可视表达，不能角色已在治疗却仍显示操炮，也不能人物瞬移但规则声称走了几秒。

## 8. 地堡补给与恢复

- 双方初始医疗份数相同，城毁前后共用，不能自动刷新或无限恢复。
- 点击“回地堡”表示主动撤回治疗；抵达时角色仍存活且受伤、有补给，才自动开始一次治疗。满血、补给耗尽或角色死亡时不消耗补给，也不虚假增加血量。
- 每次治疗使用一份补给，开始时扣除；治疗过程中逐步恢复，最多恢复该份配置的生命值且不超过上限。
- 可以提前结束治疗去攻击，已经恢复的血量保留，已使用的补给不退还，不能反复取消刷免费血量。
- 补给数量、恢复量、所需时间和治疗进度须可感知。恢复后需玩家选择可用炮位，不自动把人送回危险位置。
- 城毁前完整城池提供外围保护；城毁后治疗区也可能受到减伤后的爆炸伤害，补给不会附带无敌时间。
- 恢复从当前位置的实际抵达时刻开始，不能在撤退路上回血，不能在地堡炮位射击时同时治疗。

## 9. 受伤提示与触屏反馈

- 始终提供易发现、约 44 CSS px 或等效逻辑尺寸以上热区的“回地堡”入口，不只在受伤时临时出现。
- 轻伤：短暂轻量提示“可回地堡恢复”，回堡入口适度高亮；同一阶段不反复弹窗。
- 重伤：血条、恢复提示和回堡入口明显增强；濒死：窗口边缘红色阴影增强，表达危险但中央场景、望远镜、蓄力和触控区仍清楚。
- 红色阴影跟随当前生命值，恢复时逐渐减弱；无补给时提示剩余能力，不能继续承诺回堡一定回血。
- 必要提示同时使用文字、图标或形状，不只靠颜色；不使用强烈高频闪烁，不锁输入、不暂停对局、不自动替玩家撤退。
- 按下、拖动、装填、蓄力、发射、趴下、移动、治疗、受伤和目标破坏均有及时反馈；音效、震动遵循设置与平台能力。
- 多触点、松手、触点移出、取消、失焦、旋转、尺寸变化和全屏切换必须正确清理持续输入，尤其不能卡在蓄力/趴下或取消后误发射。

## 10. 真人匹配与机器人

### 10.1 匹配

- 开始对战优先匹配真人，配对双方使用兼容规则/地图版本及等价初始资源；匹配等待有取消入口。
- 默认短时间未找到真人后分配机器人，建议初值约 8 秒。界面和结算明确“真人”或“机器人”，不能伪装真人身份。
- 真人与机器人安排存在竞态时只建立一场对局，已取消的匹配不能迟到后强行开局；机器人对局开始后不在中途偷换成真人。
- 联网服务不可用时允许明确的本地机器人练习降级，说明联网状态，且不把本地结果计作真人战绩。
- 主页另有机器人练习入口，便于试射、熟悉角度、蓄力与地堡行动，不依赖真人在线。

### 10.2 机器人行为

- 使用相同炮位、角度/蓄力范围、弹道、装填、移动、医疗和死亡规则，不获得额外血量、无限补给或跳过时间。
- 能选择拆掩体、攻击炮位或炮手，观察自己炮弹的落点并逐步修正；受威胁时选择趴下、转移或回堡。
- 机器人可以估算射击参数，但必须受到配置的估计误差、反应时间和纠错速度约束。标准机器人应形成持续威胁，而不是每炮故意打空或直接必中。
- 不读取真人未提交的操作或未来位置，不改变飞行中的炮弹去追踪目标。难度由这些行为参数调整，首版可只提供标准一档。
- 离线练习与在线机器人共用规则；仅有本地机器人不能算完成真人对战需求。

## 11. 联机一致性、异常与生命周期

- 真人对局由服务端权威模拟或确认角度、蓄力、射击、装填、路线、治疗、伤害和结果。客户端不能自行申报命中、修改生命值或追加补给。
- 规则计算可复现，与画面帧率、观察镜头和是否打开望远镜无关；双方收到一致的炮弹、破洞、角色状态与胜负。
- 操作与结果有顺序和幂等约束，防止重复射击、补给重复扣除/发放、重复结算以及重连后恢复过期蓄力。
- 真人对局的个人菜单、后台或失焦不暂停对手；停止本地持续输入和音频，返回后恢复权威状态。纯机器人练习可以暂停双方模拟，恢复不时间跳变。
- 断线显示简洁的重连状态，保留短暂重连窗口；掉线角色不无敌、不能继续靠客户端发射或治疗。超时未恢复按退出规则结束，结算标明原因。
- 主动离开有必要的轻量确认；真人局离开后不能让对手无限等待。机器人练习退出回主页，不强记真人失败。
- 重连从同一对局的服务端状态恢复，本地存档不能伪造或重新启动旧真人对局。
- 同时死亡、双方断线、地图/规则版本不兼容和无法恢复的服务端错误需有确定的平局或中止规则；异常中止不发正常胜利奖励。
- 对局时限和防长期无操作策略在试玩与联机验证中确定，需在上线前落实，不能放任永久占用匹配房间。

## 12. 运行环境、存档与配置

### 12.1 平台与移动体验

- 独立 Web/H5、Shell 内置及 iframe 中保持一致规则和操作；保持横屏，竖屏或自动旋转关闭时整个界面旋转兜底，触点和观察拖动同步变换。
- H5 在主页/菜单提供统一的进入、退出全屏入口，拒绝或不支持全屏时仍可玩；复用公共机制，保留 sandbox/CSP 边界。
- 原生小游戏由宿主横屏承载，处理安全区与胶囊位置，不显示浏览器全屏入口。复用 Game Host 和运行环境适配层，不让规则直接依赖 DOM 或渠道 SDK。
- 同时操作角度、望远镜、蓄力和趴下需要进行多点触控验收；键鼠是补充，触屏能完成全部玩法。
- 控制远景、双城破坏、烟尘和镜头的资源及渲染开销，按需加载素材，提供加载失败重试和画质设置。
- 对局菜单的暂停图标仍为两根等高等宽、分离的实心竖条，保留明确的“暂停”无障碍名称。真人局菜单必须显示对局仍在继续。

### 12.2 存档、成长与公平

- 兼容现有三城进度、材料、已拥有外观和设置，不清空旧存档；旧关卡解锁不限制基础真人匹配与机器人练习。
- 新对战记录与旧关卡奖励分开管理，真人、机器人、离线练习和开发试玩记录分别标识；开发试玩不写正常战绩或奖励。
- 如沿用结算材料或外观成长，须结算幂等，真人结果由权威来源确认；具体对战奖励数值另行定稿。
- 旗帜、头盔等外观不改变生命值、炮弹伤害、射程、治疗份数或移动速度。首版不做付费优势、广告回血、广告复活或额外对战炮台。
- 统一支持 `SmallGamesDev` 的 URL/存储开关及入口传递；调角度、改血量、跳阶段等调试功能默认隐藏，并与普通匹配隔离。

### 12.3 规则与内容分离

- 核心实现负责弹道、碰撞、伤害、角色/炮位状态、治疗、城毁切换与结算；地图文件负责两城位置、结构、炮位、地堡、路径、地形及引用的素材。
- 弹种、装填、蓄力映射、伤害、减伤、医疗、机器人行为和匹配时间属于可校验配置，不能散落在渲染或按地图 ID 特判的代码中。
- 按 [ADR-0007](../../../../../../docs/adr/0007-game-owned-content-schemas.md) 由本 Game 拥有 schema、版本和迁移；复用仓库契约，不新增单款游戏专属的中央框架。
- 校验结构/炮位/路径 ID 唯一、引用存在、主要结构集合非空、路线可达、普通炮位与地堡阶段合法、数值有限且有效、双方资源公平，以及双方确有命中对方与暴露地堡的可用弹道。

## 13. 首轮试玩参数与待定项

## 14. 第一版范围

完整第一版必须包括一张可玩的双方战场、多个普通炮位、完整城毁/地堡阶段、两种基础弹种、真实弹道和破坏、角色受伤/趴下/移动/治疗、真实玩家匹配与同步、机器人补位、主页至结算流程及移动端适配。

暂不加入风雨、多角色兵团、自由摇杆移动、手动搬弹流程、装备数值养成、排行榜排位体系、大量地图、好友观战或复杂天气。机器人练习和本地双侧验证是实施阶段，不替代最终真人对战交付。

## 16. 实施与交付顺序

1. 依据本文生成横屏手机比例效果图，覆盖主页、匹配、近景炮位、望远镜、装填/蓄力/趴下、重伤/濒死、地堡治疗、城毁防守及结算。说明页面关系、手指位置、安全区与反馈。
2. 复用既有美术和 Game Host，先完成同一规则下的双侧弹道、建筑破坏、角色行动与地堡循环；用机器人练习和本地双侧操作验证可玩性，修正操作与平衡。
3. 接入真实真人匹配、权威同步、机器人补位、重连退出和结算；不能以伪匹配或只显示另一座城代替真实对战。
4. 运行规则、配置、存档、联网及生产构建输入验证；用实际运行截图对照效果图，覆盖表中全部验收项，修正后复验。
5. 按最终改动范围运行仓库检查及相关消费者验证；涉及统一 dev/全屏机制时运行相应检查。发布遵循准确候选版本验证，并记录本地、CI、Pages、原生平台和真机实际结果。
