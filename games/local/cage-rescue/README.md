# 打破笼子接住人

原创竖屏救援街机小游戏。用同一块挡板反弹球、击破笼子，再接住缓慢下落的队友。救回关卡内所有队友才通关，现有每关均为六人；漏接一人会进入安全网并离场，本关需重试。场上所有球掉落才损失一次机会，剩余球机会耗尽则失败。

## 运行

无需安装游戏运行依赖：

```sh
node games/local/cage-rescue/server.mjs
# http://localhost:4451/
```

或在仓库根目录执行 `pnpm --filter @coffeeeeffoc/cage-rescue dev`。已登记至 Web Shell，构建后独立入口为 `/games/cage-rescue/index.html`。

```sh
pnpm --filter @coffeeeeffoc/cage-rescue test
pnpm --filter @coffeeeeffoc/cage-rescue build
PLAYWRIGHT_EXECUTABLE_PATH=/usr/bin/chromium pnpm --filter @coffeeeeffoc/cage-rescue test:browser
```

浏览器测试使用仓库 `@playwright/test`，自行启动 4452/4454 端口的生产制品服务并在结束时关闭。可用 `PLAYWRIGHT_EXECUTABLE_PATH` 指定浏览器。

## 已实现

- 30 个数据驱动关卡，保留原六关入门与所有存档 ID；后 24 关组合装甲阵、窄门密室、侧廊、双塔、开闸、错层、深井和交叉火力。
- 无尽救援：持续生成带不同布局微调的新波次，跨波保留生命和累计救援人数，难度逐步上升后封顶。
- 分球器最多放出三球，场上最后一球掉落才扣机会；4–8 层装甲保留每次损伤，钥匙永久开闸、爆破削弱附近装甲。宽挡板与一击/两击笼子保留，撞击挡板的位置决定反弹角度。
- 全员救援目标随笼子数量确定；救回四人或五人继续游玩，接住最后一人才通关。顶部队员标记分别显示待救、下落和已归队状态。
- 卡通街机画面：大头角色、吊链与铆钉笼架、工业斜纹挡板、立体按钮与阵形缩略图；破笼星芒、接人 `+1` 和反弹光环仅作用于呈现层。
- 预测落地时间并错开队友下落；两侧目标同时逼近时短暂缓降，挡板保持原速。
- 完整主页、逐关解锁、帮助、暂停、胜负结算、免费重试和下一关。
- 本机存档、音效开关、三套小队/挡板/场景配色。完成第 2、4 关解锁装扮，不影响能力。
- 鼠标/触屏直接拖动；键盘方向键或 A/D 移动、空格发球、Esc 暂停。
- 手势取消、多触点隔离、失焦/后台暂停、窗口变化保留对局、公共 H5 全屏和开发者模式。
- 静态工地与笼子共用一张可失效缓存；暂停、结算和菜单停止重绘，后台取消动画循环，回到前台后手动继续。重开不累积关卡位图，退出释放缓存。
- 失败后可自选请求一次广告补球；只有宿主返回 `completed` 才发奖，取消、不可用和失败不发奖。救援人数不足造成的失败不可续命。

## 平台边界

`src/host.mjs` 遵循仓库的 `GameHost` 存储及奖励端口；`mountCageRescue(host)` 可由真实宿主传入能力。独立运行和当前 iframe 注册使用本地宿主，没有自动继承 Shell 的广告或云存档。默认广告返回 `unavailable`，页面明确显示暂无广告，始终允许免费重试。本实现不假装播放商业广告，也未接入付费皮肤交易。

存档键为 `cage-rescue:host:progress`，内容版本为 1；保留旧四人目标下已获得的关卡和装扮解锁，新通关记录必须完成全员救援，再玩旧关可升级原记录。保存被禁用或超出配额时保留当前会话的最新进度并提示。首次进入只解锁首关，开发试玩不结算进度或奖励。

Web/H5 `?dev=1`、`?dev=0` 和 `localStorage.dev` 通过公共 `SmallGamesDev` 生效。开发面板提供任意关试玩和结果演示；没有发布给普通玩家的修改状态接口，`__cageRescue.snapshot()` 仅返回副本。

## 结构与验证

- `src/levels.mjs`：版本化关卡目录和内容校验。
- `src/core.mjs`：无 DOM/SDK 的固定步长模拟、碰撞、缓降、胜负和续命规则。
- `src/render.mjs`：原创 Canvas 角色、塔楼、笼子、挡板和安全网。
- `src/main.mjs`：页面、触屏生命周期与宿主能力编排。
- `src/progress.mjs`、`host.mjs`、`audio.mjs`：本机成长、宿主适配、原创合成音效。
- `tests/`：规则、30 关正常输入可达性、存档及宿主、浏览器流程与广告奖励回归。
- [设计与验收](docs/design/README.md)：效果图、手机运行图、平衡参数和验证边界。
- [本轮全员救援、街机画面及性能记录](docs/design/arcade-2026-10-11/README.md)。普通浏览器回归覆盖渲染生命周期；设 `CAGE_RESCUE_STRESS=1` 运行电脑/触屏各连续两遍六关。实际 Shell 检查先构建 Shell 和本游戏，再执行 `node games/local/cage-rescue/tests/shell-performance.mjs`。

新增游戏尚未产生 Git 提交时，仓库的 `check:games` 会要求真实提交元数据。按仓库规范，在提交源码后运行 `pnpm sync:game-meta`，不要填入伪造的提交时间或 SHA。未初始化的独立游戏子模块也会阻止全仓配置及全屏副本检查。

## 同场分享与发布配置

结算页提供真实同关挑战链接；打开后从主页的好友挑战入口进入。塔和救援使用稳定关卡配置，弹珠同时保留初始随机种子，挑战结果不改普通关卡解锁和存档。链接剥离 `dev` 等参数；分享不代表服务器认证成绩，尚未提供实时在线对战。弹珠旧存档缺少初始种子时隐藏分享，避免误称复现。

构建复制 `platforms/h5/publishing.js` 公共源，开发服务器映射同一公共文件；不维护游戏副本。默认显式 `mock` 模式，弹层标记“模拟广告”，每三次自然转场最多触发一次插屏，并受公共冷却和会话上限约束。生产入口可以在模块加载前配置 `globalThis.SmallGamesPublishingConfig = { adMode: 'off' }`；真实渠道由统一平台层接入，不把密钥放入页面。救援外部 GameHost 的广告接口保留优先权，只在本地使用公共模拟奖励。塔原免费续关与各款免费重试保留。

本轮规则与触屏校验记录见 [发布改进](docs/design/publishing/README.md)。

## 通用排行榜与无尽模式

主页可进入无尽救援及独立排行榜页面。榜单使用公共 `game-services.js` / `competition.js`，区分游戏、闯关榜/无尽榜、游客和登录身份。按 120 Hz 固定步長录制真实输入，由统一服务回放验证；开发模式、好友挑战、广告补球和离线局不上全站榜。无尽本机最佳与战役解锁分开保存，旧档继续有效。

本次实现前设计稿和验证记录见 [30 关与无尽](docs/design/endless-2026-10-12/README.md)。

## 章节机制

第 7 关引入工程师，接住后获得 8 秒宽挡板；第 13 关引入阵风，下落队友会漂移，场景落点标记使用同一模拟模型；第 8 关起用带铆钉、斜纹的不可破坏钢墙构造机关房间，需要寻找开口与侧面路线。第 25 关起组合这些机制并加入医疗员，接住补回一次球机会（剩余机会不超过 3），属于局内奖励，不标记广告复活。章节首关先练新机制，后续关卡组合变化；无尽按同一波次顺序引入。

独立静态部署可在构建时设置 `COMPETITION_PUBLIC_API_URL=https://example.com/api/competition/v1`；开发服务器支持同一环境变量。仅接受不含账号、查询或片段的 HTTP(S) 基础地址，页面预先注入的 `__COMPETITION_CONFIG__` 优先，无配置时使用同源接口。无需调整旧游戏的排行榜登记。

## 窄门与机关版本

[设计、实际截图与验收记录](docs/design/mechanisms-2026-10-23/README.md) · [上架基础资料](publishing/STATUS.md)。关卡配置包含独立的墙体、机关、开关组与耐久；无尽对整组几何统一镜像，保留开口与链接。月牙使用真实轮廓，不再用深色圆覆盖天空。竞技规则为 `rescue-ranked-v2`，需与导入该核心的 Runtime API 同版本发布。

`pnpm --filter @coffeeeeffoc/cage-rescue test:mechanisms:browser` 验证窄缝分球、暂停/恢复、开门、装甲与爆破，并保存真实浏览器录屏。测试用预置进度进入后期关，游玩只通过挡板输入，不改模拟状态。
