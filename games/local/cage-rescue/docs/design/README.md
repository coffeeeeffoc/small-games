## 2026-10-26 移动操作区

手指直接拖动场地会挡住滑板、落球和队友。本次在完整场地下方增加 88–104 CSS px 高的独立操作区；[局部布局概念图](mobile-control-concept.svg)于实现前确定，当轮采用工业夜景与金色滑板；这是局部输入改造记录，不限制后续按新要求与认可效果图重做视觉。横向位置直接对应滑板目标位置，不继承直接抓板的偏移；两端到达碰撞边界，轨道标记显示实际滑板的位置和宽度。触屏和触笔仅从操作区开始，鼠标保留画布拖动，键盘保留方向键、A/D、空格和 Esc，操作区还支持 Home/End。

操作区占用独立空间，保留完整场地、安全网与底部提示。手机安全区从可用尺寸中扣除，暂停和结算保留同一布局并禁用操作区；极窄横屏压缩 HUD，保持暂停按钮完整 44×44。手势使用当前触点捕获；松手、取消、失去捕获、尺寸变化、失焦、前后台、页面切换和销毁均清理输入。沿用 Canvas、关卡、存档与确定性模拟，不修改 `rescue-ranked-v2` 规则或后端回放。

Windows / Node 24.21.0 / Chromium 140.0.7339.186 的[验证报告](mobile-control-verification.json)：59 项规则/存档/Host 测试；12 组浏览器流程；最终 320×568、390×844、844×390、1280×900 布局复测；独立操作区精确定位、左右极限、移出捕获、多指隔离、取消与键盘；广告结果、6 组无尽/排行榜和6组机关流程均通过。Shell 专用玩法契约在实际独立游戏页面执行手机操作区与桌面鼠标两种模式；同源/跨源 iframe 由游戏浏览器回归覆盖。另通过149项有限Shell接入测试（8个文件，单进程）；本轮未重建完整Shell。发布范围9项针对性复测通过，保留未知字节与弱化断言的拒绝检查。无浏览器全屏检查通过（1146个源码文件）。
