# 夜间救援行动 · 设计与验收

## 设计

先生成 [三联手机效果图](concept.png)，覆盖主页、核心玩法与选关，再实现 Canvas 和页面。美术方向是深海军蓝救援塔、橙黄队员和挡板、青绿笼架与安全网。概念图用于构图与配色参考；实际关卡名称和阵形以 `src/levels.mjs` 为准，不包含概念图文字暗示的移动笼子或风力机制。

采用 390 × 700 竖屏逻辑视口：球与队友都从上往下靠近挡板，较长的垂直距离能给玩家留出观察和移动时间。横屏保持同一个完整竖屏场地并留边，不要求旋转手机；菜单在窄宽度时改单列并可滚动。窗口大小、设备方向和全屏切换都只改变显示缩放，不重开对局。

页面关系：主页 → 开始/继续或选关 → 游玩 → 暂停/结算 → 继续、免费重试、下一关或返回。帮助、设置和装扮分别从主页进入。游玩时隐藏外围菜单，只保留救援目标、三次球机会、暂停、发球与即时提示。

## 操作与公平性

- 挡板宽 108 / 104 / 100，移动速度 1100 逻辑像素/秒，手机全程只需要一根手指。
- 球速由 250 渐进到 280，队友落速为 38–40；两种目标有明显不同的节奏。
- 接近中心的击球趋向直上，边缘最大反弹角约 65.7°；避免几乎水平的长时间往返。
- 六笼均静止、一档/两档耐久用锁扣数量表达。不同高度、左右阵形和砖块屏障改变释放顺序。
- 破笼后依据预计到达挡板的时间，至少错开 2 秒。等待释放时由缓降伞承接。
- 左右两侧的球与队友同时接近底部时，将模拟速度降到 43%，持续最多 1.8 秒，随后至少冷却 3 秒；挡板不减速。
- 漏球后的发球等待期间，已释放队友仍会下落。不会因为玩家尚未发下一球而冻结救援。
- 漏接的人进入安全网并离场，不描绘伤害；安全网不增加救援数。
- 到达四人目标立即过关，三人漏接或球机会耗尽立即失败。一次广告补球不能挽回已无法达标的局面。

## 素材与界面

人物、塔楼、笼子、颗粒、挡板和网格均为本游戏原创 Canvas 绘图；音效由 Web Audio 合成。概念图为本次生成，不使用 Atari 或其他游戏的图像、地图、人物、音效和代码。效果图不进入运行制品。

按钮提供中文名称。暂停由两根分离、等高等宽的实心竖条组成，热区至少 44 CSS px。主要操作支持触屏，音效可以关闭，背景动画尊重“减少动态效果”。

## 验收范围

2026-10-06：42 项规则与接入测试、10 组生产制品浏览器验收、广告奖励端口浏览器回归通过。Chromium 151.0.7922.173；页面与资源错误为 0。完整记录见 [validation.json](validation.json)。

实际运行图：[主页](actual-home.png)、[选关](actual-levels.png)、[游玩](actual-play.png)、[球与队友同时在场](actual-decision.png)、[暂停](actual-pause.png)、[正常操作通关](actual-result.png)。

规则与存档测试覆盖正常输入下六关可达、两档耐久、碰撞角、接人/漏接/漏球、胜负优先级、暂停、错峰、缓降、帧率一致性、单次续命、关卡解锁、坏存档、禁用存储与开发试玩隔离。

浏览器验收脚本以生产制品运行 Chromium，使用 390 × 844、320 × 568、844 × 390 手机视口及 1280 × 900 桌面视口。测试真实 CDP 触屏的拖动、松手、取消和第二触点，页面切换、暂停恢复、窗口变化、同源/跨域 iframe、全屏降级、开发开关与离线奖励结果。自然输赢测试通过正常输入和浏览器时钟推进，不直接修改游戏状态；开发者结果演示另行标记，且验证不写入存档。

广告端口测试使用明确的测试宿主，验证 `completed` 增加一次球机会，`dismissed`、`unavailable`、`failed` 都不增加机会。这不等于真实广告平台验收。

验收记录和截图见游戏目录的 `test-results/browser-report.json` 及此目录的 `actual-*.png`。本次为桌面 Chromium 模拟触屏，未完成 Android/iOS 真机、原生小游戏 SDK、真实商业广告或线上发布验收。仓库完整 Shell 构建和跨游戏检查还依赖完整工具链、已初始化子模块及源码提交后的游戏元数据。
