# 克朗棋 · Carrom Club

日期：2026-10-10。设计先行：本方案及其生成效果图先完成，再实现。

## 产品与视觉

以用户参考图为视觉方向：深孔雀绿桌毡、胡桃木边框、浅枫木棋面、黄铜雕刻、象牙白/炭黑棋子与朱红皇后。全中文玩家界面，英文 CARROM CLUB 仅作装饰。拒绝外围仪表盘；真实可操作的方形棋盘占据主视觉。

选择竖屏：方形桌面棋盘加上下席位及底部拇指操作区更适合竖屏。390×844 为主要设计尺寸，320×640 仍可用；横屏设备保留完整方形棋盘和右侧操作区，不要求用户转动手机。尊重安全区。

主页为会所式单场景：铭牌、棋盤及排好的棋子、主按钮“开始对局/继续对局”、次按钮“练习选关”、帮助和设置。选关页提供六关木质练习牌，显示解锁与星级。游玩只显示对手、棋盘、玩家、摆位滑轨与当前操作。暂停/帮助/设置用清楚的页面切换；结算保留棋盘背景并给下一关/重试/主页。

## 核心循环

人机对局：玩家白子，电脑黑子，每方九子加一枚红后。击球→圆盘碰撞/沿板滑动/反弹→落袋→规则结算→连杆或换手→清台获胜。电脑同样通过物理出杆，无瞬移落袋或隐藏加速。

采用公开说明的休闲规则：进本色继续，空杆/仅进对方换手；红后需要同杆或下一杆补进本色，否则返中；击球子落袋返还本杆本色及一枚之前得分子，欠子在后续进子时偿还并换手；红后尚未被覆盖时最后本色返场。红后获得三分展示奖励，胜负以先清完本色且红后已经覆盖为准。不声称覆盖完整赛事裁判细则。参考 https://www.indiancarrom.co.in/laws-of-carrom/ （2026-10-10 查阅）。

六关练习以独立配置控制：直线入门、斜线落袋、两侧调位、借库反弹、红后补进、收官清台。限制杆数，按杆数与犯规评星，依次解锁。每关必须通过相同物理和真实输入验证可达。非强加数值养成；星级/解锁/人机胜局为本地持久进度。

## 操作细节

底部宽轨道拖动摆位（键盘方向键作补充）；棋盘上击球子约44px热区，按住向后回拉直接瞄准，松手发射。回拉长度非线性映射到力度便于小力微调；虚线终止在首个碰撞点，展示预计受力方向。下方回拉空间至少90px，不要求手指移出屏幕。回到起点松手/点击取消均不击发。

只接受首个主触点；pointercancel、lostpointercapture、失焦、隐藏、暂停取消手势，避免误发与卡住。摆位防止与静止子重叠。碰撞音随冲量变化；落袋缩小、环光、轻震动与简短状态反馈；电脑思考与轮次明确可见。反馈遵循设置。

物理使用固定步长、多子步避免高速穿透，按质量交换冲量，滚动摩擦逐渐静止；渲染使用 requestAnimationFrame 与插值。暂停/后台冻结时间，不追赶背景时间。棋盘纹理缓存为静态层，动态层只画棋子与短暂反馈。对局只在稳定回合点存档，重载回到最近回合；存储失败可继续游玩。

## 架构与接入

games/local/carrom-club：content.mjs 独立版本化配置与验证；core.mjs 无 DOM 的物理、回合、AI；render.mjs 缓存绘图；main.mjs 与 storage.mjs 负责界面/输入/持久化。复用仓库静态 iframe 注册、SmallGamesDev 与 H5 fullscreen。普通玩家无开发控件，开发跳关显式试玩且不发奖励。无需新依赖。

本次交付可运行 H5/手机 Web 与 Shell iframe；原生微信/B站宿主打包、联网匹配和真机手感标定不伪装成已完成。
