# 120 关练习与移动端复审

2026-10-11。延续 [现有效果图](https://github.com/coffeeeeffoc/small-games/blob/57f0f85a9c69231108b1a2e172cb38993206985b/games/local/carrom-club/docs/design/refinement-2026-10-10/concept.png) 的竖屏木盘、木牌选关和回拉操作，不改主页或主要布局。此次为已有选关页的局部扩展：同样的两列关卡牌，每次最多显示 12 关，顶部增加 44px 章节前后切换，默认定位尚待完成的一关所在章节。实际截图与验证结果追加在本文下方。

## 不同角色发现的问题与处理

- 玩家：六关结束后缺少持续目标；最后结算写死“六关练习已完成”。保留原六关 ID、布局与杆数，新增到 120 关，十章逐步练角度、长台、贴边、红后补进、黑子让路和多子清台。
- 关卡设计：新增关卡必须改变布局、目标子数量、红后/障碍组合；用独立章节配置与确定性坐标生成，杆数留出试探空间，按实际固定步长物理逐关验证可通关。
- 移动端体验：把 120 个完整棋盘一次性生成会占内存且难以找到下一关；每次仅渲染当前 12 关，分享静态棋盘缓存，章节标注范围与通关进度，仍按正常逐关解锁。
- 存档与稳定性：读取存档时击球子摆位回到中央；校验需要覆盖红后状态、静止状态及杆数耗尽，避免恢复无法继续的练习。保持 v1 保存键和已有关卡兼容。

## 验收目标

全部 120 关以真实出杆和 240Hz 物理模拟完成；旧 ID 不变且各关坐标互不重复；120 关顺序解锁、星级和后期对局恢复保持一致。手机模拟使用原生 CDP 触屏验证章节切换、正常末章解锁、120 关真实出杆通关、存档、取消、暂停恢复及小屏控件。保留原有独立与 Shell 兼容，公共开发模式和全屏由主代理增量验证。已读取项目 `game-ui-ux` / `game-feel` 与覆盖说明，本次复用原有目标感知慢调、预览、音效和落袋反馈，不对多人权威模拟增加视觉停顿。

## 实际验证

Node 24.21.0、Playwright 1.55.1、Chromium 140.0.7339.186，桌面手机模拟，390×844、320×640、844×390，DPR 2；使用原生 CDP 触屏事件。本记录不代表真实手机或原生平台验收。

- `node --test games/local/carrom-club/tests/*.test.mjs`：61 项测试，包含全部 120 关真实物理通关、稳定 ID 和布局差异、顺序逐关解锁与星级保存、旧六关进度、新关摆位与红后补进存档、坏存档拒绝，以及当前好友 2/3/4 人布局、积分、重试和存档隔离规则。
- 同一启发式选杆器的物理完成杆数逐章平均为 2.3、2.7、3.2、3.9、4.3、4.2、6.6、8.0、9.0、10.7 杆；全目录最长 15 杆，均未超各自预算。这只是可达性与递进的确定性检查，不代表真实玩家平均用杆。
- `pnpm --filter @coffeeeeffoc/carrom-club build` 与 `test:browser`：正式构建通过；原有手势慢调/多触点/收杆/取消、防抖、真实胜负、暂停冻结与恢复、电脑接杆、存档、声音、全屏进入/退出与拒绝、无存储降级、输入后延迟持久化和缓存性能回归通过。翻章按钮保留 46px 热区，仅生成 12 张牌，未来章节仍锁定。
- 浏览器末章测试使用独立说明的 119 关通关 v1 存档夹具进入普通选关，第 120 关没有调用试玩或伪造获胜：全程触屏摆位/回拉，11 杆真实清台，获得两星；中途刷新恢复杆数与非中央摆位，结算隐藏下一关，再次刷新显示 120/120。前 119 关的逐关通关/解锁由固定步长物理单元测试验证，不能将夹具称为手机逐关打完 120 关。
- 最新好友入口与返回通过手机触屏验证；好友规则与客户端单元回归通过。此次没有重跑依赖独立 PostgreSQL 和真实 Runtime API 的联网多人浏览器脚本，既有记录保留在 `multiplayer-2026-10-11/validation/`。
