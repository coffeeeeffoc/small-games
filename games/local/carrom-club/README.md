# 克朗棋 · Carrom Club

木质棋盘、轻滑棋子、直接回拉击球。你可以执白子与阿洛进行九子人机对局，也可以创建好友房，在各自手机进行 2–4 人彩色个人战、2 人经典单打或 4 人经典双打；120 关练习从摆位、轻击逐步进入红后补进、绕开黑子和多子清台。

```sh
pnpm --filter @coffeeeeffoc/carrom-club dev
pnpm --filter @coffeeeeffoc/carrom-club build
pnpm --filter @coffeeeeffoc/carrom-club test
pnpm --filter @coffeeeeffoc/carrom-club test:browser
```

本地入口 `http://localhost:4428/`，正式独立入口 `/games/carrom-club/index.html`，Shell 入口 `#/games/carrom-club`。`preview` 运行正式静态制品。无新增运行依赖，首屏仅一张约272KiB的 WebP 木纹图集；加载失败降级为程序纹理。

## 操作与单人规则

拖动下方滑轨摆位，按住击球子向目标反向回拉，松手发射。回到起点、点击取消、手势被取消或切到后台都不会误发。白色虚线预览首个碰撞，带深色描边的青蓝实线箭头和目标环表示目标子预计出射方向。键盘可操作摆位滑轨，Escape 暂停或取消。

没有命中目标时，回拉方向跟随手指快速调整；真正出现目标球撞击线后，自动降低角度灵敏度，短回拉保留杠杆限幅，并过滤细小触屏抖动。松手使用最后稳定预览，避免指尖离屏前短暂偏移改变方向。瞄准时显示角度和力度，静态虚线帮助观察落点。

采用明确的休闲规则：进本色连杆；空杆或只进对手则换手。红后需同杆或下一杆补进本色，否则返场；本色棋子每枚 1 分，红后完成补进后加 3 分。任一方清完本色且红后已补进时结算，积分高者获胜，同分由清台方获胜。击球子落袋返还本杆本色及一枚已进子，不足记欠并在后续进子偿还。红后未补进时最后一枚本色返场。返场棋子不计分。使用公开说明的休闲计分规则，不声称覆盖完整赛事裁判细则。

120 关配置独立于核心规则，以十章、每章十二关组织；选关默认定位下一待完成关所在章节，一次仅生成当前章的棋盘。原六关 ID、布局和存档保持兼容，稳定 ID 关联星级和顺序解锁。借库关允许直击完成，鼓励探索角度，不使用伪造反弹进度。回合稳定时本地存档；进行中的击球在重载后回到上个稳定回合，摆位也会恢复。关闭声音/触感的偏好持久保存。存储被禁用仍可玩。

## 结构

- `src/content.mjs`：版本化关卡目录与校验。
- `src/core.mjs`：240Hz固定步长圆盘物理、落袋、回合、犯规、红后、AI与评星；不依赖DOM/SDK。
- `src/friends-content.mjs`：好友棋盘配置、人数适配、四色与符号、随机选关及布局校验。
- `src/friends-core.mjs`：好友单打、双打、彩色个人战规则与计分，复用单人物理；管理四边席位、先手轮换、出杆模拟与结算。
- `src/render.mjs`：静态木纹棋盘缓存、动态棋子、四色符号、四边视角旋转、碰撞预览、落袋反馈及插值。
- `src/main.mjs`：触屏输入、页面切换、生命周期和Shell沉浸消息。
- `src/aim.mjs`：以CSS像素为基准的目标感知粗调/微调、手势死区与松手前偏移过滤。
- `src/friends.mjs`：新好友房客户端，复用 competition 身份与 API 配置，提供房主设置、准备与开局、幂等出杆、轮询、重连、同房号续局及邀请。
- `src/multiplayer.mjs`：保留旧双人 competition 客户端接口兼容。
- `src/storage.mjs`、`src/audio.mjs`：本地持久化边界、校验与可选声音。

`?dev=1` / `localStorage.dev` 复用公共 SmallGamesDev；`?dev=0`显式覆盖。仅开发模式暴露只读状态/建议出杆及 120 个试玩入口，试玩不记录胜局、解锁或星级。原生小游戏平台没有在本次实现中接入，交付为移动端优先H5与Shell iframe。

设计依据见 [产品方案](docs/design/product.md)、[生成设计图](docs/design/concept.png)、[生成提示词与素材说明](docs/design/image-prompts.md)。实际截图与浏览器记录在 [validation](docs/design/validation/)。测试为桌面 Chromium 手机模拟和原生 CDP 触控输入，不是真机验收。

## 好友房与多人规则

主页「好友对战」进入创建或加入页面。默认创建彩色个人战、普通棋盘、最多 4 人的房间；玩家可复制邀请链接或房号，让好友在另一台手机加入。彩色房至少 2 人即可开局，不必等满 4 人。

| 对战玩法   | 人数与棋子                                              | 棋盘与胜负                                                               |
| ---------- | ------------------------------------------------------- | ------------------------------------------------------------------------ |
| 彩色个人战 | 2、3、4 人，每人分别为 8、6、4 枚专属颜色棋子；不放红后 | 普通、指定关卡或随机关卡；先清完本色获胜，其余按剩余棋子数排名，同数并列 |
| 经典单打   | 严格 2 人，一方白子、一方黑子，开球方执白               | 标准棋盘；本色每枚 1 分、红后补进加 3 分，清台后比较总分，同分清台方胜   |
| 经典双打   | 严格 4 人，面对面的两人为队友，共享黑白棋子与队伍积分   | 标准棋盘，沿用经典休闲规则；按队伍结算                                   |

经典模式保留黑白阵营、相对席组队和红后补进，计分沿用游戏已有的休闲规则，不声称覆盖完整官方赛事裁判细则。单人人机与练习规则继续按上文执行。

彩色棋子同时使用青 `●`、橙 `▲`、紫 `◆`、绿 `✚` 标记，房间席位、棋盘和得分区保持一致。进本色可续杆；误进他色返摆、不计分并换手，同杆本色仍计入；击球子犯规返还本杆本色并罚回此前一枚，尚未有得分子则记欠子。彩色单局名次积分为 4 / 2 / 1 / 0，同名次同分；经典胜队每位成员获得 3 分。

彩色对战提供环心散局、双环穿插、借库长线三套对称竞技布局，各支持 2–4 人并保证相同棋子数量与半径分布。它们独立于 120 关单人练习，不带单人杆数预算、星级或解锁限制。房主可指定布局，或在全房适配的配置中随机抽取；随机结果开局前展示，全房使用同一布局。经典玩法固定普通标准棋盘。

房主设置、准备与开始是三个独立步骤。修改模式、棋盘、关卡或重新随机后，全员准备状态重置；成员变化也需要重新准备。只有人数符合玩法、全员在线且准备完成，房主才能点击开始。开局后锁定本局参与者，后来访客不能加入当前对局。

每位玩家都从自己的底线出杆；四边视角与触屏坐标同步旋转，自己的席位在下方，其他 1–3 名玩家集中显示在顶部。每杆由服务端计时 45 秒，超时跳过当前回合，棋子运动时间不占用下一杆的思考时间。暂停只打开本机菜单，不冻结其他玩家的对局。

结算后房主可回到同一房号续局，全员重新准备，再由房主开始；保留成员时累计系列积分并轮换先手，3 人模式同时轮换座位以轮流面对空边。成员或对战模式改变后，只重置系列累计积分和胜场；同一房间的局号持续递增。主动离开会中止当前对局，其余玩家可返回房间重新组局。

服务端校验席位、准备版本、局号、回合号与出杆序号，并使用同一物理核心结算；不接受客户端上报积分或棋子位置。网络中断显示重试，仍属于当前局和当前回合的未确认出杆使用相同序号重发；同步发现局号、回合号或对局状态改变后清除待发请求，服务端也拒绝迟到的旧局、旧回合出杆。刷新后可在好友页恢复上次房间。房间在创建、开局或续局时设置 2 小时有效期，普通轮询不会延长期限；过期关闭房间。

## 联网接口与部署

新的好友房使用 `/carrom/rooms` 路由，包含创建、加入、查询、设置、准备、房主开始、出杆、同房号续局与离开；实现位于 `services/runtime-api/src/carrom/`。复用已有 competition 身份、数据库房间存储与 API 配置。原有双人 competition 接口及 `services/runtime-api/rules/carrom.mjs` 继续保留兼容；新好友流程通过 `src/friends.mjs` 进入多人房间接口。

正式静态构建带上公共 `platforms/competition/client.js`。腾讯 Runtime 打包清单除原有 `core.mjs`、`content.mjs` 外，也包含 `friends-core.mjs`、`friends-content.mjs`；发布时需要一并部署新服务端路由和这些规则依赖。仅发布静态页面不等于已部署多人好友 API。

腾讯同源发布沿用 competition API 配置；分离托管（例如 GitHub Pages）需构建时设置 `COMPETITION_PUBLIC_API_URL`，或 `COMPETITION_RELEASE_CONFIG` 中的 `carrom-club.h5.apiUrl`，服务端需允许对应站点 Origin。

性能调整：滑轨输入不触发全量 HUD 刷新；画布尺寸在进入/变化时更新，棋子渐变与阴影缓存为精灵，静止时按需重绘；本地存档延后到输入事件之后，并在退出页面前刷新。
