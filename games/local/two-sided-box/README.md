# 双面机关盒

正面打不开，问题可能在背面。第一辑「黄铜工坊」提供六个原创机关盒，使用滑轴、锁扣、挡板三类机关。正反两套二维画面共享同一个机械状态，翻面只改变可见部件。运行时使用原生 JavaScript 与 SVG，不依赖外部图片、字体或运行库。

## 试玩与操作

在本目录使用 Node.js 20+ 启动：

```sh
node server.mjs --host 127.0.0.1 --port 4412
```

打开 <http://127.0.0.1:4412/>。同一局域网手机可使用 `--host 0.0.0.0`，再访问电脑实际局域网 IP 的 4412 端口。

- 直接拖动盒内滑轴把手，或点按低、中、高挡位。点击锁扣开合；条件锁扣会标出需要对齐的另一根轴及挡位。
- 点击「转到背面 / 正面」观察共享机关。实色挡板属于当前面，虚线轮廓指向另一面的挡板。
- 从正面放球。小球遇到挡板会停住，继续调轴后自动前进；途中可以翻面，没有时间限制。
- 免费关联提示分三步提供线索，不改动机关。可以撤销完整操作、重来，或在收藏中选择任意盒子。
- 键盘 Tab 聚焦滑轴或锁扣；用方向键换挡，Enter / 空格开合锁扣。

完成记录、最佳操作数及声音偏好保存在浏览器本地。存储受限或存档损坏时仍可游玩。六盒与提示全部免费；本原型没有接入广告、支付、账户或分析 SDK。激励视频提示与海外付费章节仅是后续平台接入方向。

## 第一辑的六个盒子

| 盒子 | 名称         | 新引入的机械关系                     | 参考操作数 |
| ---- | ------------ | ------------------------------------ | ---------: |
| 01   | 打不开的正面 | 背面锁扣固定正面同一根轴             |          5 |
| 02   | 刚刚好的中间 | 抬前门会降后板，中位同时满足两面     |          5 |
| 03   | 对齐解锁窗   | B 的中位对齐 A 锁扣的释放窗口        |          6 |
| 04   | 过门，再换挡 | 前门要高位、后板要低位，必须途中调整 |          6 |
| 05   | 交错的两把锁 | 两面条件锁按次序解开，两根轴接力换挡 |          9 |
| 06   | 三轴接力     | 三根轴的解锁链与六道分段挡板         |         14 |

操作数包括翻面、有效换挡、锁扣开合和放球，球自然滚动不计入。前三盒可以预先布置通畅球道；后三盒没有任何单一静态位置组合可通关，玩家需要先让球通过前段，再调整后段。球道只向下行进，通过的挡板即使重新关闭也不会把球拉回。

审核过的完整解法保存在 [levels.mjs](levels.mjs) 的各关 `solution` 数组。动作包括 `flip`、`latch`、`shaft`、`release` 与代表等待自然滚动的 `advance`。第六盒的顺序是：先解 C 并移到低位，解 B 并移到中位，解 A 并移到高位后放球；通过前三门后，再依次调整 B 高、A 低、C 高。

## 检查与构建

零依赖规则与存档测试可直接运行：

```sh
node tests/engine.test.mjs
node tests/progress.test.mjs
node build.mjs
node server.mjs --dist --host 127.0.0.1 --port 4412
```

在仓库根目录也可以使用工作区命令：

```sh
pnpm --filter @coffeeeeffoc/two-sided-box dev
pnpm --filter @coffeeeeffoc/two-sided-box test
pnpm --filter @coffeeeeffoc/two-sided-box build
pnpm --filter @coffeeeeffoc/two-sided-box test:browser
```

构建产物位于 `dist/`，保留相对资源路径。Shell 路由为 `#/games/two-sided-box`，静态独立入口为 `games/two-sided-box/index.html`。

规则测试使用独立有限状态搜索确认六关可解，并验证后三关必须途中换挡、条件锁的死循环确实无解、翻面保持物理状态、无效操作不改状态、后板停球可恢复，以及球实际到达终点才判胜。存档测试覆盖损坏数据、非法分数、未知关卡、章节扩展和存储读写失败。

浏览器验收脚本使用仓库的 Playwright 测试依赖与 Chromium，默认启动 `dist/` 服务。需先构建，并确保浏览器存在于 `/usr/bin/chromium`，或设置 `PLAYWRIGHT_EXECUTABLE_PATH`；可用 `GAME_URL` 指向已启动的服务。脚本通过可见控件完成六盒，并检查桌面拖轴、撤销、重来、键盘、存档，以及 390×844、320×640、844×390 触屏模拟下的拖拽、取消与控件尺寸。结果及截图生成到 `test-results/`，是否通过以实际报告为准。触屏模拟不是实机验收，尚未验证真实手机与移动 Safari，也未验证付费或广告流程。

## 后续扩展

新增关卡只需在 [levels.mjs](levels.mjs) 追加一个对象，渲染与规则不按关卡编号分支：

| 字段                                  | 作用                                                                       |
| ------------------------------------- | -------------------------------------------------------------------------- |
| `id`、`number`、`title`、`intro`      | 稳定存档键、展示顺序与玩家引导                                             |
| `shafts`                              | 每根轴的 `id`、初始挡位、`min/max`、坐标、颜色，以及两面的作用说明         |
| `latches`                             | 锁住哪根轴、可操作的面、初始锁定状态；`releaseWhen` 指定关联轴可释放的挡位 |
| `gates`                               | 所属视图、连接的轴、允许球通过的挡位 `positions`、球道坐标                 |
| `path`                                | SVG 720×600 坐标空间中的连续球道点                                         |
| `checkpoints`                         | 按路径递增的 `pathIndex` 与对应 `gateIds`；最终检查点在终点且没有挡板      |
| `hints`、`solution`、`estimatedMoves` | 递进提示、可回放解法与参考操作数                                           |

同一轴可连接两面多道挡板，改变 `positions` 就能形成反向影响与分段冲突。条件锁只在松开时检查对齐条件，松开后另一根轴可以继续移动；重新扣紧会再次固定轴。`engine.mjs` 的 `validateLevel` 会检查引用、挡位、路径顺序与终点，规则测试会回放每关的解法。新增关卡应同时通过独立可解性搜索与浏览器可见操作，避免仅凭配置看起来合理。

继续扩展时优先设计新的因果组合与阶段次序，保持轴字母、挡位与锁扣条件清晰可见。所有交互应在盒内具有明确目标，避免用隐藏像素或难辨热区增加难度。
