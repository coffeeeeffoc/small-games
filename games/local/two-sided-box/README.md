# 双面机关盒 · 六面工坊

五章、50 个独立机关盒。每局随机提供两个观察角度，玩家从前、后、上、下、左、右六面逐步补全信息，操作滑轴和锁扣，让小球沿球道穿过带孔挡板。游戏使用原生 JavaScript 与 Canvas，没有外部图片、字体或运行时依赖。

## 运行

```sh
node server.mjs --host 127.0.0.1 --port 4412
node --test tests/*.test.mjs
node build.mjs
node tests/browser.mjs
```

也可从仓库根目录运行 `pnpm --filter @coffeeeeffoc/two-sided-box dev`、`test`、`build` 或 `test:browser`。独立入口为 `/games/two-sided-box/index.html`，Shell 路由仍为 `#/games/two-sided-box`。构建输出 `dist/` 包含全部关卡模块，保留相对路径。

## 观察、提示与通关

- 开始一盒时，从符合条件的面组合中随机选择两个不同的面；组合至少包含一个当前可操作的滑轴或锁扣。
- 点击已知面切换观察窗，直接在画面拖轴、点选挡位或点锁扣。画面下方提供相同操作的按钮，支持键盘和辅助技术。
- 点击未知面或「揭示另一面」免费增加一个观察角度。观察窗使用同一空间投影保留所有孔板，突出本面关联部分；只有当前面的把手和锁扣可以操作，未观察面的外部控制件不显示。
- 六面全部揭示后，最后一级提示提供完整 3D。支持拖动旋转、六面预设、双指/滚轮/按钮缩放、外壳透视与分层展开。
- 未看过最后一级提示时，通关先自动展示完整 3D，关闭结构页后才进入结算与下一关；已经看过时直接结算，也可再次查看结构。
- 观察和提示不计机关操作数。重来保留本次随机初始组合及已获得的信息；撤销只回退机关和小球，避免因撤销而遗忘已知面。
- 小球先停在关闭挡板前，孔口对齐后才穿板继续。关卡不设倒计时，可以逐门改变挡位。

第 21–50 关经过受限状态搜索：任意初始两面所能操作的机关都不足以通关，必须增加观察面。新增面是这些关卡的正常游玩步骤，当前全部免费。

## 空间模型的依据与边界

`faces.mjs` 定义唯一世界坐标：X 向右、Y 向上、Z 向前。六面使用各自的观察基向量投影同一模型，背面等相对视角自然改变左右关系，不再复制同一张二维布局。

`geometry.mjs` 同时服务于规则和绘图。同一根轴带动的孔板共享位移向量和每挡 64 单位的行程；板的滑动方向在板面内。孔口的真实位置由位移和孔偏移计算，只有球半径完整落在孔内才算通行。板的外轮廓在全部挡位覆盖球道，不能绕边过球；门前后球道沿板法线穿过，并为停球预留球半径与板厚空间。

本批关卡使用互相平行的孔板和沿 X 单调推进的球道，各板只穿过一次。验证涵盖孔板和路径的盒内边界、穿孔方向、孔径、净空和前后观察变换。这是几何一致的理想运动学模型，尚未验证完整传动机构、轴与轨道装配、制造公差或真实动力学。条件锁仍是理想联锁，图中虚线表示约束关系；分层展开是观察用的拆解方式。不能把通关验证视为实物制造证明。

## 模块边界

| 模块                              | 维护内容                                                 |
| --------------------------------- | -------------------------------------------------------- |
| `faces.mjs`                       | 六面名称、世界坐标和投影基向量                           |
| `geometry.mjs`                    | 滑轴位移、带孔板几何和过球净空                           |
| `engine.mjs`                      | 纯规则、空间配置校验、锁扣、观察权限和状态快照           |
| `levels/01.mjs` … `levels/50.mjs` | 每关独立的轴面分配、解锁条件、过门顺序和设计意图         |
| `levels/shared.mjs`               | 纯数据构造；把作者指定的挡位转成孔位、生成球道及参考动作 |
| `levels/index.mjs`、`levels.mjs`  | 关卡目录与兼容导出                                       |
| `structure-model.mjs`             | 从共享几何构造观察窗/完整结构的图元及操作对象            |
| `structure-view.mjs`              | 三维投影、绘图、命中检测、触屏/键盘观察与操作            |
| `reveal-access.mjs`               | 免费揭示与未来奖励授权的异步边界                         |
| `touch-buttons.mjs`               | 触屏取消手势后的按钮兼容与重复点击抑制                   |
| `game.mjs`                        | 页面流程、动画、撤销、提示与通关展示                     |
| `progress.mjs`                    | 可选本地存档与数据校验                                   |

规则不按关卡编号分支。关卡内容由作者显式给出，不在运行时随机生成；随机只影响初始观察面。单独调整一关时修改对应编号文件，再运行核心、关卡和浏览器检查。

### 维护一关

独立关卡传给 `defineLevel` 的字段包括：

- `id`、`number`、`title`、`intro`、`lesson`、`difficulty`：稳定标识与设计意图。
- `shafts`：`[轴ID, 所属面, 初始挡位]`。
- `latches`：`[锁ID, 所锁轴, 所属面, [[条件轴, 允许挡位], …]]`。
- `preparation`：参考解法的解锁准备动作，不修改初始机关。
- `route`：按球前进顺序的 `[轴ID, 开孔挡位, 门名]`。构造时将挡位转为实际孔偏移，运行时通行使用几何计算。

解法在关卡的 `solution` 中可读回放；这是验收参考，不向游戏操作注入状态。高级关卡验证还使用与参考解法无关的有限状态搜索，检查全解和任意双面受限状态。

## 奖励接入边界

`createRevealAccess({ provider })` 接受 `provider(request, { signal })`。请求含 `kind: 'face' | 'structure'`、`levelId` 和可选的 `face`。默认 provider 免费授予；将来接入奖励平台时，只有明确返回 `{ granted: true }` 才能解锁。取消、错误、重复点击、离开关卡以及迟到结果均不授予观察权。页面另用关卡代次隔离过期请求。

当前没有广告 SDK、付费入口或模拟广告。广告文案、投放与免费路径策略应在真实平台接入时单独配置；奖励 provider 不得直接修改游戏机关状态。

## 验证

纯测试覆盖：六面投影、孔位净空、锁扣依赖、初始随机组合、逐级揭示、50 关参考解法、独立可解性搜索、第 21–50 关全部 450 组双面受限搜索、存档与异步奖励取消。

浏览器脚本使用仓库的 `@playwright/test` 和 Chromium，默认路径 `/usr/bin/chromium`，可设置 `PLAYWRIGHT_EXECUTABLE_PATH`；`GAME_URL` 可指向已启动的服务。截图和报告输出到 `test-results/`（已忽略）。触屏模拟与真实手机验证不同；真实手机和移动 Safari 尚未验证。
