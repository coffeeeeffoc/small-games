# 双面机关盒 · 六面工坊

五章、50 个独立机关盒。每局随机提供两个观察角度，玩家从前、后、上、下、左、右六面逐步补全信息，操作滑轴和锁扣，让小球沿球道穿过带孔挡板。所有已知面以独立 Canvas 观察窗共同展示在一个画面中，木质盒体、黄铜部件、孔板厚度与投影呈现实物层次。游戏使用原生 JavaScript 与 Canvas，没有外部图片、字体或运行时依赖。

## 运行

```sh
node server.mjs --host 127.0.0.1 --port 4412
node --test tests/*.test.mjs
node build.mjs
node tests/browser.mjs
```

也可从仓库根目录运行 `pnpm --filter @coffeeeeffoc/two-sided-box dev`、`test`、`build` 或 `test:browser`。独立入口为 `/games/two-sided-box/index.html`，Shell 路由仍为 `#/games/two-sided-box`。构建输出 `dist/` 包含全部关卡模块，保留相对路径。

## 观察、提示与通关

- 开始一盒时，从符合条件的面组合中随机选择两个不同的面；组合至少包含一个当前可操作的滑轴或锁扣。
- 已知面的观察窗同时保留在观察台中，不使用 Tab 切换；窄屏可滚动查看。直接在任意已知面的画面内拖轴、点选挡位或点锁扣，全部观察窗同步反映同一份机关和小球状态。画面下方提供相同操作的按钮，支持键盘和辅助技术。
- 通过提示免费增加一个观察角度，新面追加到观察台，已经展开的面不会消失。各观察窗从本面投影同一空间模型，保留所有孔板并突出本面关联部分；每个窗内只能操作属于该面的把手和锁扣，未知面的外部控制件不显示。
- 平台提供广告能力时，也可选择视频奖励展开一面；只在宿主确认完整观看后授予观察权。独立页面默认没有广告提供方，免费提示始终可用。
- 六面全部揭示后，最后一级提示提供完整 3D。支持拖动旋转、六面预设、双指/滚轮/按钮缩放、外壳透视与分层展开。
- 未看过最后一级提示时，通关先自动展示完整 3D，关闭结构页后才进入结算与下一关；已经看过时直接结算，也可再次查看结构。
- 观察和提示不计机关操作数。重来会重新随机展示两个面；撤销只回退机关和小球，保留本局已经展开的观察面。
- 小球先停在关闭挡板前，孔口对齐后才穿板继续。关卡不设倒计时，可以逐门改变挡位。

第 21–50 关经过受限状态搜索：任意初始两面所能操作的机关都不足以通关，必须增加观察面。新增面是这些关卡的正常游玩步骤，全部可以免费取得。

## 空间模型的依据与边界

`faces.mjs` 定义唯一世界坐标：X 向右、Y 向上、Z 向前。六面使用各自的观察基向量投影同一模型，背面等相对视角自然改变左右关系，不再复制同一张二维布局。

`geometry.mjs` 同时服务于规则和绘图。同一根轴带动的孔板共享位移向量和每挡 64 单位的行程；板的滑动方向在板面内。孔口的真实位置由位移和孔偏移计算，只有球半径完整落在孔内才算通行。板的外轮廓在全部挡位覆盖球道，不能绕边过球；门前后球道沿板法线穿过，并为停球预留球半径与板厚空间。

本批关卡使用互相平行的孔板和沿 X 单调推进的球道，各板只穿过一次。验证涵盖孔板和路径的盒内边界、穿孔方向、孔径、净空和前后观察变换。这是几何一致的理想运动学模型，尚未验证完整传动机构、轴与轨道装配、制造公差或真实动力学。条件锁仍是理想联锁，图中虚线表示约束关系；分层展开是观察用的拆解方式。不能把通关验证视为实物制造证明。

## 模块边界

| 模块                              | 维护内容                                                 |
| --------------------------------- | -------------------------------------------------------- |
| `faces.mjs`                       | 六面名称、世界坐标和投影基向量                           |
| `geometry.mjs`                    | 滑轴位移、带孔板几何和过球净空                           |
| `engine.mjs`                      | 纯规则、空间配置校验、锁扣、观察权限和状态快照           |
| `levels/01.mjs` … `levels/50.mjs` | 每关独立的轴面分配、解锁条件、过门顺序和设计意图         |
| `levels/shared.mjs`               | 纯数据构造；把作者指定的挡位转成孔位、生成球道及参考动作 |
| `levels/index.mjs`、`levels.mjs`  | 关卡目录与兼容导出                                       |
| `structure-model.mjs`             | 从共享几何构造观察窗/完整结构的图元及操作对象            |
| `structure-view.mjs`              | 三维投影、绘图、命中检测、触屏/键盘观察与操作            |
| `reveal-access.mjs`               | 免费揭示与未来奖励授权的异步边界                         |
| `rewards.mjs`                     | 可选宿主广告能力检查、完成状态与超时/取消处理            |
| `touch-buttons.mjs`               | 触屏取消手势后的按钮兼容与重复点击抑制                   |
| `game.mjs`                        | 页面流程、动画、撤销、提示与通关展示                     |
| `progress.mjs`                    | 可选本地存档与数据校验                                   |

规则不按关卡编号分支。关卡内容由作者显式给出，不在运行时随机生成；随机只影响初始观察面。单独调整一关时修改对应编号文件，再运行核心、关卡和浏览器检查。

### 维护一关

独立关卡传给 `defineLevel` 的字段包括：

- `id`、`number`、`title`、`intro`、`lesson`、`difficulty`：稳定标识与设计意图。
- `shafts`：`[轴ID, 所属面, 初始挡位]`。
- `latches`：`[锁ID, 所锁轴, 所属面, [[条件轴, 允许挡位], …]]`。
- `preparation`：参考解法的解锁准备动作，不修改初始机关。
- `route`：按球前进顺序的 `[轴ID, 开孔挡位, 门名]`。构造时将挡位转为实际孔偏移，运行时通行使用几何计算。

解法在关卡的 `solution` 中可读回放；这是验收参考，不向游戏操作注入状态。高级关卡验证还使用与参考解法无关的有限状态搜索，检查全解和任意双面受限状态。

## 奖励接入边界

免费揭示继续使用 `createRevealAccess({ provider })`。它接受 `provider(request, { signal })`，请求含 `kind: 'face' | 'structure'`、`levelId` 和可选的 `face`；只有明确返回 `{ granted: true }` 才能解锁。默认 provider 免费授予，供免费提示使用。取消、错误、重复点击、离开关卡以及迟到结果均不授予观察权。页面另用关卡代次隔离过期请求。

视频奖励是独立的可选路径。接入方需在游戏初始化前，向游戏窗口注入真实平台提供的 `GameHost` 广告端口；下例中的 `platformGameHost` 必须由发布平台创建并负责广告展示和完成校验：

```js
window.twoSidedBoxHost = {
  session: platformGameHost.session,
  ads: {
    offer: (opportunity) => platformGameHost.ads.offer(opportunity),
  },
};
```

只有 `session.capabilities` 数组包含 `'advertising'` 且 `ads.offer` 是函数时，视频入口才可用。`offerFaceReward(host, face, { signal })` 按仓库契约提交 `{ id: 'two-sided-box.reveal-face', reward: { face, faces: 1 } }`，其中 `face` 必须是六面 ID 之一。宿主返回 `Promise<{ status }>`，状态为 `completed`、`dismissed`、`unavailable` 或 `failed`；只有精确的 `completed` 才能转换成揭示授权。关闭、不可用、失败、异常或 45 秒超时均不授予奖励，取消信号会使本地请求立即失效并忽略迟到结果；广告本身的关闭仍由宿主负责。

默认独立页面与 Shell iframe 没有自动注入广告能力。当前代码仅提供接口及模拟端口测试，没有真实广告 SDK、付费入口或模拟观看后直接发奖的后备路径。宿主应按会话的广告控制权处理请求，奖励 provider 不得直接修改游戏机关状态，免费提示无需广告授权。

## 验证

纯测试覆盖：六面投影、孔位净空、锁扣依赖、初始随机组合、逐级揭示、50 关参考解法、独立可解性搜索、第 21–50 关全部 450 组双面受限搜索、存档与异步奖励取消。宿主奖励测试还覆盖广告能力检查、严格完成状态、异常、超时、取消及迟到结果。

浏览器脚本使用仓库的 `@playwright/test` 和 Chromium，默认路径 `/usr/bin/chromium`，可设置 `PLAYWRIGHT_EXECUTABLE_PATH`；`GAME_URL` 可指向已启动的服务。截图和报告输出到 `test-results/`（已忽略）。触屏模拟与真实手机验证不同；真实手机和移动 Safari 尚未验证，真实广告平台尚未接入验证。

## 2026-10-11 扩围改造

换挡后所有已知观察窗短暂描边同步，反馈显示轴名与挡位；减少只看到某一面、不清楚联动是否发生的问题。新增暂停和首页入口，暂停、打开说明或切后台时小球动画保留位置。结算分享固定关卡、相同初始两面和操作数目标；挑战重开仍保留相同两面。手机旋转锁定时界面自动转为横屏，多观察窗可横向滚动、整体内容可纵向滚动，Canvas点击/拖动坐标同步转换。

分享使用公共 `platforms/h5/publishing.js`：系统分享或复制公开链接，拒绝/取消不会冒充发送成功；不可用时显示可复制的链接。挑战可在首页明确退出，挑战中途与完成结果均不写入普通关卡进度。链接校验版本、关卡与有界目标，公开链接不传播开发参数；这是本地异步成绩挑战，不是实时联网对战。

自然结算复用公共频控，默认显式 `mock` 模式；第一、第二次结算不展示，第三次才可展示模拟插屏，并受60秒冷却和会话上限约束。关闭广告不影响胜利或免费重试，也不会发放任何奖励。可以在初始化前通过 `SmallGamesPublishingConfig` 配置 `adMode: 'off'`，或注入真实渠道 provider；本次未声称接入真实广告 SDK。

局部方案与手机比例示意见 [设计记录](docs/design/2026-10-11-challenge-expansion.md)。新增生产构建浏览器专项（仓库根运行）：

```sh
node games/local/two-sided-box/tests/publishing.browser.mjs
```

专项支持 `CHROMIUM_PATH` / `PLAYWRIGHT_EXECUTABLE_PATH` 和 `GAME_URL`，默认启动本款生产构建服务器。报告与桌面/触屏截图位于本游戏 `test-results/publishing/`。验收使用 Chromium 设备模拟，真实手机与渠道 SDK 仍待验证。

可提交的实际截图与报告：[本轮验证记录](docs/verification/2026-10-11-challenge-expansion/README.md)。
