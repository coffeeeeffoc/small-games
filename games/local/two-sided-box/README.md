# 双面机关盒

正面打不开，问题可能在背面。第一辑「黄铜工坊」提供六个原创机关盒，使用滑轴、锁扣、挡板三类机关。每次开盒从正、背、左、右、顶、底六面中随机展示两个不同的面；展开的面共同留在观察台上，读取同一个机械状态。画面通过木质盒壁、黄铜轨道、玻璃观察窗与层次阴影呈现实物质感。运行时使用原生 JavaScript 与 SVG，不依赖外部图片、字体或运行库。

## 试玩与操作

在本目录使用 Node.js 20+ 启动：

```sh
node server.mjs --host 127.0.0.1 --port 4412
```

打开 <http://127.0.0.1:4412/>。同一局域网手机可使用 `--host 0.0.0.0`，再访问电脑实际局域网 IP 的 4412 端口。

- 正面与背面展示可操作的滑轴、锁扣和球道。直接拖动黄铜把手，或点按低、中、高挡位；条件锁扣会标出需要对齐的另一根轴及挡位。
- 左、右、顶、底面是同一机关的实时观察窗，展示轴位、传动、挡板或出口状态。所有已展开的面同时呈现，窄屏可滚动观察，不使用 Tab 或翻面切换。
- 点击「提示 · 展开一面」免费增加一个观察面，也可在关联提示中展开。默认优先展开尚未出现的正面与背面，确保初始随机到观察窗时仍能逐步找到全部操作入口。展开不改变机关、球的位置或操作数。
- 正面出现后即可放球。小球遇到挡板会停住，继续调轴后自动前进；没有时间限制。
- 免费关联提示分三步提供线索。撤销只恢复机关操作，已展开的面保留；重来或选择另一个盒子会重新随机展示两个面。
- 键盘 Tab 聚焦滑轴或锁扣；用方向键换挡，Enter / 空格开合锁扣。

完成记录、最佳操作数及声音偏好保存在浏览器本地。存储受限或存档损坏时仍可游玩。六盒与提示全部免费；默认独立页面没有广告提供方，「看视频 · 多看一面」不可用时仍可通过免费提示展开全部六面。可选宿主接口见下文；本原型没有接入实际广告平台、支付、账户或分析 SDK。

## 第一辑的六个盒子

| 盒子 | 名称         | 新引入的机械关系                     | 参考操作数 |
| ---- | ------------ | ------------------------------------ | ---------: |
| 01   | 打不开的正面 | 背面锁扣固定正面同一根轴             |          3 |
| 02   | 刚刚好的中间 | 抬前门会降后板，中位同时满足两面     |          3 |
| 03   | 对齐解锁窗   | B 的中位对齐 A 锁扣的释放窗口        |          4 |
| 04   | 过门，再换挡 | 前门要高位、后板要低位，必须途中调整 |          4 |
| 05   | 交错的两把锁 | 两面条件锁按次序解开，两根轴接力换挡 |          7 |
| 06   | 三轴接力     | 三根轴的解锁链与六道分段挡板         |         10 |

当前界面的操作数只包括有效换挡、锁扣开合和放球；展开观察面与球自然滚动不计入。前三盒可以预先布置通畅球道；后三盒没有任何单一静态位置组合可通关，玩家需要先让球通过前段，再调整后段。球道只向下行进，通过的挡板即使重新关闭也不会把球拉回。

审核过的完整解法保存在 [levels.mjs](levels.mjs) 的各关 `solution` 数组。动作包括 `flip`、`latch`、`shaft`、`release` 与代表等待自然滚动的 `advance`。为兼容旧版规则回放，配置中的 `flip` 和 `estimatedMoves` 保留原含义；当前界面直接对操作所在的面传参，不执行 `flip`。上表参考数是旧解法扣除翻面后的机关操作数，规则测试同时验证两种回放。第六盒的顺序是：先解 C 并移到低位，解 B 并移到中位，解 A 并移到高位后放球；通过前三门后，再依次调整 B 高、A 低、C 高。

## 可选宿主奖励接口

`rewards.mjs` 沿用仓库 `GameHost` 的广告契约。接入方必须在游戏初始化前，将已创建的真实宿主端口注入游戏窗口；例如下面的 `platformGameHost` 应由发布平台提供，并负责广告展示与完成校验：

```js
window.twoSidedBoxHost = {
  session: platformGameHost.session,
  ads: {
    offer: (opportunity) => platformGameHost.ads.offer(opportunity),
  },
};
```

只有 `session.capabilities` 数组包含 `'advertising'` 且 `ads.offer` 是函数时，视频入口才可用。游戏提交 `{ id: 'two-sided-box.reveal-face', reward: { face: 'front', faces: 1 } }` 一类奖励机会，其中 `face` 是本次待展开面的实际 ID。宿主返回 `Promise<{ status }>`，`status` 可为 `completed`、`dismissed`、`unavailable` 或 `failed`；只有精确的 `completed` 才展开一面。宿主应按会话的广告控制权处理请求，游戏不直接接触广告 SDK。

请求期间禁止重复领取；关闭、不可用、失败、异常或 45 秒超时均不展开面。换盒或重来会使旧请求结果失效。这里仅提供可选接口及模拟端口测试，现有独立页面和 Shell iframe 不会自动获得真实广告能力，也没有模拟观看后直接发奖的后备路径。

## 检查与构建

零依赖规则、视角、奖励端口与存档测试可直接运行：

```sh
node --test tests/*.test.mjs
node build.mjs
node server.mjs --dist --host 127.0.0.1 --port 4412
```

在仓库根目录也可以使用工作区命令：

```sh
pnpm --filter @coffeeeeffoc/two-sided-box dev
pnpm --filter @coffeeeeffoc/two-sided-box test
pnpm --filter @coffeeeeffoc/two-sided-box build
pnpm --filter @coffeeeeffoc/two-sided-box test:browser
```

构建产物位于 `dist/`，保留相对资源路径。Shell 路由为 `#/games/two-sided-box`，静态独立入口为 `games/two-sided-box/index.html`。

规则测试使用独立有限状态搜索确认六关可解，并验证后三关必须途中换挡、条件锁的死循环确实无解、翻面兼容回放保持物理状态、显式面操作共享机关且无需翻面、无效操作不改状态、后板停球可恢复，以及球实际到达终点才判胜。视角测试覆盖全部 15 种随机初始组合、展开顺序、无重复及六面全开；奖励端口测试覆盖能力检查、严格完成状态、异常与超时。存档测试覆盖损坏数据、非法分数、未知关卡、章节扩展和存储读写失败。

浏览器验收脚本使用仓库的 Playwright 测试依赖与 Chromium，默认启动 `dist/` 服务。需先构建，并确保浏览器存在于 `/usr/bin/chromium`，或设置 `PLAYWRIGHT_EXECUTABLE_PATH`；可用 `GAME_URL` 指向已启动的服务。脚本通过可见控件完成六盒，并检查随机两面、展开后保留所有画面、免费展开、模拟宿主奖励结果、桌面拖轴、撤销、重来、键盘、存档，以及 390×844、320×640、844×390 触屏模拟下的拖拽、取消与控件尺寸。结果及截图生成到 `test-results/`，是否通过以实际报告为准。触屏模拟不是实机验收，尚未验证真实手机与移动 Safari；奖励测试使用模拟宿主，未验证真实广告平台或付费流程。

## 后续扩展

新增关卡只需在 [levels.mjs](levels.mjs) 追加一个对象，渲染与规则不按关卡编号分支：

| 字段                                  | 作用                                                                       |
| ------------------------------------- | -------------------------------------------------------------------------- |
| `id`、`number`、`title`、`intro`      | 稳定存档键、展示顺序与玩家引导                                             |
| `shafts`                              | 每根轴的 `id`、初始挡位、`min/max`、坐标、颜色，以及两面的作用说明         |
| `latches`                             | 锁住哪根轴、可操作的面、初始锁定状态；`releaseWhen` 指定关联轴可释放的挡位 |
| `gates`                               | 所属视图、连接的轴、允许球通过的挡位 `positions`、球道坐标                 |
| `path`                                | SVG 720×600 坐标空间中的连续球道点                                         |
| `checkpoints`                         | 按路径递增的 `pathIndex` 与对应 `gateIds`；最终检查点在终点且没有挡板      |
| `hints`、`solution`、`estimatedMoves` | 递进提示、兼容旧版翻面的可回放解法与旧版参考操作数                         |

同一轴可连接两面多道挡板，改变 `positions` 就能形成反向影响与分段冲突。条件锁只在松开时检查对齐条件，松开后另一根轴可以继续移动；重新扣紧会再次固定轴。`engine.mjs` 的 `validateLevel` 会检查引用、挡位、路径顺序与终点，规则测试会回放每关的解法。新增关卡应同时通过独立可解性搜索与浏览器可见操作，避免仅凭配置看起来合理。

继续扩展时优先设计新的因果组合与阶段次序，保持轴字母、挡位与锁扣条件清晰可见。所有交互应在盒内具有明确目标，避免用隐藏像素或难辨热区增加难度。
