## 1. 要验证的乐趣

玩家不是看家具自动飞：他亲手把气球绑到家具两端，放飞后通过左右排气改变倾斜和升降，让一架看似不可能通过的钢琴斜着穿过窗口，再落上软垫。

希望出现的瞬间：钢琴右角即将磕窗框，玩家按住左排气，左端下沉、琴身转斜，擦过窗框，落地时弹出三个不和谐的琴音。笑点来自玩家造成且能解释的结果。

首轮假设：有限资源的装配，加上可挽救的飞行操作，能形成“一次失误就知道下次改什么”的短循环。现在没有证据证明它足够好玩；机械验收通过，也不能代替真人重复玩的意愿。

## 2. 三个候选玩法与取舍

| 候选 | 玩家实际做什么 | 优点 | 风险与取舍 |
| --- | --- | --- | --- |
| **A：绑气球 + 左右排气，推荐** | 起飞前分配两端气球与长短绳；起飞后按住一侧气阀改变姿态，轮流排气降低高度 | 装配影响后续轨迹；飞行有连续直接操作；一根手指能完成；过窗是明确可见的目标 | 必须交代横向动力；单向排气的修正空间有限。首轮用可见固定侧风，必须验证“可救险”而非只能等失败 |
| B：纯装配，一键放飞 | 绑点、绳长、数量确定后，只观察并重试 | 输入少，可复现性最好，容易做成紧凑物理谜题 | 飞行阶段只是观看；很容易变成猜参数。舍弃为主玩法，只保留装配作为 A 的开局 |
| C：空中牵引，拖拉家具 | 放飞后手指拖牵引绳的端点，持续拉动物体 | 控制直接，救险容易理解 | 牵引力容易压过气球策略，退化成拖家具走迷宫；再叠加绳长、双手操作会增加负担。首版舍弃，不作为失败时偷偷加的兜底 |

推荐 A，不合并三套操控。若两轮讨论或可运行灰盒证明单向排气没有足够操作空间，应重新选择玩法，不能靠自动瞄准、吸附终点或增加装饰掩盖。

## 3. 推荐方案：玩家规则

### 3.1 装配只保留三个真实决策

1. **数量**：每关最多四只气球，左右各最多三只。装得少，上升慢、顶部空间充裕；装得多，上升快、救险余量大，但更容易撞上窗沿。关卡应容许不同组合，不以“只能四只才能动”冒充选择。
2. **分配**：家具只有左、右两个清晰绑环。将气球从底部托盘拖至绑环；也支持先点气球再点绑环。重心以家具上的实心圆标记，玩家不需要读力学公式。
3. **绳长**：每侧只能选择“短绳 / 长绳”，点击绑环旁的结扣切换，画面立即重排绳与气球。初始参数为短绳 0.35 m、长绳 0.80 m；同侧多球分开少量位置显示，不再引入逐根毫米调节。

准备时家具由地面支撑，气球保持待释放状态，不提前消耗飞行时间。可移回托盘、改长短绳；轻量显示上升趋势和重心，不显示会泄露答案的完整预测轨迹。

点击“起飞”同时释放气球。整个装配不是文字表单；一眼能看见绑在哪里、绳多长、还剩几只。

### 3.2 飞行只保留两只气阀

- 底部两个至少 64 CSS px 高的大按钮：“左排气”“右排气”，带气阀形状和对应绑环图标，不只靠颜色区分。
- 按住就让该侧所有气球的剩余气量按固定速率减少；松开立即停止排气，但家具因惯性继续运动。气量不可恢复，同侧不必精确点中小气球。
- 左侧排气会减少左侧拉力，通常使左端相对下沉；右侧同理。左右短按交替可降低总升力；单指足以完成所有关卡，不要求同时双按。
- 首个调参值：每秒减少该侧各球初始气量的 25%，最小气量为 0。一次 0.15～0.4 秒短按应可见地改变姿态，并保留再次修正的余量；这些是待验证参数，不是已测结论。
- 起飞后不能加球、换绑点、换绳长，也不能拖动物体。主操作空间来自可控的排气时机，不叠加剪绳、补气、风向按钮或技能条。
- 桌面用鼠标按住按钮，另提供 A / D 对应左右气阀；界面明确显示键位。

### 3.3 横移必须有真实来源

只有浮力和重力时，家具不会无故横穿窗口。本方案在房间左侧放一台可见风机，纸带指示风向，提供固定、可重放的向右风场。玩家控制高度和姿态以穿过这条横向路线。

风同时影响家具和气球，二者受风系数不同，气球会被吹偏，绳的方向因此会改变。风口范围和窗外衰减区由关卡世界坐标固定，按位置连续衰减，不随玩家表现改变。窗外有接货软垫平台，风不是传送带，也不保证自动到达平台。

第一版不做随机阵风。上楼关卡也通过明确的开口与风场完成升层，不凭空赋予水平速度，不追踪终点自动转向。

### 3.4 绳长为何不是装饰

绳必须是连接气球与家具局部绑点的受拉约束，能松弛、不推物体。短绳降低整个组合的高度，通常更容易过低窗；长绳让气球进入更高处的风区，改变拉力方向和摆动滞后，也可能更早撞到上沿。

明确承认：静止、无风、气球悬在正上方时，只改绳长不应神奇改变最终净浮力。如果实现成“长绳额外加升力”或者气球只随家具贴图运动，就违背了本方案。

首版必须出现至少一个实测局面：绑点、气量、操作时刻完全一致，只换绳长就出现不同的碰撞或通过结果。若只能看出绳画得不同，绳长机制判失败。

## 4. 一次约 30 秒的实操

以首次玩沙发关为例；这是预期节奏，尚未实测。

| 时间 | 手指动作 | 屏幕发生什么 |
| --- | --- | --- |
| 0～3 秒 | 看见沙发、窗与接货垫，点击开始 | 只显示一句“把沙发送到黄垫上”，左侧纸带向右飘 |
| 3～9 秒 | 拖三只气球到两端，让偏重的一端多一只 | 绑环吸附反馈、绳立即连上、重心点保持可见 |
| 9～11 秒 | 点“起飞” | 气球先绷紧绳，沙发开始抬起；画面反馈没有倒计时弹窗 |
| 11～17 秒 | 看右端接近窗沿，短按对应气阀 | 气球缩小、发出嘶声，沙发角度逐步改变并过窗 |
| 17～24 秒 | 左右交替短按 | 升力下降，沙发落向软垫；操作太晚会越过平台 |
| 24～30 秒 | 松手落稳；点“再搬一次”或下一关 | 软垫压缩回弹，显示“送达！”与气球用量、碰撞次数 |

正常完成目标 30～75 秒；高阶关含一次重试可到两分钟。没有独立三分钟教程，没有“打开配置页 → 确认方案 → 看结果”流程。

## 5. 重复玩靠什么

- **起飞前取舍**：三只慢升 vs 四只快升；偏重端多绑一只 vs 两端均衡后靠操作补偿；短绳压低轮廓 vs 长绳借高处侧风。每个取舍都必须在位置、姿态或资源余量上留下差异。
- **飞行中的决定**：提前排气获得穿窗角度，还是先攒高度再转身；过窗后何时把“抬升”变成“落地”；碰擦之后是否还留有另一侧气量修正。
- **局后目标**：先送达，再尝试少用一只球、少一次碰撞。只记录三个事实：是否送达、使用几只球、碰撞次数。没有任意综合分，也不把等待时间包装成深度。
- **快速迭代**：重试保留刚才的装配、恢复全部气量。失败后两次点击以内重新起飞；准备时可显示上次首次碰撞处的一小段灰色轮廓，不做完整录像编辑器。
- **边界**：五个手工关支持掌握与优化，不声称无限耐玩；不做无穷随机关、每日任务、排行榜或成长数值。

必须拿一个关卡证明“两个不同装配都能成功，但需要不同排气时序”。如果只有一个组合可过，首版更像一次性的物理解题，需要在下一轮正面取舍，不能宣称有丰富策略。

## 6. 失败与反馈

轻碰不立即判死：家具被碰撞响应挡住或转动，发出木头、金属、琴弦各自的短音；碰撞角高亮约 0.35 秒。一秒内连续接触同一面只算一次碰撞，避免搁在墙边疯狂扣数。

直接失败仅包括：家具离开救援边界、硬碰撞超过明确阈值、或实际飞行满 60 秒仍未送达。首次卡住约三秒时提示“被窗沿挡住了，可以排气或重来”，不自动按失败处理。重来按钮全程可用。

硬碰撞使用家具接触点的法向相对速度判断，包含转动速度；初始待调阈值 2.6 m/s。不能用总速度判断侧面轻擦，也不能硬编码“这一关碰到这里必碎”。

失败镜头先留出约 0.6 秒展示具体碰撞，再给出事实型原因：“右上角撞到窗框”“气不够，落回地板”“飞过接货垫”。只有可确认的事件才写成因果；不输出假装智能分析的建议。

声音和动画属于核心反馈：绑绳“嗒”、风机低声、持续排气嘶声、材料碰撞、软垫回弹、钢琴轻碰时错音。首次用户操作后启用 Web Audio，提供静音；音频不可用仍保留可见反馈。减少动态效果设置只去掉晃镜与纸屑，不隐藏物理运动。

## 7. 五个教学 / 变体关卡

全部使用同一物理规则，不靠每关改重力或隐藏操控。尺寸与风力在灰盒阶段调整，以下是设计目标而非已证明的关卡。

| 关卡 | 家具 / 场景 | 唯一新教学点 | 决策与完成条件 |
| --- | --- | --- | --- |
| 1. 沙发先走 | 重心略偏右的矮沙发；高且宽的窗；宽接货垫 | 拖气球、按住排气、落稳 | 三球慢升或四球快升都应可过；首次简单提示指向偏重端，随后消失 |
| 2. 冰箱歪一下 | 高冰箱；开口略低于冰箱直立高度，但斜放可过 | 左右浮力不等会旋转；碰撞有真实转动 | 保持直立无法通过，先倾斜再在窗外恢复；必须在窗口前给足操作空间 |
| 3. 绳子太长了 | 同一矮沙发；低窗，上方是实心窗梁 | 气球也有体积；绳长改变总轮廓与运动 | 相同操作，长绳组会被梁阻挡；短绳组可过。不是检测绳长标签后直接判胜负 |
| 4. 钢琴，请侧身 | 长钢琴；明显偏一侧的重心；窗框与外侧雨棚形成错位开口 | 非对称装配 + 飞行中救险 | 对称绑法容易碰框，但应能被熟练操作救回；偏重端多绑可减少修正。至少两种可成功装配 |
| 5. 搬上二楼 | 同一钢琴；挑空室内，上层右侧接货垫、外侧无底护栏 | 先升高后横移，最后排气着陆 | 可见低处弱风、高处强风；过早排气够不到上层，过晚排气撞梁或错过垫；完成仍按同一落稳规则 |

每关实际飞行控制在约 15～45 秒。最后一关不是额外开发一套楼梯系统：只用现有关卡的静态矩形、风区与接货平台。五关之外不扩内容，先确认钢琴关是否成立。

## 8. 最小技术边界与物理方案

### 8.1 独立运行边界

后续拟采用零依赖原生 HTML / CSS / ES modules / Canvas 2D；中文 DOM 操作按钮覆盖在 Canvas 下方，兼顾清晰命中区与键盘操作。画面采用纵向房屋剖面，桌面保留居中游戏区，宽屏只扩背景，不改变世界坐标。

拟控制在六个运行/检查文件：`index.html`、`style.css`、`game.mjs`、`physics.mjs`、`server.mjs`、`check.mjs`。手工关卡数据先直接放在 game.mjs，不创建实体系统、插件框架、构建链或通用关卡编辑器。图形由 Canvas / SVG 基础形状组合，声音由 Web Audio 合成，字体走系统字体；可单独复制目录运行。

server.mjs 用 Node 内置 http/fs/path，只服务本目录，处理 MIME 和 URL 路径校验；默认端口 4401，端口被占用时明确报错。不能借用兄弟目录的 node_modules 或服务器。首版没有广告、支付、平台 SDK、账户或联网存档。

### 8.2 足够小、但不是假物理

- 只允许一件家具：一个带质量、转动惯量和偏移重心的二维矩形刚体。钢琴美术包络与碰撞矩形一致；不画出可以穿墙的长琴腿。
- 至多四只气球：有有限质量的圆形粒子，浮力随剩余气量减少；视觉半径按体积关系缩小。气球之间不互撞，绳之间不互撞；用托盘挂点微偏移保证可辨。
- 每根绳为一个只承受拉力的最大距离约束，家具端在局部坐标绑环上；纠正约束时同时改变家具的位置和角度。气球若受梁阻挡，绳允许变松，不能继续隔空拉升家具。
- 环境只用轴对齐静态矩形。家具用定向矩形对矩形的窄相碰撞，法向冲量作用于接触点并带动旋转；气球圆与同一环境碰撞。摩擦、阻尼、回弹为所有关卡共用的常量。
- 初始数值采用米、千克、秒：重力 9.8 m/s²，球质量为家具参考质量的 2%，每只满气球的浮力约为参考家具重量的 36%。三球应略能起飞、四球明显上升；最终以包含球重与碰撞损耗的实测为准。
- `ponytail:` 已知简化上限：一件矩形家具、四球、矩形场景，不支持凹家具、多件堆叠、绳绕柱。美术不得超出碰撞表达。若后来必须加入这些情形，重新评估成熟物理库，不逐步拼通用引擎。

绳不能穿窗框成为捷径。首版不模拟真实绕柱：若绳段横穿实心障碍，该段被切断并给出摩擦断绳动画和声音；这条规则对所有关卡相同、界面提前说明，不能静默把绳拉长穿墙。首先靠开阔布局避免频繁依赖此规则；若日常过窗就频繁断绳，视为布局/物理方案失败。

### 8.3 可复现与输入链路

输入流程固定为：Pointer Events / 键盘 → 记录目标物理帧的按下/松开 → 固定步长更新气量与受力 → 求解绳与碰撞 → 判断送达/失败 → 渲染和声音。检查脚本与浏览器直接导入同一个 physics.mjs，不另写一个“容易通过测试”的模拟器。

使用 1/120 秒固定物理步长、固定求解轮次和稳定对象顺序，requestAnimationFrame 只驱动累积时间与绘制。所有影响物理的初始状态、气量和风场来自关卡数据；不调用 Math.random 决定运动。渲染特效不回写物理。

事件落到下一物理帧并记录 tick，不以显示帧数计排气。长时间切后台时暂停并清掉按钮按住状态；恢复时不补算几秒的飞行。Pointer capture、pointercancel、失焦与抬手移出按钮都必须释放气阀，支持高 DPR 和 CSS 缩放后的正确坐标。

这里承诺的是相同版本、相同关卡和逐帧输入的可重放。相同 JS 运行环境应产生相同状态摘要；不同浏览器先按 0.005 m / 0.5° 容差验证，不能预先声称跨引擎逐位一致。

### 8.4 送达规则

家具在软垫的有效水平范围内，整个家具水平投影不越出两端；家具底部与平台顶面存在支撑接触；速度小于 0.15 m/s、角速度小于 0.15 rad/s、相对水平角不超过 12°，连续保持 0.6 秒才算送达。仅穿过窗口、中心点飞进目标框或擦到软垫不能赢。

平台提供真实摩擦与支撑，剩余浮力太大就仍会浮起。没有靠近终点自动减速、瞬移、扶正或落点吸附。

## 9. 最危险的假玩法与技术问题

| 风险 | 识别方法 | 首版处理 / 否决条件 |
| --- | --- | --- |
| 装配是装饰，任何组合轨迹差不多 | 固定气阀输入，只改变一个绑点，比较 2 秒后的姿态与首次碰撞 | 至少一关换侧后结果发生实质变化；否则不进入美术完善 |
| 绳长只是线条长度 | 同初态同输入，换长短绳；同时做无风静态对照 | 有障碍/侧风时出现可解释差异；无风静态时不能虚增浮力 |
| 起飞后只剩观看 | 同一装配比较“不操作”“明确错误操作”“合理救险” | 三者应产生不同结果；钢琴关需出现可重复的失败→救回，否则重选控制方案 |
| 单向排气太苛刻 | 把成功输入的关键时机前后移动 0.15 秒 | 至少有一套通关方案在两侧偏移后仍成功，不能只靠逐帧背答案；若始终不可救，不能偷偷自动补气 |
| 绳弹簧爆炸 / 碰撞穿透 | 满气、偏绑、长绳、持续贴窗梁运行；记录有限值与最大穿透 | 无 NaN、无速度突然爆增；最大持续穿透超过 0.01 m 或可挤过实墙，阻断发布 |
| 几何上根本无法通过 | 检查旋转家具角点、气球外轮廓与窗口净空；再跑完整操作 | 每关用相同运行代码生成可复现成功输入，不只证明家具中心可以通过 |
| 绳穿墙、约束和断绳互相打架 | 气球与家具分处墙两侧的刻意坏例 | 必须触发公开规则并能解释；普通过窗频繁误断则改布局或物理 |
| 手机手指遮住玩法、按住状态卡住 | 窄屏单指完整玩；按钮外抬起、系统中断后返回 | 气阀在底部安全区；触点状态可见；中断后没有继续偷偷漏气 |
| 开发通过等于好玩 | 观察目标用户，不向其解释哪儿有趣 | 机械检查与真人体验分别记录；效果图和自动脚本不能当作好玩证据 |

第一技术验证优先级：一件矩形家具、两个绑环、三个气球、一个窗框、一块软垫，验证真实受力与救险。核心不成立就停下讨论，不能先做五个空壳关卡。

## 10. 后续具体可运行的验收方式

以下是实施后的执行契约；本轮未创建这些程序，未执行任何玩法测试，表内不存在“已通过”结论。

### 10.1 独立启动

在 `F:\playground\playground-ai\prototypes\balloon-movers` 运行：

```powershell
node server.mjs --port 4401
```

访问 `http://localhost:4401`，关闭网络外部访问后仍可玩。复制本目录到空位置后，同一命令可启动，证明没有兄弟目录依赖。服务器只需支持原型静态文件，不添加后端产品功能。

### 10.2 一个 Node 内置 assert 检查脚本

```powershell
node check.mjs
```

check.mjs 用固定关卡数据、固定装配与逐帧输入脚本，失败时非零退出，输出每项的实际数值与最终状态。只维护这一份有意义的检查，不引入测试框架或每函数测试套件。

| 检查 | 通过标准 |
| --- | --- |
| 同步重放 | 同一输入连续跑 10 次，最终状态摘要完全一致；气量、首次碰撞 tick 和胜负一致 |
| 帧率无关 | 用 30 / 60 / 120 Hz 显示帧及抖动帧调度相同物理 tick 输入；同 tick 的状态一致；跳后台用暂停规则单独检验 |
| 绑点有效 | 用同球数、同气量、同输入，只换一只球左右绑点；2 秒时角度差至少 8°，并记录方向符合力矩来源 |
| 绳长有效 | 一个无风对照不能因绳长获得额外净浮力；一个窗梁用例只改绳长即改变碰撞/通过结果 |
| 操作救险 | 钢琴同一装配，不操作失败，预先记录的合理排气成功；成功时机前后各偏移 0.15 秒至少有一套仍成功 |
| 两种策略 | 同一钢琴关至少两种不同装配分别有成功输入；交换它们的输入至少有一组结果变差，证明时序与装配相互关联 |
| 几何与稳定 | 5 分钟固定步长压力用例无非有限状态；绳张紧误差与持续穿透各不超过 0.01 m；完全穿墙为失败 |
| 关卡可解 | 五关各有一条可重放完成输入；通过均满足同一支撑、位置、速度、角度和持续时间条件 |

这些阈值为首轮提出的可证伪门槛。若需修订，要说明实际原因，不能在失败后降低阈值却仍标记原门槛通过。脚本在真实 physics.mjs 存在后编写，不伪造通过报告。

### 10.3 实际浏览器完整流程

使用 390×844、360×640、桌面 1280×800 三种视口，从进入游戏、绑球、改绳、起飞、排气、失败、重试到送达连续走通；窄屏 UI 不压住家具路线，按钮至少 48×48 CSS px，带键盘焦点与文字标签。

必要记录包括：钢琴成功穿窗的实机渲染录像或关键连续截图、错误操作失败对照、三种视口的输入命中、pointercancel 与切后台恢复、首次用户手势解锁音频、静音开关、同一输入重放结果、浏览器控制台无错误。自动化可用环境已有浏览器工具，不给项目新增运行依赖。

手机浏览器模拟与物理手机分别报告。未用真实手机就明确标记触控手感和音频实机体验待验收。若提供“全屏”按钮必须调用真实 Fullscreen API 并检验退出后继续游戏；API 不可用则不冒充全屏，首版可只提供浏览器内自适应界面。

### 10.4 好玩与可理解的人工门槛

找至少三位未读设计文档的人，每人试玩三分钟，开发者不口头报答案。记录是否在 20 秒内开始绑球、是否知道排气会影响哪一端、失败后能否指出一个原因，以及是否愿意主动再试一次。目标是至少两人无需解释完成首关并能说出一个有效改法；这是小样本筛查，不是市场验证。

若没有这些玩家，只能交付“可玩、机制已验”的原型，不声称已验证受欢迎。用户当前明确不要求付费、广告、SDK 或上线分发，因此不把这些放入验收。

## 11. 差异化美术方向

### 推荐：老小区剖面 × 玩具搬家公司

场景像一栋被剖开的旧式居民楼：奶油色水磨石地面、粉灰窗框、墨绿门框、晾衣绳、暖黄色搬家纸箱。物体用厚实圆角、少量平涂明暗、细深色轮廓，气球用朱红与青绿两侧标记；左右另有圆点/条纹绑环图标，避免只认颜色。

钢琴是夸张的大黑木箱，露出象牙白琴键与金色脚轮，沉重家具与轻盈气球形成反差。人只在安全区以拇指大小的纸片搬运工做表情，不挤占操控区。半透明拖影只用于碰撞提示，物理轮廓必须清晰。

飞行中画面主体是家具、绳、气球、窗框和接货垫。标题、选关、说明留在准备/结算，不在飞行时摆满指标。气球鼓缩、绳绷紧、木家具轻颤与软垫回弹都依据实际状态驱动。

差异点不是霓虹仪表盘或软萌统一贴纸，而是“真实生活物件被一套荒唐但讲道理的搬运办法送出窗口”。传播画面应让人立刻知道哪里险、玩家刚做了什么。

### 备选：搬家说明书活了

米白纸底、钴蓝工程线、橙色气球，家具像从旧搬家手册里抠出来的平面图。绳、重心、风向很易读，资产成本低；但喜剧感弱，容易显得像物理作业。若灰盒认知负担太高可转此方向，当前不与老小区风格混搭。
