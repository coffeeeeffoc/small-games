# Out of Frame · 框外静止

一个关于「选择让谁继续运动」的单屏平台解谜游戏。包含十章、一百个可自由选择的房间，以巡逻机器人、沿路径移动的平台、压力开关和门组合出逐步提高难度的挑战。全场始终可见；固定大小的观察框分配局部时间。

## 启动与构建

在仓库根目录运行：

```sh
pnpm --filter @coffeeeeffoc/out-of-frame dev
pnpm --filter @coffeeeeffoc/out-of-frame test
pnpm --filter @coffeeeeffoc/out-of-frame test:browser
pnpm --filter @coffeeeeffoc/out-of-frame build
```

开发地址为 `http://localhost:4417/`。构建产物位于本目录 `dist/`，可直接作为静态站点发布；使用相对资源地址，支持目录与 iframe 载入。`node server.mjs --dist --port 4417` 可预览构建结果。游戏已接入仓库 Shell 游戏目录。

浏览器测试会自动启动本地服务器；也可用 `GAME_URL=http://localhost:4417/` 指向已运行的源码或构建预览。它使用工作区 Playwright，优先选择 `/usr/bin/chromium`；其他环境可设置 `BROWSER_EXECUTABLE` 或安装 Playwright Chromium。报告和截图写到仓库根目录 `.scratch/out-of-frame/`，不随游戏发布。

## 规则与操作

- 只有带菱形核心的机器人和平台受观察框控制。**核心点在框内（含边界）就运动，框外就精确冻结。** 物体部分越界不决定状态。
- 玩家始终可以移动和跳跃。被冻结的机器保留实体碰撞，可当作台阶或持续压住开关；运动中的平台能载人。
- 开关接受玩家和机械的重量，门需要对应的所有开关同时被压住。退出观察框不会撤销已经压住的开关。
- 拖动框内或边缘移动观察框，点击框外将框中心放到点击处。`I J K L` 也能移动框。
- 拖框时显示机械核心和压力开关范围，画面下方即时显示运动、冻结与压住的开关数量。
- `A D` / 左右方向键移动，空格 / `W` / 上方向键跳跃；触屏使用底部方向与跳跃按钮，支持同时按住方向和跳跃，以及另一只手拖框。
- `Z` 或回退按钮免费回退约一秒，恢复角色、机械、开关及观察框；记录保留到本关开始。坠落后仍可回退。`R` 重开，`Esc` 暂停。
- 打开说明、切后台或窗口失焦会暂停并清理按住的输入，继续按钮恢复游戏。横屏的暂停菜单也提供说明与选关。
- 主界面与暂停菜单按章选关，每章显示十个房间，标明完成状态、最佳时间及章节进度；完成后可直接进入下一关。

本地保存各关最佳完成时间、声音偏好、当前房间及进行中的局面。每两秒以及暂停、返回首页、离开页面时保存；刷新后点击「继续」恢复角色、机械、观察框、用时及最近的回退记录。旧版六关成绩使用稳定关卡 ID 迁移，损坏的局面会忽略，存储被禁用时仍可正常游玩。音效由 Web Audio 合成，默认关闭，无运行时外部素材请求。

## 一百关的递进

| 关卡范围 | 挑战重点                                             |
| -------- | ---------------------------------------------------- |
| 01–10    | 单机械定格、凝固台阶、横渡平台，最后组合开关和渡台   |
| 11–20    | 分别冻结两位守门人，处理不同位置的开关与地形         |
| 21–30    | 三开关阶梯回路，逐级接通三道门                       |
| 31–40    | 两岸开关与升降台，组合定位和连续跳跃                 |
| 41–50    | 双开关与折线路径渡船，学习用框边界隔离机械           |
| 51–60    | 两个平台之间转乘，在逐渐收窄的中间岛上重新安排观察框 |
| 61–70    | 三开关回路与远航渡船，保住开关并跨越长缺口           |
| 71–80    | 平台转乘与垂直隔离，避免唤醒已经定格的多位守门人     |
| 81–100   | 多层守门人与平台综合调度，完成多开关终局             |

原六关保留稳定 ID；综合关「一个框，两件事」「排练双重定格」「世界为你停一拍」移至递进结构中适合的位置。难度通过机关组合、地形、转乘步骤和有效定位范围提高。关卡难度值表示探索顺序；实际解谜难度仍需持续根据玩家反馈调整。参考路线只证明可达，不代表玩家实际解谜时长。

## 扩展关卡

`levels.mjs` 是唯一关卡数据入口，导出 `LEVELS` 和十章的 `CHAPTERS`。导航、目标、提示、进度和房间编号均从数据生成。增加房间时保留旧关卡的稳定 `id`，添加下面的数据并补充可通过真实控制完成的参考路线：

| 字段                                                                   | 约定                                                                            |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `id / number / kicker / title / goal / hint`                           | 稳定存档 ID、显示文案和逐条展开的提示                                           |
| `chapterId / chapterNumber / chapterTitle / chapterLevel / difficulty` | 所属章节、章内顺序与探索难度顺序                                                |
| `spawn / frame`                                                        | 玩家与固定尺寸观察框的初始左上角                                                |
| `solids`                                                               | 静态碰撞矩形，使用 `x / y / w / h`                                              |
| `objects`                                                              | 动态物体；`kind` 为 `robot` 或 `platform`，包含稳定 `id`、矩形、`speed`、`path` |
| `path`                                                                 | 世界坐标中的左上角折线节点，抵达终点后沿路径折返，第一点应与初始位置一致        |
| `switches`                                                             | 开关矩形；底部与地面齐平，中心落在开关范围内且脚底接触才触发                    |
| `gates`                                                                | 门矩形及 `requires` 开关 ID 数组，全部压住才打开                                |
| `exit`                                                                 | 出口触发矩形；所有门打开且玩家接触出口即完成                                    |
| `hazards`（可选）                                                      | 失败区域矩形；现有关卡以坠落作为失败条件                                        |

世界坐标为 `960 × 540`，观察框为 `340 × 270`。界面缩放不改变模拟尺度。`engine.mjs` 不依赖 DOM，以固定 `1/60` 秒步长模拟；`render.mjs` 只负责显示；`game.mjs` 负责输入、回退、界面和生命周期。新物体类型应明确共享的核心点观察判定、冻结碰撞、载人和开关规则，再扩展引擎与绘制分支。

`tests/solutions.mjs` 用 `watch / frame / walk / jump / ride / wait` 等真实控制动作描述解法。规则测试用它证明全部一百关可达，并检查重复执行的确定性和额外操作延迟；浏览器测试把相同动作转换成真实键盘和鼠标输入，并仅用只读快照等待条件。增加关卡时应同步增加参考路线及其门开关组合断言。

## 设计来源与范围

本实现采用始终可见的舞台、局部时间选择框和核心点判定，以机器人、开关、平台的组合关系组织原创房间。界面、角色、场景均使用自行编写的 CSS / Canvas 绘制，没有使用示意图的素材或复刻其摄影界面。

「观察影响状态」属于已有解谜机制方向；这里不主张机制首创，也未做商业作品的完整相似性或权利检索。后续商业化前仍应比较具体关卡解法、角色与视觉表达。首版没有接入门户广告、支付、Steam 或第三方平台 SDK。

## 验证

规则测试覆盖观察边界、精确冻结、机器人与平台碰撞、移动平台载人、开关组合、回退快照与一百关可达性；持久化测试覆盖旧版成绩迁移、损坏和禁用存储、非法时间与过期关卡过滤、局面恢复、回退记录、存储配额错误。

Chromium 浏览器回归覆盖桌面一百关真实键鼠通关，以及 `390 × 844`、`360 × 640` 的真实触摸事件：拖框、冻结压开关、双触点移动跳跃与同时拖框、快速点击跳跃、触摸取消、暂停/说明、回退/重试、章节选关、最佳成绩保留和刷新后续玩，并检查横竖屏溢出和画面比例。失焦输入清理使用合成 `window.blur` 事件验证处理器，因为无头 Chromium 切换页面不能稳定产生原生失焦事件。手机环境为浏览器设备模拟，不等同于物理手机验收；最终执行结果以 `.scratch/out-of-frame/browser-report.json` 为准。
