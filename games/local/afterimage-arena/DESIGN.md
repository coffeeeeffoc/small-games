## 1. 项目边界与本轮判断

- 独立目录：`F:\playground\playground-ai\prototypes\afterimage-arena`。不改根目录、兄弟项目、games1–8；不提交、不推送、不创建 agent。
- 面向 16–35 岁玩家，先做中文 UI、手机触控与桌面均可玩的 Web 原型；Steam 是方向，本轮不做打包承诺。
- 核心承诺：每 20 秒游戏时间重置战场；最多三个过去的自己重演玩家真实操作，玩家始终控制现在的自己。过去的行动必须改变当下的战斗结果。
- 目标首次体验 3–5 分钟。优先验证“我录下的动作帮到了现在的我”，不做广告、支付、平台 SDK、联机、装备树、程序生成或长线养成。
- 推荐一句话：**把破盾动作留给过去的自己，自己绕到另一侧打入核心。**

本轮采用 brainstorming 的候选比较与逐轮收敛方法；按用户明确要求，只写此文件、等待挑战，不采用 skill 中另建计划目录及提交 Git 的步骤。

## 3. 推荐规则：交叉火线

### 空间、输入与攻击

- 单个固定俯视竞技场，逻辑尺寸 720×880；Boss 固定在 `(360, 400)`，碰撞圆禁止玩家中心进入半径 140。没有随机墙、移动平台、身体碰撞或击退。
- 玩家移动速度初值 180 逻辑单位/秒。桌面 WASD/方向键移动，空格或鼠标主键按住开火；手机左侧拖动摇杆、右侧大按钮按住开火。两根手指即可同时移动射击。
- 子弹固定朝 Boss 中心，必须有真实开火输入才发射，射击间隔 0.25 秒。不加瞄准杆、技能轮盘或冲刺；走位决定攻击从哪个方向进入。这是公开的自动瞄准规则，残影不会自己改目标或补操作。
- 射击以发射瞬间的射线判定，曳光约 0.1 秒只承担视觉表现。残影不挡子弹，不挡路。
- Boss 周围有数个宽 30° 的有效射界，带大图形标识。由玩家**实际所在方向**决定命中哪个封印或核心；站错方向的射击撞在装甲上，产生钝响及火花。

### 破盾与核心

- 从对应方向命中封印，使其点亮 0.60 秒；重复命中刷新时间。不是踩在地板上自动触发。
- 仅在全部封印同时点亮，且 Boss 处于 `6–8 秒`或`14–16 秒`的核心窗口时，从核心方向发射的子弹才能造成伤害。一个有效核心命中造成 1 点伤害。
- 封印不永久损坏，不累积跨轮进度；窗口外可以练习点亮，但不能伤害核心。核心开合有明确轮廓、倒计时环及声音提示。
- 第一关是一枚西侧封印＋东侧核心；第二关是西、东两枚封印＋南侧核心；第三关是西、北、东三枚封印＋南侧核心。
- 相邻有效射界的最小角间距为 60°。按半径 140 与速度 180，绕行至少约 0.81 秒，超过 0.60 秒封印持续时间。没有加速或远程延时弹，因此一个角色不能在封印仍亮着时跑到相邻射界承担第二个角色。后续测试必须实际检查此边界，不以公式替代模拟。
- 第三关需要四个同时有效的射击角色：三个残影提供封印，当前玩家补第四个方向。只有三个残影时不能打伤核心，避免玩家录完就看自动通关。

### Boss 攻击与血量

- 初值：玩家 3 格生命；受到伤害扣 1 格，并有 0.6 秒受击保护。受击不会击退、减速或取消射击，避免悄悄改变旧轨迹。
- Boss 发出有约 0.9 秒预警的细射线和横扫。窗口中的细射线覆盖射界中线，玩家可以在同一射界内横向躲避并继续开火；非窗口横扫要求离开原位、再返回。
- 初始编排以第 3、7、10、15、18 秒为攻击节点；具体角度、宽度与持续时间在原型中通过可执行路线验证。攻击由轮内时刻决定，不追踪最近角色，不因封印开启而取消，也不因多出残影而增强。
- 核心血量初值为 10 / 12 / 14。每个窗口最多约 8 发，要求至少利用两个窗口，避免一开盾便秒杀。能否兼顾躲避与足够命中仍待原型验证。
- 除胜利终止外，Boss 的攻击时序、地图及出生点始终相同。这样第二轮的变化来自玩家多出来的历史行动，而非暗改敌人行为。

### 重置、记录与失败

- 每轮 1,200 个 60 Hz 模拟 tick，满 20 秒恢复地图、Boss 全血、角色全血、所有封印及攻击时间表；仅保留本关最近的操作记录。
- 第一、二、三关分别保留最多 1 / 2 / 3 段记录，逐步教学。每到轮末，当前这段成为残影；超过上限时丢弃最旧段。下一轮将消失的记录提前以“下一轮替换①”标出，编号随记录保留，不随槽位改名。
- 轮末约 0.45 秒闪回动画随后继续；不弹配置表，不让玩家逐条编程。上一段的出生、移动、开枪和受击都会按其原时刻重演。
- 当前玩家死亡：立即暂停，显示致命射线及“你在 7.2 秒进入预警线”，可点“重试本轮”。丢弃本次未完成记录、保留已有残影，避免强迫旁观十几秒。
- “重试本轮”也可主动使用：恢复本轮起点，已有记录不变。普通超时则按正常记录及替换规则推进。
- 胜利立即结束本关；下一关清空记录，开始新的布局。没有跨布局硬套历史输入的行为。
- 切后台、失焦或暂停时停止游戏时钟；恢复前松开所有输入，倒计时确认后继续。20 秒指有效模拟时间，不能后台超时或回来后瞬间死亡。

## 4. 前 30 秒：真实操作脚本

计时从进入第一关开始，不以说明页充数。以下是一条示范路线，不是游戏偷偷替玩家执行的脚本。

| 时间 | 玩家操作 | 可见结果与理解 |
| --- | --- | --- |
| 0–3 秒 | 从南侧出生点拖摇杆向西；按住开火 | 装甲撞击与西侧封印亮起形成差别；一行提示“这一轮，给下一个自己留下破盾火力” |
| 3–6 秒 | 避开带地面预警的扫线，回到西侧射界 | 移动立即生效；封印断火后熄灭，继续射击后重新亮起 |
| 6–8 秒 | 持续射击，并横向避开射界中线的细射线 | 东侧核心展开，连线标明“另一侧可命中”；尚无伤害也有明确原因 |
| 8–14 秒 | 躲开第二次横扫，返回西侧 | 边缘时间环预告下一窗口，不要求记住说明文字 |
| 14–16 秒 | 再次在西侧开火、侧移躲避 | 第二段破盾行动被记录；记录轨上出现真实开火区段 |
| 16–20 秒 | 继续避开终场射线 | “即将回溯”响起，自己的运动尾迹在收束中转为①号残影 |
| 20–24 秒 | 新一轮移动到东侧；看①沿刚才的路线走向西边 | 能辨认这是自己的旧动作，轨迹不由 AI 生成 |
| 24–28 秒 | 等预警环收束时在东侧按住开火并走位 | ①点亮西封印，自己打入核心；Boss 首次扣血，封印—核心出现短促因果连线 |
| 28–30 秒 | 避开横扫，准备第二窗口 | 玩家知道下次该复现西侧支援还是修正当前东侧输出，而非只等动画 |

关键风险：首次真正协作要等 20 秒。首轮必须已有可操作的射击、躲避、封印反馈；如果首测玩家仍说“前 20 秒在等”，本方案需要重做入口，不能用虚假预录残影伪装首次合作。

| 3. 四人一瞬｜“过去破盾，现在终结” | 读三条轨迹，补齐缺失方向，理解最旧记录会被替换 | 第 4 轮，3 残影＋本人 | 三枚封印，14 血；两窗口都要利用，固定时间的横扫检验回位路线 |

计划规模是 2＋3＋4 个 20 秒轮次，完整走满约 180 秒；最后一轮提前击杀会缩短到约 165 秒有效操作。首次理解与少量失败将目标体验带到 3–5 分钟；熟练玩家可能更快，不加入强制等待凑时长。实际首次用时必须试玩测量。

三关结束给出“再打一局”和“重试本关”，不追加第四套机制。后续若核心成立，可研究镜像射界作为变体；第一轮不承诺无限随机关卡。

## 6. 可以反复做的决定与反馈

- **路线与半径：**贴近 Boss 换边更快但角度误差更敏感；远一点更容易留在射界内，但绕行更长。记录实际运动，差异会在未来保留。
- **输出与存活：**窗口内维持火力并侧移，还是先离开射界避险？一段满是输出但在下一轮无法接上的记录，并不等于好记录。
- **录哪个方向：**自己的下一段要补当前缺口，还是先修好将被覆盖的支援？三条记录各自保留方向与时间信息，没有固定要求必须西→北→东录制。
- **重试还是继续录：**失败来自当前操作就重试本轮；失败来自旧段错过窗口就进入下一轮修正历史。没有购买容错或随机数值补偿。

失败反馈必须说清因果：

1. 打到硬装甲：钝声、灰火花，命中点附近短字“射界不对”。
2. 正对核心却没破盾：缺失封印描边闪一下，短字“缺少北侧火力”；不把长教程盖在角色上。
3. 封印亮了但窗口关闭：核心显示下一次展开倒计时，而非毫无反馈。
4. 轮末未击杀：最多显示一条主要原因及窗口记录，例如“14 秒窗口：北印中断 0.8 秒”，来自实际封印状态统计，不能写固定安慰文案。
5. 死亡：冻结致命预警形状、定位发生时刻，明确“重试本轮”保留哪些记录。

回玩来自行动质量和组合的修正，不来自刷数值。若同一套按住开火不移动就能过关，说明动作层失败；若改变旧行动不改变成败，说明时间协作失败。

## 7. 残影可读性与界面

- 当前角色为实心白色，带“现在”小标；历史①青色圆环、②琥珀三角、③紫色方框。编号、轮廓与颜色共同区分，色觉差异下仍可辨认。
- 常态只显示各残影最近约 1 秒的细尾迹，以及未来 0.8 秒的淡虚线预告。预告严格来自已录制输入的演算；不常驻整场蜘蛛网。
- 封印受某个残影射击时，短线标出其编号；正在贡献的记录条亮起。玩家能回答“哪个我打开了哪块盾”。
- 顶部仅放 Boss 血条、20 秒计时、生命；底部是操作区与三条简洁记录轨。战斗中不放关卡目录、升级、解释面板。
- 死亡或暂停后可以单独高亮一段旧记录及其完整路径，提供复盘，不播放另一套模拟规则。
- 手机基线按 390×844 竖屏规划，兼顾 360×740 与 844×390。画面等比适配，触控区最小 48 CSS 像素，照顾安全区；旋转后重新换算坐标。横屏调整 HUD 位置，不改变世界速度或射界。
- 使用 Pointer Events 与 pointerId 区分双指；pointercancel、失焦、旋转必须释放按键，不能自动连射或卡住移动。

## 8. 差异化美术、动画与声音

**主方向：黑纸上的长曝光机械剧场。**背景是近黑蓝的哑光刻度盘；Boss 像悬浮机械快门，装甲用切开的同心环组成；玩家是有明确朝向的小型发光梭形体。长曝光只用于过去的运动线，当前玩家保持最锐利、最实的边缘。避免通用像素地牢和满屏霓虹粒子。

- 回溯：时间环在约 0.45 秒内逆向收束，旧玩家分离成编号残影，新玩家在出生点聚实；缩放和闪烁保持克制。
- 封印：射击命中时机械叶片转开，断火时按剩余 0.60 秒缓慢合拢；核心展开露出暖白光，给玩家可观察的窗口。
- 命中：当前武器有短促后坐，Boss 有局部压缩/裂纹，扣血以核心闪光与清脆声确认；提供减弱震动/闪烁选项。
- 声音：首次用户手势启用 Web Audio；开火轻短音、装甲低钝音、封印三种不同音高、有效核心命中清亮重音、倒数脉冲与回溯降调。四人射击时限制同时发声数和总音量，默认不叠加背景音乐。
- Canvas 几何、渐变、尾迹即可实现此美术；效果图不成为运行所需资源，也不以生成图片替代游戏对象与动画。

备选方向是“米白工程纸＋朱红时间印章”，更清楚但战斗张力较弱。只在主方向的低亮度/手机对比度测试失败时考虑，首轮不制作两套皮肤。

## 9. 最危险的假玩法及技术边界

| 风险 | 会怎样伪装成完成 | 本方案约束与失败判据 |
| --- | --- | --- |
| 预制残影冒充回放 | 随便操作都会出现相同破盾队友 | 输入按 tick 保存，实际路径与发射时刻逐项比较；录制完全不同路线必须得到不同残影 |
| 站桩录像冒充动作游戏 | 所有轮次只按住开火便通关 | 射界中线攻击和横扫要求真实移动；固定站位脚本必须失败，移动解必须存在 |
| 三个分身自动通关 | 第四轮玩家可以放下手机 | 三封印＋第四方向核心使三个角色不能自给自足；停用当前开火必须零核心伤害 |
| 残影只是伤害倍率 | 去掉其碰撞、射击仍照样破盾 | 封印只接受真实射线事件；删除某段开火输入应直接关闭对应协作窗口 |
| Boss 被新行动改写导致回放漂移 | 旧角色追踪新目标、重新躲避、被新击退 | 本原型敌人固定时序、不追踪角色；无互撞、击退、动态墙，破盾不取消攻击 |
| 小数时间、帧率导致错拍 | 低帧率下多开枪、迟重置或走不同轨迹 | 所有行动冷却、预警、命中及重置用整数 tick；渲染只插值；不跳过模拟 tick |
| 协作阈值掩盖不可解 | 需要超出窗口极限的伤害或无法躲开的射线 | 每关至少一条完整手工记录输入解，自动重放打通；当前血量与攻击参数未验证，不称平衡完成 |
| 20 秒录制像劳动 | 等满计时才开始游戏 | 第一轮就有实时躲避与可见封印；首测仍感到等待则修改入口，不靠延长文案解释 |
| 轨迹可见但看不懂 | 四条彩线淹没关键信息 | 编号/形状/局部尾迹/短预告；首次玩家能指出谁打开了哪块盾，否则可读性不达标 |

### 回放契约：先记录输入，再用同一套规则重演

1. 每个 tick 记录量化后的移动轴及开火状态；按 tick 编号取输入。键盘和摇杆经过同一层归一化，不能记录浏览器事件时间再凭插值猜动作。
2. 玩家与残影共用 `stepActor`、射击冷却及世界碰撞规则；没有 ghost 专属寻路、纠错、目标选择、伤害加成或无敌。
3. 一段输入之外保留真实成功发射事件及每 tick 状态摘要作为对照数据，供预告/调试。不能以预录姿态强行覆盖输入演算结果来掩盖漂移。
4. Boss 危险区域由关卡和 tick 决定；射击只改变封印/核心生命，不改变危险区时序。每个角色独立结算同一套受击规则，因此增加残影不会改变某一角色旧路径的生存与动作。
5. 采用固定 60 Hz 累积时间步；正常渲染帧可能执行多个模拟 tick。严重卡顿时暂停并显示“已暂停”，不丢 tick、不补一个巨大步长。渲染随机粒子不能参与游戏判定。
6. 本原型只承诺同一规则版本、本机运行内可复现。跨浏览器导入录像、版本兼容、联网锁步不在范围；若将来需要，另验证整数物理或兼容格式，不先造系统。

## 10. 最小独立实现草案（本轮不创建）

未来目录内仅需：`index.html`、`style.css`、`game.mjs`、`sim.mjs`、`server.mjs`、`verify.mjs`，加本设计文件。原生 HTML/CSS/ES modules、Canvas 和 Web Audio，Node 内置模块，不依赖兄弟目录、CDN、构建器或新 npm 包。

- `sim.mjs`：关卡常量、纯模拟状态、输入记录/重放、圆形世界碰撞、射线与封印判定。真人与残影走同一条逻辑；浏览器和校验脚本直接导入。
- `game.mjs`：输入适配、模拟时钟、Canvas 渲染、原生 HUD、暂停及声音。DOM 按钮保留语义与键盘焦点。
- `server.mjs`：默认 `127.0.0.1:4406`，支持显式 `--host 0.0.0.0` 做同网手机验证；只服务本目录，正确 MIME，拒绝目录穿越，不改机器防火墙。端口占用报错，不默默换端口。
- `verify.mjs`：使用 Node 内置 `assert` 的单个可运行校验入口，核心测试数据来自规范输入或实际录制；不另加测试框架与管理后台。
- 记录存在内存即可；单关重新载入重新开始。静音偏好可用本地存储，但不做云存档或后端。

### 模拟验收：`verify.mjs` 必须失败即非零退出

1. **真实复现：**录一条包含转向、停火、避险的 1,200 tick 输入，记录状态与发射事件；从初始状态重复回放 100 次，逐 tick 相等。将同样输入按 30/60/144 FPS 的帧切分驱动，最终状态和事件仍相等。
2. **整点重置：**第 1,199 tick 尚未提前重置；完成第 1,200 tick 后，Boss 血、封印、位置、时钟恢复且记录正确入列；达到记录上限只删除最旧一段。
3. **全局短局可解：**每关保存至少一组真实操作或明确合法的控制输入，通过同一个 `sim.mjs` 从第一轮跑到胜利；不存在预先设置残影位置或直接改 Boss 血量的捷径。
4. **合作消融：**同一组第三关输入，完整四角色可赢；删除任一必要残影的开火输入，或让当前角色始终不开火，应无法打伤核心。必须比较命中事件和封印状态，而不只截图血条。
5. **防伪与边界：**两条不同路线产生不同轨迹；停火后不再产生新攻击；封印在 36 tick 后按统一更新顺序到期；相邻射界之间最快合法绕行不能在一次封印持续期内完成双职。
6. **动作层：**三个预录固定站位支援＋固定站位当前角色不能过最终关；合法躲避路线能过。若站桩能赢，调攻击而不是只加血。
7. **重试隔离：**死亡及主动重试不写入失败记录，不改变已有输入数组；新关清空记录；暂停时 tick、射击和残影全部停止。

## 13. 真实第二轮挑战与第三轮收敛（实施依据，覆盖冲突旧条目）

本轮挑战由用户于第二轮明确提出，以下是本负责人收敛，未引入其他参与者或虚构试玩。

1. 接受“窄射界、精确窗口、血量组合导致录制苦工”的质疑：首关射界总宽 100°，二/三关 54°/50°；核心从第 4 秒持续开放到轮末。取消两个 2 秒输出窗口。每关 40 血、每秒 4 发，留 6 秒输出余量。先验证有转弯、径向躲避的普通连续操控路线，再做消融。温和/标准容错可在开局选：预警 2/1.6 秒，受击保护 0.75/0.6 秒，整局记录继承同一规则。
2. 保留 20 秒、真实逐 tick 输入、最多三残影与四角色最终配合。地图中心半径 180 不可通行，速度 170，封印续亮 0.55 秒；最终相邻射界至少相隔 40°，绕行下限约 0.74 秒，不能一人占两职。角色与残影受击、开火、移动使用同一函数；新玩家不改变旧角色危险区、血量或动作。
3. 接受反证验收：内外危险环交替，没有永久安全半径；第三关增加带预警的轴向细线。静止开火、缺任一必要旧记录、当前不开火都必须失败。可解路线必须真实移动且用同一输入接口。
4. 当前轮失败/主动重试均保留旧记录。满槽后默认保留三段旧记录，当前轮可反复进攻；点可见的“重录①”等按钮，将该旧记录暂时撤下并开始替换录制，旧版本保留到新段完整成功录下，失败不丢失。重录与取消均有明确目标。未满槽时每 20 秒自动新增记录。这取代自动静默删除最旧记录。
