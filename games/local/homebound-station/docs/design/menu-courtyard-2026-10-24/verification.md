# 独立首页、紧凑车场与触屏反馈验收

2026-10-24，北京时间。真实 Cocos Creator 3.8.8 Web Mobile，Windows 桌面 Chromium 触屏模拟。未提交、推送、上传或提审。

## 画面与交互

- 首页已移除棋盘、演示车辆与后台模拟，使用现有站前插画、新透明站牌标题和独立开始/继续入口。选关、设置保留，窄屏副标题有浅色衬底。横屏采用插画与菜单两列。
- 第1关390×844的停车阵列顶部由上一版约470px提前至344.6px，阵列高度约347px（上一版约258px）。第100关车阵约303px起，6×9布局继续使用真实触屏拖动；不以隐藏行或缩小点击范围换取“全部显示”。
- 车身停车/行驶/横停全程使用同一尺寸；分段布局只分配空间，不改变道路拓扑、碰撞体、接客与独立补客规则。站房裁片保持比例，复用花箱/灯具，增加路缘与分隔带层次。
- 车顶显示方向，容量为次要角标。按下描边、受阻标记原车；不可滚动关卡也支持滑开取消，滑开再移回不派车。暂停/失焦不派车，重开清除受阻标记。
- 独立只读复核提出的较方横屏裁行、标记跨局、顶部角标越界问题均修复，并纳入检查。800×600可以显示并点击第100关末排；320×568拖动能到达全部末行车辆。

## 实际证据

- 43项规则/存档/奖励/加载测试全部通过，含100关正序、倒序和固定随机顺序共300局。见[rules.log](rules.log)。
- Creator类型检查、实际构建，以及16组浏览器流程通过，页面零错误。浏览器版本、准确构建身份与输入记录见[runtime/verification.json](runtime/verification.json)。
- 横停、补客和两车并行采用每帧只读观测，派车仍使用CDP真实触摸，不注入规则动作或修改模拟时钟。记录真实接收时间，验证首人上车前两车均已移动，未派下一辆车时下一组自行补入。[状态证据](runtime/parallel-departure.json)。
- 本机强制 `--use-angle=swiftshader` 的测试曾发生启动超时和自动化响应延迟；改用Chromium默认渲染选择并允许软件回退后重验通过。测试保留错误输出，不以超时当作通过。
- 之后一次复跑遇到本地资源请求 `ERR_NO_BUFFER_SPACE`，该次未计为通过。最终完整复跑同时记录请求失败与页面错误，结果均为零，16组检查通过；最终构建、截图和录屏的源码指纹一致。
- 实际录屏从首页进入第1关，以1×真实触摸完成接送和结算；另交付宣传剪辑，两者无音轨、H.264、390×844，完整解码通过。见[上架资料](../../../publishing/STATUS.md)和[录屏输入](runtime/recording-input.json)。
- 横向上客截图取自最终完整实玩视频的第6秒，已检查实际停靠和乘客位置；避免外部截图响应延迟导致把离站画面标作上客。视频其他抽帧保存在runtime中，未改写游戏画面。

效果图是[concept.png](concept.png)，素材来源见[artwork.md](artwork.md)。最终展示和验收以runtime中的真实截图为准；真实场景的车辆数量、布局和泊位状态取决于关卡与输入，不以效果图替换游戏。

## 复现

游戏目录依次执行：`node scripts/typecheck.mjs`、`node scripts/build.mjs web-mobile`、`node --test --test-concurrency=1 tests/*.test.ts tests/*.test.mjs`；设置 `CAPTURE_GAME_EVIDENCE=1` 后执行 `node tests/cocos.browser.mjs`。保持 `node scripts/serve.mjs` 的4326预览服务运行，再执行 `node tests/recording.browser.mjs` 导出两类视频。

没有执行物理手机、原生渠道和真实广告投放验收。桌面触屏模拟不等同于这些结果；本轮未扩大平台范围、改存档格式或引入新依赖。
