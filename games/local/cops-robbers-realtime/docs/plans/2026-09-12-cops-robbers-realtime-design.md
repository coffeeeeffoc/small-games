# 《别跑！街区围捕》游戏设计方案

日期：2026-09-12。本文保留实施前的设计提案；游戏与 48 关已实施，并按试玩反馈加入每关 1–3 个逃脱口、小偷寻路逃脱及逃掉一人即失败的规则。下文早期提案涉及封闭路网的内容已被替代，当前范围和验证结果见根目录 README.md。

## 1. 游戏是什么

一款手机友好的实时围堵游戏。玩家是现场指挥官，在道路网络上指挥 M 名警察，堵住 N 名小偷的退路并逐步收网；抓获全部小偷即通关。

核心乐趣：看到小偷准备绕路，立即调一名警察抢占路口，同时让另一名警察从背后逼近；小偷由得意变成惊慌，最后发现两边都有人，只能举手投降。

推荐采用俯视卡通街区、沿道路连续移动、点选警察后指定位置的方案。道路让包围关系清晰，连续运动提供实时调度的紧张感。

另外两种方案的取舍：自由二维追逐需要精细瞄准，容易偏离路径围堵；只能停在离散格子的棋盘操作较容易理解，但连续改道和途中拦截受到限制。本方案允许指定路口和道路中途的位置。

## 2. 一局怎样玩

1. 开局看清道路、警察、小偷的位置，点击“开始行动”。
2. 点击一名警察，再点击道路位置，该警察立即沿可达道路前往。
3. 到达目的地后，警察留守，阻挡小偷通过。
4. 玩家切换其他警察，抢占绕行出口，或逼近已被封住的小偷。
5. 小偷实时逃跑；玩家可随时替换警察的当前目的地。
6. 退路被堵且警察已经靠近时，出现短暂抓捕进度，小偷举手被捕。
7. 所有小偷被捕，立即结算，可进入下一关或重试刷新用时。

开局布置、正式行动、结算是游戏状态，不是行动回合。行动期间，选人、点目标、拖动预览和切换警察均不暂停时间。

普通关不设硬性倒计时、不消耗体力，允许反复调整。记录通关用时和最佳成绩，让新玩家能学会围堵，熟练玩家能追求更快。实际单关时长以试玩调整，目标约 1–3 分钟。

## 3. 实时操作

### 主操作：点警察，再点位置

- 点击角色或底部编号头像选中警察；用编号、轮廓和光圈一起表示选中状态。
- 点击路口或道路，立即下达移动命令；目标出现小旗，当前路线用与该警察一致的标记显示。
- 选中状态保留，可连续点击新位置改道。新命令替换旧命令，不排成长队。
- 点击另一个警察只切换选中对象，不打断原警察正在执行的命令。
- 点击离道路较近的位置时吸附到道路；明显点在建筑上时提示“请点道路”，保留原命令。
- 提供“原地守住”，让选中的警察在道路当前位置停下。
- 多条路可达时自动选择当前最短道路；希望走另一条路时，可以先指定那个方向的路口。

### 快捷操作：从警察拖向目标

从角色拖向道路，显示路线预览，松手确认。拖动过程中游戏继续运行。手指挡住角色时，底部头像仍可用于稳定选人。

点选是完整操作方式，拖动只是快捷方式。无需长按菜单、框选或双指手势。桌面补充数字键选警察，鼠标点击下令。

### 操作反馈

- 选中：警察抬头敬礼或点头，短促“收到”，同时亮起光圈。
- 下令：目标落旗，路线出现，警察起跑并留下短暂脚步尘土。
- 改道：身体先转向，再沿道路连续移动，不瞬移到最近路口。
- 留守：警察张开手臂或摆出拦截姿态，脚下显示很短的封锁标记。
- 无效目标：目标处轻弹一次提示，警察继续原行动。

按钮和选人区域以至少 44 CSS 像素为目标；视觉角色可以较小，但触摸判定不跟着缩小。重叠角色可通过编号头像准确选择。

## 4. 怎样才算围住

玩家规则只有一句：**堵住退路，再靠近收网。**

警察身体会截断所在道路，小偷不能穿过。警察脚下沿道路显示一小段抓捕范围。小偷所在空间没有任何未被抓捕范围覆盖的退路，并持续 0.8 秒，就算被捕。

典型情况：

| 场景         | 玩家要做什么                     | 抓捕发生的时机                 |
| ------------ | -------------------------------- | ------------------------------ |
| 死胡同       | 一名警察把小偷逼向尽头           | 尽头到警察之间已没有安全位置   |
| 直道路段     | 两名警察从两边逼近               | 两侧抓捕范围合拢               |
| 三岔路口     | 封住分支，或把小偷赶到其中一条路 | 小偷所有可走方向都没有安全位置 |
| 大环路       | 先切断绕圈路线，再从两侧收网     | 剩余空间缩小到抓捕范围内       |
| 多名小偷聚集 | 围住整个小群体                   | 满足条件的小偷分别被捕         |

封住大区域不直接抓获，小偷仍可以在区域内跑动。隔着房屋看起来很近也不算，距离和阻挡都沿道路计算。

为了保证判定一致，实现时在警察所在位置临时截断道路，找出每名小偷当前可到达的道路连通区域。只有该区域的全部位置都被边界警察沿道路延伸的抓捕范围覆盖，才累积抓捕进度。抓捕范围和 0.8 秒持续时间是待试玩校准的参数。

如果有人撤走，重新出现安全位置，抓捕进度立即清零。移动和迎面相遇采用连续路段碰撞处理，不能因为单帧位移较大而穿过警察。

警察之间允许通过，不制造队友卡路。小偷之间也不互相堵路，避免偶然挤在一起替玩家完成包围；同处一段道路时错开绘制。被捕角色退出移动和碰撞，警察立即可以重新调度。

## 5. 小偷怎样行动

首版只做一种能看懂、会绕路的小偷，不靠不断提速制造难度。

- 无近处威胁时沿道路游走，不原地等玩家。
- 警察逼近时，沿仍可通过的道路逃离。
- 到岔路时，优先选择远离附近警察、出口更多的方向，尽量避开明显死胡同。
- 前方被堵时可以停步转身，但有短暂的方向保持时间，避免左右抖动。
- 只依据实际道路和警察当前位置反应，不读取玩家尚未执行的目的地，不预知下一次点击。
- 看不到安全出口时缩肩、冒汗、左右张望；抓捕条件满足后才举手。

警察和小偷先采用接近的基础速度。单纯追着同一个方向跑不能稳定追上，玩家需要抄近路和夹击。速度、转向反应时间通过前六关试玩调整，不引入冲刺、道具和警察职业差异。

示例：环路上小偷顺时针跑，1 号警察持续施压，玩家把 2 号警察调到前方路口。小偷发现前方有人后转向，1 号继续逼近；两边逐渐靠拢，最终出现抓捕进度。小偷转向发生在真实运动中，玩家仍可临时调整两名警察。

## 6. 48 关的递进方案

以下是关卡设计范围，不代表已制作。首版目标为 8 组、每组 6 关，共 48 关；每关单独配置道路、出生点、警察数 M 和小偷数 N。

| 关卡           | M   | N   | 道路变化                     | 主要学习内容                     |
| -------------- | --- | --- | ---------------------------- | -------------------------------- |
| 1–6 街角见习   | 1–2 | 1   | 直巷、折巷、死胡同、简单岔路 | 选人、下令、留守、改道、首次夹击 |
| 7–12 绕圈高手  | 2   | 1–2 | 单环、带支路的环、长短两条路 | 识别无效尾追，利用另一端拦截     |
| 13–18 路口封锁 | 2–3 | 2   | T 字、十字、错位岔路         | 判断优先守哪个路口，保留封锁     |
| 19–24 双环街区 | 3   | 2–3 | 两环相连、桥形连接、短捷径   | 切开活动区域，防止小偷换圈       |
| 25–30 分头追捕 | 3–4 | 3   | 不对称街区、远近两片区域     | 同时观察多名小偷，及时补位       |
| 31–36 收网接力 | 4   | 3–4 | 多条支巷、共享出口、组合小环 | 抓到一个后迅速复用警察           |
| 37–42 紧缺警力 | 4–5 | 4–5 | 多环与瓶颈混合、更多绕行分支 | 用少量警察封锁关键路段           |
| 43–48 全城围捕 | 4–5 | 5–6 | 前述结构的非对称组合         | 确定先抓谁，跨区域连续调度       |

人数不要求逐关递增。偶尔用较少角色配更巧的路网，让难度来自空间和时机，也给玩家节奏变化。

前六关具体安排：

1. **巷尾见习，1 警 1 偷：** 一条短死巷，学会点选和指定目标，看到第一次收网。
2. **拐角也能走，1 警 1 偷：** L 形巷，理解角色自动沿路前进，不能穿墙。
3. **别跟着兜圈，2 警 1 偷：** 小环路，引导第二名警察去另一头，第一次两面夹击。
4. **路口留一个，2 警 1 偷：** 环路接支巷，一人封口、一人逼近，理解留守。
5. **他转弯了，2 警 1 偷：** 不对称环路与捷径，需要在警察移动途中改目的地。
6. **独立出警，2 警 1 偷：** 小环、岔路和死巷组合，取消手把手提示，综合完成围捕。

每组六关按“介绍变化 → 两关练习 → 组合应用 → 节奏缓冲 → 综合挑战”组织。道路在不同关卡之间变化；首版单局内不突然改变连通关系。

制作约束：

- 每关都要实际验证至少一种可完成的指挥过程，不能只检查道路是否连通。
- 禁止生成一名警察必须在纯环路中追上同速小偷的无解目标。
- 出生点不重合，不在开局瞬间触发抓捕；地图边缘不设置未说明的逃生出口。
- 先保证前六关顺手，再完成全量；其余关卡需要实质性的道路与调度差异，不能只换背景颜色。
- 采用人工配置路网，不用随机生成器凑关数。后期也限制屏幕复杂度，优先修改连接方式，不一味增加路口。

## 7. 画面、动作和表情

默认方向：轻松卡通，但后期需要认真调度。俯视的微立体街区，奶油色地面、清晰道路、低矮建筑。建筑和装饰不能遮住路口、角色与路线。

警察以蓝色制服、帽子、编号和不同配饰区分；小偷有面罩、背包和明显不同的轮廓。颜色不承担唯一的识别作用。

| 状态           | 动作与表情                           | 声音             |
| -------------- | ------------------------------------ | ---------------- |
| 警察被选中     | 抬头、敬礼、编号弹起                 | 短促确认音       |
| 警察起跑       | 前倾、小碎步、脚步尘土               | 轻脚步声         |
| 警察守路口     | 叉腰或伸手拦截，目光跟随小偷         | 不持续播放警笛   |
| 小偷暂时安全   | 抱紧背包、回头偷笑                   | 偶尔轻笑         |
| 小偷发现堵路   | 急刹、瞪眼、鞋底滑出短痕             | 短刹车音         |
| 小偷被两侧逼近 | 冒汗、左右看、脚步慌乱               | 渐短的紧张提示   |
| 抓捕           | 小偷举手，背包落下，警察完成收押动作 | 哨声和收押提示音 |
| 最后一个被捕   | 警察短暂庆祝，小偷垂头               | 简短通关旋律     |

动画必须跟真实状态变化对应，不能用预录桥段代替玩家操作。单次抓捕不暂停其他角色、不弹遮挡地图的大窗口；只有整关结束才展示结算。

## 8. 页面和设备体验

- 首屏：继续游戏、选关、声音开关。
- 选关：按街区分组，清楚显示已通关与未解锁。
- 游戏上方：关卡名、已捕数量、用时、暂停。
- 中央：道路地图，占据主要空间。
- 底部：编号警察头像、选中状态、原地守住。
- 结算：用时、个人最佳、下一关、重试。

手机优先横屏，尽量让一张地图完整可见；竖屏也保留可操作布局，复杂地图提示旋转，但不以强制旋转挡住游戏。头像栏避开系统安全区，地图不能触发页面滚动或浏览器缩放。

显式暂停时停止模拟并关闭下令，恢复后继续实时行动；切到后台也暂停，回到页面后由玩家继续。没有“暂停布置下一回合”。音效首次操作后启用，支持静音；支持降低装饰动画幅度，角色真实移动仍可辨认。

## 9. 最小实现边界

首版完整范围：48 关、实时点选与拖动下令、连续寻路移动、小偷逃跑与绕路、统一围堵判定、动作表情和音效、暂停重试、选关与本地进度。

不引入联网对战、账号、商城、装备升级、随机地图、职业技能和关卡编辑器。它们不帮助验证这款游戏的核心交互。

实现可用原生网页模块、Canvas 绘制和浏览器音频，先保持单页静态 H5。道路和关卡用数据描述，实时模拟与输入、绘制分开；无需大型游戏引擎或后端。

围堵范围、角色速度和反应时间按统一游戏坐标计算，屏幕缩放不改变难度。模拟使用固定步长，渲染跟随屏幕刷新，暂停和后台时间不计入抓捕持续时间。

## 10. 怎么确认真的好玩、真的实时

先用前六关完成一次完整试玩闭环，再批量制作后续关卡。设计通过的标准：

- 玩家不做操作时，小偷也在真实移动；选人和拖动预览不会冻结世界。
- 点目标后，警察在下一次画面更新中给出反馈，沿路连续执行；途中改令立即影响路线。
- 一名警察在环路尾追难以解决问题，第二名警察抢占另一头能改变结果。
- 死巷能单警抓捕；直路能两警夹击；大区域被封不会提前判抓；隔墙不算接近。
- 连续相向移动不会穿人；临时撤走警察会打断抓捕；多个小偷被捕不会重复计数。
- 玩家可以在另一组角色仍运动时完成一次抓捕，并继续指挥空出的警察。
- 触屏点选、拖动取消、重叠角色选择、暂停恢复、后台恢复和重开都不残留旧命令。
- 最后一个小偷被捕时只结算一次；下一关人数和地图确实变化；重新打开能恢复已通关进度。
- 围堵、寻路改令与多人计数保留小型可运行回归检查；完整操作流程还需浏览器实玩和手机验证。

以上为提案阶段的验收要求。实施后的实际检查和设备验证边界以根目录 README.md 及 artifacts 中的运行报告为准。
