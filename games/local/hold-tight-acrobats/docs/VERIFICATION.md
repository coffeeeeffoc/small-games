# 实际验证记录

> 以下为原型迁移前的历史记录，随源文档保留。原型的 `test-results/` 报告和截图未复制；迁移后的生产输入、触屏及全屏复验见 [生产验收记录](MIGRATION-SMOKE.md)。下文的五关通关记录仍属于原型历史结果。

验证日期：2026-09-26。此文件记录运行结果，不把构建成功当成玩法验收。

## 已执行

- 锁定依赖安装、TypeScript 严格检查、Vite 生产构建。
- 核心单元与固定步长 Matter 模拟测试：27 项通过（22 项机制测试、5 项全关卡真实输入路线），输出保存在 `test-results/unit-tests.txt`。
- 第三关模拟路线：末端队员摆荡并自动抓住新横杆；同时保留旧吊环和新横杆；切换①释放旧支点；分别落到回收平台和较低安全面；三人全部站稳通过。
- 第五关模拟路线：人链换支点、全员营地检查点、三次地面起跳抓吊环、三次摆动松手、全员完成。
- 桌面 Chrome 对 `http://localhost:4319/` 的生产构建执行真实按键，连续完成全部五关。三人均通过游戏的安全支撑和 0.6 秒停留判定；每关保留通关截图，第三、五关另有两端抓握截图。最终报告为 `test-results/browser-report.json`，控制台错误数为 0。
- Chrome 触屏模拟：844×390 横屏、390×844 竖屏，必要按钮均在视口内；头像选择、触摸拖出后一次释放、双指取消不误发力、真实 Fullscreen API 进入 / 退出均通过。
- 50 次关卡重置检查了刚体和约束数量、手部占用、输入、蓄力及冷却，不持续增长；浏览器再进行 20 次重试后，单次释放仍只产生一次动作。输入监听器只在场景首次创建时绑定，重置不重新绑定。
- 输入取消测试先确认蓄力仍有效，再验证切换、pointercancel、双指 touchCancel、失焦和重复失焦。另验证 Tab 切换、镜头坐标转换后的角色点击、菜单的 Tab 焦点导航与空格激活。
- 生产包不包含 `__acroDev` 调试控制入口。所有素材请求来自本地服务，补齐 favicon 后没有 404。

## 五关浏览器验收

| 关卡 | 实际执行 |
| --- | --- |
| 1 | 三位队员分别蓄力跳过缺口并安全到达 |
| 2 | 三次起跳抓环、三次摆动、独立松手并全部落地 |
| 3 | 从预牵手人链摆到新横杆，保持两端抓握后切换①松开旧吊环，全员回收 |
| 4 | 全员在加宽营地站稳激活检查点，再完成第二段 |
| 5 | 人链换支点、全员检查点、三次抓环摆动飞跃、全部到达 |

路线只通过玩家输入与只读观测执行。到达集合区后会逐个松开牵手，使身体能够站稳；不会放宽胜利或检查点规则来适应测试。停靠顺序根据实际落地先后选择，避免控制后面的队员持续推挤前面的人。

## 机制覆盖

选中者单次冲量 / 队友持续模拟；切换保持抓握并取消旧输入；短按、分级蓄力与满值封顶；无支点禁跳、空中无行走力；经队友连到吊环与无锚点闭环的区别；开始 / 释放支撑类型复验；脚接触和头 / 墙接触区分；手端、臂展、实体遮挡；快扫抓取；双向手部占用、一条约束与冷却滞回；单手解除；松手动量保持；30 / 60 / 120Hz 一致性及快抓；全员低速支撑停留；检查点安全重建；帧间断 / 暂停；持续摆动速度安全上限；键盘和指针互斥消费；摆动力分级；四种站定满蓄力方向均不能直接跳过第二关峡谷。

## 验证范围

模拟路线使用与浏览器相同的 Phaser 内置 Matter 和游戏逻辑，执行的是选择、行走、蓄力、松手以及正常物理步进。未使用通关传送、给队友复制冲量、直接改关卡结算或手工设置运动轨迹。

头碰地、扫掠、隔墙等单元测试允许构造专门的初始条件和纯连接图夹具；这些夹具只存在于测试目录，不能作为正式关卡通关证据。

不声称实体 Android / iPhone、Safari、原生微信 / Bilibili 小游戏平台验收通过。没有提供未经验证的第二条捷径。卡通站姿与手臂辅助的简化见 README。
