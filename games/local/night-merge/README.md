# 合成守夜人 · Night Merge

中文竖屏 H5：3×4 合成营地、4 个城墙驻防位、自动塔防与局内随机祝福。共 10 波、2 位领主，目标每局约 3–5 分钟；每波至少持续 20 秒，并在清空敌人后结束，实际时长会随阵容变化。

## 运行

在仓库根目录执行：

```powershell
pnpm --filter @small-games/night-merge dev
pnpm --filter @small-games/night-merge test
pnpm --filter @small-games/night-merge build
pnpm --filter @small-games/night-merge test:browser
pnpm --filter @small-games/night-merge test:combat
```

开发地址为 `http://localhost:4196`。先执行 `build`，再执行 `test:browser`；回归脚本会自动启动临时预览服务，也可用 `GAME_URL` 指定已有服务。构建输出到本目录 `dist/`，使用相对资源路径。`test` 运行 Node 内置测试，`build` 包含 TypeScript 检查。

## 玩法

- 开局有 54 金币和两名 1 阶弓箭手；至少派一人驻防后，可以敲响夜钟开战。
- 同兵种、同阶守卫合成，最高 3 阶；等级伤害倍率为 1、2.5、6。不同守卫可互换位置，营地与城墙之间也能移动、交换和合成。
- 只有城墙上的 4 名守卫自动攻击。营地里的守卫占用合成空间；可以撤下驻防单位，为下一次合成保留材料。
- 每次消耗 18 金币，从已解锁兵种中等概率召唤一名 1 阶守卫。开战后每 14 秒自动送来援军；满格时保留待领援军，腾出位置即可接收。
- 遣散 1／2／3 阶守卫分别获得 6／12／24 金币。击杀普通敌人获得 3 金币、领主 28 金币；清波奖励为 `12 + 波次 × 2` 金币。
- 第 4、9 波结束时暂停，随机展示三份未获得的祝福，选择一份后进入下一波；第 5、10 波分别迎战「枯木领主」「永夜君王」。普通波间有 3 秒整备时间。
- 「破晓钟」对全场造成 `44 + 波次 × 1.5` 伤害，并施加 3.5 秒减速，冷却 24 秒。城门耐久归零失败，清空第 10 波获胜。

### 兵种与敌人

| 兵种   | 解锁    | 作用                                                                      |
| ------ | ------- | ------------------------------------------------------------------------- |
| 弓箭手 | 开局    | 攻击较快，稳定单体输出                                                    |
| 盾卫   | 开局    | 近身攻击；每名盾卫阻挡一名邻近敌人，阻挡期间城门承担该敌人 15% 的攻击伤害 |
| 焰法师 | 第 3 波 | 命中目标并对附近敌人造成 75% 溅射伤害                                     |
| 冰法师 | 第 6 波 | 单体攻击，命中附带 2.5 秒、35% 减速                                       |

4 个兵种各有 3 阶原创造型。6 类普通敌人为爬行怪、疾行兽、蛮怪、蝙蝠、重甲怪、萨满，对应代码 `crawler / runner / brute / bat / armored / shaman`；双领主对应 `ogre / nightlord`，具有独立轮廓与生命、伤害配置。

### 八种祝福

| 祝福     | 效果                                             |
| -------- | ------------------------------------------------ |
| 疾风箭弦 | 弓箭手攻速 +30%                                  |
| 穿云之箭 | 弓箭额外穿透同列一名敌人，造成 70% 伤害          |
| 荆棘壁垒 | 盾卫阻挡时反伤，伤害为敌人攻击 ×2.5＋盾卫阶数 ×5 |
| 薪火相传 | 每次合成回复城门 8 点耐久，不超过上限            |
| 星火跃升 | 合成有 20% 概率额外升一阶，上限仍为 3 阶         |
| 凛冬之拥 | 寒冰减速增强至 65%，冰法师伤害 +20%              |
| 余烬回响 | 焰法师爆破范围扩大，伤害 +25%                    |
| 夜行赏金 | 每次击杀额外获得 2 金币                          |

### 操作与暂停

- 鼠标或触屏拖动守卫到格位；也可先点守卫、再点目标格。选中后点击「遣散」，或直接拖到遣散按钮。
- 键盘 `Tab` 切换按钮，`Enter`／空格选择、放置或触发按钮；`Esc` 取消选择／拖动，无选择时打开暂停。
- 拖到无效区域会取消；`pointercancel`、失去指针捕获、窗口失焦和切到后台都会清理拖动状态。
- 暂停、说明、手记、祝福与结算面板会停止战斗计时、援军和技能冷却；后台返回后需要继续守夜。正常前台低帧率保留完整经过时间，战斗按小时间步推进。
- 声音使用 Web Audio 合成，可静音；浏览器不支持音频时仍可游玩。

### 打击反馈

- 攻击分为蓄力、发射、命中三个阶段：弓箭 0.32 秒、盾击 0.22 秒、火球 0.48 秒、冰枪 0.38 秒，伤害在到达目标时结算。目标提前死亡不会重复击杀或发金币。
- 驻防守卫有拉弓／蓄力、武器动作和出手后坐；实体箭、盾击弧、火焰尾迹、冰晶拖尾各有独立造型。命中产生受击形变、短促闪光、碎片和实际伤害跳字，死亡保留消散残像。
- 远程守卫等敌人进入战场上方四分之一处再攻击；最后一击保留约 0.55 秒展示时间，再进入祝福或胜利面板。
- 发射／命中音效按事件同步，长帧会跳过过时声音，静音会清理旧声音。表现层不消耗战斗随机数；命中特效最多保留 96 条，及时过期。暂停冻结弹道、动作和特效，系统的减少动态设置关闭晃动、形变和爆闪。
- `test:combat` 自动启动独立开发服务，真实 UI 检查驻防攻击与暂停；另用独立确定性场景检查四兵种、Boss、缩减动态和命中时序，生成阶段截图与短片。独立场景不会注入正式游戏状态。

## 手记与免费续火

失败后每局可免费续火一次：城门恢复最大耐久的 60%，敌人被击退、减速，技能冷却归零，保留阵容和祝福。复活来源明确记录为 `free`。

结算余烬为 `max(2, 波次 × 2)`，获胜额外 +10；领取结算后写入手记，每局仅发放一次。余烬可升级「不灭城墙」，每阶永久增加 10 点初始／最大耐久，上限 5 阶；下一阶费用为 `(当前阶数 + 1) × 8` 余烬，下局生效。进行中的重新布阵不领取结算奖励。

天赋、余烬、声音设置和最近 20 份战报保存在当前浏览器。进行中的阵容与波次没有跨刷新续玩存档；浏览器禁用存储时，本次仍可游玩，手记会提示记录仅保留到页面关闭。

## 本地指标

本地存储键：

- `night-merge.profile.v1`：`embers / talent / bestWave / wins / runs / firstDay / days / records / muted`；访问日期最多保留 60 天，战报最多 20 条。
- `night-merge.metrics.v1`：事件列表，运行时最多保留 1,500 条，载入时取最近 1,000 条；约每 5 秒、页面离开及结算时写入。

每个事件也通过 `window` 的 `night-merge:telemetry` 自定义事件发出，载荷为 `event.detail`，`at` 是毫秒时间戳，战斗事件另有 `elapsed` 秒数与 `wave`。手记中的「导出守夜战报」导出包含 `version / profile / events` 的 JSON。

| 目标指标            | 对应记录                                                                                                   |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| 召唤次数及来源      | `summon`：`kind / source / level`，来源为 `gold` 或 `supply`；结算包含召唤次数、`stats.summonByKind`       |
| 合成层级分布        | `merge`：`kind / fromLevel / level / area`，结算包含 `stats.mergeLevels`                                   |
| 棋盘满格率          | `board_occupancy`：`occupied / capacity / full`；`run_end.boardFullRate` 为有效战斗时间内满格占比          |
| 祝福选择            | `buff_choice.id`，结算战报保留所选祝福                                                                     |
| Boss 到达与失败波次 | `boss_reached`、`stats.bossReached`、`run_end.failureWave`                                                 |
| 复活后成功          | `revive.source = free`；`run_end.successAfterRevive`、`reviveSource`；`run_settled.adReviveSuccess = null` |
| D1／D3 本地回访     | 每日首次进入的 `visit` 事件：`day / cohortDay / d1 / d3`，按首次访问后的自然日计算                         |

这些数据只在当前浏览器收集，没有远端聚合、统一用户标识或跨设备关联。清理存储会重置本地队列和回访基准；D1／D3 字段是回访信号，不能当作已测得的全量用户留存率。未接入广告 SDK、支付、月卡或 Battle Pass；广告复活成功率没有真实样本。

## 实现与验证边界

- TypeScript＋原生 DOM／Pointer Events＋Canvas 2D，无运行时第三方依赖。开发工具为 Vite、TypeScript 与 Playwright。
- 守卫 SVG、森林城墙、敌人、技能图标与音效均由代码原创生成；美术和声音无需外部资源请求。
- `src/game.ts` 为可独立测试的规则状态机；`src/main.ts` 管理界面、生命周期、音频和本地记录；`src/art.ts` 绘制角色与战场。
- 本地构建和浏览器自动化不等同于已部署验证；正式发布还需核对平台目录、直达页、嵌入页和线上资源版本。移动端模拟也不替代 Android／iOS 真机、宿主 WebView、触屏与性能验收。
