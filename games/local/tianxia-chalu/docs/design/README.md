# 天下岔路 · 移动端设计

参考需求来自「墨战核心玩法分析」对话：保留节点、自动产能、多方博弈，把操作从选兵派遣改为控制兵流；架空古代人物势力，不使用蚂蚁或现代军队包装。第一版以单人也能成立的 AI 对战验证核心。

## 画面与操作

设计先生成 [三屏效果图](concept.png)，再实现对应页面。暖色纸本山河图承载战场，深青漆色承载菜单，金边表示可操作岔口，朱红标记我军与出征按钮。背景为原创生成的无字山水画，经 WebP 压缩后用于主界面及弱化后的战场底图；规则对象由实时渲染绘制，不把效果图充当游戏界面。

采用竖屏：核心是观察纵向驿路图并单指点按离散节点，无需持续移动或双手摇杆。普通手机无需旋转或全屏即可完成所有操作。横屏保留同一沙盘，状态信息移到两侧；尺寸变化不重新创建对局，DOM 岔口热区始终和地图坐标一致。全屏入口在设置/暂停页，复用公共 H5 全屏机制。

页面关系：主页 → 山河图/直接出征/四方试炼 → 战场 → 暂停或结算 → 下一战、再战、主页。帮助和设置是独立页面。战场只显示关卡名、时间、各方城数、驻军和兵流，没有外围目录、能力菜单或统计侧栏。

岔口至少 44 CSS px，轮换出口后箭头旋转、路线变化、短提示和可关闭音效即时反馈。城池显示名称、兵数、我军/AI/无主字样，避免仅依赖阵营颜色。暂停按钮使用两根独立等长实心竖条。

## 与效果图的取舍

保留效果图的纸本山河、深青外框、朱红操作及金色节点；实现版本用简洁城楼符号替代绘画中的密集建筑，用城池旁一城一岔的具体规则替代示意图中的共享岔口，使点击权限和兵流归属清楚。AI 在界面中明确标记。主页只提供已经可用的征战、选关、试炼、帮助和设置入口。

浏览器测试生成的实际截图和 `browser-report.json` 位于本目录。它们是 Chromium 手机尺寸与触控模拟，未进行微信开发者工具、原生小游戏包或手机真机验证。
