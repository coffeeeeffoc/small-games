# 子弹花园 · Bullet Garden

一个可独立运行、也可由 Web Shell 的 iframe 承载的 Canvas 2D 战术射击游戏。首个关卡为失落庭院：十波敌人、五分钟挑战，核心选择是直接击中怪物，还是把种子射向空地，为下一波种下有用的地形。

## 运行

无需安装运行依赖，使用 Node.js 20 或更新版本：

```sh
cd games/local/bullet-garden
node server.mjs
# http://127.0.0.1:4410/

node --test tests/simulation.test.mjs
node tests/balance.mjs
node build.mjs
node server.mjs --root dist --port 4411
```

在仓库工作区中也可使用 `pnpm --filter @coffeeeeffoc/bullet-garden dev`、`test` 和 `build`。开发服务器接受 `--host`、`--port`、`--root`；构建生成 `dist/`，保留相对资源地址，可以直接部署到静态站点的子目录。Web Shell 的访问标识为 `bullet-garden`。

浏览器回归复用仓库的 Playwright 开发依赖。先启动 4410 开发服务，在另一个终端运行：

```sh
pnpm exec playwright install chromium
pnpm --filter @coffeeeeffoc/bullet-garden test:browser

# 如果使用系统 Chromium，可以省略上面的浏览器安装步骤：
CHROMIUM_PATH=/usr/bin/chromium pnpm --filter @coffeeeeffoc/bullet-garden test:browser
```

## 玩法

- 普通射击弹药无限，自动向附近怪物射击；普通弹落空不会生成地形。
- 三种种子独立储备。选择种子，瞄准庭院空地并播种；种子弹直接命中怪物时造成伤害，未命中才在落点生长。
- 荆棘限制敌人移动，寒冰柱改变通路，爆炸蘑菇延迟爆炸。组合它们，把追击者引向事先布置的区域。
- 场上最多保留 18 株植物，满额时替换最早的一株；植物还会自然消失或被摧毁，不会永久堵满庭院。种子定时恢复，每波额外补充一颗。
- 三类敌人采用不同的移动和障碍处理策略。波次递进时压力增加，阶段间选择强化，最后存活到五分钟即完成关卡。
- 结算显示击杀和植物相关表现，帮助判断主动朝空地播种是否有效。

| 种子 | 初始储备 / 单颗恢复 | 空地生成效果                                     |
| ---- | ------------------- | ------------------------------------------------ |
| 荆棘 | 6 / 5 秒            | 持续 14 秒，敌人减速 58%，每秒受到 12 点伤害     |
| 寒冰 | 4 / 7 秒            | 持续 12 秒，105 耐久；阻挡双方移动，可绕行或拆除 |
| 蘑菇 | 4 / 6 秒            | 2.4 秒后爆炸，造成 105 点范围伤害                |

三类敌人为普通芽怪、快速疾行芽和耐久较高的岩壳巨芽。每 30 秒进入下一波，完成第 3、6、9 波后暂停选择强化；普通弹默认伤害为 19。实际数值集中在配置与模拟模块中。

## 操作

| 动作       | 触屏                       | 键盘与鼠标                  |
| ---------- | -------------------------- | --------------------------- |
| 移动       | 拖动左下摇杆               | WASD / 方向键               |
| 瞄准       | 点击或拖动画面中的地面     | 移动鼠标                    |
| 普通射击   | 默认自动射击               | 默认自动射击 / 按住鼠标左键 |
| 选择种子   | 点击三张种子卡             | 1 / 2 / 3                   |
| 播种       | 点击播种按钮或直接操作场地 | E / 鼠标右键                |
| 冲刺       | 点击冲刺按钮               | 空格                        |
| 暂停与继续 | 点击暂停与继续按钮         | Escape                      |

普通射击默认自动进行。屏幕控件支持移动和瞄准同时操作；触点取消、切到后台和暂停时会清除持续输入。

## 结构与扩展

| 文件                        | 责任                                           |
| --------------------------- | ---------------------------------------------- |
| `src/config.mjs`            | 关卡、种子、敌人和强化的配置                   |
| `src/simulation.mjs`        | 确定性模拟、碰撞、植物生命周期、敌人行为和流程 |
| `src/renderer.mjs`          | 庭院、角色、植物、弹道与特效的 Canvas 绘制     |
| `src/main.mjs`              | 触控与键鼠输入、界面、音效、暂停及结算         |
| `tests/simulation.test.mjs` | 核心机制和关卡流程回归                         |
| `docs/CONTRACT.md`          | 状态结构、模块接口与浏览器检查约定             |

新关卡从 `LEVELS` 添加独立配置开始，通过 `createGame(levelId, seed)` 选择；配置关卡时长、波次时长、场地边界、玩家出生点、刷新节奏、强化时机及植物上限，再在准备界面添加关卡入口。`spawn.composition` 的 `fromWave` 与各敌人的 `weights` 控制不同阶段的敌人组合。共用战斗模拟与界面，避免复制整套游戏。新增植物或敌人时，在配置和模拟中补充行为，并在渲染模块提供对应外观；同步补充覆盖新规则的测试。

模拟与 DOM 分离，种子随机数可重现战斗。`window.__bulletGarden.snapshot()` 仅提供状态副本，供浏览器验收观察；它没有跳关、改血量或伪造结算的接口。Web Shell 的真实操作检查位于 `apps/shell-web/scripts/standalone-game-checks.mjs`，覆盖开始、选种、播种、移动和暂停恢复。

当前仅实现第一个关卡，不含广告、在线服务或付费系统。美术由 Canvas 程序绘制，无外部图片、字体或音频请求。

## 本次验证

- 核心模拟测试 26 项通过，覆盖三种种子的命中与落地差异、普通弹不生长、地形上限与过期、冰柱碰撞与敌人绕行/拆除、种子恢复、暂停、强化、胜负和确定性重放。
- 源码和 `dist/` 制品分别在 Chromium 中验收：1440×900 桌面 iframe、390×844 竖屏触控、844×390 横屏触控。真实点击/触摸走通开始、选种、播种成冰柱、移动、暂停冻结和恢复；无脚本错误、资源 HTTP 错误或横向溢出。横屏种子卡尺寸已调整，战场中央可直接触控；镜头在靠近界面边缘时平移，实测走到场地底部仍可看到角色。暂停图标为两根分离的实心竖条。
- 独立浏览器回归还验证了帮助与返回、窗口失焦自动暂停、按住左键时右键播种、松开后停止手动射击、自然失败和重开重置。两种手机尺寸均使用两个同时存在的真实触点，验证边移动边点击空地生长、触点取消后停止移动且不误播种，以及切种与冲刺。
- 完整浏览器挑战确认在 300 秒进入胜利：剩余生命 82、击退 285、落地生长 130、植物击退 18、地形伤害约 2226，并完成三次强化选择。过程使用原生键鼠输入和正常生命、弹药、敌人规则，由 Playwright 虚拟时钟加速动画帧，没有修改游戏状态。
- 仓库游戏配置审计通过（45 个游戏、0 个问题），workspace 依赖边界检查通过；静态服务器检查了入口别名、模块 MIME、HEAD 请求、无效路径及资源访问范围。
- `tests/balance.mjs` 用固定随机种子比较仅射击与主动布置植物的五分钟生存表现。该脚本保留正常生命值与受伤规则，可通过 `test:balance` 单独复现；它验证系统效果，不代替真实玩家测试“是否会主动打空”。

完整挑战最初因脚本沿用模拟机器人的较高植物击杀门槛而报告断言失败，游戏本身已经通关。浏览器验收随后明确为植物击退至少 10 个、地形伤害超过 2000，并用同一次运行保存的最终状态重新核验通过；没有重新运行整场，也不将原始脚本记录描述为未修改即通过。

验收证据：[浏览器报告](docs/qa/browser-report.json)、[第五波桌面战斗](docs/qa/desktop-wave-5.png)、[390×844 触屏画面](docs/qa/mobile-390x844.png)。报告保留最初的断言失败及最终状态重新核验结果。

上述手机测试使用桌面 Chromium 的触屏模拟，尚未进行 Android/iOS 真机安装验收。无头 Chromium 无法触发真实后台标签页可见性切换，已验证窗口失焦暂停，未把它等同于真机切后台验收。本次验证独立 Game 制品和 Shell 的实际操作检查，未运行整个仓库的完整 Pages 构建、APK 编译或 iOS 构建。
