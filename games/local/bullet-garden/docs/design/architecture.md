# 子弹花园：战役与成长架构

设计先于实现。本文件定义成长、经济、枪械、增益及存档规则；关卡、怪物、植物、地形和天气的详细内容由同目录专项设计维护。每种机制与每张地图必须在实现前有对应效果图，新增怪物也必须有外形效果图。效果图记录最终资产路径、覆盖对象和生成时间，形成可核查的设计 → 效果图 → 实现顺序。

## 战役边界

保留第一关 `ruins`，新增十关，共十一关。第 4、8 关为首领关，第 11 关为 BOSS 终章。关卡编号与波次严格分开：关卡表示地图和内容进度，波次表示单关中的刷怪阶段。第一关保留十波、300 秒以及 dev 分支的自动地形祝福、双槽能量技能、经验升级、武器构筑和 1/2/3/5 倍速；后续关卡可以自行配置时长和波次。清关后到结算及营地，不自动开始下一关，玩家能查看奖励、花金币升级，再出发。

`LevelDefinition` 是数据，而不是 `if (levelId === ...)` 代码。稳定 ID 不依赖数组位置。新增关卡可在数据包中声明：`{id, order, name, duration, waveDuration, waves, bounds, playerStart, spawn, terrain, weather, rewards, encounter, art}`。`order` 决定战役排序，`encounter` 指定普通 / 首领 / BOSS、特殊怪物 ID 与出场波次；追加数百关无需调整渲染和结算分支。每关有显式 `art` 路径。

内容依赖单向：内容 → 成长 / 模拟 → 渲染和界面。模拟中不得调用浏览器 API。所有永久进度与战斗状态都可 JSON 序列化，不存函数、DOM 或 Map。原有双指触屏移动、武装技能后瞄准施放、能量槽、冲刺和倍速保持可用，新增准备 / 结算 / 营地界面与战斗分开。每关从空祝福开始，只有选择经验升级提供的 `boon-*` 才获得对应自动生长地形；旧手动种子 API 不授予植物。

## 永久进度模型

```js
{
  version: 1,
  xp: 0,
  coins: 0,
  completed: [],             // 稳定关卡 ID，用于首次奖励与解锁
  settledRuns: [],           // 最近 128 个已结算 runId，防止同一结算重复到账
  upgrades: { attack: 0, fireRate: 0, health: 0, armor: 0, seedMastery: 0, pet: 0,
              weaponDamage: 0, weaponRate: 0, weaponPierce: 0 },
  equippedWeapon: 'bloom-rifle',
  equippedPet: 'sprout-helper',
  selectedLevelId: 'ruins'
}
```

玩家等级由累计经验推导，不重复保存：升级至下一级需要 `80 + 当前等级 × 35` 经验，等级从 1 开始，无总经验上限。金币和经验只能是有限非负整数；成长等级必须限制在已知定义的上限内。未知关卡 / 成长 ID 在迁移时忽略，已有合法值保留。未知武器和宠物回落到可用默认项；错误 JSON 返回初始进度并向界面报告保存问题。

第一关始终解锁，其余关卡需要前一关已清关并达到关卡配置的 `unlockLevel`；本章所有关卡的 `unlockLevel` 均为 1，主线无需刷旧关才能正常推进。等级控制成长、植物和助手可用性；本章怪物按到达关卡序号解锁，未来章节可追加独立玩家等级条件。关卡必要首领无需玩家等级过滤，以免错失终局目标。植物 `sunflower` 玩家等级 2 解锁、`stormreed` 等级 4、`bloomturret` 等级 6。重玩旧关与失败重试保留永久成长。

## 成长机制

成长是一个注册表，每项声明 `{id, name, unlockLevel, maxRank, baseCost, costGrowth, effects, icon, art}`。金币购买先检查解锁、上限和余额，成功后一次性扣币和加一级；失败返回 `{ok:false, reason:'locked'|'maxed'|'insufficient-coins'|'unknown-upgrade'}`，不改变任何数据。

| 成长                    | 解锁等级 | 每级效果                                      | 首级费用 |        费用成长 | 上限 |
| ----------------------- | -------: | --------------------------------------------- | -------: | --------------: | ---: |
| 攻击力 `attack`         |        1 | 普通枪械伤害 +8% 基础值                       |       35 | ×1.35，向上取整 |   20 |
| 攻速 `fireRate`         |        1 | 攻击频率 +6% 基础值                           |       35 |           ×1.35 |   15 |
| 生命 `health`           |        1 | 生命上限 +15；下一局满血出发                  |       30 |           ×1.32 |   20 |
| 护甲 `armor`            |        2 | 护甲 +3；减伤 `护甲 / (护甲 + 100)`           |       45 |            ×1.4 |   15 |
| 种植 `seedMastery`      |        1 | 植物强度 +8% 基础值（伤害 / 治疗 / 耐久）     |       40 |           ×1.35 |   20 |
| 宠物 `pet`              |        5 | 解锁助手后可升级；伤害 +25%，跟随射击频率 +5% |       90 |           ×1.45 |   10 |
| 枪械伤害 `weaponDamage` |        2 | 枪械伤害 +10% 基础值                          |       70 |            ×1.5 |   10 |
| 枪械连发 `weaponRate`   |        3 | 枪械射击频率 +8% 基础值                       |       75 |            ×1.5 |   10 |
| 枪械穿透 `weaponPierce` |        4 | 普通弹额外穿透一个目标                        |      120 |            ×1.7 |    3 |

默认人物：100 生命、0 护甲、202 移速。默认枪械：19 伤害、0.245 秒射击间隔、535 射程。基础值沿用原游戏，使第一关无成长时仍可通关。永久攻击 / 攻速百分比先相加，再与局内增益和天气乘算。护甲减伤最多 60%，结算显示真实扣血；任何来源的有效伤害最低 1，不能出现负伤害或无限护甲。

`effects` 使用明确支持的数值键，例如 `{stat:'damage', op:'addPercent', value:0.08}`、`{stat:'maxHp', op:'add', value:15}`。`registerGrowthDefinitions(definitions)` 原子追加永久成长定义，验证稳定 ID、费用、解锁、上限、效果图以及已支持的 stat/op。当前数值处理器支持 damage / fireRate / maxHp / armor / seedPower / pierce / petDamage / petFireRate，以及 add / addPercent。追加 `{id:'vitalRoots', effects:[{stat:'maxHp',op:'add',value:5}], ...}` 会复用存档净化、商店价格与战斗数值，无需复制商城代码。未实现的 energy 等新行为明确拒绝，需要新增经过测试的系统处理器；配置不得执行任意脚本。

## 枪械机制

武器定义与永久武器升级分开。初始实现为花火步枪 `bloom-rifle`；配置可扩充不同武器的 `damage`、`interval`、`range`、`projectileSpeed`、`pellets`、`spread` 和 `pierce`。装备检查玩家等级，在营地切换，战斗中不改变永久装备。

枪械分为伤害、连发、穿透三条可独立付费的升级路线；前三者分别在玩家等级 2 / 3 / 4 解锁。连发直接提升射击频率，穿透每层增加一个可穿过的敌人，上限 3。`state.bullets` 记录 `remainingPierce` 与命中 ID，防止穿透弹连续帧重复打同一怪物。局内继续保留 dev 分支的攻击 / 攻速强化、散射、短连射、边界反弹、寒霜弹、燃烧弹、爆炸弹、一次分裂及碎片爆炸；永久伤害与攻速作为它们的基础。普通子弹永不生长植物。弹夹与换弹属于未来武器行为，可通过系统扩充，不加入本期玩法。

枪械升级效果图至少包含伤害强化、连发枪口反馈和穿透弹轨迹。界面每次购买展示当前与下一级效果，费用不能只写在购买按钮上。统计 `shots` 表示枪械射击动作数，未来散射一次发多弹也记为一次动作。

## 助手机制

玩家达到等级 5 解锁芽灵助手，解锁不消耗金币；永久升级需要花金币。助手在玩家周围固定环绕 / 跟随，不参与碰撞、不阻挡植物，不吸引近战敌人，不代替玩家承担伤害。基础伤害 12、射击间隔 1.15 秒、射程 360；只朝最近可受攻击怪物射击，空场不浪费子弹。宠物射击使用 `source:'pet'`，与种子和枪械统计分开。

状态为 `{kind, x, y, angle, shotCooldown}`，宠物的解锁判定和永久等级在 `progression.mjs`，逐帧跟随 / 选目标由模拟实现，造型 / 命中反馈由渲染实现。尚未解锁时营地显示等级需求，战斗中不出现占位宠物。后续可加入治疗、拾取、护盾等助手，通过 `behavior` 注册表扩充，保持相同接口。

## 局内增益机制

单关经验存在 `state.progression`，从等级 1、首级 12 经验开始，每级需求增加 10；击杀奖励经验，经验溢出保留，连续升级进入有序队列。永久经验存在 `profile.xp`，只由结算改变，两条等级曲线互不覆盖。每关重新开始时清空本局经验、祝福、增益、技能能量及武器效果，保留永久成长与两个所选技能。

经验升级提供三选一，本局等级达到 5 后提供四选一；带权候选保证至少一个武器类别、至少一个地形类别，随后洗牌。候选过滤已拥有的祝福、未满足永久植物等级要求的条目、满层与前置条件；例如碎片爆炸需先有分裂弹，植物强化需先获得对应自动植物。不足候选允许少于三种，耗尽时消耗队列并给予治疗，不留空菜单阻塞战斗。

旧 `shrub/trench/frost/poison` 自动地形及五技能 `blast/gale/cart/horse/laser` 完整保留。冰柱、爆炸蘑菇、暖阳花、引雷芦、花瓣炮通过各自 `boon-*` 升级获得自动生长；暖阳花、引雷芦、花瓣炮另检查永久玩家等级 2 / 4 / 6。每个升级声明 `{id,name,description,category,maxRank,weight,requires,effects,unlockPlayerLevel}`，效果汇总读取注册表而不缓存旧 Map，后续追加增益可以即时生效。

## 数值和效果优先级

同一数值的固定顺序：基础 → 永久固定加值 → 永久比例加值 → 局内增益 → 环境乘数 → 临时状态 → 下限 / 上限。攻击间隔从最终攻击频率换算，避免用负间隔表达攻速。生命上限变化与当前生命恢复是不同事件。

天气分为基础天气 `sunny|cloudy|rain|fog|hail` 和叠加事件 `wind|thunderstorm`，同一时刻只有一个基础天气。天气只提供有目标标签的修改器，如 `plant:thorn damage ×1.2`、`monster:runner speed ×0.85`，可以同时有收益和损失。天气持续视觉不能影响碰撞、模拟随机数或技能计时。

怪物能力也是数据 + 系统处理器：护甲改变受伤数值，盾牌先扣盾值，防控缩减减速 / 控制，冲刺改变状态机，受伤分裂、钻地、升空、远程攻击在独立能力处理器执行。地面伤害按层级过滤；钻地 / 升空会有可见预警和再出现窗口，不能永久无敌。地图阻挡、减速和爬坡滑落使用同一移动入口，不由渲染坐标判断。

## 清关经济与奖励

本局击杀金币记在 `state.coins`，不直接修改永久钱包。成功清关时结算击杀金币 + 地图奖励金币 + 经验，并标记完成关卡、解锁下一关。每关 `rewards:{coins,xp}` 明确配置；首关 90 金币 / 110 经验，首领关 160 / 185、215 / 250，终章 BOSS 300 / 360，完整表见 `encounters.md`。未来关卡未覆盖时使用 `45 + order × 12` 金币、`80 + order × 35` 经验作为回落基线。重玩已清关地图只获得 35% 地图奖励、35% 击杀金币及 35% 地图经验，避免第一关无风险无限刷最优收益。失败提供 25% 击杀金币，经验按已存活时长比例 ×25% 地图基础经验，不给予清关奖励和解锁。

奖励属于同一个 `runId` 的事务，结算按钮重复点击和重新渲染均不会重复发币。`settleLevel` 只能处理 `won|lost`，返回 `{ok, reward:{coins,xp,firstClear}, previousLevel, playerLevel, unlockedLevelId}`，界面用这个结果展示奖励。在 `startGame` 时生成新 `runId`，注入模拟而不依赖模拟内部读取时间。

重复结算历史按最近 128 个保存；同一网页生命周期另有 `savedResult` 防抖。战斗状态暂不持久化，不提供断点恢复，因此早于这 128 个的历史局不能再次提交；未来加入战斗断点续玩时必须改为单调结算序列或持久交易 ID，不能沿用有限历史假装全局幂等。

## 模块接口建议

```js
// progression.mjs：纯函数 / 受控原地修改，绝不调用 localStorage。
createProfile((raw = null)); // 迁移 / 净化为当前版本
levelFromXp(xp); // {level, earned, required}
profileStats(profile); // {damage, fireInterval, maxHp, armor, seedPower, pierce,
//  petUnlocked, petRank, petDamage, petInterval, level}
upgradeCost(profile, id); // 有效下一层价格；满层返回 null
purchaseUpgrade(profile, id); // {ok, reason?, cost?, rank?}
isLevelUnlocked(profile, id); // boolean
settleLevel(profile, state); // 幂等一次结算，返回上述奖励结构
registerGrowthDefinitions(definitions); // {ok,added? / errors?}，永久成长原子追加

// loadout.mjs：单关构筑与永久成长分离。
createRunLoadout((skills = ['blast', 'gale']), (firstXp = 12));
configureLoadout(state, { skills });
selectSkill(state, index);
gainRunExperience(state, amount);
drawUpgradeChoices(state, random);

// simulation.mjs：保留现有调用，新增参数可选。
createGame((levelId = 'ruins'), (seed = 42), (profile = null));
startGame(state); // 使用 state.profile，不重置永久成长
step(state, dt, input); // 继续最多 0.1 秒并细分至 1/60
```

`createGame` 持有净化后的成长快照 `state.profile`，开始 / 重试沿用。主界面在购买后用新成长快照重建 ready 预览；战斗中永久成长不可购买，保证成长快照稳定。`state.levelId`、`LEVELS`、旧图标辅助 `SEEDS` 和测试可观察快照继续兼容。第一次运行不强制购买成长；dev 分支原有自动地形、技能、武器构筑测试继续验证。界面速度属于墙钟到模拟时间的倍率，不修改状态中的技能伤害或经验曲线。

## 存档与离线可用性

准备、购买、结算、关卡选择后保存到 `bullet-garden.profile.v1`。`bullet-garden.best` 和声音选项保留各自旧键，无需伪造从 best 分数恢复关卡通关。读取和写入独立适配函数捕获 `localStorage` 拒绝或配额异常；内存中的战役仍可完成，界面明确显示“本次进度未保存”。写入完成之前不能显示“已保存”。不写鉴权、网络或平台绑定，后续 Game Host 存档适配可复用纯模型。

## 内容包与后续数百关

Dynamic Content schema 属于本 Game，遵循 ADR-0007。`registerContentPack` 提供经过整包校验的关卡、怪物、植物、天气和增益扩展；`registerGrowthDefinitions` 提供永久成长扩展。注册只接纳当前处理器支持的 `behavior/effect`，验证唯一 ID、关卡顺序、引用、非负权重、至少一种可出场怪物、边界内出生点、安全出生区与效果图。整个追加成功才修改共享目录，失败保留旧目录。内容包不得包含函数、代码片段或任意 URL 脚本；全新行为仍需要源码系统扩展。

地图生成使用明确种子和固定骨架，结合微调障碍坐标、通道和环境区域；同种子生成同地图，每关仍须提供独立效果图。战役显示列表只渲染可见行 / 当前章节，避免几百关的 DOM 按钮覆盖战斗。模拟容量继续有敌人 / 植物 / 子弹上限，新技能产生小兵也受敌人上限约束。阶段终局怪物不可因普通怪物占满上限而永久不出场，预留终局槽位或暂停普通刷怪。

## 验证边界

必要测试覆盖成长价格 / 等级边界、购买失败无修改、保存净化、奖励重复结算、下一关解锁、首领 / BOSS 必须击败、配置引用、地图安全区、各种怪物能力与天气增损，以及追加定义实际被商店和战斗使用。保留自动地形获取限制、碰撞、技能能量 / 取消、状态到期、武器构筑、暂停、确定性、五分钟和容量测试。浏览器验证包括 390×844 双指移动并施放武装技能、营地升级与重载保存、关卡选择、经验三 / 四选一、倍速、暂停图标形状，以及首领 / BOSS 预警实际画面；测试不得用可变 window 调试入口跳过游戏流程。
