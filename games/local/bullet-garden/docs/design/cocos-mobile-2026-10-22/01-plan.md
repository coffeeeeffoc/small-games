# 子弹花园：Cocos 手机重构（2026-10-22）

## 产品方向

竖屏俯视花园生存闯关，Cocos Creator 3.8.8 原生 Sprite / Graphics / UI 渲染。竖屏让移动、冲刺和技能在双拇指区域内完成，所有页面保持相同方向；浏览器只作为同一游戏的预览入口，不显示全屏按钮。保留已有花园、芽怪、植物祝福、枪械构筑和十四关稳定 ID，复用经过测试的纯模拟与存档规则。原 Canvas 页面不再是正式入口，不用把网页嵌入 Cocos 冒充迁移。

## 核心循环

首页继续冒险 → 选关或直接开局 → 摇杆移动、自动射击、冲刺避险 → 击杀积累经验 → 独立强化页选择祝福或枪械成长 → 到时停止刷怪、清理余敌及首领 → 结算金币与永久经验 → 解锁下一关、花园营地升级。

首关60秒，只教学移动和自动攻击；后续逐步开放怪物、天气、植物和技能。技能最多储存三次，玩家拖动技能按钮瞄准、松手施放，取消不消耗。地图身份与关卡绑定，避免普通开局随机抽图掩盖章节进展；天气按关卡推进，后期可变化。具体改动依据已有模拟能力实施，不为了新界面削减战斗机制。

## 页面与美术

1. 首页：暖色阳光中的石砌花园，叶帽守园人与发光种子武器，米金色标题“子弹花园”。下方一个主要“继续冒险”按钮，次级“选择关卡”，底部营地、帮助和设置。小型永久等级与金币，不铺设图鉴或数据面板。
2. 关卡：藤蔓串联的章节节点，每页少量关卡；当前节点显著，锁定节点同时用锁形和文字表达。清晰返回；选中卡显示时长、主要目标和新增威胁。
3. 战斗：上方紧凑生命、波次/剩余时间、经验；战场为大面积明亮花园，怪物轮廓与弹道清晰。底部固定深绿叶片操作带，左摇杆、右冲刺与两个技能，不覆盖关键敌人。暂停为两根分离实心竖条。
4. 强化：三至四张纵向大卡，图形、名称、实际效果；暂停模拟。暂停、结算、营地和帮助用清晰页面切换。
5. 图标与加载：方形无字图标，守园人/叶芽与金色种子弹环；启动加载使用同一图标、中文名称和实际进度，覆盖默认 Cocos 标志。失败有重试。

色彩：森林绿、苔藓绿、蜂蜜金、奶油白；敌方紫/红作危险色。素材按本次认可的花园与怪物效果图落实，已有美术匹配目标时复用，缺失部分补齐或重做，并新增品牌图。字体与按钮按手机尺寸设计，常用操作有效热区至少44 CSS px，安全区与平台胶囊留白。

## 激励广告

只使用玩家主动点击的激励视频，普通游玩、过关、选关、重试始终免费。失败页提供每局一次“复苏补给”：完整观看后恢复50%生命、3秒保护，继续未结算战斗；普通结束按钮不依赖广告。暂停页提供每局一次“花露补给”：完整观看后恢复30%生命，不增加永久奖励；满血不出现。每局最多两个机会，无横幅、插屏或自动播放。

复用仓库广告 provider，游戏只负责资格、幂等授奖和生命周期。短期仅启用明确配置的 TapTap 平台；build 配置注入平台、AppID与该游戏广告位，不硬编码或借用其他游戏 ID。不配置/SDK缺失即不可用，隐藏或提示后返回正常游戏。completed 才授奖；dismissed/unavailable/failed、重复/迟到回调、退出/重开不授奖。广告期间冻结模拟并清空输入，前后台不能意外解除暂停；native 与H5渠道须明确区分。

## 架构与验证

核心与关卡配置维持独立，原存档 bullet-garden.profile.v1 保留迁移和幂等结算。新 Cocos 场景负责呈现、触屏、资源与宿主生命周期；用构建步骤导入纯 JS 模拟，避免两套规则。浏览器宿主/原生 SDK 只在适配层。

验证现有规则与十四关平衡、广告状态和幂等、生产 Cocos 构建；手机320/390/430宽与横屏视口、独立及iframe；真实触屏输入走通首页、关卡、移动、冲刺、技能取消、强化、暂停、前后台、结算、解锁、旧存档及禁用存储。保存实际截图对照概念图。开发模式沿用统一 SmallGamesDev 且开发结算隔离。更新真实发布消费者与精确SHA候选验证，提交推送dev，分别记录本地验证、远端分支、CI与平台真机边界。
