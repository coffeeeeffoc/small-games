# Bullet Garden module contract

Native ES modules and Canvas 2D; no runtime dependencies. `WORLD` is1440×900, default arena x100..1340/y150..750. The campaign preserves the original11 stages and appends deepsoil/stonebloom/skyreach, for14 stages. Stable IDs and `order` drive completion, unlocks and extension.

## Data and extension

`config.mjs` exports `LEVELS`, `ENEMIES`, `SEEDS`, `WEATHER`, `WEATHER_MODIFIERS`, `BOONS`, `SKILLS`, `UPGRADES`, `WEAPONS`, and `registerContentPack`. SEEDS describe plant behavior and artwork; they are not manually selectable ammunition. BOONS grant ownership only through an offered run-XP upgrade.

Levels have `{id,order,unlockLevel,name,duration,waveDuration,waves,world,bounds,playerStart,plantCap,spawn,progression,terrain,weather,rewards,encounter,visual,enemyKinds,introducedEnemy}`. Stage one is60seconds/3waves, with reduced difficulty and only sprout; later stages have6waves and introduce at most one new enemy kind, including leaders and spawned minions. Both stage and player-level gates filter enemies; replaying stage one at high level cannot add species. Minimum player levels are `[1,2,2,3,4,5,6,6,7,8,9,10,11,12]`. Terrain is circular `{id,kind:'wall'|'mud'|'slope',x,y,radius,...}`. Weather is `{kind,wind,thunder}`; wind and thunder overlay one base weather. Encounter is null or `{kind,rank,atWave,required:true}`; required enemies must die before victory.

`registerContentPack({version:1, levels:[], enemies:[], plants:[], weather:[], buffs:[]})` validates the complete append-only JSON pack before changing stable catalogue containers. Definitions are frozen; IDs/order cannot replace existing content. `validateContentPack` in content-schema.mjs checks references, supported handlers, finite bounded values, art references, safe player spawn and connected traversable arena. Register before creating a run. A new behavior requires a source handler; JSON cannot execute code.

Enemy definitions combine hp/radius/speed/damage/xp/coins, rank, armor, controlResistance, shield, unlockStage/unlockLevel and `abilities:[{type,...}]`. Supported abilities are controlResist/charger/brood/burrower/glider/spitter/shield/shieldBreakStun/bossPhases. Plants use effects slowAura/damageAura/block/explode/healAura/chainLightning/shoot. Catalogue `unlockPlayerLevel`/`unlockLevel` fields gate skills, boons, upgrades and weather. Visuals consume the same geometry as collisions.

## Permanent progression

`progression.mjs` exports createProfile, levelFromXp, profileStats, upgradeCost, purchaseUpgrade, isLevelUnlocked, settleLevel, registerGrowthDefinitions, PERMANENT_UPGRADES and UPGRADE_DEFINITIONS. The registry powers shop, validation, saves and stat aggregation. Permanent profile and run XP remain separate.

Profile remains `{version:1,xp,coins,completed:[],settledRuns:[],upgrades:{},equippedWeapon,equippedPet,selectedLevelId}` under `bullet-garden.profile.v1`; existing permanent XP, coins and upgrade ranks are preserved. Purchases mutate only after all guards pass. Terminal runs settle once by a nonempty `runId`. First clear earns full rewards; replay35%; loss25% partial rewards. The last128 receipt IDs persist; active runs are not saved or restored. A profile cannot be used as a saved combat session. `settleLevel` rejects `developerRun`, `dev` or `runOptions.dev` without changing XP, coins, clears, upgrades or settlement history.

Stats include damage/fireInterval/maxHp/armor/seedPower/pierce/level/petUnlocked/petRank/petDamage/petInterval. Player level5 unlocks the helper. Plant/boon routes open gradually: shrub1, trench/sunflower2, frost/ice3, poison/mushroom4, stormreed5, bloomturret6; their run boon still requires acquisition. A stage requires both its previous clear and configured permanent level. The unchanged XP curve requires115XP forLv.2; the first ruins clear awards115. Cumulative first-clear rewards meet every next-stage gate without required replay farming. Main handles localStorage and visible save failure; the model never reads storage, wall clock or DOM.

## Simulation

`createGame(levelId='ruins',seed=42,profile=null,options={})` creates a serializable ready preview. Options accept `{dev,weather,map,skills}`. Ordinary runs automatically roll weather, map and up to two distinct skills from unlocked catalogues; map order cannot exceed the chosen campaign stage. Lv.1 has no skills. Lv.2 unlocks blast/gale, Lv.3 cart, Lv.4 horse and Lv.5 laser. Only `dev:true` honors manual options; normal overrides are ignored. Main supplies fresh random seed and UUID on every start.

`getRunLevel(state)` merges campaign combat rules with the selected map's visual/arena definition and run weather; use it for bounds and rendering instead of assuming `LEVELS[state.levelId]` is the selected map. `getAvailableEnemies(levelId,permanentLevel=1,dev=false)` applies stage and level gates. `startGame(state)` resets combat/run XP/energy/boons while preserving profile, `runOptions`, rolled configuration and caller-injected runId. `configureLoadout(state,{skills})` accepts two distinct known skills outside combat only in developer mode.

`selectSkill(state,index)`, `castSkill(state,target,index=state.selectedSkill)`, step, chooseUpgrade, pauseGame, resumeGame and dash retain their gameplay roles. Legacy selectSeed/castSeed return false. Each run starts with empty terrain/plants/boons; authored map obstacles are not loaded into battle. Only acquired boons generate plants. Kill XP offers up to3 choices, expanding to4 at run level5, filtered by permanent player level, prerequisites and bounded ranks; wave transitions do not award upgrades. Unassigned/locked skills cannot be cast.

Each skill slot stores at most3 casts (`SKILL_CHARGE_CAP` in loadout.mjs), represented by energy0..300. Casting subtracts100, preserves partial charge, and retains the0.3s shared release cooldown. Main stays armed after casting if another charge remains. At `time >= duration`, ordinary spawning stops and a single clear-ready event fires; time and combat continue. Winning additionally requires zero living enemies and any required encounter defeated.

Ordinary bullets never grow terrain. Weapons retain multishot/burst/ricochet/ice/fire/explosive/split upgrades. `source` distinguishes normal/seed/pet/plant/skill/enemy damage. `layer:'ground'|'air'|'underground'` controls legal targets; burrowing and flight expire and have visible transitions. Shields precede armor; contact damage uses player armor. Piercing bullets record hit IDs to avoid repeating a hit across frames. All entities have caps; a required encounter has a reserved spawn slot.

State includes phase ready/playing/paused/upgrade/won/lost, time/duration/wave, profile/permanent, dev/runOptions/runConfig/mapId/availableEnemies/availableSkills, loadout/skillSlots/selectedSkill/skillCooldown/skillEffects, boons/boonTimers, progression, player/pet, enemies/plants/bullets/particles/floaters/telegraphs, terrain/weather/encounter, upgrades/upgradeChoices/stats/events, randomState and runId. Skills/statuses/weather/terrain freeze outside playing. Renderer never consumes battle RNG.

`world.mjs` exposes terrainSolids, terrainPointBlocked, terrainMovement and weatherStats. terrainMovement returns speedMultiplier and optional slip displacement; all displacement passes through common collision movement. Slip RNG is evaluated at slope entry, not every frame. Weather hazards have timed visible circles before damage.

## Renderer and controls

GardenRenderer exposes resize, render, screenToWorld, worldToScreen. `planting` means an armed skill. drawSeedIcon supports skills, boons, plants and shop icons; drawPortrait draws the gardener. Canvas context loss pauses play and cache restoration invalidates textures. Artwork caches are bounded; offscreen culling never alters simulation.

Stable selectors remain start/pause/resume/restart/arena/joystick, `[data-skill-slot]`, `[data-upgrade]`, cast/dash/game-speed. Manual loadout-skill-0/loadout-skill-1 and dev-weather/dev-map controls live inside dev-controls. Speed values1/2/3/5 are app timing multipliers, recorded in read-only snapshot.controls.speed. Page selectors include ready-campaign/ready-shop/ready-last-result/result-home, `[data-level]`, `[data-purchase]`, close-campaign/close-shop, reward-coins/reward-xp/reward-note/save-status. Campaign pages render at most12 rows. Each page fills the viewport with its own scroll; body.dataset.screen identifies the only visible screen. The result page returns home; last-run review is session-local and never settles again. Tactical controls live below the Canvas.

`home.mjs` renders current player level, currency, completion count, nearby selectable stages and six catalogues through `[data-catalog]`: monsters, boons, weapons, skills, plants, journey. Home stage buttons use `[data-home-level]`; status distinguishes cleared/replayable, available and locked, with prior-clear/player-level requirements. Full campaign and permanent shop remain accessible. Stable IDs include home-player-level/home-progress/home-level-list/catalog-panel/close-catalog/catalog-shop; battle-home is the lightweight return entry.

Main enables developer mode only using URL `?dev`, `?dev=1` or `?dev=true`. Removed/false dev parameters disable it; the old localStorage developer flag no longer activates it. All level selections and manual weather/map/skill options become available without granting permanent stats. Developer runs show the normal overview but skip rewards, completion and best-score updates; progression also guards settlement independently. snapshot.controls.developerMode exposes the active flag and is not mutable.

Touch follows arm→target→pointerup; unarmed field touch only aims, cancellation never spends energy. Joystick and target use independent pointers. Keyboard1/2 selects skills, E/right-click confirms, Escape cancels aiming before pause, Space dashes. Focus/visibility loss clears controls. Pause uses two separate filled SVG rectangles with aria-label="暂停". Restart returns to preparation with permanent growth retained.

window.\_\_bulletGarden.snapshot() and .profile() return deep copies only; no mutable test shortcuts. Tests may import pure modules for controlled fixtures, while public browser flow uses native input.

## Landscape and fullscreen

`display.mjs` exports setupDisplay, isMiniGameRuntime, landscapeViewport, clientToElement and elementToClient. Touch capability is retained for the page lifetime, so switching the primary pointer to a mouse does not remove the landscape layout. Touch and minigame entries attempt `screen.orientation.lock('landscape')`. Portrait viewports fall back to automatic clockwise CSS rotation of the entire logical game, with corresponding inverse pointer transforms for joystick and arena. Renderer sizing uses logical canvas clientWidth/clientHeight. Browser direction lock is best effort; it is not a guarantee of operating-system rotation.

Web entries always expose `#fullscreen`; a user click requests/ends native fullscreen with failure feedback. HUD controls reserve the button's measured logical width plus a 10px gap; label and font changes refresh this space without using rotated bounding-box widths. The same-origin Shell `[data-game-display-host]` is preferred when it owns the game iframe; cross-origin embeds need host fullscreen permission. Minigame entries omit the button. Detection recognizes GameGlobal, supported SDK canvas/system-info APIs, and known minigame query values including `?runtime=minigame`; a wx SDK object alone in the WeChat browser is not enough. Display refresh/reset preserves mapped touch behavior on resize and orientation changes.

The focused fullscreen regression is `pnpm --filter @coffeeeeffoc/bullet-garden test:display-browser` against a running source or dist server. It verifies native pointer hit areas, fullscreen/exit, pause/restart, portrait/landscape, offset iframes and touch capability changes. The existing Pages gameplay gate also checks HUD separation after touch-session detach and while fullscreen.
