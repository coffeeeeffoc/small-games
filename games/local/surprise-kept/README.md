# 惊喜别穿帮

暖色插画风的目击记忆谜题。八关生日故事，两位朋友、三个箱子、礼物与钥匙；没有倒计时，也不限制撤销次数。

## 运行

在仓库根目录执行：

```powershell
pnpm --filter @coffeeeeffoc/surprise-kept dev
```

打开 http://localhost:4448 。`?level=3` 直接进入参考图对应的第三关。也已登记到 Web Shell，路由为 `#/games/surprise-kept`。

```powershell
pnpm --filter @coffeeeeffoc/surprise-kept test
pnpm --filter @coffeeeeffoc/surprise-kept build
pnpm --filter @coffeeeeffoc/surprise-kept test:browser
```

构建产物是 `dist/` 的静态文件，使用相对路径，可放在网站任意子目录。浏览器测试自行在 4459 端口启动 **构建产物**，截图和报告保存在仓库 `test-results/surprise-kept/`。

## 怎么玩

- 拖动物品到箱子；也可选择物品，再点目的箱。双物品关卡用上方「礼物 / 钥匙」切换。
- 点人物，请他去倒茶；再点人物或茶桌，叫他回来。本关不能离席的人会明确提示。
- 屏风可拖到人物面前，也可点「遮挡一次」再点人物。
- 点记忆气泡查看每件物品的最后目击。时间轴记录搬运、谁看到、谁因倒茶或屏风而没看到。
- 揭晓时人物按各自的记录先去找，逐条检查目标。错误安排也会真实演出，可返回撤销；回放不修改当前安排。

固定规则：只有有效搬运更新目击者对**被搬物品**的记忆。返回、读记录、同箱拖放均不更新记忆。屏风布置时扣库存，遮挡选中角色的下一次有效搬运，搬礼物或钥匙都消耗；被遮挡者离开也不会把屏风保留到更晚的搬运。两件物品可以放在同一个箱子。钥匙在本章是独立的信息载体，没有隐含开锁条件。所有角色回来才能揭晓。

## 代码边界

| 目录                    | 职责                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------ |
| `src/core/`             | 纯规则、状态转换、目击事件、目标判定、数据校验；没有 DOM、主题图形、计时器或存档依赖 |
| `content/manifest.json` | 主题文件与章节文件目录；关卡数量来自内容                                             |
| `content/themes.json`   | 房间主题名称、横幅、墙/地板/窗帘/装饰颜色                                            |
| `content/chapters/`     | 每关初始真实位置、每人记忆/在场、资源与权限、目标、提示和参考解                      |
| `src/content/`          | 加载与导入校验；重复 ID、未知主题、错误物品/人物/箱子会被拒绝                        |
| `src/render/`           | 原创 SVG 插画及 DOM 渲染、中文事件说明；不决定目击规则                               |
| `src/input/`            | Pointer Events、拖动预览、命中检测、取消/移出/多触点处理                             |
| `src/runtime/`          | 当前关卡、完整状态历史、撤销、时间轴回放、揭晓演出、弹窗与生命周期                   |
| `src/platform/`         | 可降级的本地保存、用户手势解锁的合成音效                                             |

## 扩展关卡与主题

1. 复制 `content/chapters/birthday.json` 中的关卡数据，赋予唯一 `id`，修改初始状态、规则与目标。不要在运行核心中增加关卡编号分支。
2. 新章节格式为 `{ "id": "chapter-id", "title": "章节名", "levels": [...] }`，在 `manifest.json` 的 `chapters` 追加相对路径。核心没有八关上限；每个导入章节最多 300 关、文件最多 2 MB，章节数不限。
3. 每关 `theme` 引用 `themes.json` 中的 ID。新主题可增加色板和横幅而不修改规则；增加新的房间布局或插画种类属于渲染层扩展。
4. 可在选关页的「导入自己的故事章节」立即试玩 JSON。导入只在当前会话保留；要正式发行需加入内容目录。
5. `solution` 可省略；运行时从不自动执行它。`recommendedSteps` 是提示中的参考步数，不是失败限制。内置关卡使用独立状态搜索验证参考步数与可解性。

关卡字段：

- `items`：`gift` 和/或 `key`。
- `initial.locations`：各物品实际箱子，箱子为 `red / blue / green`。
- `initial.characters.blue/orange`：`present` 与每件物品的 `beliefs`。初始错误记忆合法，显示为「开场前最后目击」。
- `rules`：`screens`、`maxAway`（1 或 2）、`canLeave`、`movableItems`、`requireEveryoneHome: true`。
- `goals.locations`：需要检查的实际位置；`goals.beliefs.blue/orange`：需要检查的首次寻物目标。可以只约束部分物品，但每个角色的映射必须存在。
- `title / intro / objective / hints`：玩家文案，按文本渲染。

新增箱子或角色不是普通关卡配置：当前产品明确为两人三箱，需同时扩展核心 ID 校验、布局和测试。支持任意数量的关卡不意味着支持任意新增规则。

## 验证与交付边界

规则与内容测试覆盖八关解法、独立搜索、屏风耗尽/无效动作/错误时机、初始错误记忆、单物品更新、状态不可变、撤销分支、未来配置和存档失败。浏览器脚本通过真实触屏点按走八关，并验证触屏拖拽/取消、撤销、回放、恢复、失败解释、动态第九关、不同屏幕宽度以及 Shell 共用检查在 iframe 中运行。

本次为 Web/H5 游戏。未进行实体 Android/iPhone 验收，未实现微信/B站原生 Canvas 入口、真实广告或付费章节。参考图用于构图、暖色描边与物件风格；所有图形由本项目 SVG 独立绘制，没有把参考截图作为游戏背景贴图。
