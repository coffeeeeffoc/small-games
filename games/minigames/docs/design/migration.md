# Cocos 小游戏迁移设计

## 范围与复用

仅迁移围捕小队、街区追逐、象棋五子棋。旧 H5 页面继续发布到 GitHub Pages。三个独立 Creator 工程使用共享运行层，避免跨平台 SDK、引擎生命周期和构建产物侵入旧页面。

保留原纯规则、关卡、AI、存档格式与现有美术；通过构建时打包导入原模块。实时警匪与象棋复用已存在的原生 Canvas 控制器；回合制警匪在新目录维护展示控制器，补齐五模式，规则和搜索仍直接导入旧源码。提示仅使用已有认证答案的后续步骤，偏离已验证路线时明确反馈，没有重复实现搜索器。

## 渲染与移动端交互

采用宿主真实离屏 Canvas2D 绘制、Cocos Texture2D 上传和 Sprite 显示；启动场景、相机、屏幕尺寸和输入由 Cocos 管理。游戏不通过 WebView/DOM 运行。此阶段保留现有 Canvas 展示代码，以降低移植与 H5 回归风险；不是把所有图元改成 Cocos 节点。后续若真机上传耗时成为瓶颈，可按画面层逐步改为 Cocos Sprite/Graphics，而不动规则层。

回合制警匪和象棋为竖屏，实时警匪为横屏。设计沿用已有概念与实测图：

- `games/local/cops-robbers/docs/design/native-2026-10-06/`：主页、游玩、选关。
- `games/local/cops-robbers/docs/design/`：五模式与角色/先手既有设计。
- `games/local/cops-robbers-realtime/docs/design/`：街区和场内指令。
- `platforms/competition/xiangqi-five/docs/design/`：主页、棋盘、训练。

主要路径为主页、选关/准备、游玩、暂停、结算、继续或返回。对抗角色与先手放在单独准备页；普通关卡遵守解锁进度。五模式按钮与热区覆盖 320×568 安全区测试，棋盘对象直接触控。象棋保留大棋盘拖动、双人、电脑和训练；实时警匪保留场内指挥、冲刺/回溯支援。

Cocos 触摸事件是唯一输入入口，鼠标使用引擎自带的触摸合成。多指、移动、取消、后台恢复统一处理；恢复时先更新视口和安全区。原生宿主事件保留邀请参数。离屏 Canvas 与引擎主 WebGL Canvas 必须是不同对象。

DPR 上限 1.5、像素预算约 200 万；纹理仅在尺寸变化时重建。实时画面上传上限 30 Hz，原模拟继续按 60 Hz；棋类按实际绘制上传。实时控制器当前静态页仍周期重绘，不能把桥接层的脏帧测试当成该控制器静态零上传的证明。

## 验收标准

- 三个包均通过真实 Creator 编译和引擎类型检查，TapTap 经过固定官方插件转换。
- 真正的引擎浏览器产物显示非空画面，鼠标与触摸能操作真实棋格/节点，暂停、恢复、主页和训练结算可达。
- 每个平台检查方向、真实输出入口、包体预算、AppID、源文件与产物清单。未知渠道/第四款游戏/未审核构建脚本不自动放行发布范围。
- 既有 H5 的源码、目录登记、构建入口不改；按仓库增量门禁回归 Pages 与开发者模式。
- 真机仍需检查离屏纹理上传、触摸取消、刘海/胶囊安全区、低端机帧率、音频、存储、登录、广告与分享。报告清楚区分引擎浏览器、官方转换和实际设备。

## 已知边界

跨渠道存档无法自动共享；浏览器预览与旧 H5 存档隔离。两款警匪联网维持最新 dev 的关闭状态。象棋沿用现有原生 AI 预算；原生界面与 H5 的 DOM/Worker 实现不承诺逐像素或计算预算一致。Creator 3.8.8 不支持百度；快手依赖外部官方工具适配，未提供经验证的无头转换器。
