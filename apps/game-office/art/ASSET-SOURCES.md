# Office sample asset provenance and reproduction

## Human source

- Official Blender Human Base Meshes bundle v1.0.0: <https://download.blender.org/demo/bundles/bundles-3.6/human-base-meshes-bundle-v1.0.0.zip>
- ZIP SHA-256: `46a912c0524072ac3b78c35d5d2471df7b8df102394a050ca8cd7184e3393648`.
- Imported objects: `GEO-body_male_realistic` and its two eye meshes. The body has 15,093 source vertices before subdivision and adaptation.
- Creator credit retained: **Julien Kaspar / Blender Studio**.
- The source collection `Body Male - Realistic` records `asset_data.license = CC0`; the bundle's `README` text states that all provided assets are public domain under CC0. The source is allowed to be modified and incorporated in rendered game assets.
- An unrelated legacy text block named `License` mentions the Rain Rig and CC BY 4.0. This sample does not import Rain Rig objects or rig code. The selected human collection's explicit CC0 metadata and bundle README are the provenance used here; this distinction is recorded rather than silently deleting source information.
- CC0 deed: <https://creativecommons.org/publicdomain/zero/1.0/>.

The three characters share this anatomical base mesh. Clothing shells, hair regions, a compact anatomical rig, contact targets, small expression deformations, the office, lighting and animation timing are authored in `build_scene.py`. This is an interactive animation sample with basic procedural skin/hair/fabric, not a claim of photorealistic skin scans, professional motion capture or AAA facial animation.

## Reproduce

From the repository root, with Blender 5.2.1 and Python with Pillow available:

```powershell
python apps/game-office/art/fetch_source.py
& 'D:\setup\Blender\blender.exe' --background --factory-startup --python apps/game-office/art/build_scene.py -- preview
python apps/game-office/art/render_all.py 'D:\setup\Blender\blender.exe'
```

`--cpu` after `preview` or `render` uses CPU Cycles when GPU/shared memory is unavailable. The raw download, unpacked library, `.blend` snapshot, render frames and previews are local ignored build products. The reproducible scripts, source credit and packed game assets are tracked. No external asset package is downloaded by the running game.

`render_all.py` uses one CPU Blender process at a time with four threads and at most three frames per process, releasing memory between chunks. A long Cycles process exhausted system commit memory in this session; six-frame chunks also reached approximately 2.8 GiB of private memory, so the final runner uses smaller chunks. Its ignored progress file permits restarting after interruption and preserves already completed larger chunks. It derives normal and quick stow from the exact pickup frames in reverse, then invokes the packer. This avoids re-rendering the same pose path with slightly different contact positions.

## Audio

The WAV files under `public/office-scene/audio/` are original procedural sound modeling and synthesis generated by `generate_audio.py` in this directory. They do not incorporate a downloaded Foley recording, commercial sound library, real employee voice, or music recording. These are sample interaction and environmental sounds; they are not presented as recorded human dialogue or a final cinematic mix.

## Runtime contract

The fixed scene is 390 × 500 logical pixels, displayed at y = 90 in the 390 × 844 game view. Atlas rectangles use source-image pixels; `draw` rectangles and hotspots use scene coordinates. Background, boss, player, and foreground are composited in that order. PNG atlases are cropped on a common bound per clip with transparent padding, preserving contact positions between states.

The locked camera and employee are on opposite sides of the monitor. The prototype initially assigned the dark camera-facing panel as a display, which was a spatial error. The runtime explicitly renders that visible panel as a monitor back with ventilation details and shows the employee's actual computer content in a labeled picture-in-picture view. `screenCorners` therefore locate the visible back-panel overlay in this sample; they must not be used to paint an employee-facing spreadsheet directly onto it. A later side-camera composition should resolve the source layout before final art production.

The phone starts screen-down on the desk. Pickup first reaches the phone, then maintains a rigid hand/device transform. Stow reverses the same contact path and switches the screen off before the hand returns to the keyboard. The first sample therefore uses a visible desk return; the drawer is an environment prop and action hotspot, not an animated opening drawer.

`pack_scene.py` checks that every clip contains actual changed rendered pixels, no frames are empty, and final atlases fit within 2048 × 2048. It records compressed download bytes and decoded RGBA bytes in the final manifest. These are asset checks; platform frame rate, input timing and perceived realism require the runtime checks and playtesting described in the design plan.
