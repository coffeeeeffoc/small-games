# 2026-10-09 main 累计同步的范围证明

此次用户要求完成夜航守望改版后推送 dev，并将 dev 合并到 main。同步基线为 `b551fe6e7d7f2bc1229e2e1d44666a878eec5a07`，既有 dev 为 `bc3b386c435edc0e126f38065d4c496a10488c46`。main 是 dev 的祖先，相差 116 个既有提交。

预检发现单次变更分类规则无法证明累计的两个工作流与锁文件差异，因而按规则阻止发布。本次补充只接受下述已审查的完整文件哈希组合，不修改工作流执行、依赖或任何校验开关。

- CI/Pages 的规划步骤读取锁定的象棋子模块，并安装根清单指定版本的 Prettier 解析器；CI 还包含现有原生验收开关。其准确文件版本已由原有逐次分类规则接受，现在允许从已审查的早期版本累计到达同一准确版本。任意权限、命令、依赖版本及额外字节变化继续阻断。
- 锁文件仅增加五个游戏的 importer/本地链接（cage-rescue、flick-arena、retreat-rally、three-choose-two、tower-brake）、支付宝和 TapTap importer/本地链接、travel-bund 对已有 draco3d/esbuild 的引用、runtime-api 对 three-choose-two 的本地链接。外部 packages、snapshots、完整性值和工具链没有变化。
- 锁文件消费者严格等于实际变化的 11 个 importer：上述五个游戏、travel-bund、两个平台、shell-web、shell-minigame、runtime-api。测试从历史 Git 对象检查完整依赖解析不变、消费者集合精确相等，并拒绝更改链接、完整性值、基线或候选内容的样例。
- Shell 清单与锁文件的原有联合证明也会被累计的平台变更打断；补充仅接受上述准确锁文件与准确 Shell 清单组合，并验证清单差异只有五个游戏的 `workspace:*` 链接，其范围仍仅为这五个游戏。

该证明不赋予未来锁文件变更通用许可。后续任何未匹配变化仍必须提供范围证明。发布继续对远端实际 base 和最终准确 head 执行正常候选校验与 pre-push hooks。

累计校验还发现两项既有测试问题并修复：依赖边界测试统一 Windows 诊断路径的分隔符，保留 8 个非法引用断言；城堡火炮入口在 CI run `37832284486` 中固定按住 450ms 后仅蓄力 14.8%，改为从可见按钮等待至少 25% 蓄力再松手，仍断言真实发射威力大于 15%，且用 finally 释放触屏或鼠标。该入口测试的精确源码指纹同步更新，范围仍仅为城堡火炮。

词屿好友竞技浏览器测试保存截图时使用了 URL.pathname，Windows 产生重复盘符。所有截图调用改用 fileURLToPath；三种触屏视口的真实拼词、取消/拖拽/多点触控、结果与返回，以及两种窄屏 iframe 流程重新通过。
