# Chromium 140 输入回归修复

失败基线：dev、main 均为 `3d7b7b01eb6e2204ff4746937ced76af4e811abc`。

## 远端证据

- dev CI `37839397077` 与 Pages `37839397731`：一炮拆城触屏望远镜断言失败，期望 `scope=true`，实际 `false`。
- main CI `37839400138`：一炮拆城确认离开后仍为 `confirm`；Pages `37839401665` 同时出现望远镜失败与笼中救援拖动后暂停失败。
- main 定时 Pages `37855140872`：同样在一炮拆城触屏望远镜检查失败。
- 上述任务中的构建和夜航守望检查通过；错误发生在实际浏览器交互阶段。

## 复现与修复

本地新版 Chrome，包括软件渲染及 CPU 降速，未复现望远镜问题。安装与 CI 相同的 Playwright 1.55.1 / Chromium 140.0.7339.186 后，原有 `assertCastleDuelEntry` 在同一断言失败。事件记录显示按钮收到 `pointerdown`、`pointerup`，随后是 `pointerType=touch, detail=0` 的 `click`。

一炮拆城把所有 `detail=0` 的点击视为键盘操作，导致已经由指针松手处理的动作再执行一次。现在只将没有指针来源的点击转交键盘操作通道，保留原有鼠标、触屏、取消和键盘操作。新增 `definition.test.ts`：修复前断言失败，修复后通过，覆盖 touch/mouse/pen 的零 detail 点击以及键盘点击。

笼中救援原有 `assertCageRescueGameplay` 在同版浏览器中复现拖动后暂停失效。追踪显示暂停收到触屏事件，但未生成 click。移除拖动结束后立即断开 CDP 会话的操作后，原有断言连续 20 次通过。会话随调用方的手机页面 context 关闭；`pages-smoke.mjs` 已在 finally 中关闭 context 并断言资源释放。未改变游戏逻辑或降低断言，更新发布范围检查的完整源码摘要，范围仍仅为笼中救援。

## 本地验证

- 一炮拆城：65 项单元测试、构建、类型检查、lint 通过。
- Chromium 140 软件渲染：一炮拆城 390×844 触屏与 1280×800 鼠标，蓄力发射、望远镜、暂停恢复、确认离开，各连续两轮通过。
- 笼中救援：Chromium 140 / 390×844 触屏，发球、拖动、暂停恢复及返回主页连续 20 轮通过。
- 正常 pre-push 钩子继续对最终候选 SHA 执行受影响项目与依赖检查；以推送后对应 SHA 的 CI/Pages 结果作为远端验收。

验证为桌面浏览器与触屏模拟，没有进行手机真机或原生小游戏平台验收。
