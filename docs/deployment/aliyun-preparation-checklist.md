# 阿里云部署准备清单

核验日期：2026-09-23。对应六款游戏当前实现，进度见 [本轮记录](../plans/2026-09-23-six-games-online.md)。本轮没有购买资源、注册账号或部署正式环境；测试隧道不作为正式服务。

## 首期资源与容量边界

建议先准备 **1 台 ECS、1 个主域名、1 个 PostgreSQL 实例**。数据库同机时无需另购数据库服务器；采用 RDS 时购买 1 个托管数据库实例，不再增加应用 ECS。六款游戏不需要六台服务器、六个域名或六套数据库。

| 对象 | 首期数量 | 用途及边界 |
| --- | ---: | --- |
| ECS 虚拟服务器 | 1 | Linux，运行应用及反向代理；这是租用实例数，不是独享物理宿主机承诺 |
| 游戏业务进程 | 2 | runtime-api；kart-server 权威模拟。卡丁车无需重写到 HTTP 进程 |
| 公网反向代理 | 1 | TLS、静态 H5、公开 API、WSS；拒绝 internal、管理与工作区路径 |
| 数据库服务实例 | 1 | PostgreSQL；同机 1 个数据库进程，或同地域 RDS；业务数据使用 runtime schema，管理数据保持 management schema/独立角色 |
| 管理业务进程 | 0（按需 1） | 本轮 PK 无需启动 Management Service；若以后使用 Creator Studio，仅通过管理网络开放 |
| 主域名 | 1 | 示例 `example.com`，仅占位，需用户自己注册或指定已有域名 |
| 对外子域名 | 1（推荐） | `games.example.com` 下 `/games/`、`/api/competition/v1/`、`/kart`；确需拆分时增加 api、realtime 子域名，不增加主域名 |
| PostgreSQL 逻辑数据库 | 开发、测试、生产分别隔离 | 可以在同实例分库；production 不导入 competition_test 的测试账号或成绩 |
| Redis、消息队列、Kubernetes | 0 | 当前没有必要；不以六款游戏数量推导进程或机器数量 |

面向中国内地小规模试运营，优先评估华东2（上海）或华东1（杭州），ECS 和 RDS 放同地域 VPC。首期建议 **4 vCPU / 8 GiB、80–100 GiB ESSD、5–10 Mbps 固定带宽或限制峰值的按流量带宽**；它是等待云上压测的起点，不是容量承诺。固定带宽和按流量的峰值保障不同，地域也影响费用；最终购买前用所选地域、规格、出网流量和备份空间做报价。[地域选择](https://help.aliyun.com/zh/ecs/user-guide/regions-and-zones)、[带宽计费](https://help.aliyun.com/zh/ecs/public-bandwidth)、[计费项](https://help.aliyun.com/zh/ecs/billing-overview)。

当前实测：WSL PostgreSQL 12.22 仅作本地开发替代，本轮查询链路在 102 个独立测试玩家、20 次串行全量排名查询下 p50=1.51ms、p95=1.85ms（首次运行）；有真实双 WebSocket 权威竞赛检查，不等于 16 房并发压测。正式目标沿现有 Compose 使用受支持的 PostgreSQL 17，需再执行相同迁移/恢复/性能验收。证据 `.scratch/competition/integration.json`，后续复跑数值以本轮记录为准。

首期运营假设为 10–30 人同时在线、最多 4 个双人卡丁车房，其余为低频题目/棋步挑战；这是计划限额，**尚无相应云端并发测量**。开通前要测 4 房卡丁车 + 实时围捕轮询 + H5 冷启动下载混合负载。扩容触发：权威 tick 连续超过预算、HTTP p95 >200ms、错误率 >1%、CPU 持续 >65%、内存 >75%、数据库锁等待/连接池排队、磁盘 >70%、带宽长期接近购买上限。先定位瓶颈，静态资源出网压力大时再接 OSS/CDN；数据库 IO 或恢复要求上升时迁 RDS；卡丁车 CPU 饱和才拆 ECS。

## 同机数据库与 RDS

| 选择 | 成本与责任 | 适用条件 |
| --- | --- | --- |
| ECS 同机 PostgreSQL | 少一项托管实例费用；应用、数据库与磁盘共享故障域。用户负责安全更新、备份外存、容量、故障恢复和恢复演练 | 封闭测试/数据可重建阶段，可接受维护中断；每日离机备份，不能仅靠同盘副本 |
| 同地域 RDS PostgreSQL | 增加实例、存储与可能的超额备份费用；按所选高可用产品获得托管能力，仍需用户验证应用恢复和权限 | 公开试运营、有持续真实用户数据，要求更可控的备份恢复或独立资源时优先 |

不写未经报价的固定月价。先保留购买页报价截图/配置单，分别填 ECS、系统/数据盘、带宽/出网、RDS、备份/快照与域名年费；不要拿促销首年价当续费价。RDS 的备份免费额度和计费依实例形态而异，按当时官方说明核算。[RDS PostgreSQL 备份费用](https://help.aliyun.com/zh/rds/apsaradb-rds-for-postgresql/billable-items-and-pricing-for-the-backup-storage-of-an-apsaradb-rds-for-postgresql-instance)。

## 备案与平台资格分开确认

域名实名、网站ICP备案、小游戏主体资质/应用备案/审核是不同事项，任何一项完成都不能替代其他项。中国内地网站使用域名开通Web服务需要ICP备案；域名已备案但更换接入商可能还要接入备案。境外地域不能被解释为“所有平台资格都无需办理”。具体主体、经营方式和省份的适用要求需在官方申请入口核验。[阿里云不同场景备案说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/product-overview/faq-about-icp-filing-applications-in-different-scenarios)、[跨地域说明](https://help.aliyun.com/zh/ecs/cross-region-usage-faqs)。

B站官方说明登录code由服务端交换openid/session_key，密钥不能下发；openid只在对应小游戏内唯一。分享接口与启动参数是原生链路，网页链接不代表原生邀请验收。[小游戏登录](https://miniapp.bilibili.com/small-game-doc/open/login)、[服务域名](https://miniapp.bilibili.com/small-game-doc/guide/urlwhitelist)、[原生转发](https://miniapp.bilibili.com/small-game-doc/open/share/share)。

微信使用官方 [wx.login](https://developers.weixin.qq.com/minigame/dev/api/open-api/login/wx.login.html) 与 [auth.code2Session](https://developers.weixin.qq.com/minigame/dev/api-backend/open-api/login/auth.code2Session.html)。本次公开文档抓取返回不可访问，不能据此声称已核验最新主体审核细则；正式发布前必须在用户有权限的微信后台重新确认逐款资质、合法域名与体验权限。密钥仅通过服务端Secret交付。

## 正式发布、迁移与回滚

1. 用户先确定主体、地域和上述资源；实施者拿到必要权限后在独立预发库配置12应用身份。不得把本机测试库导入生产。
2. 从明确commit构建H5及12原生目标，固定比赛规则版本。服务部署包含 `services/runtime-api/rules` 与这些规则复用的游戏纯模块，不能只复制 `dist/app.js`。
3. 使用迁移专用owner执行既有初始化及010迁移，应用改用runtime角色；验证管理schema不可读、数据库不对公网。
4. 公网反向代理只转发公开比赛HTTP和`/kart`；internal接口仅本机+内部密钥。Secret更新先配置两端，再验证真实权威结算和补交队列。
5. 先预发双客户端完整玩法、伪造/越权/重复/重启、Top100/榜外排名，再逐款微信/B站开发工具、体验版、实体两手机验收。关闭工具域名校验仅用于开发，不能算正式域名通过。
6. 发布前做离机备份及新库恢复，保留上个应用制品和规则版本。发生问题先停新比赛、让已开始比赛按已固定版本结束或明确中断，回滚应用；数据库不做破坏性回退，必要时从备份恢复到新库再切换。
7. 完整链路和冻结质量门槛未满足时保留未通过项，不宣布全面上线。
