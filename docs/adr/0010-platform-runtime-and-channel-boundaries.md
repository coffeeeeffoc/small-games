# 运行环境、渠道适配与单款发行分离

状态：目录管理部分已实施，其余架构调整仍为提议。
目录管理部分已实施：微信/B站独立 workspace 包迁入根目录 `platforms/`，运行入口与工程配置由渠道包拥有。更深的语义端口和海外浏览器路径仍是后续提议。

## 背景

平台将逐款接入微信、B站及更多国内外渠道。现有 Game Host 与 Canvas 目标已经隔离游戏和宿主；`native-game-shell` 提供共享生命周期与媒体处理，但 `NativeSdk` 的方法、同步存档及激励视频对象仍接近微信/B站 SDK。直接把所有新渠道填入这个接口会将平台差异扩散到共享运行层。

要求：复用游戏规则与内容；每款每渠道独立构建；广告奖励可靠且幂等；缺少可选能力时可以继续正常游戏；保持小包体、可验证的启动性能和清晰的发行维护边界。

## 提议

1. 保留游戏、Game Host 与渲染目标的边界。规则和内容不依赖 SDK；Canvas 与 DOM 入口可以共享规则，具体渲染入口按运行环境选择。
2. 将原生 SDK 名称与回调转换放在各渠道 Adapter。共享运行层只依赖画布、输入、媒体、可见性等已实际使用的语义端口；Game Host 继续提供存档、广告、导航和遥测。广告 Adapter 各自处理初始化、加载/展示、完成判断及清理，只输出统一 RewardOutcome。现有 wx/bl 的公共实现可以复用，但不成为其他渠道必须模仿的 SDK 形状。
3. 原生小游戏与浏览器分别组装运行环境。浏览器渠道采用自己的 SDK 初始化和页面工程；具体 SDK 加载方式按渠道要求确定。保留 ADR-0002 的审核代码/远程制品边界及现有沙箱，不放宽 iframe CSP 来容纳渠道 SDK。
4. 平台入口拥有启动上报、侧边栏、桌面、录屏分享等渠道功能。游戏只发送统一的加载/玩法事件，渠道将其转换为官方接口；玩法开始/停止与前后台可见性分开定义。优先复用现有遥测端口，并保证上报失败不阻断游戏。
5. 构建期选择单款游戏和一个渠道。渠道描述负责入口、产物格式、配置生成与校验；发行配置按 gameId × platformId 保存 AppID、广告位及语言等实际需要的设置。发布状态与平台构建版本独立记录，同一个游戏版本可在不同渠道处于不同审核状态。只有选择的 Adapter、游戏与素材进入产物；运行时不根据 URL 动态选择可执行模块。
6. 明确必需能力与可选能力。初始化后根据 SDK 版本、设备及账号权限确定可用能力；缺失必需能力时启动明确失败，缺失广告等可选能力时正常玩法仍可用。广告展示失败不能伪造完成，完成奖励不得重复发放。玩家/存档身份包含渠道，跨平台账号绑定另行设计；AppSecret 留在服务端。

## 取舍与实施顺序

采用现有 monorepo、Game Host、Canvas 目标和 Vite 构建，无需新增框架或每个平台复制全部 Shell。先把 wx/bl 转换收敛到渠道 Adapter、共享运行层移除原始广告 SDK 假设，并将构建脚本的平台分支转为渠道描述。再按实际接入顺序实现抖音、快手；支付宝先确认选用的运行形态。首个海外浏览器渠道验证另一条组装路径，之后复用该浏览器运行环境。

现在不预建未知渠道的空实现，也不扩展尚未使用的支付、排行榜或统一账号接口。每个平台保留差异代码会增加 Adapter 数量，但能避免游戏和共享运行层充满平台判断。支持多渠道不意味着任意 DOM 游戏可以自动在原生 Canvas 运行，也不意味着所有渠道能力相同。

## 验证与发行维护

沿用 Host 契约检查、实际产物回归和包边界检查。每个已实现渠道覆盖正常启动、SDK 初始化失败、广告完整/关闭/失败/重复回调、存档异常、前后台与资源清理；未实现的渠道不进入通过列表。构建后检查 SDK/资源隔离和大小。真实 SDK、官方工具、设备性能、库存与审核逐渠道验证，VM 检查不替代这些步骤。

## 官方接口差异示例

- [快手小游戏激励广告](https://open.kuaishou.com/miniGameDocs/gameDev/api/ad/rewardAd/ks.createRewardedVideoAd.html)的接入示例直接调用 show；共享层不应要求所有渠道具有相同 load/show 流程。
- [CrazyGames SDK 初始化](https://docs.crazygames.com/sdk/intro/)需要等待初始化；[加载与玩法事件](https://docs.crazygames.com/sdk/game/)分别报告加载开始/结束和玩法开始/停止。
- [抖音再得广告](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/open-ability/rewardagainintroduce)具有多次观看及计数语义；当前单次奖励模型只覆盖实际使用的单次激励，不宣称支持该扩展。

与 [ADR-0002](0002-dual-game-delivery.md)、[ADR-0005](0005-ad-authority-is-host-owned.md)保持一致。现有工程使用方式见 [独立小游戏平台工程](../architecture/native-platforms.md)。
