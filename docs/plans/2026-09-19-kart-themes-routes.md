# 卡丁车主题与路线图独立选择实施计划

**目标：** 开赛前独立选择主题与路线图，八套现有主题适配全部八条路线，并按效果图完善布景。

**架构：** RouteCatalog 保存唯一道路几何配置；ThemeCatalog 保存视觉与接受 TrackData 的布景函数。比赛、碰撞、AI、道具、检查点和成绩由路线决定，主题只负责视觉。保留 Cocos Creator 原生渲染和已有资源加载，不增加依赖。

**技术：** TypeScript、Cocos Creator 3.8.8、Node test、Playwright。

## 1. 通用架构，先单独提交

- 将 WorldDefinition/WorldCatalog/WorldTrack 改名为 ThemeDefinition/ThemeCatalog/ThemeView，scenes 配置目录改为 themes；Cocos 原生 Scene 与资源历史路径不改。
- RouteCatalog 从现有八个定义中提取路线，主题不再携带固定路线。
- Selection、KartController、HUD、KartGame 使用 theme/route/vehicle/driver 四个独立字段与选择行。兼容旧 world 存档，现有每场景成绩键对应原路线，继续保留。
- 提供沿路定位与保守净空检查，布景根据所选路线生成；渲染与物理共用 TrackData。
- 添加独立切换、旧存档迁移、八乘八组合与净空检查；保留八条路线三圈驾驶回归。
- 运行 test、typecheck 和 Web build；提交通用架构。

## 2. 冰川主题

- 冰川专属智能体查看效果图、现有截图与素材后负责 GlacierSample/GlacierGeometry/themes/glacier。
- 雪岸、冰壁、拱桥、科考站适配路宽、坡度及近道，所有道路分支均有可见路面；天空与光照切换恢复完整。
- 运行冰川几何回归和浏览器组合驾驶检查，提交冰川接入。

## 3. 其余主题，每个主题一个智能体

- 城市、沙漠、跨海高速、七彩丹霞、高原与高山、青藏高原草原、浪湾海岸各自调查效果图和现状，记录差距、所需素材与实际准备方式。
- 专属智能体只编辑其主题文件、专属几何/素材与检查记录，共享接口由主智能体维护；分批调度，不同时构建。
- 优先复用已交付模型和贴图；缺失的模块准备后再接入，不能以调查文档代替实际改造。
- 每套主题相对路线布置近景，地标和地形避让主路与近道；路基/桥体随道路高度变化。

## 4. 统一验收与最终提交

- Node 单元检查、类型检查、仓库游戏配置检查。
- Web 构建后运行八乘八加载矩阵，检查主题独立切换不改变道路，路线独立切换保留主题；加载失败/快速切换、选择持久化、按路线成绩。
- 真实键盘和手机触控开始/驾驶/暂停/返回选择，横竖屏截图、典型升降路线和近道组合、错误日志与视觉对照。
- 更新 README、playtest 与各主题素材审计；提交全部成果。用户本次要求提交，未要求推送或平台发布。
