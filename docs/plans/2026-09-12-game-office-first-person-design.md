# 《打工人摸鱼记》第一人称与一周场景设计

日期：2026-09-12。范围：`apps/game-office` 的新玩法、场景目录、一周编排与首个完整场景。

本设计依据用户本次明确要求，替代 [2026-09-07 固定镜头设计](2026-09-07-game-office-realistic-design.md)。保留旧文档的办公室生活灵感、动作因果和公平预警原则；删除旧版固定镜头、按住自动涨分和随机切换老板注视的玩法。新方向是**站在角色眼睛的位置，自己走动、转头、操作物体，度过由不同时间与地点组成的一周**。

本次实现范围是第一人称操作、一周日程与场景选择，以及一个完整可玩的“迟到的最后一分钟”。其他 19 个场景只有明确的设计与预览，展示“待制作”；查看或跳过它们不算通关，不产生摸鱼成绩。下文区分本期交付规则和后续设计，不代表全部场景已经上线。

## 1. 体验与玩法取舍

核心循环是：观察空间与人的意图 → 决定路线或休息机会 → 亲手执行 → 看见危险变化 → 处理自己留下的证据 → 完成收尾。玩家的动作必须改变位置、物体、他人行为或任务状态；仅点击菜单、切换背景或等计时器不构成一个新场景。

一周由五个工作日组成，各日依次经历入场、上午、午间、下午、离场。时间可以从 09:18 跳到 10:07，再到 12:16，不能在下午关结束后无解释地返回上午。每个场景是可探索的小空间，场景之间以明确的时间地点卡切换；本期不实现整栋公司从早到晚连续运行的开放世界。

| 路线                          | 适配结果                                                                          | 决定                         |
| ----------------------------- | --------------------------------------------------------------------------------- | ---------------------------- |
| 固定图片加晃动或全景热点      | 能环顾，不能产生前后左右移动时的视差与真实遮挡，不能完成用户要求                  | 移除旧路线                   |
| Canvas 软件透视的小型三维空间 | 用实际世界坐标投影，移动、碰撞、视线与物体交互共享空间；能复用现有 Web / B 站入口 | 本期采用，控制几何与场景规模 |
| WebGL 与完整实时三维资源管线  | 更适合大量角色、曲面和高质量材质，但需要额外的渲染适配与资源制作                  | 以后按实测画质、帧率需要评估 |

首版采用可读的几何场景，优先把“在办公室里走动并成功躲过老板”做成真实玩法。它不是照片级录像；真实感先来自一致比例、透视变化、遮挡、因果动作和声音。后续画质提升不能改变已经验证的空间规则。

## 2. 第一人称移动与手机操作

- 相机在主角眼睛处。向前后左右移动会改变实际坐标，桌子、屏风、人物的大小与遮挡随之改变；不能用背景平移冒充走路。站立与蹲下改变眼高及可见范围。
- 手机横屏优先。左手虚拟摇杆移动，右侧拖动环顾；触控指针分别跟踪，允许边移动边观察。方向相对于当前朝向，松开、取消触摸或切后台立即停步。
- 提供“启用手机转头”按钮，在需要的平台上通过用户点击请求方向传感器权限。转动或倾斜手机只控制相机朝向，先记录当前中立方向，允许重新校准。无传感器、权限拒绝或宿主不支持时仍能用拖动完成全流程。
- 普通手机方向传感器无法可靠追踪玩家在真实房间里前后左右的位移。游戏内行走由摇杆或键盘控制；不能承诺拿着手机在现实中走一步就会在游戏中走一步。
- 桌面键盘提供移动、蹲下和交互，鼠标拖动观察；不要求传感器或强制鼠标锁定才能游玩。降低视角晃动，限制俯仰，避免默认自动转头或镜头剪切造成不适。
- 视线中心的物体进入可操作距离、没有墙体阻挡时，才显示“拿文件”“启动打印机”“打卡”等具体提示。看不见或隔墙的道具不能远程操作。
- 危险有可见人物朝向、视野提示、字幕和疑心反馈。声音增加空间感，但静音可完成；暂停后计时、输入、风险和声音全部暂停。

## 3. 一周如何组合

完整目标流程：新一周 → 周一迟到场景 → 当日各时段场景 → 当日离场 → 日末结算 → 次日 → 周五离场 → 一周结算 → “开始新的一周”。失败只重试当前场景，不清空前几天的成绩。日末卡明确说明下一天，周末卡明确说明一周已结束。

内置日程由 `src/week.ts` 管理：每条目录包含稳定 ID、名称、地点、时段、直接交互、乐趣和制作状态。`createWeek(seed)` 生成五天各五个场景：

1. 周一第一项固定为 `late-arrival`。其余场景只在适配时段中选择，例如午休不会出现在早晨入场之后的 09:10。
2. 每个时段池按种子洗牌，再跨五天轮换。五天的整体组合都不相同；部分地点可以重访，上午与下午的动作和事件不同。
3. 周一首关固定 09:08 开始。其余叙事窗口分别从 09:08、10:00、12:00、14:00、17:40 开始，各随机增加 0–24 分钟，场景计划时长为十分钟。相邻窗口不重叠；叙事十分钟与玩家真实游玩的秒数分开。
4. 相同种子生成相同周计划，重试关卡保持同一变体，方便学习；“新的一周”换种子，重新组合日程。后续第二个场景出现具体时间限制时，再增加它所需的时间窗口字段。
5. 每个场景加入游戏前独立完成交互与失败验收，再将制作状态从 `planned` 改为 `playable`。不能只修改状态而复用第一关的画面和操作来冒充另一关。

本期可切换日期、查看场景内容、游玩已制作场景，未制作条目提供“查看设计 / 跳过未制作场景”的明确入口。预览走到日末和周末是**日程预览结束**，不宣称玩家已通关全部场景。周统计分别展示实际完成与未制作跳过的数量；只对真实完成的互动计分。待后续场景逐个完成，原有编排自然成为完整可玩的一周。

场景选择页允许直接练习已制作场景。练习重新开始当前关，不悄悄改变整周日期；当前只有首关可练习，不摆出其余关卡的假“开始”按钮。当前不引入解锁货币、通行证、复杂员工关系或无限升级来掩盖内容量。

## 5. 首个完整场景：迟到的最后一分钟

情境：周一早晨，你晚到了几分钟，老板在办公区巡视。目标是从门厅出发，避开持续注视，走到自己的电脑前打卡。不是看一段潜行录像，也不是点“躲藏”后自动抵达；路线与动作均由玩家控制。

### 空间与可操作物体

- 门厅出生点能观察主通道。屏风和桌组构成绕行路线，开阔通道较短但有暴露风险；办公室边界、桌组与屏风参与碰撞。
- 老板有连续位置、朝向与巡逻路径。朝向、距离、视野夹角和遮挡共同决定能否看到玩家，疑心按实际经过时间变化；不随机掷硬币决定“被看见”。
- 屏风允许玩家蹲下利用真实高度差获得遮挡；走到开口处仍有被看见的可能。降低相机不等于获得全局隐身。
- 文件架：走近并对准后拿起文件形成伪装。它能降低部分注意，近距离仍会被识破，不能从拿起那一刻永久免疫。
- 打印机：主动操作后引开老板约 12 秒，并有冷却。打印声音、机器状态和老板转向一致；使用窗口由实际动作产生，不能隔墙无限触发。
- 咖啡：可选的短暂偷闲得分机会。先判断老板在哪里再选择是否冒险；不取咖啡也能完成核心目标。
- 自己的电脑：走到操作距离并对准后打卡，产生明确成功结果。单纯走过终点、计时耗尽或点空白区域不能判为成功。

### 玩家会作出的决定

第一次先在安全入口学会行走和转头，看到老板朝向后选择等待、借屏风绕行，或拿文件再通过。有经验后可以使用打印机制造机会，再绕到咖啡处偷一点闲，最后返回工位。各道具改变的是具体空间条件，玩家应能解释“我这次为什么成功”。

至少保留安全完成和冒险加分两种路线。首次体验的可见预警要容得下一次正常转向或撤回，短暂进入视线先给疑心反馈，不能立即失败。被发现时画面冻结到可解释的现场，给出原因、重试入口和本次实际成绩；成功给到达、用时与额外偷闲评价，再进入本日安排。

本场景变体优先改变老板巡逻相位、已有物体的可用状态和路线机会。后续可以改变屏风/桌组位置，但每个布局都必须重新验证出生点、目标与至少一条可通行路线。随机布局不能把人关进桌子，也不能把唯一目标放到墙后。

| 第三批   | 咖啡、打印机零食、会议室、午休沙发                         | 紧张与放松交替，至少两种有效解法；静音和触屏同样可玩             |
| 第四批   | 电梯、同事协作、线上会议与其他目录场景                     | 每天有足够的已制作内容形成不同组合，再将完整一周作为正式通关体验 |
| 后续品质 | 更多可验证布局、人物表演、材质、空间声、设备分档           | 每次新增都用真实交互与设备数据判断，不先承诺照片级画面或帧率     |

Game Host 仍负责存档、生命周期及平台能力，场景规则不直接调用平台 SDK。Web 与 B 站使用同一套规则和 Canvas 透视语义，宿主分别传入可用的输入与方向能力。继续遵守 ADR-0002 的审核代码交付，以及 ADR-0007 的 Game 自有内容边界；未来场景实现属于 Source Extension，不能通过 Dynamic Content 下载新脚本绕开审核。

本期日程是 Game 内置的纯数据模块，不提前搭建通用关卡编辑器或把整个目录塞入平台公共 schema。旧存档中的共享钱包、其他 Game 字段和旧成绩保持各自语义，新场景成绩不与旧按秒涨分纪录混算；只有完成的新结果才允许发出奖励或写入新成绩。

## 7. 验收清单

- 从入口完整移动到目标，观察左右转头、前后退步和横向绕行时的真实视差；身体不能穿桌、穿屏风或越界，交互不能穿墙。
- 同一个老板位置下，无遮挡暴露、实体遮挡和蹲下遮挡产生可以解释的不同结果；风险不依赖渲染帧数。
- 实际操作文件架、打印机、咖啡和电脑，分别验证反馈、作用限制与收尾；完成一条安全路线、一条冒险路线和一次失败重试。
- 移动与环顾同时进行、触控取消、暂停恢复和销毁重进无卡住的输入、持续音效或隐藏风险增长。
- 手机拒绝方向权限后可用拖动继续；有真实设备时验证启用、校准、横竖屏变化。浏览器触屏模拟不能代替真实陀螺仪验证。
- 相同种子复现日程，不同种子发生变化；连续多组种子均是五天、五段、时间递增、无重叠、每天组合不同。
- 仅首关显示可玩；跳过待制作条目不增加得分或已通关数量；日末、周末、开始新一周和场景练习的入口语义准确。
- 完成 Game 单测、类型检查、构建、代码检查、宿主契约和实际浏览器全流程；原生或真实手机没有运行过的部分在交付中单独说明。

好玩性需要后续真实玩家验证：重点看首次是否知道往哪走、失败后是否理解原因、第三次是否主动试另一条路线，以及能否从紧张中获得成功后的放松。不能用构建通过或界面停留时长代替这些观察。
