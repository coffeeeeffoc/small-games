# 卡丁车按需加载与小游戏邀请

1. 将 resources 大包中的美术拆成按模型、纹理和场景道具组织的 Asset Bundle，保留原资产 UUID。资源加载只请求当前所需包，缓存并合并重复请求；首屏完整加载当前主题、路线、本人车辆和车手，比赛开始才加载机器人与道具，音效按首次操作/使用加载。赛道几何继续只生成当前选定路线。
2. 微信/B站适配代码放在 platforms 下，由游戏构建注入轻量分享桥接；分享携带房间码与房主的四项选择，接收冷启动与热启动邀请。游戏只调用桥接，不直接依赖平台 SDK。保留浏览器邀请链接。
3. 修复 Cocos EditBox 标签左上角锚点与尺寸；邀请入口显示确认/取消，确认后直接加入，已有房间时不静默退出；展示准备、加载、比赛、结束状态。
4. 验证首屏网络请求只包含当前主题/路线/车辆/车手，不包含其他选择及机器人/道具，选车只加载新车，比赛按需加载并可驾驶；检查邀请冷/热启动、取消、失效、重连、输入框缩放定位。完成三端构建、类型检查、单元与双客户端浏览器回归。真机分享/合法域名需平台环境验收。

5. 房间内只有房主可以修改四项选择，服务器校验权限并增加配置版本；所有好友切换并按需加载新选择，旧版本加载回执无效，全部完成后才能准备和开赛。

## 验证记录

- 78 项游戏单元测试、2 项真实 WebSocket 服务测试，游戏/服务类型检查和工作区依赖检查通过。
- Web、微信、B 站构建通过；原生主包约 2 MB，总包约 20 MB，最大独立分包约 1.59 MB。
- 8 个主题与对应路线加载回归通过，冰川材质随所属分包按需加载。
- 两个真实 Cocos 浏览器客户端通过邀请确认、零机器人、独立操作、同步比赛、刷新重连和返回单机。
- 首屏实际网络请求仅包含默认组合的素材；分享链接首次按房主四项选择加载；房主连续修改四项选择、好友同步加载、旧链接更新、无效房间及取消通过。1593 × 726 输入框截图确认文字位于输入区域内。
- 公网隧道首屏单次实测约 28 秒（此前约 70 秒），传输约 3.4 MB；这不是稳定带宽基准。
- 微信/B 站分享桥接已通过 SDK 模拟的冷启动、热启动和分享参数测试；微信体验版两台真机分享、平台域名白名单仍需现场验收。
- 完整三圈触控回归、桌面/横竖屏控制、暂停恢复、键盘和触控音效/静音/氮气、真实超车名次与机器人重新随机回归通过；触控三圈测试中位帧率 60 FPS。
