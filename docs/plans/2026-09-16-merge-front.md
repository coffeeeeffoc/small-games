# 神机合阵 Implementation Plan

**Goal:** 在 `games/local/merge-front` 交付可独立运行、可由 Shell 承载的中文手机策略游戏，完整实现征兵、拖格、合字、升星、武器联动、自动战斗与两种胜负循环。

**Architecture:** 原生 ES Modules，将确定性战斗状态与 Canvas 关节模型分开。DOM 承担可访问的拖放、按钮与说明；同一份状态驱动战场、生产线、合成反馈和结算。复用仓库 Vite、Playwright 与静态 Game Catalog 管线。

**Tech Stack:** JavaScript / Canvas 2D / CSS / Pointer Events / Web Audio / Vite / Node test / Playwright。

## 一、产品与美术方向

名称《神机合阵》，第一卷「云上工坊」。原创神话机关世界：浮空石台、青绿灵晶、纸白工坊面板、朱砂机关与金色符文。采用民间神话人物，不复刻参考游戏题材、素材或关卡。比较三种表达：纯汉字棋子容易读但缺少角色生命力；全 3D 会扩大首版资产和操作成本；本版选用分层关节 Canvas 模型，保留辨识度、攻击动作和完整生命周期。

每个角色有独立头部、躯干、四肢、饰物、标志武器。哪吒红绫、双髻、风火轮；孙悟空金冠、猴面、金箍棒；杨戬三目、青甲、三尖刃。完整人物替代残字印章；机关装备成为人物整体的一部分。首版模型是程序绘制的二维关节模型，并非三维资产。

## 二、主循环与交互

1. 指定购买残字/机关，进入六格候补席；灵石不足或候补满时明确提示且不扣费。
2. 将单位拖至十二格部署台，或点选单位再点目标格。鼠标、触摸使用同一 Pointer Events 流程；取消、失焦与弹窗中断不发生误移动。
3. 同角色不同残字重叠，合并姓名。哪+吒、孙+悟+空、杨+戬均不要求顺序。未补齐的姓名沉睡，不能战斗或生产。
4. 两个同名、同星完整神将合成，最高三星。保留合法装备；冲突装备拒绝合成且不丢物。不同单位可交换位置。
5. 对应机关拖到神将身上成为合体；也可在部署台四邻接触发联动。一件邻接机关只供一位神将使用，避免无限乘区。
6. 战斗持续掉落灵石，可以继续征兵、升星、调阵。神机超频与修复核心提供主动决策。

## 四、双模式

### 防守 · 云关守御

4 列 × 3 行阵地映射到三条战线，右侧先接敌。核心在左，敌人自右来袭。准备阶段主动鸣鼓开战，随后八波推进；波间补给，阵亡神将休整 11 秒后归队。空阵会失败，合理完整阵容、升星和支援可以通关。高波加入混合兵与首领，不能仅靠开局一个神将守到底。

### 进攻 · 神机远征

同一部署台转为生产配方，进度条逐格运行；完整神将/机关到时生成战斗单位，配方保留循环生产。沉睡残字停产。生产前装备/邻接对应机关形成合体配方，增加生产时长，换取更强伤害、生命与技能；修改配方重新计时，避免临出厂免费加装。双方三路自动出兵，战斗单位自主行军、寻找目标、攻击与推晶；敌晶归零获胜，己晶归零失败。单位总量有性能上限，满额时生产等待名额而不吞配方。

## 六、实现步骤与文件

1. `src/content.mjs`、`src/engine.mjs`：角色、残字、武器、交易、合成、邻接匹配、生产、寻敌、技能、双模式胜负；以 `tests/engine.test.mjs` 检查无损事务、睡眠、联动、生产及胜负。
2. `src/render.mjs`：浮空战场、独立角色关节模型、机关、弹道、各生命周期。
3. `index.html`、`src/main.mjs`、`src/style.css`：模式选择、工坊、拖放/点击备选、实时 HUD、图鉴、暂停/结果、音效与成绩。
4. `package.json`、`vite.config.mjs`：独立开发与相对路径构建。Game Catalog、Shell workspace dependency、现有 smoke marker 增加本游戏，保留其他未提交工作。
5. `tests/browser.mjs`：真实拖动唤醒、征兵合成、装备、战斗、生产、暂停、取消、重开与窄屏验证。保存代表性截图到忽略的 `artifacts/`。
6. 完成规则测试、构建、浏览器回归、依赖边界检查；在 README 记录启动方式、实现范围及验证边界。

## 七、平衡与验证标准

- 所有经济与战斗动作由引擎统一校验；无灵石、满席、无效组合不消耗物品。
- 标准模式有可复现的空阵失败和合理策略胜利，险境提高敌方压力；测试胜利不代表所有随机策略都平衡。
- 游戏时间使用完整前台经过时间，运动与交战小步积分；暂停和隐藏时间不补算。
- 验证桌面、390×844 手机竖屏、320×740 窄屏及 844×390 横屏；移动模拟不等于真机或微信客户端验证。
- 按后续要求提交并推送，验证 CI、Pages、SDK 与移动端构建。当前仓库其他进行中的修改不回滚。

## 八、后续优化顺序

1. 实际游玩数据驱动数值：首波失败率、残字滞留时长、常用阵型、两种模式通关时间。
2. 拖拽预览显示落点的合成/交换/联动结果，武器邻接优先级可视化；生产队列支持暂停某条线。
3. 扩充关卡与三选一局内成长，再增加角色。先验证现有三将都有用处。
4. 需要更强近景表现时替换为完整美术帧动画或三维骨骼资源，复用现有生命周期接口；增加真机与微信 WebView 性能验证。
5. 若对局时长证明有需要，再增加版本化中途存档、关卡解锁与长期进度。

## 九、本版交付验证

- 引擎测试、Vite 生产构建、工作区依赖边界、Shell 目录集成测试通过。
- 构建后的 Chromium 浏览器通过 8 组场景：真实鼠标与触摸拖拽、两字/三字觉醒、合体、升星、取消、暂停/后台恢复、生产联动、空阵失败重开、双模式胜利切换，以及 390×844、320×740、844×390 排版检查。
- 实际 UI 操作参考策略：进攻 69 秒 / 27 击杀，防守 353 秒 / 120 击杀，均保住核心；单个合体神将与空阵在引擎模拟中均失败。该结果用于证明可玩与可通关，后续仍需通过玩家试玩调整难度。
- 用例只读取状态快照，购买、放置、技能通过可见 UI 操作；加速前台时间用于完整战局回归。未完成物理手机和微信客户端验证。
