# Fold the World 100 关 Implementation Plan

**Goal:** 在多 agent 产品设计与复审收敛后交付可游玩的 100 关，验证并提交推送。

**Architecture:** 沿用现有 Puzzle、物理、折叠与输入；关卡和提示为静态数据。内容按设计分工隔离为四份关卡数据与对应输入路线，主入口负责组合。前段采用重排方向，让第 4 关开始承担判断；旧进度通过显式版本迁移保留，旧成绩只迁入确认完全一致的关卡。

**Tech Stack:** 现有 TypeScript、Phaser、Vite、node:test、tsx、Playwright；不新增依赖。

**实施验收：** 100关与四章入口完成；151项正式测试、100关生产浏览器路线、1/24/25/45/100全触摸通关、章节键盘、全屏、存档迁移及Shell集成均通过。物理参数未改，局部公平性校准与独立复核单独记录。当前执行证据见[游戏测试记录](../../games/local/fold-the-world/docs/TESTING.md)及其中的带源码指纹报告；真人首玩难度和手机真机仍未验证。

## 开始条件

已满足：四份逐关设计完成，R1–R4独立评审/修订有记录，主产品文档已冻结，100/100关D通过。用户已授权继续实现、提交和推送，无需额外批准流程。正式物理校准若改变核心解题依赖，须记录并复评。

## 1. 关卡与提示

- `games/local/fold-the-world/src/levels.ts`：组合为恰好 100 关。
- `games/local/fold-the-world/src/hints.ts`：组合对应的 100 份三层提示；不改变提示只读原则。
- 关卡按 01–25、26–50、51–75、76–100 分为四个独立数据文件；最终文件名在实现分派时固定，避免写入冲突。
- 复用正式 `defineLevel` 校验原始与所有允许折后几何；沿用平台、钥匙、出口、尖刺四类实体。
- 对每关走通正式输入路线。失败先定位不成立的空间依赖，再修订关卡/路线；不能修改物理参数让单关硬通过。

## 2. 章节与进度

- `games/local/fold-the-world/src/main.ts` 与 `src/style.css`：100 关按小章节浏览，显示章进度及当前关，手机 44px 控件、关闭返回和键盘可访问性保留。
- `games/local/fold-the-world/src/progress.ts` 仅按已冻结的迁移决策修改；新存档键保留原 v1 数据，音效偏好和合法访问权限延续，改版关卡不继承旧最佳成绩。验证末关上限、旧通关延续及损坏数据边界。
- `games/local/fold-the-world/tests/core.test.ts` 中原以 99 代表越界的样例需换为真实越界值，保留合法 99 关成绩。
- 通关、重玩、提示与选关以同一关卡序列为准。
- 同一道折痕的左右两个方向以完整折法区分按钮/测试选择器，不只匹配 crease ID。固定支撑若被折入层视觉遮住，需让可操作顶面明确可读，不能要求玩家盲试。

## 3. 全量可解性与质量检查

- `tests/routes.ts` / `tests/routes.test.ts`：扩展为 100 条真实运动路线，验证钥匙、成功状态、死亡数、折叠计数、提示阶段和无状态修改。
- 记录逐关已知解统计；增加代表性错误折法/省略关键步骤反例，不把给定解证明误称最短解证明。
- 检查数量、标题、数据唯一性及章节边界；人工检查结构相似项，拒绝镜像/平移凑数。
- 运行 `pnpm --filter @coffeeeeffoc/fold-the-world test`、`typecheck`、`build`。

## 4. 浏览器验收

- 复用并按新章节入口调整 `tests/browser.ts`，测试生产构建真实输入路径。
- 全量正式物理检查与实际浏览器覆盖分开列出；覆盖早、中、末段、每种核心依赖和最终关。
- 覆盖新增章节切换、旧存档/继续、100 关末尾、暂停/恢复、提示、触控、窄屏、真实全屏。
- 记录执行日期、构建地址、浏览器和未覆盖环境。任何跳跃/提示/章节问题修复后重验受影响流程。
